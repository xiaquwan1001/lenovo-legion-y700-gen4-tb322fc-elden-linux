# Q28 诊断上机包 —— vk73-q28diag（DSI 命令 DMA 超时点寄存器 dump）

> 生成时间 2026-10-09。产物：`out/boot-elden-vk73-q28diag.img`（+ `.manifest`）。
> 内核改动 = `patches/q28-dsi-regdump.patch`（仅诊断打印，成功路径零功能变更）。
> 目的：在 `CONFIG_STRICT_DEVMEM=y` 下绕开 `/dev/mem`，从驱动内部在 bonded 命令 DMA
> 超时（`-ETIMEDOUT`）的那一刻 dump DSI host 寄存器，钉死 Q28「首条 bonded 命令 -110」时
> **DMA 引擎到底跑没跑 / 有没有被编程 / 是不是根本没电**。

## 0. 一句话身份（务必核对再上机）
- 镜像 `uname -r`（烤进 Image 的 UTS）= **`7.2.0-debug-vk64-gd02658e63cf6`**
  = 设备已装模块目录名（与 `out/boot-elden-vk72-q28dsi2.manifest` 的 `kernel_uts` 逐字一致）。
  → 已装模块的 vermagic 能匹配，可直接 `fastboot boot`，**不需要刷模块、不需要写盘**。
- DTB / ramdisk / cmdline 与 vk72-q28dsi2 **逐字节一致**（`dtb_packed_sha256`、
  `ramdisk_sha256`、`cmdline` 三项在两份 manifest 中完全相同），唯一差异是内核二进制
  （多了 regdump 打印，`kernel_payload_sha256=0d5a2936…` ≠ vk72 的 `6b435858…`）。
- `image_sha256=8596f1c7fc7e72b7f3294a65ed839d5e0124a3c02961734a9d0b947fbe5e91b4`
  （以实际 manifest 为准，重打会变）。

## 1. 刷写（父进程执行，零写盘）
```
fastboot boot out/boot-elden-vk73-q28diag.img
```
`fastboot boot` 只加载到 RAM 跑一次，不写 boot/boot_b 分区。设备当前无 USB 常连通道，
此步由父进程独占硬件执行；子代理不碰设备。

## 2. 上机通道 = SSH（USB-NCM），**adb 恒无效**
设备是 mainline Linux，**没有 adbd**，任何 adb 命令都无意义。USB-NCM 打通后：
```
# 主机侧 IP = 192.168.7.2，设备 = 192.168.7.1
ssh root@192.168.7.1
```
（若 NCM 未自动起：主机 `ip addr show` 找 usb0/ncm 接口配 192.168.7.2/24。）

## 3. 抓 dmesg（诊断行以 `Q28` 打头，每个失败点最多 dump 2 次，master/slave 共用配额）
```
dmesg | grep -E "Q28|bonded|dcs data|timing 1904|Failed to init|PLL.*lock failed|command DMA"
```
关键打印形如（`role`=master/slave，`DSI0`=ae94000 / DSI1）：
```
Q28 master DSI0 CTL=… STATUS0=… FIFO=… CMD_DMA_CTRL=… CMD_DMA_CTRL1=…
Q28 master DMA_BASE=… DMA_LEN=… TRIG_CTRL=… TRIG_DMA=… INTR_CTRL=… PHY_RESET=…
Q28 master CLK_CTRL=… CLK_STATUS=… LANE_STATUS=… TIMEOUT_STATUS=… ACK_ERR_STATUS=…
Q28 master ctx: ch=… lanes=… bonded=… en=… cmd=… vid=… cmd_dma_busy=… cmd_engine_busy=… pll_unlock=…
```

## 4. 失败态重启纪律（硬约束）
- **禁止 `reboot -f`、禁止连续热重启**：累积热重启会加剧 Q28（见 Q28b 取证）。
- 需要重来：`echo b > /proc/sysrq-trigger`（硬看门狗复位），并**优先冷启**（彻底断电后
  再上电），别在失败态间连打温启。
- 本轮 Q28b 现场已取证完毕，下一次上机前需冷启。

## 5. 判读表（逐寄存器：位域含义 + 失败时预期 + 「若 X ⇒ 结论 Y」）

位定义全部取自本树 `drivers/gpu/drm/msm/generated/dsi.xml.h`；ctx 解码取自
`dsi_host.c`。**前 5 条是最关键判据，先只看这 5 条。**

### ★ 判据 0（最显眼，先判）：全寄存器读回 0 ⇒ GDSC 断电，不是 DMA 楔死
- 现象：`CTL=0 STATUS0=0 CLK_STATUS=0 CMD_DMA_CTRL=0 DMA_BASE=0 DMA_LEN=0 INTR_CTRL=0
  LANE_STATUS=0` … **一片 0**。
- 含义：MSM DSI host 挂在 `mdss_gdsc`/`gfx` genpd 上；电源域 off 时对外读返回 0
  （读不回真实值）。这正是 Q28b 记录的第二种签名（panel init 成功但 mdss_gdsc/gfx
  genpd 全程 off、`dmesg` 见 `DSI PLL(0) lock failed status=0x00000000`、
  `disp_cc_mdss_*: orphan reparent failed -110`、`/proc/interrupts` dsi1_isr=0）。
- **结论**：全 0 ⇒ **根因在电源域没上电（genpd/GDSC/clock 从未 enable），不在 DSI 命令
  DMA 逻辑本身**；命令 DMA「没跑」只是没电的表象。→ 转 `dpu_kms`/genpd attach 路径查，
  别在 `dsi_cmd_dma` 里调。
- 反向：若寄存器**读到非 0**（CTL 的 en/cmd 位可见、STATUS0 有 busy 活动），说明这次
  **有电**，进入判据 1~4 正常判 DMA 引擎是否跑过。

### 判据 1：DMA_BASE==0 或 DMA_LEN==0 ⇒ DMA 根本没被编程
- `DMA_BASE`(REG 0x44)、`DMA_LEN`(0x48)。`dsi_cmd_dma()` 正常会写 DMA_BASE=命令缓冲 IOVA、
  DMA_LEN=len。
- **结论**：有电（判据 0 已过）但 `DMA_BASE=0` 或 `DMA_LEN=0` ⇒ 超时这一刻 DMA 描述符
  为空/未编程 ⇒ **-110 的原因是 DMA 从未被喂进数据**（xfer 编程/内存映射问题），而非
  引擎跑起来后卡死。→ 查 `dsi_cmd_dma()`/`msm_dsi_host_bonded_cmd_arm_master()` 的
  写入路径与 iova。

### 判据 2：STATUS0 的 CMD_MODE_DMA_BUSY(bit1=0x2) / CMD_MODE_ENGINE_BUSY(bit0=0x1)
- `STATUS0`：bit0 `CMD_MODE_ENGINE_BUSY`、bit1 `CMD_MODE_DMA_BUSY`、bit4 `DSI_BUSY(0x10)`。
  ctx 已解出 `cmd_dma_busy=`/`cmd_engine_busy=`。
- **若 `cmd_dma_busy=1`（超时仍 busy）** ⇒ DMA **确实起跑且没跑完** ⇒ 引擎/总线真楔住
  或下游（PLL/byteclk/lane）不吞数据 ⇒ 「DMA 跑了一部分卡住」。
- **若 `cmd_dma_busy=0` 且 `cmd_engine_busy=0`** ⇒ 超时这一刻引擎空闲 ⇒ 要么早已完成但
  done IRQ 丢了（见判据 4），要么根本没被触发（配合判据 1/3）。
- 若同时 STATUS0 **非全 0**（如 DSI_BUSY 亮）但 busy 位都灭 ⇒ 状态机活着，问题在触发/中断。

### 判据 3：CLK_STATUS 的 PLL_UNLOCKED(bit16=0x10000) + byteclk/escclk active 位
- `CLK_STATUS`(0x11c)：bit16 `DSI_CLK_STATUS_PLL_UNLOCKED`（**置 1 = 未锁**）；低位
  byteclk/pclk active：`DSI_DYN_BYTECLK_ACTIVE(0x80)`、`DSI_AON_BYTECLK_ACTIVE(0x40)`、
  `DSI_DYN_CMD_PCLK_ACTIVE(0x1000)`、`DSI_CMD_PCLK_ACTIVE(0x2000)`、`ESCCLK_ACTIVE(0x100)`。
  ctx 已解出 `pll_unlock=`。
- **若 `pll_unlock=1`（bit16 置位）** ⇒ DSI PLL 没锁 ⇒ 没有 byteclk ⇒ 命令 DMA 即使
  起跑也发不出去 ⇒ -110 根因是 **时钟/PLL**（与 `dmesg` 里 `DSI PLL lock failed` 交叉印证）。
  全 0（判据 0）也满足此判据，但全 0 已优先归因断电。
- **若 `pll_unlock=0`（已锁）但 byteclk/pclk active 位全灭** ⇒ PLL 锁了却没喂给 DSI 通路
  ⇒ clock 树 / disp_cc_mdss_* 门控问题（Q28b 里 orphan reparent -110 的形态）。

### 判据 4：INTR_CTRL 的 CMD_DMA_DONE mask(bit1=0x2)
- `INTR_CTRL`(0x10c)：`DSI_IRQ_MASK_CMD_DMA_DONE = 0x2`。`dsi_cmd_dma_intr_update()` 在
  等 DMA 时清该 mask（放行 done IRQ），成功后再屏蔽。
- **超时这一刻 `INTR_CTRL & 0x2` 应为 0**（done 中断应被放行）。
  - **若 =1（仍被屏蔽）** ⇒ done 完成中断被 mask 掉 ⇒ `wait_for_completion_timeout()`
    收不到完成、必然 -110，但 DMA 可能其实传完了 ⇒ 完成信号/中断路由问题（对照代码里
    已有的 "command DMA completed without IRQ" 分支）。
  - 若 =0（放行）却仍超时 ⇒ 真没产生 done（回到判据 1/2/3：没编程 / 卡住 / 没时钟）。
- `INTR_CTRL` 还常读回其它已屏蔽位属正常，只看 bit1。

### 判据 5：CTL 模式位 + CMD_DMA_CTRL 编程位（确认「在命令模式、命令 DMA 已配置」）
- `CTL`(0x0)：bit0 `DSI_CTRL_ENABLE`、bit1 `VID_MODE_EN(0x2)`、bit2 `CMD_MODE_EN(0x4)`；
  ctx 解出 `en=`/`cmd=`/`vid=`。
- **bonded 命令传输期望 `en=1 cmd=1 vid=0`。**
  - **若 `cmd=0`（CMD_MODE_EN 没置）** ⇒ host 不在命令模式 ⇒ 上层模式配置错误，命令
    DMA 不该跑；-110 是路径走错。
  - **若 `en=0`** ⇒ host 根本没使能（配合判据 0：多半是没电）。
- `CMD_DMA_CTRL`(0x38)：`PACKET_TYPE(0x01000000)`、`FROM_FRAME_BUFFER(0x10000000)`、
  `WC_SEL(0x20000000)`、`LOW_POWER(0x04000000)`、`BROADCAST_EN(0x80000000)`、
  `BROADCAST_MASTER(0x40000000)`。首条 DCS（`ce 8c a9 00`）正常应有 `PACKET_TYPE` 等
  非零编程。
  - **若 CMD_DMA_CTRL 全 0 但已排除断电** ⇒ 命令包类型/长度没编程（同判据 1 一族）。
  - bonded 场景 `BROADCAST_EN/MASTER` 位应体现主从分工（master 侧）。

### 辅助寄存器（次要，佐证用）
- `FIFO_STATUS`(0x08)：命令 FIFO 读写指针；配合 busy 位看数据有没有进 FIFO。
- `LANE_STATUS`(0x0a4)：各 data lane 状态位；全 0（有电前提下）⇒ lane 没起来。
- `TIMEOUT_STATUS`(0xbc)、`ACK_ERR_STATUS`(0x64)：非 0 ⇒ 总线层报超时/ACK 错误（链路/时序），
  与「-110 但寄存器活着」并列时优先看这两个是不是有置位，能区分「引擎卡死」vs「对端 NAK」。
- `TRIG_CTRL`(0x80)/`TRIG_DMA`(0x8c)：DMA 触发源配置；正常命令模式用软件触发。
- `PHY_RESET`(0x128)：PHY 是否在复位态；置位可能解释为何无字节发出。

## 6. 交叉：与 vk72-q28dsi2（无 dump 的上一版）比对
同一 UTS 下 vk72 的 `dmesg` 只有 `command DMA timeout: status=0x…`（status 即 INTR_CTRL 值）。
本包在同一超时刻补全了上面整套寄存器 ⇒ 若某 boot 两次都有，直接对照「status 位 + 本包
的 STATUS0/DMA_BASE/DMA_LEN/CLK_STATUS」即可判定：**没电 / 没编程 / 没时钟 / 卡住** 四选一。
