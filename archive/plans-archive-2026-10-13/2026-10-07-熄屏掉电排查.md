## 0. 已确立的复现器（务必用这个，别再用旧命令）

```sh

P=$(pidof phoc); D=$(tr '\0' '\n' < /proc/$P/environ | sed -n 's/^DBUS_SESSION_BUS_ADDRESS=//p')

  --object-path /org/gnome/ScreenSaver --method org.gnome.ScreenSaver.SetActive true
```
**禁用**：`wlr-randr --off`、`modetest -w 36:DPMS:3`（本机为空操作，dpms 不变）。
`scripts/g1-22-dpms-test.sh` 已改用真实触发。

判据（每变体 ≥5 轮）：
- 存活 = `boot_id` 不变 + `uptime` 递增 + `/root/powerlog.txt` 空 + `blankspy` 连续。
- 复现 = 触发后 ~6 s 断；`powerlog` 空（非用户态）、`blankspy` 截断、kmsg 无输出、pstore 空。

## 1. 先确认「镜像/模块」是不是真变量（不重建内核，只需 fastboot）

已知唯一存活样本 = `fastboot boot out/boot-elden-sd-base.img`（vk47，UTS `sd-base`，**磁盘无该 UTS
模块目录 ⇒ 相机等 `=m` 全不加载**）×8；boot_b（vk47clean，模块**全加载**）稳定复现。

步骤（保持 USB 插着以自动回启；DP/USB 状态全程一致）：

1. **复现基线**：`fastboot boot out/boot-elden-vk61.img`（boot_b 同物）→ 真实触发 ≥3 轮 → 预期**断**。
2. **确认存活**：`fastboot boot out/boot-elden-sd-base.img` → 真实触发 ≥5 轮 → 预期**存活**。
   若这里也断 ⇒ 「sd-base 存活」不成立，跳 §3。
3. **单变量加模块（关键）**：在设备上把 vk47clean 的模块目录**软链/复制**成 sd-base 的 UTS 名：
   ```sh
   cd /lib/modules
   ln -sfn 7.2.0-debug-vk47clean-gbd114ca335e1 7.2.0-debug-sd-base   # 或 cp -a
   # 注意 camera-modules-load.sh 用 `uname -r` 找目录；depmod 会在 boot 时重建
   ```
   再 `fastboot boot out/boot-elden-sd-base.img` → 真实触发。
   - **断** ⇒ **`=m` 模块（几乎全是相机栈）是变量**，进 §2。
   - **仍存活** ⇒ 与模块无关，差异在 **RAM initramfs `/init` 版本**或内核构建，进 §3。

> 说明：直接 `modprobe -r` 相机模块不可行（绑定传感器）；`blacklist` 也拦不住
> （`modprobe --showconfig` 已生效但模块仍载入，怀疑 RAM initramfs/ 显式 insmod）——所以用
> 「有/无模块目录」来开关，而不是卸载。

## 2. 若模块是变量：二分到具体模块

用 `sd-base` 的「模块目录」做开关，逐组放进/移出（每组一次 fastboot boot + 真实触发）：
- 组 A `clk/i2c`：`camcc-sm8750`、`cambistmclkcc-sm8750`、`i2c-qcom-cci`
- 组 B `pmic`：`wl2868c-regulator`（相机 LDO）
- 组 C `media`：`qcom-camss` + `v4l2-*`
- 组 D sensors：`s5kjns`/`gc08a8`/`gt9764`/`leds-qcom-flash`
先 A→D 逐个加；命中后再在其内部二分。重点盯 **`wl2868c`（LDO）与 `camcc`（CAM_CC GDSC）**：
它们改的是**供电/GDSC**，最可能让面板 disable 时的电压轨塌陷。

## 3. 若与模块无关：查 RAM-init 与内核

1. **RAM initramfs `/init`**：sd-base 用 `out/initramfs-full-elden.cpio.gz`（旧 init `7eae6f39`），
   boot_b 用「原 ramdisk 换新 `/init`」（`ae65f758`，= 真源）。做 A/B：
   `KDIR=/tmp/kdirD2 RAMDISK=out/initramfs-full-elden.cpio.gz VERSION=x` vs 用 boot_b 的 ramdisk 重打包同一内核。
2. **内核字节级对比**：`sd-base` 内核 vs `vk47clean` 内核（`extract-ikconfig` 比 config；`objdump`/strings 比
   panel/camcc/regulator 段）。同源 `bd114ca33`，config 应≈同，差异可能只是 `LOCALVERSION`。

## 4. 机制取证（与上面并行/若都排除）

面板 disable 是嫌疑（`PITFALLS` #124：仅关背光幸存，禁用 DSI/面板供电即断电）。需**拿到断电前最后一步**：
1. **加 printk**（需重建内核）：在 `panel` 的 `disable`/`unprepare`、`msm_dsi` 的关断、
   `regulator_disable`（`vreg_6v1_vsp`/`vreg_5v8_vsn`/`vreg_1v8_vddio`）路径加带时间戳的 printk。
2. **ftrace 落盘**：`echo 1 > .../events/regulator/enable` + `trace_pipe` 重定向到 ext4 并**每条 fsync**
   （`kmsgspy` 的同类思路），抓断电前最后事件。
3. **逐轨拨供电**：停合成器后，用 `/sys/class/regulator/*/state` 手动 off/on 三条面板轨，定位哪条导致整机断电。
4. **串口兜底**：`ttyGS0`（USB ACM）在 `usb-gadget` 起来后才有；早期不可用（#110）。若走 USB 串口，
   注意 USB 会带来 VBUS/自动回启。

## 5. 纪律与陷阱

- 每次换镜像都需 `fastboot boot`（要 USB）——**USB/VBUS 是恒定项**（本轮已证不是单变量），
  但记录时注明「USB=插着」。
- 断电后：USB 插着 → **VBUS 自动开机**（看着像重启）；纯电池 → 真关机，需**物理按键**（用户执行）。
- 判「存活」必须同 `boot_id`；判「复现」必须 `powerlog` 空 + `blankspy` 截断。
- 单变量：一次只动一个（镜像 / 模块组 / ramdisk / printk）。
- 禁止再用 `wlr-randr`/`modetest` 当触发（空操作）。
