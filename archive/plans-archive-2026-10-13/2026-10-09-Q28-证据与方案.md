# Q28 面板 init 间歇失败 — 证据与方案（2026-10-09）

> 权威状态仍在 `TASKS.md §5 Q28`；本文件只放本轮新证据与候选方案。

## 1. 本轮新证据（2026-10-09，U2/vk72 设备实测）

### 1.1 失败序列（含 retry 补丁的真实行为）
```
[    8.794] msm_dsi ae94000.dsi: timing 1904x3040@165Hz clk=1064606 ... (bonded=1 dsc=1 wide=1)
[    9.035] msm_dsi ae94000.dsi: bonded command DMA failed: master=-110 peer=0
[    9.035] panel-novatek-nt36536 ae94000.dsi.0: sending dcs data ce 8c a9 00 failed: -110
[    9.035] panel init attempt 1 failed: -110, resetting and retrying
[    9.064] panel-novatek-nt36536 ae94000.dsi.0: sending dcs data ff 20 failed: -5
[    9.094] panel init attempt 2 failed: -5, resetting and retrying
[    9.094] Failed to initialize panel: -5
```
- 首条 DCS = **`ce 8c a9 00`**（不是 `ff 20`），在 **bonded 双 DSI 命令 DMA** 上超时（`master=-110 peer=0`，master = DSI0/ae94000）。
- retry 补丁（vk64 commit d02658e63）**跑了但无效**：第二次/第三次拿 **-5 (EIO)** ⇒ 失败后 **DSI host 已被楔死**，不复位 host/PHY 的重试必然失败。
- 失败后 DPU 全面崩：`vblank timeout 4208c0`、`reset failure: -22`、`frame done timeout`、`drm_crtc_wait_one_vblank` WARNING 刷屏。
- 面板连接器仍报 `connected/enabled/dpms=On`，背光 511（=上电但无画面）。

### 1.2 ★冷/热启差异（本轮实测定性）
- **热重启**（`reboot -f` / sysrq-b）连续 **5/5 失败**；
- **完全断电冷启后正常进桌面**（用户实测）。
- 补充：`reboot -f` 在面板失败态会**挂住**（DPU 卡死挡住关机路径）⇒ 失败态重启必须 `echo b > /proc/sysrq-trigger`。
- ⇒ 强假设 **H_cold**：失败态不被 warm reset 清除，**面板/DSI PHY 的复位在上电冷启才发生**；连续失败会累积。

| H_bonded（双 DSI bonded 命令 DMA 本身） | ◐ 首条即挂在 bonded DMA master 侧 |

## 2.5 ★根因机制（父进程静态分析，2026-10-09）：bonded 命令失败是永久闩锁

- `drivers/gpu/drm/msm/dsi/dsi_manager.c:41` `static bool dsi_bonded_cmd_failed;`
- 失败时 `dsi_mgr_bonded_cmd_xfer()` 置 `WRITE_ONCE(dsi_bonded_cmd_failed, true)`（:642；另 :375 同）。
- 之后 `msm_dsi_manager_cmd_xfer()`（:674）`if (lock_pair && msm_dsi_manager_cmd_failed()) { ret = -EIO; goto out_unlock; }`
  ⇒ 后续**所有** bonded 命令直接 `-EIO`。
- **全树无任何地方把它清回 `false`**（`grep dsi_bonded_cmd_failed ... | grep -i false` 零命中）。
- ⇒ 解释实测：首条 DCS -110 → 闩锁置位 → retry 必拿 **-5(EIO)** → 本 boot 永无恢复；只有**全新 boot**（静态变量复位）才可能成功。

### 2.6 对应修复方向
1. **在 DSI host/PHY 复位路径里清除闩锁**：给 `dsi_manager.c` 加复位函数（`dsi_bonded_cmd_failed = false` + 复位 master/slave 命令 DMA 引擎与 CTL），并在 `msm_dsi_host_reset`/`msm_dsi_manager_reset`/mode reset 时调用。
2. **让面板 retry 前触发一次 DSI 复位**：`novatek_prepare()` 的 retry 目前只 `novatek_reset()`（面板 GPIO+供电），**不碰 DSI host/PHY** ⇒ 即使清了闩锁，host 也可能仍楔死。retry 应走「DSI host 复位 + PHY 重锁 + 清闩锁」再重发首命令。
3. **首选先降低首条 -110 概率**（真正根因）：首条 DCS 发在 bonded 同步命令 DMA 上，超时 `master=-110`；检查首命令前 DSI PHY PLL 是否已锁、CTL 是否已使能、`bonded_wait_video` 是否真等到了 video 引擎就绪。

> 实现须在设备上验证（Q28 每 boot 间歇），并与 `PITFALLS #16` / vk64 的 retry 补丁一起收敛。注意：不要连续热重启（累积失败），失败态 `reboot -f` 会挂住，用 SysRq-b。

## 2.7 已实现的候选补丁（主机侧，2026-10-09）

- 补丁文件：`patches/q28-dsi-cmd-recover.patch`（基于 **vk64 源 d02658e63**）。
- 内容：
  - `dsi_manager.c`：新增 `msm_dsi_manager_cmd_reset()`；新增有界恢复 `dsi_mgr_bonded_cmd_recover()`（对 master+slave 做 `msm_dsi_host_reset()` 后清闩锁）；`cmd_xfer` 的闩锁短路改为「最多 3 次恢复后重试」，成功时计数清零。
  - `dsi_host.c`：新增导出 `msm_dsi_host_reset()`（`dsi_sw_reset` + `msm_dsi_host_reset_phy`）。
  - `dsi.h`：对应声明。
- 测试镜像：`out/boot-elden-vk72-q28dsi.img`（sha `9db52462…`；内核=`Image-vk64-q28.gz`，UTS `7.2.0-debug-vk64-gd02658e63cf6-dirty`；DTB=`out/sm8750-lenovo-elden-q28-dsi.dtb` 含 G1-34 的 fastrpc non-secure；ramdisk=full；`elden_nocamera=1`）。
- ⚠️ 因树 dirty，`uname` 带 `-dirty` ⇒ **与设备 `/lib/modules` 不匹配**（显示/builtin 不受影响，传感器模块会加载不上）；若需传感器共存，应在 d02658e63 上 commit 后再编或同步重编模块。

### 测试判据（任一 boot）
- **修复生效**：dmesg 出现 `panel init attempt 1 failed: -110` 后**不再出现** `Failed to initialize panel`，且后续有 `bonded cmd failed; host/phy reset, retrying`，面板出画面。
- **未生效**：仍见 `Failed to initialize panel: -5`。
- 仪用 `fastboot boot`（零写盘）；失败态重启用 SysRq-b。

## 3. 候选方案（按代价×把握）

1. **retry 前复位 DSI host + PHY**（改 panel/msm 驱动：第 N 次重试前对 DSI host 做软复位、关开 PHY PLL、重置 CTL），或把失败重试改成**触发一次 DRM modeset 级重初始化**。代价中、把握中——直击「-5 host 楔死」。
2. **boot 早期显式复位 DSI/面板**：在 msm 或 panel probe 前，对 DSI host/PHY 与面板 reset-gpio 做一次确定的掉电/复位序列，清 bootloader 遗留态（对应 H_cold 观测）。
3. **首命令时序**：`regulator_bulk_enable` 后加建立延时、reset 末→首命令留 t_init_delay（DCS 常 120ms）+ 遵循 6–40ms 窗口。
4. **取证增强**：失败态抓 DSI host/PHY 寄存器（`/sys/kernel/debug/dri/0/DSI-1/*` 或加 debugfs dump）+ 读 PLL 锁定状态，定位是「命令发不出」还是「发出无 ACK」。

## 4. 设备操作注意（本轮踩坑）

- 面板失败态下 **`reboot -f` 会挂住**；用 `echo b > /proc/sysrq-trigger`。
- 失败后**不要连续热重启**（累积失败）；要么冷启，要么先修 retry 的 host 复位。
