## 0. 结论先行（一页）

| # | 结论 |
|---|---|
| 1 | **硬前提：所有 x86 转译链（Box64 / FEX / Hangover / qemu-user+wine / Steam）都是 glibc 生态**。本机是 **musl 1.2.6**，无 glibc、无 32 位 glibc。Box64 在 musl 上**编译失败**（上游 issue #3396，2026-01），FEX 无 Alpine 包。→ **必须在设备上先有一个 glibc aarch64 用户态**（chroot / LXC / proot）。这是所有方案共同的、无法绕过的第一步。 |
| 2 | **首选方案：glibc aarch64 容器 + Box64(DynaRec NEON) + Wine(wow64/WowBox64)**。社区最成熟、文档最多、可离线可控；预期 CPU 损失 ~30–50%。备选更快的"首个 exe"：**Hangover 11.16 单 tar**（Wine arm64ec + box64/qemu，预编译）。 |
| 3 | **Valve 官方路线（FEX+Proton，Steam Frame 同款）存在且最"对路"**，但本机 **无 SVE/SVE2** → FEX 走 NEON 回退，性能红利打折；且 FEX 还需再拉一个 x86_64 rootfs，落地最重。 |
| 4 | **图形栈没有障碍**：宿主 Mesa 26.1.x 的 freedreno（=Turnip）Vulkan 已实测 `Adreno (TM) 830 / turnip Mesa driver / api 1.4.354`。DXVK/VKD3D-Proton → 宿主 Vulkan 通路成立。 |
| 5 | **取巧路径（Waydroid + Winlator/GameHub）反而可能是"真玩游戏"成功率最高的一条**：Android 侧 Turnip 对 A8xx(Gen8) 的支持 2026 年已成熟、Winlator 社区体量最大；本机 Waydroid 已跑通且自带自编 Mesa 26.1.8（含 libvulkan_freedreno）。代价：依赖容器内 Android Vulkan（需验证）+ 触屏交互别扭。 |
| 6 | 硬约束逐一核实：**无 AVX/AVX2 物理指令** → Box64/FEX 会**模拟暴露**（BOX64_AVX=2 默认），游戏不会拒跑，只是 256 位 SIMD 拆成 128 位 NEON 更慢；**无 /dev/kvm** → 无硬件虚拟化加速（纯用户态 JIT 才是正路，本就不该用 qemu 全系统）；**32 位**靠 wow64/Box32/FEX 双精度，**不装 32 位宿主库**；**RAM 实测 10.6G**（非 8G）但现代 3A + Steam 客户端 + shader cache 仍吃紧；**反作弊/DRM 是无解硬门槛**（EAC/BattlEye/Vanguard 拒绝模拟器环境）。 |

## 2. 核心架构判断：musl 与 glibc

- Box64：C 编写、cmake 构建，**musl 上编译失败**（issue #3396，2026-01），官方预编译产物为 Debian glibc `.deb`（Pi-Apps-Coders 每日构建 `box64-generic-arm`）。
- FEX：仅官方支持 Arch/Fedora/openSUSE/Ubuntu（全 glibc）；**无 Alpine 包**；且在 AArch64 上**强制要求一个 x86_64 rootfs**（FEXRootFSFetcher 下载）。
- Hangover：预编译 tar 面向 debian12/13、ubuntu22.04/24.04/25.10/26.04（glibc）。
- Wine：Alpine 的 `wine-11.0` 是 musl aarch64 版，只能跑 ARM64 Windows 程序；跑 x86 必须 glibc 版 wine（多架构或 WOW64）。
- Steam：客户端/运行时 glibc，且 Steam 客户端引导是 32 位 x86。

**结论：** 不在 Alpine 宿主机上硬塞 glibc（sgerrand glibc 方案有与 musl 包冲突风险，且 wine/steam 依赖链路长）。采用**隔离的 glibc aarch64 rootfs**：

```
Alpine 宿主 (musl, 不动)
└─ glibc aarch64 rootfs (Ubuntu 24.04 / Debian 13)   ← chroot / LXC / proot 三选一
   ├─ Box64 (DynaRec, NEON) / FEX / Hangover          ← x86→arm64 转译
   ├─ Wine (wow64/WowBox64) 或 Proton                 ← Windows API
   └─ DXVK / VKD3D-Proton (x86, 被转译运行) → 宿主 Vulkan(Turnip/Adreno830)
```

首选 **chroot + bind-mount**（已 root、最简单、GPU 直接透传 `/dev/dri` `/dev/shm` `/dev/null`），LXC 次之（本机已有 lxc 且 Waydroid 验证过挂载机制），proot 最省事但 GPU 性能与兼容性略差。

## 3. 排序后的方案表

> 排序权重：落地难度(低→高) × 成功率 × 性能。性能损失指 CPU 侧转译开销（GPU 侧由宿主 Turnip 原生承担，损失≈0）。

| 排名 | 方案 | 依赖包/组件 | 预期性能 | 风险 | 落地难度 |
|---|---|---|---|---|---|
| ★1 | **Box64 + Wine(wow64)** 于 glibc rootfs | Ubuntu/Debian arm64 rootfs；box64-generic-arm(.deb)；wine64(amd64 多架构) 或 WowBox64；DXVK/VKD3D-Proton | CPU ≈ 原生 50–70%（DynaRec NEON，`BOX64_DYNAREC_BIGBLOCK=3` 等调优）；GPU 原生 | Wine 版本/游戏兼容需逐个试；32 位靠 wow64 | 中（rootfs+apt 装 wine，文档最全） |
| ★2 | **Hangover 11.16**（Wine arm64ec + box64/qemu） | 单 tar（`hangover_11.16_ubuntu2404_noble_arm64.tar`）；仍需对应 glibc rootfs | 只转译应用本体、Wine 本身原生 → 整体开销略低于"整 Wine 转译"；box64cpu 后端最快 | 社区小、文档少；ARM64EC 兼容面略窄 | **低（最快出第一个 exe）** |
| 3 | **FEX-Emu + Proton/Wine**（Valve 同款） | FEX（glibc 宿主）+ x86_64 rootfs + Proton(x86_64，被 FEX 转译) | FEX 转译质量高、AVX 翻译好；但**本机无 SVE → NEON 回退**，性能≈Box64 档 | 双层 rootfs、配置最重；Valve 分支 Proton-ARM 才最优 | 高 |
| 4 | **QEMU user(qemu-x86_64) + Wine** | `apk add qemu-x86_64`（**musl 可直接装**）；x86_64 glibc sysroot + x86 wine | TCG 解释/块转译，**最慢（数倍于 Box64/FEX）** | 兼容性最广（AVX/AVX2 全模拟），适合验证/兜底 | 中（但性能不实用） |
| 5 | **Waydroid + Winlator/GameHub（取巧）** | 本机 Waydroid（已跑通）+ Winlator/GameHub APK + Android Turnip | Android 侧 Turnip(A8xx) 2026 已成熟，实测 1080p 可 60fps 级（社区报告） | 依赖容器内 Android Vulkan 是否可用（需验证）；反作弊同病；触屏 UI | **低（若容器 Vulkan 可用则最省事）** |
| 6 | （基线，勿做）**QEMU 全系统 Windows** | qemu-system-x86_64 + Windows 镜像 | 无 KVM → **不可用** | — | — |

**一句话排序理由：** 要在"本机 Linux"上跑 Steam/Windows 游戏，**先建 glibc rootfs（第 1 步）**；想最快验证用 **Hangover**，想长期主力用 **Box64+wine**，想"省事出画面"先试 **Winlator in Waydroid**；FEX 是 Valve 方向但本机无 SVE 且配置最重，留作 Box64 不满足时升级。

## 4. 各候选路径详述

### 4.1 Box64 + Wine（★ 首选长期）
- **原理**：Box64 用户态 JIT（DynaRec）把 x86_64 ELF 转译成 aarch64；wine64 作为 x86_64 进程被 box64 运行。
- **依赖**：glibc rootfs；`box64-generic-arm` deb（Pi-Apps-Coders 源，每日构建）；wine64（`dpkg --add-architecture amd64` 后装 wine64-amd64，或 WowBox64）；binfmt_misc 注册（或直接 `box64 wine64 ...` 运行，PoC 够用）。
- **调优**：`BOX64_DYNAREC_BIGBLOCK=3`（wine 程序）、`BOX64_DYNAREC_STRONGMEM`、`BOX64_DYNACACHE`（默认开，落地 ~/.cache/box64）、`BOX64_AVX=2`（默认暴露 AVX/AVX2）、`BOX64_PROFILE=fast`。本机 big.LITTLE 可用 `BOX64_SKIPCPU` 让大核承担。
- **优劣**：优=文档/社区最大、可控、可离线、DynaRec 成熟；劣=需逐个游戏试 wine 版本/补丁。

### 4.2 Hangover 11.16（★ PoC 最快）
- **原理**：Wine 跑原生 aarch64，x86 应用段用 **ARM64EC ABI + box64(qemu/FEX) 作后端**只转译应用代码，Wine 自身不转译。
- **依赖**：`hangover_11.16_ubuntu2404_noble_arm64.tar`（或 debian13_trixie）；对应 glibc rootfs + 少量系统库。
- **优劣**：优=单 tar 解包即用、整体开销低（基准显示优于"整 Wine 转译"）；劣=社区小、ARM64EC 兼容面比纯 x86 wine 窄、更新慢。

### 4.3 FEX-Emu（Valve 路线）
- **原理**：FEX 转译 x86→arm64，可作 Wow64/ARM64EC 后端；thunklibs 把 GL/Vulkan 转发到宿主；Valve 的 Steam Frame/Proton-ARM 即此栈（FEX+Proton+Lepton）。
- **依赖**：FEX（glibc 宿主二进制）+ **x86_64 rootfs**（`FEXRootFSFetcher` 拉 Ubuntu x86_64）+ Proton。
- **优劣**：优=转译质量/AVX 处理强、Valve 背书、有 FEXConfig GUI；劣=**本机无 SVE/SVE2 → NEON 回退**（FEX 的 SVE 快速路径用不上）、双层 rootfs 最重、无 Alpine 包。

### 4.4 QEMU user-mode + Wine（慢但通用兜底）
- **依赖**：Alpine `apk add qemu-x86_64`（**唯一可直接装在 musl 宿主机的**）；x86_64 glibc sysroot + x86 wine。
- **优劣**：优=兼容最广（AVX/AVX2 全模拟）、可跑任意 x86 Linux 二进制做验证；劣=TCG 慢数倍，游戏不实用，仅作"能跑"验证或兼容性兜底。

### 4.5 Waydroid + Winlator/GameHub（取巧）
- **原理**：Winlator=Android 内嵌 box64+box86+wine+dxvk+turnip 全家桶；GameHub 同类。复用本机已通的 Waydroid。
- **依赖**：Waydroid 容器内 **Android Vulkan 可用**（本机自编 Mesa 26.1.8 vendor 镜像含 `libvulkan_freedreno.so`，但需验证容器内 loader/hal 是否就绪）；Winlator/GameHub APK。
- **优劣**：优=社区最大、A8xx Turnip 2026 已成熟（社区报告 1080p 60fps 级）、零 glibc 折腾；劣=依赖容器 Vulkan、反作弊同样无解、键鼠/手柄与触屏 UI 别扭、音频走容器。

## 5. 图形栈成熟度（Adreno 830 / freedreno=Turnip）

- **Turnip（Mesa freedreno Vulkan，Gen8/A8xx）**：A8xx 在 2024–2025 曾"打破 Turnip 生态"，但 **2025-11 起 Rob Clark 的 A830/A840 支持已进 Mesa**，2026 年 Winlator/GameHub 在 8 Elite 上已可玩（GTA IV / 1080p 60fps 级社区报告）。**本机宿主 Mesa 26.1.x 已实测 Adreno 830 Vulkan 可用** —— 这是本机最大优势：别人卡在"Turnip 不支持 A830"，本机已经通了。
- **DXVK**：DX9/10/11→Vulkan，用 x86_64 版（wine 进程内被转译），GPU 侧由宿主 Turnip 原生执行。DX9 游戏基本可用。
- **VKD3D-Proton**：DX12→Vulkan，成熟度略低于 DXVK，8GB 级显存（共享 10.6G 内存）跑中等 DX12 游戏可试。
- **Gamescope**：可选。作用=嵌套 Wayland 合成器，解决全屏/分辨率缩放/嵌入 Phosh 窗口、FSR 上采样。需要宿主 Vulkan（已具备）+ glibc aarch64 构建（Ubuntu/Debian 有包或自编）。非必需。
- **XWayland**：wine 游戏多为 X11 应用，chroot 内需 XWayland（宿主已有 phosh/phoc → 提供 `wayland-0`，XWayland 由宿主起，容器内 wine 连 `DISPLAY` 即可；见 PoC 步骤）。

## 6. 已知硬约束核查

| 约束 | 结论 |
|---|---|
| AVX/AVX2 缺失 | **非硬门槛**。Box64 默认 `BOX64_AVX=2` 向 guest 暴露 AVX/AVX2（DynaRec 全实现）；FEX 同样模拟。代价=256 位 SIMD 拆 128 位 NEON，AVX 重度游戏 CPU 更吃紧。AVX-512 基本不被游戏用，忽略。 |
| 反作弊/DRM | **无解硬门槛**。EAC/BattlEye/Vanguard/Ricochet 检测模拟器/虚拟机环境 → 直接不启动或封号。凡联机竞技游戏（如 APEX、Valorant、很多 Steam 联机）不可行；单机/无 AC 游戏 OK。Denuvo 有 wine 兼容性但需在线激活。 |
| 32 位支持 | 用 **wow64（WowBox64 或 wine wow64）/ Box32 / FEX** 在 64 位进程内跑 32 位 x86，**无需 32 位宿主库**。Steam 客户端引导是 32 位 → 需要这条。 |
| 内存带宽 / RAM | 实测 10.6G 共享内存（CPU+GPU 共用，无独立显存）。现代 3A（>8G 常驻 + 转译开销 + shader cache）紧张；建议轻/中负载或降分辨率+FSR。DXVK 首次运行 shader 编译卡顿明显。 |
| 无 SVE/SVE2 | FEX/Box64 的 SVE 快速路径用不上，走 NEON。性能比 SVE 机型（如 8 Elite Gen5/PC 级 X Elite）低一档，但仍可用。 |
| 无 /dev/kvm | 不影响用户态 JIT（Box64/FEX/qemu-user 都不需要 KVM）；只封死 QEMU 全系统 Windows。 |

## 7. PoC 最小验证计划（在设备上跑通 1 个 x86 Windows 小程序）

> 目标：以最少步骤证明「x86_64 Windows 代码在本机可转译执行」。验证目标先选 **Wine 自带 `notepad.exe`**（win64，无需外部下载），再用一个真实 exe 复验。

### 阶段 A：建 glibc rootfs（第 1 步，必须先做）
```bash
# —— 主机侧（离线资产准备，一次） ——
cd ~/y700-elden/pkgs-x86   # 新建
curl -L --noproxy '' -o ubuntu-base-24.04-arm64.tar.gz \
  https://cdimage.ubuntu.com/ubuntu-base/releases/24.04/release/ubuntu-base-24.04.5-base-arm64.tar.gz
# sha256 已校验: a91d5a93010193712d346d761372b7c9db6dfcf093893161c64ca107f05914f2（已下载至 pkgs-x86/）

# —— 设备侧（root@192.168.7.1） ——
scp ubuntu-base-24.04-arm64.tar.gz root@192.168.7.1:/root/
ssh root@192.168.7.1 '
  mkdir -p /data/glibc-rootfs && tar -xzf /root/ubuntu-base-24.04-arm64.tar.gz -C /data/glibc-rootfs
  # chroot 环境准备（bind-mount 设备节点 + 临时 fs）
  for m in /dev /proc /sys /dev/shm /dev/pts; do mount --bind $m /data/glibc-rootfs$m; done
  cp /etc/resolv.conf /data/glibc-rootfs/etc/resolv.conf
  # 进入
  chroot /data/glibc-rootfs /bin/bash
  # 容器内（glibc Ubuntu）：
  apt update && apt install -y ca-certificates wget xz-utils
'
```
**验证标准 A：** `chroot` 后 `ldd --version` 显示 **glibc（非 musl）**，`uname -m`=aarch64。

### 阶段 B1（最快路径）：Hangover 跑 notepad
```bash
# 主机：下载 hangover tar → scp
# 容器内：
cd /opt && tar -xf /root/hangover_11.16_ubuntu2404_noble_arm64.tar
export PATH=/opt/wine/bin:$PATH   # 按 tar 实际布局
export DISPLAY=:0                # 连宿主 XWayland
export XDG_RUNTIME_DIR=/run/phosh # 按宿主 phosh 会话
wine notepad.exe                 # 或 wine cmd.exe /c echo hello
```
**验证标准 B1：** `wine notepad.exe` 进程起来、在 Phosh 桌面**出窗口**（或 headless 下 `wine cmd.exe /c echo hello` 输出 "hello"）。若报缺库，`apt install` 补对应 lib（freetype/fontconfig 等）。

### 阶段 B2（长期主力路径）：Box64 + wine64
```bash
# 容器内：
dpkg --add-architecture amd64 && apt update
apt install -y wine64   # 装 amd64 wine（或 apt install wine64-tools）
# 装 box64（Pi-Apps-Coders 源，见 §4.1）或直接下载 deb
wget -qO- https://pi-apps-coders.github.io/box64-debs/KEY.gpg | gpg --dearmor -o /usr/share/keyrings/box64-archive-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/box64-archive-keyring.gpg] https://pi-apps-coders.github.io/box64-debs/debian ./" > /etc/apt/sources.list.d/box64.list
apt update && apt install -y box64-generic-arm
# 用 box64 跑 x86_64 wine，验证 notepad
box64 wine64 notepad.exe
```
**验证标准 B2：** 同上出窗口；`BOX64_LOG=1 box64 wine64 --version` 能看到 DynaRec 启用日志。

### 阶段 C：真实 Windows 程序复验
- 选一个 ~几百 KB 的 **win64 x86 单机小程序**（如 7-Zip x64 命令行 `7z.exe`，或 `notepad++` 便携版），放容器内：
  ```bash
  box64 wine64 /root/7z.exe    # 或 Hangover: wine /root/7z.exe
  ```
- **验证标准 C：** 程序执行并产出正确输出（7z 列出压缩包内容 / 程序窗口出现），证明非 wine 自带、真实 x86 代码链路通。

### 阶段 D（Steam 起点，风险最高，放最后）
- Steam 客户端引导是 32 位 x86 → 需 wow64/Box32；客户端本体还要 Steam Runtime（glibc）。两条路线二选一：
  1. **Steam 客户端**：容器内装 box64+wow64 后 `box64 wine64 SteamSetup.exe`（或 Linux 版 `box64 steam`，文档见 box64 wiki "Steam" 页）；已知坑多。
  2. **SteamCMD + 单独游戏**（更稳）：`apt install steamcmd`（arm64）或 box64 跑 x86 steamcmd 下载游戏，再用 wine/Proton 启动游戏 exe，绕开 Steam GUI。
- **验证标准 D：** Steam 登录窗口出现 / steamcmd 成功登录并列出库。

> **先做哪一步？** —— 先做 **阶段 A 的 glibc rootfs + `ldd --version`**。这是唯一共通依赖，且一旦成立，A/B/C/D 都只在其上叠加。**不要**直接上 Steam。

## 10. 风险与未决项（需后续验证）

1. **容器内 Android Vulkan 是否就绪**（决定 Waydroid+Winlator 捷径成立与否）——下次单点验证：容器内 `cmd vulkaninfo` 或装个 Vulkan 测试 APK。
2. **chroot 内 XWayland 连接**：宿主 phosh 的 `XDG_RUNTIME_DIR=/run/phosh`、`WAYLAND_DISPLAY=wayland-0` 需透传给容器；必要时宿主起 XWayland 并 export `DISPLAY`。
3. **wow64 具体 wine 版本**需在容器内实测（Hangover 已内置；Box64 路线用 WowBox64 或 wine 10+ 自带 wow64）。
4. Steam 客户端 32 位引导是最大变量，SteamCMD 路线更稳。
