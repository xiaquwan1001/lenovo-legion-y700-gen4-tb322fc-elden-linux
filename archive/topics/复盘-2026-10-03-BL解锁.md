## 3. 「要不要解锁」——最终判定框架（不再有歧义）

**解锁不是目标，是迭代效率手段。** 判定只看「这一步要不要 fastboot 写权限」。

| 你要做的事 | 需要解锁？ | 依据 |
|---|---|---|
| 写分区（boot_b / dtbo_b / vbmeta_b / GPT / 整 LUN） | **不需要** | firehose 用官方签名 programmer，EDL 裸写不看 lock 位（`qdl`）；U2 本次 259→1.1 全量降级就在 locked 态下用 EDL 做的 |
| 让自签 mainline 内核被 ABL 接受 | **不需要** | 原厂 AVB 主链 = 公开 testkey `2597c218`；`scripts/build-locked-chain.sh` 验证全绿 |
| `fastboot fetch`（备份读回）、`fastboot boot`（**零写盘 RAM 验收**） | **需要** | locked 下 ABL 一律拒（这也是本次 Phase 0 改用 `qdl read` 的原因） |
| 反复迭代 boot_b（一天几十次 `scripts/flash-b.sh`） | **需要**（效率） | EDL 每次要进 9008 + 重新 attach，慢一个数量级 |
| 切槽 `--set-active` / `slot` 属性 | **需要** | 120 的 ABL：`Slot Change is not allowed in Lock State` |
| 只是采属性、dump、对照取证 | **不需要** | adb + EDL read 足够 |

**不可逆代价（必须先拍基线）**：擦 `/data`；保修失效；FOTA 不可用；**Widevine L1→L3**（TEE 内密钥，永久）；开机解锁警告。
基线脚本＝`scripts/bl-preunlock-evidence.sh <SN>`（U2 已拍：`backup/HA2EXB0E-16+512/pre-unlock/`，Widevine=**L1**，含 SHA256SUMS）。

**执行结论（当前台账）**
- **U1（12+256）**：2026-08-16 已解锁（当时走 073 降级）→ 现在 stock 259 + root，做 Android 侧对照取证。**回锁无收益，不再动。**
- **U2（16+512）**：**2026-10-03 已解锁**（降级 1.1.11.073 + `oem unlock`）。后续 mainline 走标准 RUNBOOK（fastboot 路可用，`fastboot boot` RAM 兜底恢复可用）。
- **未来新单元**：若任务是「反复改 boot_b 的 bring-up」→ 直接按 §4 一次做到 unlocked，**不要先在锁上试**；若任务只是采集 → 保持 locked 走 EDL。

## 4. 「怎么解锁」——唯一权威顺序（版本门决定一切）

```
0) 读版本 + 判门           getprop ro.build.display.id / ro.build.fingerprint
   ├─ ≤ 1.1.11.073 / .076          → 直接第 3 步（解锁命令存在）
   ├─ 1.1.11.120                   → ⛔ TRAP：会显示成功但回滚、root 不可能 → 先降级
   └─ 1.5.x（.229 / .259 / C16…）   → 解锁通道被堵 → 先降级（本次 U2 即此路）
1) 拍 locked 基线           scripts/bl-preunlock-evidence.sh <SN>     ← 擦机前唯一机会
2) 全量降级到 073           LTBox Simple Flasher（用户 GUI 操作）或 qdl 全 LUN
   ★ 必须"全量含 GPT"：只写内容不写 GPT = 120 版 GPT 配 073 内容 → 卡 logo（8/16 已踩，
     取证 `.pi/skills/qualcomm-edl-flashing/references/tb322fc-bootloop-gpt-mismatch.md`）
   ★ 只用 lolinet/官方包：4PDA 改包改过 SN + bootload_sn，变砖（qtotter #129/#131）
   ★ Gen4 **无 rollback-index 保护**（同型号独有），降级本身安全；仍需全量而非部分刷
3) 不进回系统、保持在 fastboot：
   fastboot flash unlock sn_<64hex>.img     # 073 上这一步实测可省（直接第 3b）
   fastboot oem unlock                      # ★ 判定行；屏出确认菜单 → 音量下×2 + 电源
   （flash 与 oem unlock 之间**不得重启**，重启 = 授权失效）
4) fastboot flashing unlock_critical       # 又出一次确认菜单；`flashing unlock` 此 ABL 不认
5) 校验：getvar unlocked=yes；oem device-info: Device unlocked=true / critical unlocked=true；
        adb getprop ro.boot.flash.locked=0、ro.boot.verifiedbootstate=orange；重测 Widevine 回填 GAPS Q1/Q5
```

**判定纪律（避免再被"假进展"骗）**
1. `flash unlock` 的 `Sending 'unlock' (0 KB) OKAY / Writing OKAY` **什么也不证明**：by-name 里没有 `unlock` 分区（size=0，ABL 特判缓冲），刷垃圾也是同一串。判定只在 `oem unlock`。
2. 失败特征串 → **立刻停手，不要重复刷**：`Download is not allowed on locked devices` / `Unlock command not allowed` / `oem unlock-go` 返回 OKAY 但 `unlocked` 仍 `no`（后者 = 中 trap）。
3. 双重闸门可放心试一发：验签失败 ABL 直接报错，**不擦机不改锁**；成功才出屏显菜单，按键确认才擦 `/data`。
4. 已判死、不必再试的路：**四代 1.5.x 上的任何 sn.img**（官方 / 三代免签模板 / 第三方签名服务）——四代 ABL 换了 key 且不外发公钥，签名文件这条路对新固件无效。
