# WiFi 到可用约 2 分钟（2026-10-06 实机排查）

> 证据层 · 只增不改。结论口径见 `TASKS.md §5 Q26`、`PITFALLS` #117。
> 触发：载具冒烟镜像 `out/boot-elden-inittest-veh.img` 启动后，用户报「WiFi 连接比较慢但成功」。

## 1. 一句话结论

clean boot 下 **`wlan0` 28 s 就关联上**，但拿到 IPv4 要到 **~140 s**；中间是
**每 ~16–18 s 一次的周期性掉线**，掉线推手 = **NetworkManager 的 DHCP 拿不到租约 →
反复重激活**。设备上还**同时跑着两套 supplicant**（NM 的 `wpa_supplicant -u` +
手动 `wpa_supplicant -B -i wlan0`），是 `net-up.sh`（NM 版）超时回退时引入的第二套。

## 2. clean-boot 时间线（uptime 秒）

| 时刻 | 事件 |
|---|---|
| 7.9 | `ath12k` 内建首次 probe `-110`（MHI POWER_ON 超时）→ 设备 unbound |
| 8.7 | `ath12k-retry` 启动（`sleep 12`） |
| 20.7 | 重探；21.3 `qmi TME-L power-on hardware-restricted (stock-compatible)` |
| 22.7 | `net-up: NetworkManager started` |
| 26.2 | `ath12k-retry: phy0 up` |
| 28.3 | `wlan0: associated`（NM） |
| 39.9 / 57.5 / 75.5 / … | 掉线周期 ~17.7 s：`ath12k: failed to flush transmit queue, data pkts pending N` + `wlan0: Connection to AP 00:00:00:00:00:00 lost` |
| ~117–141 | NM 等地址 80 s 超时 → `exec net-up-manual.sh` → 起第二个 supplicant + `udhcpc` |
| ~140 | 拿到 IPv4（`192.168.43.42`），此后稳定（掉线循环停止） |

期间 `nmcli` 恒为 `wlan0:connecting (getting IP configuration):P40 Pro`；`nmcli connection up`
报 `IP configuration could not be reserved (no available address, timeout, etc.)`。

## 3. 已排除 / 未排除

| 假设 | 结论 | 依据 |
|---|---|---|
| `power_save` 掉电省电导致 beacon loss | ❌ 排除 | `iw set power_save off` 后仍 5 次/80 s 掉线 |
| NM DHCP 后端 `internal` 有问题 | ❌ 未证实 | 换 `dhcp=dhcpcd`（设备有 dhcpcd）仍 `IP configuration could not be reserved` + 5 次/50 s；**已回滚该 conf.d** |
| 手动 `udhcpc` 一定可靠 | ⚠️ 不成立 | 后段手动测试 6 次 `broadcasting discover` **无 offer** ⇒ 手机热点 DHCP 自身也在抽风（环境变量） |
| 双管理器并存 | ✅ 确认 | `ps` 见 `wpa_supplicant -B -i wlan0`(pid 3334) 与 `wpa_supplicant -u`(pid 3348) 同时在跑 |

## 4. 代码侧问题

1. **双管理器**：`scripts/net-up-nm.sh`（= 设备 `/usr/local/sbin/net-up.sh`）在 NM 存活时
   仍 `exec net-up-manual.sh`；`net-up-manual.sh` 未先停 NM → 第二套 supplicant。
   规则：**一张网卡只允许一个 supplicant/管理器**；回退前必须先停前一个。
2. **命名分叉**：仓库 `scripts/net-up.sh` 是**手动版**（wpa_supplicant），`scripts/net-up-nm.sh`
   是 **NM 版**；设备上 `net-up.sh` 实际是 NM 版内容。`build-rootfs.sh` 装的是手动版 ⇒
   仓库/设备不一致（同类于 PITFALLS #109）。
3. **固定开销**：`ath12k-retry.sh` 的 `sleep 12` + `sleep 5` 序列可压缩（如 6 s）。

## 5. 待决策（留给后续）

- 路线二选一：**NM**（Phosh 网络 UI 好看，但本机 DHCP 反复失败）vs **手动 `udhcpc`**
  （此前拿到租约，但 UI 不联动）。
- 先修「双管理器」（确定性 bug，与路线无关），再单变量比路线。
- 设备侧测试会改状态；本次实验结束时已恢复：NM 单实例、`wlan0` connected `P40 Pro`、
  IP `192.168.43.42`、`conf.d` 仅 `99-unmanaged.conf`、`power_save` 为实验所设 off（重启恢复默认）。
