## 4. ★ 应固化的排查思路

1. **零号纪律**：先 grep 本地结论 → 刷前备份+写后读回校验 → 持久系统不做自锁实验 → **无设备证据不得写「已修复」**（本轮新增，见下 §5）。
2. **零写盘优先**，且**变体明确**（持久 = RAM 内核+磁盘根；`-ram` 无桌面/服务，PITFALLS #92/#93）。
3. **判据必须设备侧、可复现、同口径、量化**；主机侧成功不计入。
4. **单变量 + ≥3 轮长时窗 + 已知良好基线**；间歇故障先建统计口径。
5. **副作用与观测分离**：渐进触发，不轮询；观测通道要能存活。
6. **先诊断基础设施**（预算/网络/代理）+ 脚本内时间盒（`timeout -k`）。
7. **失败/半成品必落盘**，状态词只允许「未解/未证实/未上机」。
8. **并发只走 lane/fork + registry + trailer**，父 agent 独立复跑（worker 自报不可信）。
9. **结论可反转** → 保留推翻记录（本节 F4/Q24 即例），archive 只增不改。
