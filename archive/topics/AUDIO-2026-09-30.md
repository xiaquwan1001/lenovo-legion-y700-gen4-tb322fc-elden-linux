## 2. 关键疑点：tplg 未被加载

| 观察 | 含义 |
|---|---|
| 我们 tplg 在位时，boot dmesg **无** `tplg firmware loading ... failed`、**无** `tplg component load failed` | `request_firmware` 要么成功、要么根本没被调用 |

## 7. SMMU 核对（2026-09-30）— 排除

| 来源 | `q6apmdai` iommus |
|---|---|
| 主线 `sm8750.dtsi` | `<&apps_smmu 0x1001 0x80>`, `<&apps_smmu 0x1041 0x20>` |
| 我们 elden 覆盖 | `<0x1001 0>` `<0x1081 0>` `<0x1041 0>` `<0x1061 0>` |

展开主线掩码：`0x1001 & ~0x80 | {0,0x80}` = **{0x1001,0x1081}**；`0x1041 & ~0x20 | {0,0x20}` = **{0x1041,0x1061}**。
→ **两边覆盖完全相同的 4 个 SID，SMMU 不是问题。**

## 9. 厂商 AGM vs 主线 q6apm（静态比对，2026-09-30）

- 厂商的 `SHARED_MEM_MAP_REGIONS` 包在 **用户态（AGM lib）** 构造，经 `/dev/audio_pkt` 下发；
  厂商内核 `ipc/audio-pkt.c` 只做**地址翻译**：若 `property_flag & APM_MEMORY_MAP_BIT_MASK_IS_OFFSET_MODE(0x4)`，
  用 `msm_audio_get_phy_addr()` 把 ION **offset/handle** 换成物理地址再填 `shm_addr_lsw/msw`。
- 主线在内核构造：`mem_pool_id=APM_MEMORY_MAP_SHMEM8_4K_POOL(3)`、`num_regions=1`、`property_flag=0x0`、
  `shm_addr = phys | (sid<<32)`（高 32 位放 SMMU stream id）、`token = graph_id`。
  `sid` 由 `q6apm-dai` 从 `iommus` 第一个 phandle 取（`of_parse_phandle_with_fixed_args`）→ 我们 = `0x1001`，
  与主线一致。
- **结论**：参数（pool/flag/addr/sid）无显式差异；厂家的差异只是“用户态 vs 内核态”。
  → 静态比对**未能定位**，需要动态追踪（ftrace）看 GPR 往返。

## 11. ★ ftrace/kprobe 定位根因（2026-09-30，vk20-debug 已刷）

刷 `vk20-debug` 后用 kprobe（`q6apm_send_cmd_sync` 被同文件内联，改 probe 导出的外层）抓到：

```
map: (q6apm_map_memory_fixed_region)  gid=0x0  phys=0x1fff00000  sz=0x80000
map_ret: (q6apm_dai_pcm_new+0xcc <- ...) ret=0xffffffea (-22)
qcom-apm: Error (1) Processing 0x0100100c cmd   [SHARED_MEM_MAP_REGIONS]
```

**根因**：`q6apm-dai.c` 把缓冲区地址编码为 `phys | (sid << 32)`，
其中 `sid = iommu 第一项 SID & SID_MASK_DEFAULT(0xF)`（我们 = `0x1001 & 0xF = 1`）。
但本次 `snd_pcm_set_fixed_buffer_all()` 分到的 DMA 缓冲区地址是 **`0x1FFF00000`（> 4 GiB，bit32 已置位）**，
于是 **sid 字段与物理地址高 32 位冲突** → DSP 拿到错误的地址/SID → 共享内存映射失败（status 1）。

→ 与厂商 AGM 的差异：厂商 buffer 用 ION 且走 `property_flag` 的 offset 模式（内核翻译物理地址），
不依赖“地址高 32 位放 sid”这条约定。

## 12. 下一步（修 buffer 地址 / 分配域）

方向：**让 PCM 缓冲区落在 4 GiB 以下**（或改走 offset 模式）。候选：
1. 给 q6apm-dai 设备设 **32-bit DMA 限**（`dma_set_mask_and_coherent(dev, DMA_BIT_MASK(32))`），
   或 DT 加 `dma-ranges` / 音频 reserved-memory（<4GiB）供 buffer 分配。
2. 对照上游（torvalds）`q6apm-dai.c` 是否对 buffer 放置有额外约束（例如用 `qcom,audio-…` reserved region）。
3. 检查 SMMU/IOMMU IOVA 分配为何给到 8 GiB（可能与 `arm-smmu.disable_bypass=0` 或 iommu 域有关）。

## 13. 尝试修复 buffer 低地址（2026-09-30，均未生效）

| 尝试 | 结果 |
|---|---|
| ① `q6apm_dai_probe` 里 `dma_set_mask_and_coherent(dev, DMA_BIT_MASK(32))` | 地址仍 `0x1fff00000`（mask 返回 0，但分配未受限） |
| ② DT 加 `<4GiB` `shared-dma-pool`（`q6apm-audio-mem`,16MiB@`0xf1c00000`）+ `&q6apmdai { memory-region=... }` + `of_reserved_mem_device_init()` | 池已建、DT 节点已带 `memory-region`，但**地址仍 `0x1fff00000`** |

镜像：`out/boot-elden-vk21-dma32.img` / `out/boot-elden-vk22-audiomem.img`（均已在 vk20-debug 基础上）。

**推断**：`snd_pcm_set_fixed_buffer_all(SNDRV_DMA_TYPE_DEV, component->dev, …)` 拿到的地址
既没受 32-bit mask 限制、也没走 reserved coherent pool → 很可能是 **IOMMU/旁路域下的 IOVA**，
或分配用的 device 与我们在 probe 里设置的并非同一个。

## 14. 下一步候选

1. **DT `dma-ranges`**：在 `&q6apmdai`/SMMU 节点上限制 IOVA 到 `<4GiB`（IOMMU 域的 dma-ranges）。
2. **对 q6apmdai 关闭/旁路 IOMMU**，使其用 dma-direct（此时 32-bit mask 才生效）。
3. **运行时确认** `dev->dma_mem` 是否挂上、`coherent_dma_mask` 是否为 32-bit（加临时 dev_info 重编）。
4. 改 `q6apm-dai` 显式用 `dma_alloc_from_dev_coherent`/`dma_alloc_attrs` 从池分配。

## 15. 修正：地址/SID 均非根因（2026-09-30，DBG 打印）

`vk23-dbg` 打印（`q6apm_dai_probe` + `q6apm_dai_memory_map`）：

```
DBG probe:  dma_mem=0  coherent=0xffffffff(32bit)  dma_mask=0xffffffff  rc_resv=0
DBG memory_map: addr=0xfff00000  sid=1  phys=0x1fff00000  dma_mem=0
```

- **`substream->dma_buffer.addr = 0xfff00000`（< 4 GiB）** —— 之前以为的“buffer 在 8.6 GiB”是**误读**：
  `0x1fff00000` 是 `addr | (sid<<32)` 的合成值。
- `coherent=0xffffffff`：32-bit DMA 限生效（地址确在 4 GiB 内）。
- `dma_mem=0`：reserved pool 未挂上（`of_reserved_mem_device_init` 返回 0 但 `dev->dma_mem` 仍 NULL——待查）。

**实验（vk24-nosid）**：强制 `pdata->sid = -1`（`phys = addr`，`msw=0`，即厂商的编码）：
```
DBG memory_map: addr=0xfff00000 sid=-1 phys=0xfff00000
qcom-apm: Error (1) Processing 0x0100100c cmd ; DSP returned error[100100c] 1
```
→ **仍失败**。

**结论**：`SHARED_MEM_MAP_REGIONS` 失败与 **地址范围、SID 编码都无关**。
配合开机 `APM_CMD_GET_SPF_STATE 超时` → **ADSP 侧 APM 服务本身不工作/不响应**。
