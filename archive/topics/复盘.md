## 一、已达成的结论

**✅ mainline Linux 内核能启动到 userspace（决定性证据）**
- diag2/diag3 镜像在 initramfs 里放了 `elden_diag_reboot=1` → init 跑到用户态后 40s 自动 `reboot -f`。
- 实测：`fastboot boot` 后 USB 静默 ~55s，随后设备以**全新的 fastboot 设备(Device 015→016)**回来。
  → 内核确实执行到了 init 脚本。
- 也证明 `fastboot boot`（RAM、零写入）链路可用。

**✅ dtbo overlay 是 ABL 交接失败的原因**
- stock `dtbo` 是含 **76 个 overlay** 的合法 dtbo（平台代号 `kera`）。
- 写假 dtbo（4KB 全零 → magic `0xd7b7ab1e` 不匹配）后，ABL 跳过 overlay：屏幕从"卡 logo"变成"过解锁警告→黑屏"，ABL 成功把控制权交给内核。
- 备份：`backup/dtbo_a.img`（32MB，stock 原始内容）。恢复：`fastboot flash dtbo_a backup/dtbo_a.img`。

## 二、未解决

**❌ 无显示输出**：DRM_MSM 开/关都黑屏。
- 关 DRM_MSM（保留 simpledrm+fbcon，framebuffer 定义在 `chosen/framebuffer@fc800000`，内核 `drivers/of/platform.c:581` 确实会为 chosen 下的 simple-framebuffer 建平台设备）仍然黑屏。
- 推断：ABL 交接时可能已熄灭面板扫描输出，simpledrm 只写内存不显示；需要 DRM_MSM 真正点亮 panel（DPU/DSI/PHY/regulator 链）。

**❌ USB gadget 不绑定**：`/sys/class/udc` 一直没有 → ttyGS0 不出现。
- 已试：`dr_mode="peripheral"` + `/delete-property/ usb-role-switch`（绕开 pmic-glink/ADSP）仍无 UDC。
- config 与作者**逐符号一致**（PHY_QCOM_M31_EUSB/EUSB2_REPEATER/QMP_COMBO/QMP_USB、USB_DWC3_QCOM、REGULATOR_QCOM_RPMH 等全 =y）。
- 推断：dwc3/PHY 根本没 probe，疑似其依赖的 regulator/power-domain/clock 没就绪（与显示失败同源）。

## 三、已知的坑（操作经验）

1. `fastboot fetch` **本机不支持** → 不能用 fastboot 读分区；读分区只能 EDL。
2. `fastboot boot` 一次失败后 ABL 进脏状态 → 连续报 `Failed to load/authenticate boot image: Load Error`；`fastboot reboot bootloader` 或冷启可清除。
3. `fastboot boot` 成功后若内核挂住，设备需**物理重启**才能回到 fastboot/adb。
4. EDL：`adb reboot edl` 可进 9008；`~/y700-elden/qdl/build/qdl -s ufs <melf> read <分区名> <文件>` 直接吃 `xbl_s_devprg_ns.melf`（已实测成功读 dtbo_a）。
5. git 树编译需 flex/bison（kconfig 词法器）；已装。

## 七、根因定位（两个真 bug）

### 根因 A（我的错）：diag 内核缺 `CONFIG_ARCH_QCOM`
- 在做 diag 版时执行 `scripts/config -d DRM_MSM` + `make olddefconfig`，**连带把 `CONFIG_ARCH_QCOM` 也删了**。
- 于是 diag/diag2..diag6 **所有内核都没有 QCOM 平台支持** → 显示/USB/UFS 驱动根本不存在 → “三者全灭”。
- **教训**：改 `.config` 后必须 `grep '^CONFIG_ARCH_QCOM='` 验证；不要在同一份树上反复 `-d` 关键符号。
- 已恢复：`cp .config.panel .config`（`CONFIG_ARCH_QCOM=y`）。

### 根因 B（上游 DT 的未修 TODO）：`splash_region` 名字
- GEEKiDoS 的 elden DTS 里节点名是 `splash-region@fc800000`（连字符），但同一处的注释就写着 `Please 's/-/_/'`。
- 作者 DT 明确：**ABL 精确查 `/reserved-memory/splash_region`，节点缺失就跳转内核前关闭显示**。
- 已修：节点名改为 `splash_region`（保留 label `splash_mem`，`&mdss memory-region` 引用不变）。DTB 已验证含 `splash_region`。

### 修复版产物

**根因 #5（显示黑屏的真因）：`&mdss_dp0` 被启用**
- `msm_dp` 是 DRM 的 component；没有 ADSP 时 `af54000.displayport-controller` / `aux_bridge` 永远 defer。
- `component_master` 要等**所有** component 就绪 → `msm_drm_bind` 被卡 → 根本没有 `card0` → 面板黑屏。
- 作者 DT 里 `dp0` 出现次数 = 0（压根没启用）。
- 修复：`&mdss_dp0 { status = "disabled"; };`
- （dmesg 里 `DSI PLL(0) lock failed` 是 `clk_ignore_unused` 在无 panel mode 时提前 enable PLL 造成的干扰项，非真因。）

### ⚠️ 血的教训
**`make olddefconfig` 在本树上会把 `CONFIG_ARCH_QCOM` 整行删掉！** 任何改 `.config` 后**不要跑 olddefconfig**，改用 `scripts/config -e/-d` 后直接 `make`，并每次都 `grep ^CONFIG_ARCH_QCOM=` 验证。这个坑让我们白跑了十多轮 diag 内核。

## 九、用户态 / GPU 阶段

### Alpine in-RAM rootfs（已跑通 ✓）
- 免 sudo 构建法：`qemu-aarch64 -L <rootfs> <rootfs>/sbin/apk --root <rootfs> --arch aarch64 add ...`（unshare 用户命名空间被禁，无法 chroot；SSH host key 用本机 ssh-keygen 生成，与架构无关）
- 产物 15.7 MB；`init`/`usb-gadget`/`reboot2` 来自作者 project/rootfs
- 真机验证：USB-NCM 网络 `192.168.7.1` + 免密 `ssh root@192.168.7.1` ✓（bash/tmux/strace/i2c-tools 均在）

### GPU 固件
- 驱动要 `gen80000_{sqe.fw,gmu.bin,aqe.fw,zap.mbn}`；Ubuntu linux-firmware 有前三个，但 **zap 必须是设备 vendor 的那份**（作者 DT 注释："signed per device... copy from the vendor image"）。
- 两份 zap 同为 12088B 但 sha256 不同；linux-firmware 那份被 TZ 拒（`qcom_scm_pas_init_image` 返回 `-EINVAL`）。
- 取法：`fastboot boot` TWRP 100MB 会被 ABL 拒（`Bad Buffer Size`）→ 改用**刷入/进入 TWRP（root）** → `adb pull /vendor/firmware/gen80000_*.{mbn,fw,bin}`（TWRP 里 `/vendor/firmware/` 可读，含 `gen80000_zap.mbn`）。
- rootfs 内放 `lib/firmware/qcom/sm8750/`（对应 DT 的 `qcom/sm8750/gen80000_zap.mbn`）。

### ⚠️ A/B 槽巨坑（导致“卡 logo”反复）
- **`fastboot boot` 失败/进 Android/TWRP 后，ABL 可能把 `current-slot` 从 a 切到 b**（slot-unbootable 会翻转）。
- 假 dtbo 只写了 `dtbo_a` 不够：ABL 读的是**当前槽**的 dtbo → 卡 logo。
- **修复：`fastboot flash dtbo_a out/dtbo-dummy.img` 且 `fastboot flash dtbo_b out/dtbo-dummy.img`（两个槽都写）**；或 `fastboot --set-active=a` 后再写 a。
- 排查手法：`fastboot getvar all | grep -iE 'current-slot|slot-unbootable'` 对比历史。

## 十、GPU / 图形栈（Turnip 已跑通 ✓）

- Alpine 有 Mesa 26.1.6：`mesa-vulkan-freedreno`(Turnip) / `mesa-dri-gallium`(GL) / `mesa-egl` / `vulkan-loader` / `vulkan-tools`。
- **`libgallium` 会拉 `libLLVM.so.22.1`（168MB，压缩后 ≈85MB）→ 会超 `fastboot boot` 的 ~96MB 限制**。
  - Vulkan-only 精简：只装 `mesa-vulkan-freedreno vulkan-loader vulkan-tools`，删 `libgallium`/`libLLVM`/GL 栈/`usr/lib/dri` → 压缩后仅 **31MB**（boot.img 48MB）→ 可直接 RAM 启动。
  - 要跑 GL/桌面则需把含 LLVM 的完整 Mesa 放 UFS 根分区（RAM 放不下）。
- 实测 `vulkaninfo --summary`：
  ```
  deviceName = Adreno (TM) 830
  driverName = turnip Mesa driver
  deviceID   = 0x44050000
  apiVersion = 1.4.354
  ```
  ✅ **Adreno 830 / Turnip 在 mainline 上完全可用。**
- ⚠️ **不要打作者的 `patch-mesa-a830.sh`**：它把 Mesa 设备表的 wildcard `0x0000ffff44050000` → `0x0000ffff44050001`。
  但本机内核 A830 catalog 报 `ADRENO_CHIP_IDS(0x44050000)`，DRM 给 Turnip 的 chip_id 是 `0xE844050000`（**patchid=00**），正好匹配**原版** wildcard 表项；打补丁反而变 unsupported。
  （作者设备报 patchid=01 才需要补丁——两台机器/内核不同，需看实际 `vulkaninfo` 输出决定。）

## 2. 关键技术结论

### 2.1 kexec = 装载可用，执行不可用 ⚠️
- 内核内建 `CONFIG_KEXEC=y`、`CONFIG_KEXEC_FILE=y`、`CONFIG_EFI_STUB=y`，`kexec_load_disabled=0`。
- `kexec -s -l/--initrd=…` → `FILE_LOAD_OK`；`kexec -l/--initrd=…` → `LOAD_OK`。
- **`kexec -e` 执行黑屏挂死**（新内核未起、无 USB gadget），需物理重启。
- 判定：arm64/Qualcomm 平台限制（跳转后无法复位 GIC/PMIC/次级 CPU）。
- **弃用 kexec 做内核热切换**。

### 2.2 `reboot` 软回 fastboot = 可用 ✅（替代 kexec 的软切换路径）
- 在 Linux 内 `reboot`（或 `reboot -f`）→ **约 12–15s 自动进 fastboot**（假 dtbo 使 Android 无法引导，ABL 落到 fastboot）。
- 由此得到**串行迭代链**（不按电源键）：
  `cycle.sh --soft`（Linux→fastboot）→ `cycle.sh <img>`（fastboot→Linux，约 78s）。
- 只有"早期 hang 死"才需要物理按键。

### 2.3 UFS 分区测绘 + LP 元数据
- **5 个 LUN**：`sda`=LUN0（super/userdata）、`sdb`=LUN1(xbl)、`sdc`=LUN2、`sdd`=LUN3(cdt/ddr)、`sde`=LUN4(uefi/tz/modem/bluetooth/dsp/boot/dtbo…)。
- LUN0 尾部**无空闲**（userdata 到盘尾）；要加分区必须缩 super/userdata。
- LUN4 尾部有 **623335 扇区 ≈ 2.43 GiB** 空闲，本来是占位分区 `last_parti`。
- **`super`(sda10) 可直接读**：从 sda10 前 8 MiB 解析 LP 元数据 → 各动态分区 extent 的 `{offset,len}`（单位 **512B 扇区**）→
  `losetup -o <off> --sizelimit <len> /dev/loop0 /dev/sda10 && mount -o ro /dev/loop0 /mnt`。
  已验证 `vendor_a` 挂载成功。映射：`probe/result/lp-map.txt`。

### 2.4 持久盘（零 GPT 手术、零数据丢失）✅
- `last_parti`（序号 79，425236–1048570）的 **Type-UUID 是全零** → 内核 GPT 解析器跳过，不建 `/dev/sde79`。
- 修复：`fdisk /dev/sde` → `t 79` → `Linux filesystem` → `w`。内核随即生成 `/dev/sde79`（259,191），**重启后仍在**。
- `mkfs.ext4 -F -L linux /dev/sde79` → 2.3 GiB，读写 OK，跨重启数据保留。
- GPT 快照（改动前）：`backup/sde-gpt-head.bin`、`backup/sde-gpt-tail.bin`。
- 只改第 79 条类型 GUID；名称仍 `last_parti`；**未动任何现有分区**；ABL 按名读，不受影响。

### 2.5 `/persist` 自动挂载 ✅
- init 后台等待 `/dev/sde79` 出现后 `mount -t ext4 -o rw,noatime /dev/sde79 /persist`。
- 实测开机自动挂载、跨重启写入保留。

## 10. 本轮踩过/确认的坑

1. **`last_parti` Type-UUID 全零** → 内核跳过不建节点；fdisk/gdisk 与内核口径不一致。用 fdisk `t` 改类型解决。

3. **ADSP 固件命名**：必须 `adsp.mdt`（配 `adsp.b*`），不是 `adsp.mbn`。

5. **别跑 `make olddefconfig`**（会删 `CONFIG_ARCH_QCOM`）。
6. **fastboot `Load Error`** = 脏状态：`fastboot reboot bootloader` 后再 `fastboot boot`（`cycle.sh` 已内置重试）。
7. probe.sh 里的 `tar --ignore-failed-read` 在 busybox 上无效导致拷贝为空 → 改用整目录 `tar czf`。

## 11. 会后追加：持久 root 打通（2026-09-28 深夜）

- **目标**：把系统从 RAM root 迁到 UFS（`/dev/sde79`），彻底脱离 RAM boot。
- **实现**：`init` 支持 `elden_root=LABEL=linux`：initramfs 内挂载 sde79 → `switch_root` 到磁盘 `/init`；
  用 `stat -f -c %T /` 区分 initramfs 与磁盘模式（磁盘模式跳过 `/persist` 与 switch_root，防递归）。
- **写入**：`rootfs/alpine` 整树 → sde79（176 MB / 2.3 GB）。
- **验证**：`/` = `/dev/sde79 ext4`；ADSP `running`、BT `hci0`、触屏 `firmware version 1a.01` 全部开机自动；sshd 自动；数据跨重启保留。
- **新基线镜像**：**`out/boot-elden-vk7.img`**（77 MiB，`EXTRA_CMDLINE="elden_root=LABEL=linux" ./pack.sh`）。
- **关键坑**：用 `tar czf - -C rootfs/alpine .` 拷贝会**保留主机 uid=1000**，
  导致 sshd 报 `/var/empty must be owned by root` 拒绝启动（症状：ping 通、SSH `connection refused`）。
  修复：`find / -xdev -uid 1000 -exec chown 0:0 {} +`；拷贝改用 `--owner=0 --group=0`；init 内置 chown 防御。
- **救急通道**：SSH 失效时用串口 `/dev/ttyACM0`（ttyGS0 getty，直接 shell）：
  ```bash
  stty -F /dev/ttyACM0 115200 raw -echo
  { printf '\r'; sleep 0.5; printf '<cmd>\r'; } > /dev/ttyACM0 & timeout 5 cat /dev/ttyACM0
  ```
- **`pack.sh`** 现支持 `EXTRA_CMDLINE` 环境变量追加 cmdline。
