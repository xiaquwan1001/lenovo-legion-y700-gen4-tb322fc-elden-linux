## 1. 三条路线评估

### 路线 A：LineageOS 移植（erhai → TB322FC）★ 主推
同平台 SM8750 的类原生 ROM 生态已成熟：

| 资产 | 内容 | 状态 |
|---|---|---|
| `LineageOS/android_device_oneplus_sm8750-common` | SM8750 通用设备树 | **官方维护**（LuK1337/bgcngm） |
| `LineageOS/android_device_oneplus_erhai` | erhai 设备树 | 官方，当前版本 **23.2 (Android 16)** |
| `LineageOS/android_kernel_oneplus_sm8750` | 6.6 内核源码 | 官方 |
| XDA 帖 `[ROM][OFFICIAL][erhai] LineageOS`（4761418） | 已知问题：触笔/键盘 BT 不稳、144Hz 闪屏、语音转文字异常 | 活跃开发 |
| AICP `[ROM][OFFICIAL][erhai][desktop mode]`（XDA 4764515） | Android 16 + 桌面模式 | 官方 |
| /e/OS（erhai，基于 Lineage） | 去 Google 化变体 | unofficial 可用 |

- 移植先例：B站 **悲伤的压缩包** 已把一加 Pad2 Pro 的"金标系统"（ColorOS16）、澎湃OS3 移植到 Y700 四代成功 → 证明两机 vendor/HAL 高度接近。
- **需要自己解决的差异**：屏参（1904×3040 vs erhai 2400×3392）、NT36536 触屏、aw88461 音频、TF 卡槽、Lenovo 特有外设（游戏助手/双马达）。
- TWRP 16.0 设备树已有现成（见 §2），其基础是 `twrp_device_oplus_sm87xx` + `twrp_device_xiaomi_sm8750_thales` —— 又一个 sm8750 硬件层通用的证据。

### 路线 B：GSI（最快验证）
- **官方 AOSP 16 GSI**：`developer.android.com/about/versions/16/gsi-release-notes`（`gsi_gms_arm64` / `aosp_arm64`，带 GMS 或纯净版）
- **TrebleDroid**（phhusson 后继社区）：`TrebleDroid/device_phh_treble`；原 `phhusson/treble_experimentations` 已归档（2025-01），社区接棒
- Y700 四代 vendor = Android 15 GKI 6.6，支持 Treble；刷法：`fastboot delete logical partition product` → `fastboot flash system xxx.img` → **必须清 userdata** → vbmeta 本机已解锁可 `--disable-verity --disable-verification` 直接刷
- 参考资产（一代 Y700，方法论通用）：
  - `LinuxDroidMaster/Lenovo-Legion-Y700-ROMs`（★119，GSI 刷法+已知问题清单）
  - `reindex-ot/LegionY700-GSI-Fix_MOD`（★10，GSI 修复 Magisk 模块）
- 风险：新平台 GSI 的相机/音频/指纹 HAL 兼容性未知；Reddit 社区对 Y700 刷 GSI 评价偏谨慎（二代帖）。**开工第一步：设备上装 Treble Info 确认 arch（arm64 AB）与 VNDK 版本**。

### 路线 C：ZUX OS 精简（兜底，非真类原生）
- `bc1qwerty/y700-cleaner`：Windows GUI 去预装/性能优化
- 思路：保留原厂系统 + KSU root + adb 去广告。若 A/B 都不顺，这是保底。

## 5. 已知风险与坑（本项目专属）

1. **ARB/防回滚**：升 A16 后防回滚计数上升，回退 A15 ROM 可能熔断。刷任何 ROM 前先确认 firmware 部分（fw 分区）版本。
2. **槽位陷阱**：本机 b 槽 chain key mismatch（另一套固件密钥），`fastboot boot` 失败会翻槽；刷写前后都要 `fastboot getvar current-slot` 确认。
3. **userdata 与 metadata**：换任何系统（GSI/LineageOS）都必须清 userdata + metadata（FBE 加密元数据不兼容）。
4. **双 Type-C**：fastboot 只认长边口。
5. **GPT 已手术**：本机 userdata 已缩到 146.4G、sda17 65G——刷回任何"全量原厂线刷包"会重写 GPT，需注意 sda17 分区会被冲掉（先备份其中数据，或改用不写 GPT 的 fastboot 路径）。
6. **erhai ≠ elden**：同 SoC 不等于免改——屏参/触屏/音频/TF/传感器都要适配；TWRP 树显示 recovery 层（ bootloader 后半段）通用性好，但全系统 HAL 还是要逐一验证。
7. **GKI 便利**：四代是 GKI 6.6 内核 → 换内核（SukiSU/自编）不牵扯全量内核适配，root 和内核魔改门槛低于老机型。

## 6. 建议的下一步（按顺序）

1. **设备现状核查**（Android 侧）：`adb shell getprop` 抓 `ro.treble.enabled`、`ro.vendor.api_level`、`ro.product.*`、 Treble Info app 确认 arch（应为 arm64 AB）→ 决定 GSI 变体
2. **TWRP 顶底**：刷 polygraphene 的 TWRP release 到 recovery（可救砖/刷包/备份），EDL 兜底链路已就位
3. **路线 B 冒烟（1 天级）**：官方 AOSP 16 GSI（vanilla 先不装 GMS）刷 system + vbmeta 禁验证 + 清数据 → 验证显示/触屏/GPU/充电/WiFi/蓝牙/音频 哪些 HAL 能通 → 产出兼容性矩阵
4. **路线 A 立项（主工程）**：基于 LineageOS erhai 树建 `device/lenovo/TB322FC`，vendor 从官方 OTA 提取（aweiyry/lenovo-ota-tool），内核先用官方 6.6 + Y700 dtb，逐步适配屏参/触屏/音频
5. **备份纪律**：所有刷写前 `backup/stock-259/` + sda17 数据先导出；每步都留回退镜像
