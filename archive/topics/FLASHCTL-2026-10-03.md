## 0. 结论（三条能力现状不同）

| 能力 | 现状 | 现成机制 | 缺什么 |
|---|---|---|---|
| **reboot → fastboot** | 🟢 机制**已在设备上** | DT `reboot-mode{nvmem-reboot-mode}`（pmk8550）+ PMIC SDAM `reboot-reason@48`，`mode-bootloader=0x02` | 仅缺 userspace：以 reason 调 `reboot(2)`（RESTART2） |
| **reboot → EDL** | 🔴 主线 7.2 树**无通路** | 需 **PSCI SYSTEM_RESET2 vendor reset**（`mode-edl=<0x80000000 0x1>`）或 **TCSR dload cookie**（`qcom,dload-mode`） | 驱动 + DT（`psci-reboot-mode` / `qcom,dload-mode`）+ 用户态触发 |
| **槽位：active / successful / retry** | 🟢 已有 `scripts/slot-attr.py` | GPT 分区项 attribute 第 6 字节（`boot_*` on **LUN4 `/dev/sde`**） | 包成 CLI；与 C7 合并 |

## 1. 实机证据（2026-10-03，U2 运行 vk40re，SSH `192.168.7.1`）

- `/sys/firmware/devicetree/base/reboot-mode/` 存在：`compatible=nvmem-reboot-mode`、
  `mode-bootloader=0x02`、`mode-recovery=0x01`、`nvmem-cells=<reboot_reason>`。
- `/sys/bus/platform/drivers/nvmem-reboot-mode/reboot-mode -> devices/platform/reboot-mode`：**驱动已绑定**。
- nvmem 设备 `spmi_sdam1`（DT `nvram@7100`），cell `reboot-reason@48,1` 当前值 `0x00`。
- `/sys/kernel/reboot/mode` 读 `cold` —— 这是内核的 **reboot_mode（cold/warm/hard/soft）**，
  `kernel/reboot.c` 的 attr，**与本特性无关**（易误认，勿用）。
- `init`（busybox/Alpine 3.24.2）；`/sbin/reboot` 是 busybox，**不接受 reason 参数** → 需自备触发器。

### 机制如何工作（mainline `drivers/power/reset/reboot-mode.c`）
`kernel_restart(cmd)` → `reboot_notifier` → `get_reboot_mode_magic()` 把 **cmd 字符串**与 DT `mode-*`
属性名匹配（`bootloader`/`recovery`…）→ `reboot->write(magic)`。即：**只有带 reason 字符串的
`reboot(2)`（`LINUX_REBOOT_CMD_RESTART2`）才能触发**，普通 `reboot -f` 不行。

## 2. EDL 的两条主线路径（本树都缺）

### 2.1 PSCI SYSTEM_RESET2 vendor reset（上游 SM8750 的正解）
上游 2026-05 系列 `psci_sys_reset2 reboot modes`（Anurag Pateriya）给 sm8750-mtp/qrd 定义：
```dts
&psci {
        reboot-mode {
                mode-bootloader = <0x80010001 0x2>;   /* fastboot */
                mode-edl        = <0x80000000 0x1>;   /* EDL / Firehose */
        };
};
```
配合新的 `psci-reboot-mode` 驱动 + `drivers/firmware/psci/psci.c` 的 vendor-reset 出口
（`reboot-mode: add trigger op`）。
**本树现状**：`drivers/power/reset/psci-reboot-mode.c` **不存在**；`psci.c` 的 `SYSTEM_RESET2`
写死 `reset_type=0`（architectural warm reset），**无 vendor 出口**。→ 需移植 2 个补丁 + DT。

### 2.2 TCSR dload cookie（`qcom,dload-mode`）
上游 2026-01 补丁给 `sm8750.dtsi` 的 `scm` 节点加 `qcom,dload-mode = <&tcsr 0x19000>`；
`qcom_scm_set_download_mode()` 会写该寄存器（`QCOM_DLOAD_MASK`）。本树 `sm8750.dtsi` **无此属性**
（`hamoa.dtsi` 有，可作模板）。但它**没有用户态触发**（主线只用于 crashdump 路径），需自加 trigger。

### 2.3 两步兜底（零内核改动）
`reboot bootloader`（若 §0 第一行成立）→ 进 fastboot → `fastboot oem edl`。需要 host 侧执行
fastboot；适合作为验证 PSCI 失败时的 fallback。

> **TWRP 参考**：`twrp/twrp.img` 是 Android bootimg（header v4，kernel_size=0，ramdisk 52 MB **LZ4**）。
> TWRP 的「Reboot to EDL」走的是**厂商内核**的 reboot handler（vendor 私有），**不能直接移植到 mainline**；
> 主机暂无 `lz4`（python lz4 被 PEP668 拦），ramdisk 内脚本待解（需要的只是行为对照，不是代码）。

> **已知死路（勿重试）**：`misc` BCB `bootonce-bootloader` 写后 `reboot -f`，**ABL 不采纳**
> （`PITFALLS` #88 / `AUDIT3` §7，2026-10-03 实测）。

## 3. 设计：`eldroid-bootctl`（单文件 Python，随 rootfs 下发）

设备端已具备 `python3`（`slot-attr.py` 即实机 python）。一个脚本，子命令：

```
eldroid-bootctl reboot <bootloader|recovery|edl|system>   # RESTART2 + reason；edl 依赖内核支持
eldroid-bootctl slot info                                  # 读 boot_a/boot_b byte6 解码
eldroid-bootctl slot active                                # 打印当前活动槽
eldroid-bootctl slot set-active <a|b>                      # 写 AB_SLOT_ACTIVE_VAL=0x3F
eldroid-bootctl slot mark-successful [a|b]                 # 当前槽 active+succ+retry=7（默认当前槽）
eldroid-bootctl slot set-retry <0..7> [a|b]                # 只补/改计数
```

- reboot 实现：`libc.reboot(0xfee1dead, 672274793, 0xa1b2c3d4, reason)`（ctypes），无需编译。
- slot 实现：直接复用 `slot-attr.py` 的 `Gpt` 类（import）或 `subprocess`。
- 安全：所有写操作要求 root；写前自动 `dd` 备份 GPT 前/后 34 扇区；写后读回校验。

## 4. 分阶段（低风险 → 高风险）

| 阶段 | 内容 | 设备动作 | 风险 |
|---|---|---|---|
| **S1** | 落 `eldroid-bootctl`（reboot+slot），**先只测 `reboot bootloader`** | 用户执行；进 fastboot 即成功，`fastboot reboot` 回来 | 🟢 可逆（最坏进 fastboot） |
| **S2a** | 若 S1 的 PMIC-SDAM 路不被 ABL 采纳 → 移植 `psci-reboot-mode`（驱动+psci.c+DT），出 `vk41-flashctl` | 用户刷 b 槽测 | 🟡 需内核构建；PSCI vendor reset 是否被 TZ 支持未知 |
| **S2b** | 加 `qcom,dload-mode` + 用户态 trigger 作 EDL 备选 | 同上 | 🟡 |
| **S3** | slot 子命令上机验证（与 C7 合流） | 用户执行 | 🟢 |

**基座**：S2 的内核构建建议以 **`elden/vk34-recon`** 为基（已验稳定，且本特性的 DT 改动与音频/热区增量正交）；
产出后可与任何功能基线合并。

## 5. 待验证 / 风险

1. **PMIC SDAM reboot-reason 是否被 SM8750 ABL 采纳** —— 上游 SM8750 反而新加 PSCI vendor reset，
   暗示 SDAM 路可能无效；S1 一测即知。
2. **TZ/hyp 是否支持 PSCI SYSTEM_RESET2 vendor reset type**（签名 Gunyah 在 EL2；PSCI 走 TZ）——
   S2a 一测即知；不支持则只能走 S2b（dload cookie）或 2.3 两步。
3. `reboot` 与长轮询不得同条命令（`AUDIT3` 教训）；`fastboot boot` 失败的脏状态用
   `fastboot reboot bootloader` 清（`PITFALLS` #4/#41）。
4. 本特性与 **C7（切槽脚本）** 重叠 → 合并，避免两套。
