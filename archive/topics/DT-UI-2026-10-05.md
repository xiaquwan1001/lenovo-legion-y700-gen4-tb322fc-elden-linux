## 1. ★ 关键操作坑：`gsettings` 写入必须有活的 session bus

- 直接用 `gsettings set ...`（无 `DBUS_SESSION_BUS_ADDRESS`）时，写入**没有生效**——
  之前据此得到的"改了也没变化"截图/结论**全部无效**（写到了过期/不存在的总线）。
- **可靠写法**：`HOME=/root dbus-run-session -- gsettings set <schema> <key> <val>`；读回同样 `HOME=/root gsettings get ...`。
- 教训：本机无登录会话，`gsettings` 的 dconf 后端依赖 session bus；**不要用裸 `gsettings set` 判定 dconf 是否生效**。

## 2. G1-26/G1-27 根因（深色无效 + 电源菜单图标反色）—— 同一根因，已用无头 GTK3 探针**证实**

无头 GTK3 探针（模拟 phosh：设置 `gtk-theme-name` + `gtk-application-prefer-dark-theme`，查 `theme_fg_color`/`theme_bg_color`）：

```
gtk-theme       prefer_dark   theme_fg_color        theme_bg_color
Adwaita-dark    True          rgb(46,52,54)  ← 深色字   rgb(246,245,244) ← 浅色底   ❌ 实际解析成【浅色】
Adwaita         True          rgb(238,238,236) ← 浅色字 rgb(53,53,53)    ← 深色底   ✅ 深色
Adwaita-dark    False         rgb(46,52,54)            rgb(246,245,244)
Adwaita         False         rgb(46,52,54)            rgb(246,245,244)  ← 未强制 dark 时 = 浅色（符合预期）
```

**根因**：GTK3 的 `gtk-theme-name='Adwaita-dark'` 解析失败（无对应 theme 资源），
**回退到浅色 Adwaita**；而 GTK3 的"深色 Adwaita"是靠 **`gtk-application-prefer-dark-theme=TRUE` + 主题名 `Adwaita`** 选择 dark 变体，
不是靠名为 `Adwaita-dark` 的主题。当前 `color-scheme=prefer-dark` 已设、phosh 自身也强制 dark，但**主题名写错** ⇒ 拿到浅色前景。

- **G1-26（深色无效）**：即上述解析回退；phosh 本体用浅色前景/背景。
- **G1-27（电源菜单四图标反色）**：**同一根因**——symbolic 图标取 `theme` 前景色；浅色主题的前景色（近黑 `rgb(46,52,54)`）
  画在 phosh 深色弹窗上 ⇒ 黑到分不清。修复深色即同时修复图标。

**修复（待上机）**：`gtk-theme='Adwaita'`（保留 `color-scheme='prefer-dark'`）。备用：`GTK_THEME=Adwaita:dark` 环境变量。
**回退**：改回 `gtk-theme='Adwaita-dark'`（原始值）。**重启后需保持** ⇒ 写入 phosh 会话的 dconf（`/root/.config/dconf/user`），非临时 env。

## 3. G1-26 附：accent（主题色）无法切换

- 会话**读 phosh 源码**发现：phosh 的 accent 处理对 `gtk-theme-name == 'Adwaita-dark'` **提前 return**（只接受 `Adwaita`）
  ⇒ 当前 `accent-color=pink` 被忽略。
- 因此 **`gtk-theme='Adwaita'` 是 #1/#2/#4 的单一修复点**：既让 GTK3 拿到 dark 变体（前景转白），又放行 accent。
- 备注：`accent-color` 是 GNOME 47+/libadwaita 机制，GTK4 应用走 `color-scheme` 另算；phosh 本体（GTK3）需此 guard 放行。
  **待上机确认** accent 是否即时生效（会话内 blue/pink 截图相同的观测是在"写入无效"的错误前提下取得，需重测）。

## 4. G1-28 亮度滑块无效 —— 根因在 elogind，不在设备名/绑定

- 背光 **可写**：`/sys/class/backlight/aw99706-backlight`（max 4095，`echo` 生效，`actual_brightness` 跟随）。
- `upower -i .../DisplayDevice` **无 `Brightness` 属性**；Phosh 日志：
  `phosh-backlight-WARNING: Setting backlight on DSI-1 failed: GDBus.Error:System.Error.EISDIR: Is a directory`。
- 直调 elogind `Session.SetBrightness`（任意 name，含空串）**均返回 `EISDIR`** ⇒ 非设备名/滑块绑定问题。
- elogind 255.24 源码：`logind-brightness.c` 走「brightness writer 子进程 + `/sys/class/tty/tty0/active`」，
  并有 `Only owner of session may change brightness.`；本机 **`loginctl list-sessions` 为空、无 VT/active tty0**、cgroup 无 session 管理 ⇒ 该机制走不通。
-（父会话补充）Phosh **自带 sysfs 后端**（`PhoshBacklightSysfs`/`backlight-sysfs.c`），但优先走 logind；
  且 `/sys/class/drm/card0-DSI-1/backlight` 符号链接不存在。

**候选修复方向**（择一，未定，需用户拍板；会话中断于此）：

| **B** | 换/降级 elogind（走简单 sysfs writer 路径） | 影响全局电源/会话管理 |
| **C** | 让 Phosh 走 sysfs 后端（补 DRM connector backlight 链接或 patch phosh） | 最小侵入，方向待验 |
| **D** | 小 root 守护桥接（监听 gsd-power，直写 sysfs） | 另起进程，非标准 |
