# TF 卡（SDHCI/SDC2）调查 — 2026-09-30

> 入口 `INDEX.md`；厂商源码见 `STOCK-DRIVERS-2026-09-30.md`。任务：C2（TF 卡可靠性）。

## 0. 一句话

**间歇性小写丢失、控制器零报错**。未能排除“卡本身不可靠”与“驱动缓存一致性/时序”。
需要做 **换卡 A/B** 才能定性。主线驱动确有一处厂商具备、主线缺失的特性：`qcom,uses_level_shifter`。

## 1. 复现与证据

| 实验 | 结果 |
|---|---|
| `mmc0/err_stats`（命令/数据 CRC、超时、ADMA、tuning…） | **全 0** |
| `mkfs.ext4 p2` 后立刻 `mount` | 失败：`JBD2: no valid journal superblock found`（超级块本身可读） |
| `mkfs.ext4 -O ^has_journal` 后 `mount` | 也失败：`Checksum for group 0 failed … group descriptors corrupted!` |
| `e2fsck -fn`（drop_caches 前/后各一次） | 结果**完全相同** → **卡上数据确实坏了**，非单纯读缓存陈旧 |
| 4KB 小写压测（2000 块） | **12/2000 不一致** |
| 同一压测复跑（3000 块） | **0/3000**（→ **间歇性**） |
| 1MB 大块跨卡写读（100/5000/15000/30000/45000/58000 MiB） | 全部一致（→ 非扩容卡、非大范围坏区） |

结论：
- **总线层“成功”但数据损坏** → 丢在“控制器→卡”之后，或内存↔DMA 一致性。
- 非扩容卡；非纯信号完整性（否则应有 CRC/超时）。
- 间歇性 + 白牌卡（`NCard`、date 01/2010、OEM 0x0303）→ **高度怀疑卡本身**，但需排除驱动。

## 2. 驱动 / DT 差异（厂商 GPL 源码）

| 项 | 主线 | 厂商 |
|---|---|---|
| `qcom,uses_level_shifter` | **无**（驱动无此属性处理） | 有；`msm_set_clock_rate_for_bus_mode()` 里对 `SD_HS` 用 `LEVEL_SHIFTER_HIGH_SPEED_FREQ=37.5MHz` |
| `qcom,external-fb-clk` | 无 | 无（本机未用） |
| UHS | `no-1-8-v`（强制 3.3V / HS 37.5MHz） | `cap-sd-highspeed` + `sd-uhs-sdr12/25/50/104`（1.8V） |
| vqmmc | `vreg_l8b_1p8`（LDO8，1.8–3.008V） | `pm_humu_l8`（1.8–2.96V，可变） |
| `qcom,dll-config`/`ddr-config` | `0x0007442c` / `0x80040868` | 基线（未从预编译 dtb 成功反出，待查） |

主线 `&sdhc_2` 的注释已自述：“UHS SDR104 下 mkfs/mount 静默损坏、原始 I/O 正常；
强制 3.3V/High-Speed 后**较慢但稳定**”。但实测**3.3V 下仍间歇写坏** → 该 workaround 对本卡不足够。

## 3. 下一步（需要物理介入）

1. **换一张已知良好的 TF 卡** → 复跑同一压测。
   - 若新卡正常 → **本卡不良**（任务即闭环：换卡）。
   - 若新卡也坏 → 驱动/DT 问题，继续下面。
2. **本卡插安卓（ZUXOS）或电脑读卡器**测同样的写。
   - 安卓/读卡器也坏 → 卡不良。
3. 若判定为驱动问题，候选改动（按代价）：
   - 移植 `qcom,uses_level_shifter` + 相关 DLL 字段到主线 `sdhci-msm.c`；
   - 试 **去掉 `dma-coherent`**（排查非相干 DMA）；
   - 试 **启用 UHS 1.8V**（去掉 `no-1-8-v`，用可变 vqmmc）（需重编 DTB、重启）；
   - 降速（`max-sd-hs-hz`）验证信号余量。
