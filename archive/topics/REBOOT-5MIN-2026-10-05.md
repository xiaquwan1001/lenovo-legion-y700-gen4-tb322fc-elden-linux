# 未解释现象：进桌面后 ~5 min 整机硬重启（2026-10-05，仅记录，未受控复现）

> 状态：**未解 / 未受控复现**。结论以 `TASKS.md` §5 Q24 为准；本文件只存原始观测。

## 1. 观测

- 平台：U2，boot_b 持久直启；内核 `7.2.0-debug-g4c68eb5ed4e3-dirty`（= commit `4c68eb5ed`，vk46 + 未提交 vk47 DTS）。
- 现象（用户报告）：**进入桌面后约 5 min 自动整机重启**；**已观察到 2 次**。
- 复位性质：**硬复位**——`/sys/fs/pstore/` 为空、无 panic；无 `/dev/watchdog*`，dmesg 明确 `watchdog: Hard watchdog permanently disabled`（排除看门狗）。
- 桌面 `idle-delay = 300`（5 min）⇒ 时间上高度吻合「空闲熄屏（DPMS off）」（关键词：G1-22 / Q21）。

## 2. 与已知 G1-22 的关系（重要）

- G1-22 根因 = **vk40 音频调试插桩**（N1：`dev_info` 内同步阻塞 `q6apm_get_apm_state()`）+ 热区 DTS；`vk42` 干净重落后判为**免疫**。
- 但 `git diff eb432f18a(vk42) 4c68eb5ed(vk46)` **只改了 DTS**（`sm8750-lenovo-elden.dts`，+111 行，WCD939x/SWR/DMIC），**驱动代码与免疫的 vk42 完全一致** ⇒ 不是旧的 N1/N4 插桩。
- G1-22 的「免疫」是在 vk42 上验证的；此后 boot_b 为音频 bring-up 换成了 vk44–vk47（仅 DTS 变），**免疫结论未在新 DTS 上重新验证**。

## 3. 为何「未受控复现」

- 本次会话中设备在桌面态、`idle-delay=300` 下**连续稳定运行 ≥60 min，未重启**；一次专门盯守里 uptime 到 **304 s 时 `dpms` 仍为 `On`**（未熄屏），随后同一 `boot_id d7fb5705` 继续跑到 **475 s 仍未重启**。
- 即：**无法用「等待 5 min」稳定复现**；用户侧的 2 次未能被独立观测到。

## 7. 2026-10-05 复现确认（append-only 补充）

**结论：受控复现成功——触发 = 熄屏（DPMS off），与电源键是同一路径。**

### 7.1 受控 DPMS off（决定性）
设备上 `sh /tmp/g1-22-dpms-test.sh 1`（内部 `wlr-randr --output DSI-1 --off`）：
输出止于 `BASE_DPU_WAIT=0`，随后 SSH **立即断开**、`boot_id` 改变 ⇒ **硬复位**。

### 7.2 电源键路径（跨重启 `dmesg -w` 抓取，用户单击一次）
```
[  275.813] elogind[646]: Power key pressed short.        # 无 "will power off"
[  280.066] power_supply qcom-battmgr-usb: driver failed to report `online' property: -110
Timeout, server 192.168.7.1 not responding.               # USB 掉线 → 复位
```
无 suspend 痕迹、无 poweroff、pstore 空 ⇒ **电源键 → phosh 熄屏（DPMS off）→ 硬复位**；
即用户所感「单击电源键直接关机」。`elogind` 配置为 `HandlePowerKey=ignore`，非 elogind 发起。

### 7.3 相机排除（反驳"本轮新加载相机模块所致"）
停 wireplumber + `modprobe -r qcom-camss`（`lsmod|grep -c camss`=0）后 `wlr-randr --off`
**仍复位** ⇒ 与 2026-10-05 新加的相机 boot 自动加载无关。

### 7.4 与 G1-22「免疫」结论的矛盾（重要）
- 当前 boot_b 解包核对 = `out/boot-elden-vk47.img`，UTS `7.2.0-debug-g4c68eb5ed4e3-dirty`，
  `kernel_git_head=4c68eb5ed`（vk46）+ 未提交 vk47 DTS。
- G1-22 曾声称**同一 UTS 的内核**「10 轮 + 90 s 熄屏不复位 ⇒ 已免疫」——**与本次受控复现直接矛盾**。
  ⇒ 该「免疫」结论必须重新审视（疑点：当时的 `wlr-randr` 是否真正连上 Wayland 生效、或环境/状态不同）。
- 各镜像内核身份（解包实测）：`vk42`=`7.2.0-debug-vk42-geb432f18a0d1`（head eb432f18a, clean）；
  `vk46`=`…ga923477be3a9-dirty`；`vk47`=`…g4c68eb5ed4e3-dirty`；`vk34recon`=`…ge72a036ed4be`。

### 7.5 下一步（单变量，需 fastboot）
`fastboot boot` **vk42** 与 **vk34recon** 镜像（**同一持久 rootfs**，零写盘），各跑 `g1-22-dpms-test.sh`：
- vk42 免疫、vk47 复位 ⇒ 回归源在 `vk42..vk47` 的 **DTS 增量**（WCD939x/SWR/VA-macro，+111 行）；
- vk42 也复位 ⇒ 早先「免疫」判断本身有误，需回到 vk34recon 基线重查。

### 7.6 vk42 对照实测（2026-10-05，用户 `fastboot boot out/boot-elden-vk42.img`）

`git diff vk42..vk47` 仅 DTS ⇒ 回归源锁定 **DTB/DTS 增量**。

### 7.7 单变量隔离镜像（已备，待引导）
`out/boot-elden-vk47-dtb42.img` = **vk47 内核 + vk47 ramdisk + vk42 DTB**（`dtb` 段逐字节 == vk42 镜像的 DTB）。
用途：保持内核/config/ramdisk 不变，只换 DTB——若免疫 ⇒ 触发在 DTS（WCD939x/SWR/VA-macro 的实例化）；
若仍复位 ⇒ 触发不在 DTB（转向 config/其他）。

### 7.8 决定性判定：干净重建免疫 ⇒ 根因在 boot_b 的 `-dirty` 构建（2026-10-05）

单变量链条：
| # | 内核/镜像 | 源码 | 熄屏 DPMS off | 结果 |
|---|---|---|---|---|
| 1 | `vk42` 镜像 | 干净 eb432f18a | 2 轮 | ✅ 免疫 |
| 2 | boot_b = `vk47` 镜像 | vk46 + **未提交改动**（`-dirty`） | 立即 | ❌ 硬复位 |
| 3 | `vk47` 内核 + **vk42 DTB**（`out/boot-elden-vk47-dtb42.img`） | 同上 | 1 轮 | ❌ 硬复位 ⇒ **DTB 无关** |
| 4 | **干净重建**（`bd114ca33` clean + `/proc/config.gz` 的 vk47 config，`out/boot-elden-clean.img`） | 已提交 | 2 轮 | ✅ **免疫** |

旁证（排除法）：
- vk42 与 vk47 的**内嵌 config `diff` = 0 行**；两内核**字符串集合几乎相同**（无额外音频调试串）；ramdisk 提取内容相同（仅 gzip 率/符号链接差异）。
- ⇒ 二者差异只能来自 **boot_b 那份 `-dirty` 二进制的未提交改动**（git 提交历史里看不到——未知是否/如何被后续提交覆盖）。

**结论**：G1-22 的修复（vk42 干净重落）在**源码层面成立**；但 **boot_b 实际烧的是用脏树构建的 vk47 镜像**，把 bug 又带了回来。因此：
- **修复 = 用干净源码重建内核并重刷 boot_b**（干净重建已实测免疫）；
- **教训 = 镜像不可复现于任何提交**：`kernel_git_state=dirty` 的镜像必须视为不可信（这正是 vk50 起用 manifest+`LOCALVERSION` 双钉的动因）。
