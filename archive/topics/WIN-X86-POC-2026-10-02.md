# WIN-X86-POC-2026-10-02 — Box64 + Wine 在 elden 上跑通 Windows x86_64 程序（真机 PoC）

> 承接 `WIN-X86-2026-10-02.md`（可行性调研）。本文件是**阶段 B 的落地结果**。
> 设备：TB322FC / SM8750 / Adreno 830，宿主 Alpine musl 1.2.6 + Phosh，mainline `7.2.0-debug`。
> 结论：**成功**。在设备上的 glibc aarch64 chroot 内，用 Box64 0.4.5(DynaRec) + Wine 9.0(wine64:amd64)
> 跑通了 Windows x86_64 程序：headless（`cmd /c echo hello`、外部 `strings64.exe`）与 GUI（`notepad.exe`，Phosh 窗口可见）。

**升级到 box64 0.4.5 后彻底消失**。并新增 cgroup pids 上限 + 超时 + 退出全清三道防护。

## 1. 环境构建（可复现步骤）

### 1.1 glibc rootfs（阶段 A，已完成）
设备侧已有 `/root/glibc-rootfs`（Ubuntu 24.04 arm64 base，`ldd`=glibc 2.39）。
本仓库固化脚本：`scripts/win-x86-rootfs.sh build|deploy`（下载/解包/部署 rootfs 并 bind-mount 验证）。

### 1.2 chroot 挂载（幂等）
```sh
R=/root/glibc-rootfs
for m in /dev /proc /sys /dev/shm /dev/pts /run; do
  [ -d "$R$m" ] || mkdir -p "$R$m"
  mountpoint -q "$R$m" || mount --bind "$m" "$R$m"
done
cp -f /etc/resolv.conf "$R/etc/resolv.conf"
```

### 1.3 安装 Box64（主机侧下载 → 设备安装）
```sh
# 主机：scripts/fetch-x86-assets.sh 的 box64 模式会取 Pi-Apps-Coders 源
# 本次固定到 2026-10-01 构建：box64-generic-arm_0.4.5+20261001T122452.f5ffcd0-1_arm64.deb
scp pkgs-x86/box64-generic-arm_0.4.5.deb root@192.168.7.1:/root/
# 设备：注意 deb 必须放进 chroot 内路径才能被 dpkg 看到
ssh root@192.168.7.1 '
  R=/root/glibc-rootfs; cp -f /root/box64-generic-arm_0.4.5.deb $R/root/
  chroot $R apt-get remove -y box64            # 移除 Ubuntu 旧 box64(0.2.6)，否则 Conflicts
  chroot $R dpkg -i /root/box64-generic-arm_0.4.5.deb
  chroot $R /usr/local/bin/box64 --version     # Box64 arm64 v0.4.5 ... with Dynarec
'
```

### 1.4 安装 Wine（wine64 amd64，随 w/box64 运行）
```sh
ssh root@192.168.7.1 '
  R=/root/glibc-rootfs
  chroot $R dpkg --print-foreign-architectures            # 应含 amd64
  # 若无 amd64：chroot $R dpkg --add-architecture amd64 && chroot $R apt-get update
  chroot $R apt-get install -y wine64                     # wine64:amd64 9.0 + libwine
'
```

### 1.5 让 wineserver / wine64 走 box64
Ubuntu `wine64` 只提供 `/usr/lib/wine/wine64`（**没有** `/usr/bin/wine64`），Wine 启动 wineserver
时会直接 exec 它；须把二者换成经 box64 调用：
```sh
R=/root/glibc-rootfs
# /usr/lib/wine/wineserver: 末尾 exec 行改为
#   exec /usr/local/bin/box64 $wineserver -p0 "$@"
sed -i 's#exec $wineserver#exec /usr/local/bin/box64 $wineserver#' $R/usr/lib/wine/wineserver
# 便捷 wrapper（本仓库做法）：
cat > $R/usr/local/bin/wine64-box64 <<'EOF'
#!/bin/sh
exec /usr/local/bin/box64 /usr/lib/wine/wine64 "$@"
EOF
chmod +x $R/usr/local/bin/wine64-box64
```

运行包装脚本：**`scripts/win-x86-run.sh`**（设备上 `/root/win-x86-run.sh`，自带防护，见 §3）。

## 3. 防护：fork 风暴的教训与对策（必读）

**事故**：首轮用 Ubuntu box64 **0.2.6** 跑 `wineboot` 初始化 prefix，触发 `explorer.exe` 无限重生：
262 个 wine/box64 进程、`loadavg` 74、可用内存 <5MB，OOM，SSH banner 超时，**拖垮了同时在用设备的
AudioPilot4 / CameraPilot3**（已致歉并让出窗口）。`pkill -9 -x` 按真实 comm 名（`explorer.exe`、`services.exe`、
`wineserver64`）清空后恢复。

**根因**：box64 0.2.6（2024-01，Ubuntu noble 包）与 Wine 9.0 的 wineserver 握手不兼容 → 每进程起一个新
wineserver/explorer，雪崩。**0.4.5（2026-10）无此问题**。

**对策（已固化进 `scripts/win-x86-run.sh`）**：
1. **cgroup v2 `pids.max`**：cgroup2 已挂 `/sys/fs/cgroup`，`/sys/fs/cgroup/wineguard` 设上限（默认 150），
   进程数到顶即 fork 失败，无法雪崩；
2. **`timeout -k 5 <秒>`** 硬截止；
3. **`trap cleanup EXIT`**：退出时按 comm 名 `pkill -9` 全部 wine/box64 并清空 cgroup；
4. 设备纪律：SSH 禁长 sleep，`nohup ... &` + 短命令轮询；运行前 `send` 报备设备窗口。

## 4. 已知问题 / 部署坑

| 坑 | 说明 / 处理 |
|---|---|
| `wine64: not found` | Ubuntu `wine64` 无 `/usr/bin/wine64`，用 `/usr/lib/wine/wine64` 或 wrapper `wine64-box64` |
| `wine: failed to open ... c0000135` | 外部 exe 必须**位于 chroot 内**（`cp` 到 `/root/glibc-rootfs/root/`），host `/root` 对 chroot 不可见 |
| box64 “native lib” 初始化失败告警 | `libfreetype/fontconfig/X11/xcb/SDL2` 等在容器内以 **emulated** 方式回退，**仅 warning，不影响运行**；需要的话在容器内 `apt install` 对应库 |
| GUI 必须解锁 | Wine 用 XWayland `:0`；Phosh 锁屏遮住窗口。`grim` 截图需 `XDG_RUNTIME_DIR=/run/phosh` |
| 旧 box64 冲突 | Pi-Apps deb 与 Ubuntu `box64` 包冲突，先 `apt-get remove -y box64` |

**性能**：本轮只验证“能跑通”，未做基准。冷启动（`wine64 cmd /c echo hello`，含 prefix 初始化）约数十秒；
已确认 box64 **DynaRec 启用**。后续基准（task-7 框架）可量测。
