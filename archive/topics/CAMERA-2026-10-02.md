## 1. 静态分析（DTS / 驱动 / config）

### 1.1 DTS 接线复核（`sm8750-lenovo-elden.dts`）

板级 DTS 的相机部分**已按厂商逆向填好且自洽**：

| 节点 | 内容 | 行 |
|---|---|---|
| `&camss` | `status=okay`，CSIPHY0–5 0p9/1p2 供电；`ports/port@3`→`camss_rear`（data-lanes 0-3），`port@4`→`camss_front` | 2146 |
| `&cci0` / `&cci0_i2c0` | okay + pinctrl；`rear_lens: lens@c`(gt9764, 0x0c, LDO5/LDO7)、`rear_camera: camera@56`(s5kjns, 0x56, MCLK3@19.2M, reset tlmm11, LDO7/1/4, link-freq 672M, 4-lane, `lens-focus`/`flash-leds`) | 2183 |
| `&cci1` / `&cci1_i2c0` | okay + pinctrl；`front_camera: camera@31`(gc08a8, 0x31, MCLK4@19.2M, reset tlmm7, LDO7/2/3, link-freq 336M, 4-lane) | 2231 |
| `&i2c10 pmic@2f` | `willsemi,wl2868c`，reset tlmm126，LDO1–5/7 电压（含厂商偏移） | 2064 |

`sm8750.dtsi`：`camss: isp@ad27000`（`qcom,sm8750-camss`，6×csiphy/5×csid/5×vfe），`cci0@ac7b000`/`cci1@ac7c000`（`qcom,sm8750-cci`,`qcom,msm8996-cci`）。

**结论：无需改 DTS。**

### 1.2 驱动侧

- `drivers/media/i2c/s5kjns.c`：`samsung,s5kjns`；要求 4-lane `data-lanes=<1 2 3 4>`、link-freq 含 **672MHz**、19.2MHz xclk、supplies `dovdd/dvdd/avdd`、reset GPIO；probe 读 ID `0x38ee`。→ 与 DTS 完全一致。
- `drivers/media/i2c/gc08a8.c`：`galaxycore,gc08a8`，同构。
- `drivers/media/i2c/gt9764.c`：`giantec,gt9764`，用 2 路 supply（vdd/vddio）。
- `drivers/regulator/wl2868c-regulator.c`：`willsemi,wl2868c`，读 ID `0x82`，注册 ldo1–7（`of_match="ldoN"`）。DT 缺 ldo6 节点，注册会退化为无约束，不影响 sensor 用的 ldo1–5/7。
- `drivers/i2c/busses/i2c-qcom-cci.c`：匹配 `qcom,msm8996-cci`（DTS 第二 compatible），提供 cci0_i2c0/cci1_i2c0 两条 I2C 总线 —— **上一轮遗漏的关键项**。
- `drivers/clk/qcom/camcc-sm8750.c` / `cambistmclkcc-sm8750.c`：提供 `CAM_CC_TITAN_TOP_GDSC` 电源域 + `CAM_BIST_MCLK_CC_MCLK3/4` 相机时钟 —— **上一轮遗漏的关键项**（sensor 靠它出 19.2MHz MCLK）。
- camss：`sm8750_resources`，`csiphy_res_8750` 含 id 0–5（3/4 对应板级 port@3/4），`camss_probe` 会注册 6×csiphy + 5×csid + 5×vfe 子设备。

## 2. 落地方案（主机侧已完成）

### 2.1 配置片段

`patches/fragment-camera-sensors.config` → 合并入 `.config`（`merge_config.sh` + `olddefconfig`）。
快照：`patches/config-vk38-camera`（4096 行，含上述全部符号）。
备份：`patches/config-vk32-camera-base.bak`。

### 2.2 构建

```bash
cd ~/y700-elden/linux
export PATH=$HOME/bin:$PATH ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu-
make -j16 modules
make -j16 INSTALL_MOD_PATH=/tmp/modstage modules_install
```
产物 vermagic：`7.2.0-debug-gba28ec16f01f-dirty SMP preempt mod_unload aarch64`（与设备运行内核逐字节一致）。

### 2.3 依赖闭包（17 个 `.ko`）

```
drivers/clk/qcom/camcc-sm8750.ko
drivers/clk/qcom/cambistmclkcc-sm8750.ko
drivers/i2c/busses/i2c-qcom-cci.ko
drivers/regulator/wl2868c-regulator.ko
drivers/media/mc/mc.ko
drivers/media/v4l2-core/videodev.ko
drivers/media/v4l2-core/v4l2-async.ko
drivers/media/v4l2-core/v4l2-fwnode.ko
drivers/media/v4l2-core/v4l2-cci.ko
drivers/media/common/videobuf2/{videobuf2-common,videobuf2-memops,videobuf2-dma-sg,videobuf2-v4l2}.ko
drivers/media/platform/qcom/camss/qcom-camss.ko
drivers/media/i2c/{gt9764,s5kjns,gc08a8}.ko
```
打包：`out/camera-modules-<ver>.tar.gz`（8.1 MiB）。

### 2.4 部署脚本

`scripts/deploy-camera-modules.sh`：scp → 解包到 `/lib/modules/<ver>/` → `depmod` → 按依赖序 `insmod` →
采集 `/sys/bus/i2c/devices`、`/dev/video*`、`media-ctl -p`、`v4l2-ctl --list-devices`、`dmesg`。
**不刷 boot、不重启。**

> **持久化缺口**：rootfs 无相机模块自动加载机制（无 udev/mdev 规则），需在 `/etc/modules` 或 init 脚本里加 `camcc-sm8750 cambistmclkcc-sm8750 i2c-qcom-cci wl2868c-regulator qcom-camss gt9764 s5kjns gc08a8` 才能冷启生效。

## 4. 剩余缺口与工作量

| 缺口 | 影响 | 工作量 |
|---|---|---|
| 冷启自动加载 | 重启后需手动 modprobe | 小（写 /etc/modules 或 init 脚本）|
| 模块持久化进 boot/rootfs 镜像 | 换内核时要重做 | 小 |
| `camera@56 ↔ isp@ad27000` fwnode 依赖环 warning | 非致命，可能影响 probe 顺序 | 小-中（可选）|
| camss 出流（VFE/CSID 实际抓帧） | 主线 ISP 为 best-effort，拍照/3A 未必可用 | 大（超出"最小可跑"）|
| 前摄 GC08A8 同时起 | 两个 sensor 抢 CSIPHY？各自独立，应可共存 | 小 |
