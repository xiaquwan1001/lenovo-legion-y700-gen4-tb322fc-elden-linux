## 0. 一句话

U2（`HA2EXB0E`）本日从「已解锁 + 原厂 259」做到 **b 槽持久 mainline vk40 + Phosh 自启**（G1-1/2/3 达成）；
但暴露**致命回归：桌面空闲熄屏（DPMS blank）→ 整机重启**，且改成 10 s 复现后进入重启环，未能救回。

## 1. 时间线（2026-10-03）

1. **解锁已在前序完成**（降级 1.1.11.073 + `fastboot oem unlock`）；U2 现态实为 **259 + unlocked**（旧「073/locked」记录作废）。
2. adb 只读采集 → `backup/HA2EXB0E-16+512/current-259/`；核验 b 槽原厂备份（`stock/` = 1.5.10.229）。
3. `fastboot boot out/boot-elden-vk40-ram.img` → **卡联想 logo**（== 2026-09-28 已知：ABL 把 stock 的 76 个
   Android overlay 合进内核 DT）。改用 **刷 b 槽**（blank `dtbo_b` + vk40 RAM + `vbmeta_b`）→ 直启成功。
4. mainline 起来 → 经 ssh 完成 **GPT dump**（U2 自己的 `backup_lba=123871231`）。
5. **GPT 手术**：`userdata` 449.7 → **256.7 GiB**，新增 **`linux17`=193.0 GiB**（idx16 → `/dev/sda17`）；写后重 dump CRC OK。
6. `mkfs.ext4 -L linux17 /dev/sda17` + 解包 rootfs 归档（30852 项 / 8.3 GB）→ 持久根。
7. 刷持久 `boot_b` + 清 `userdata`/`metadata`（给 a 槽 Android 重建 256.7 GiB 的 `/data`）→ 重启。
8. **首次持久启动 panic**：`Kernel panic - not syncing: VFS: Unable to mount root fs on unknown-block(0,0)`，
   反复重启；ABL 把 `boot_b` 重试计数从 7 扣到 4（`byte6=0x27`，succ=0），最后落到 fastboot。
9. 救回：回刷 RAM 核；做**诊断镜像**（在原 persistent ramdisk 的 `/init` 里提前初始化 USB 控制台并打点），
   dd 到 `boot_b` → **成功切根**（dmesg：`switching root to /dev/sda17 (/init)`）→ Phosh 自启。
10. `slot-attr.py mark-successful b`（`byte6 0x27→0x7f`）；重启验证仍进 `/dev/sda17`。
11. 用户报告 **熄屏即关机重启**；复现（`idle-delay` 300→10）→ 陷入重启环，SSH 窗口过短，未能改回。

## 2. 已确认的事实（可复用）

| 项 | 结论 |
|---|---|
| GPT 手术 | U2 `userdata`=256.7 GiB、`linux17`=193.0 GiB（`/dev/sda17`，idx16）；`backup_lba=123871231`；双表 dump 在 `backup/HA2EXB0E-16+512/`（`gpt_{main0,backup0}.bin` 术前、`gpt_post-surgery_*` 术后） |
| 持久直启 | `findmnt /`=`/dev/sda17`（ext4）；Phosh（phoc/phosh/gnome-session）自启；重启保持 |
| **`fastboot boot` 陷阱** | 必须先 **blank `dtbo_b`**，否则 ABL 套用 stock overlay → 卡 logo。见 `RUNBOOK §3`、`INDEX §4` |
| **槽位重试计数** | 在 GPS `boot_a/b` 分区项 attribute byte6：bit6=successful、bit3-5=retry。启动失败会扣；归 0 → UNBOOTABLE → 停 fastboot。自编 mainline 不置 successful → 反复调试会把 b 试到不可启动。修：`scripts/slot-attr.py mark-successful b`（详见 `PITFALLS` #71） |
| 内核迭代路径 | 持久根里 `/dev/disk/by-partlabel/` 存在 → `scripts/flash-b.sh`（自签 + dd `boot_b` + 读回校验）可全程免 fastboot |
| b 槽当前镜像 | **诊断版持久镜像**（早初始化 USB 控制台）→ 归档 `bootslot-b/boot_b_vk40-persist-diag.img`；原 `out/boot-elden-vk40.img` = 干净持久版（首次启动曾 panic） |

主机侧可用镜像：
- `out/boot-elden-vk40-ram.img`（纯 RAM，**已实测可用**）
- `bootslot-b/boot_b_vk40-ram.img`（RAM + AVB）
- `out/boot-elden-vk40.img`（干净持久；未复测）
- `bootslot-b/boot_b_vk40-persist-diag.img`（**当前 b 槽在用**，诊断版）

## 3. 「熄屏即重启」故障（本轮最严重，未解）

**现象**：桌面空闲熄屏（`card0-DSI-1/dpms=Off`）后整机重启（用户描述“直接关机，并且会重启”）。
`idle-delay` 改 10 s 后每次都触发，形成重启环。

**证据**：
- 串口日志 `logs/serial-20261003-192121.log`：重启前最后 3 行——
  ```
  ucsi_glink.pmic_glink_ucsi pmic_glink.ucsi.0: timeout waiting for UCSI read response
  ucsi_glink.pmic_glink_ucsi pmic_glink.ucsi.0: failed to reset PPM!
  ucsi_glink.pmic_glink_ucsi pmic_glink.ucsi.0: error -ETIMEDOUT: PPM init failed
  ```
  随后直接 `Booting Linux …`（**无 `Kernel panic` / `soft lockup` 打印**）。
- `/sys/class/watchdog/` 为空（硬 watchdog 永久禁用）；`/sys/power/state` 空（**`CONFIG_SUSPEND` 未开**，无 `mem_sleep`）。
- 内核 cmdline 带 `panic=15`（panic 会 15 s 后自动重启）。
- DP/altmode 本就不工作：`pmic_glink.altmode … failed to acquire mode-switch for port: 0`（关联 **G1-9**）。

**推测（未证实）**：熄屏触发面板/电源域动作 → **ADSP（pmic_glink/UCSI PPM）崩溃或失联 → 整机复位**；
或为 PMIC 电源域硬复位。因为没有 panic 打印，更像**硬件/固件级复位**而非内核 panic。

**为什么“之前版本绕开”**：`PITFALLS §64–66` 记录早期做法是
`echo s2idle > /sys/power/mem_sleep` **+ 取消桌面空闲熄屏（`idle-delay=0`）**。
但当前内核 `CONFIG_SUSPEND=n`（无 s2idle 可设），所以剩下的规避手段就是 **禁止空闲熄屏**
（`org.gnome.desktop.session idle-delay=0`，或 phosh caffeine 常开）。
本 rootfs 归档里没有 dconf 覆盖 → 默认 `idle-delay=300` → 5 分钟熄屏 → 命中。

## 4. 当前危险状态（下轮开工前必读）

- `linux17` 的 dconf 里 **`idle-delay=10`**（本轮的实验值），导致每次熄屏即重启 → **重启环**；
  设备当前 **不可达**（SSH 窗口 < 熄屏周期，未能改回）。
- `boot_b` = 诊断版持久镜像；`dtbo_b` = blank；active=b。
- a 槽 Android 259 原样，但 `/data`/`metadata` 已擦（未验证过 a 槽能否重建 `/data`）。
- `misc` 首 4 KiB 曾被 `cycle.sh --fastboot` 清零（A/B 控制在 GPT attribute，不受影响）；下次可 `fastboot --set-active=b` 重写。

## 5. 恢复方案（下轮第一件事，优先级最高）

**目标：先把机器弄回可达状态，再修 sleep。**

- **路线 A（推荐）**：物理键进 fastboot（关机后长按 电源+音量下）→
  ```bash
  cd ~/y700-elden
  fastboot flash boot_b bootslot-b/boot_b_vk40-ram.img   # 先回纯 RAM（无桌面，不会熄屏）
  fastboot --set-active=b && fastboot reboot
  sudo bash elden-net.sh   # 需要时
  ```
  起来后 **挂 linux17 把 dconf 的 idle-delay 改回 0**：
  ```bash
  ssh root@192.168.7.1 'mount /dev/sda17 /mnt/new'   # 或直接从 RAM 环境改
  # 设备上（持久根）用 gsettings 会依赖 session bus；更稳的是在 start-desktop.sh 里加一行
  #   gsettings set org.gnome.desktop.session idle-delay 0   （需等 session bus）
  # 或 phosh 的 caffeine quick-setting 常开
  ```
  **加固（务必）**：把「禁止空闲熄屏」写进 `scripts/start-desktop.sh`（并同步 rootfs 归档），
  使任何一次重建 rootfs 都不会再命中。
- **路线 B**：切 active=a 进 Android 兜底（`slot-attr.py set a` 或 `fastboot --set-active=a`）。
- **路线 C**：把 linux17 的 `/root/.config/dconf/user` 离线改掉（dconf 二进制，需 `dconf` CLI）。

> ⚠️ 恢复前先 `fastboot fetch`/EDL 备份现状；不要再次在不可回滚的持久系统上做熄屏实验。

## 6. 教训（防复发）

1. **实验性改动要可回滚**：`idle-delay` 这种“一改就自毁”的参数，必须在**能用 RAM 环境兜底**时验证，
   不能在“只能靠 SSH 进持久根改回”的单点状态里试。
2. **“能起来” ≠ “能稳定用”**：RAM 镜像没有桌面栈，持久镜像有 → 行为不同；桌面/电源管理必须纳入 bring-up 验证清单。
3. **睡眠/熄屏是 bring-up 一等验证项**：`PITFALLS §64–66` 早在 2026-09-29 就写过，本轮又踩；
   应把“长时间空闲不重启 / 电源键熄屏唤醒 / 挂起不挂死”做成自动验收脚本（配 `dpms-watch.sh`）。
4. **变更 GPT/槽位前先 mark-successful**：调试型持久启动会快速耗尽 `boot_b` 重试计数。
5. **记录当前状态比“再试一次”重要**：陷入重启环时，先记录、先救回，再分析。
