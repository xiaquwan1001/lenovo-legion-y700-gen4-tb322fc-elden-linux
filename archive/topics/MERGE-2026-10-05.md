## 0. 合并后的一句话结论

1. **迭代通道**（K 裁决）：kexec 快环**已死**（`kexec -e` 硬挂、分支点未定位）。统一迭代 = **`fastboot boot`（零写盘）/ `--flash`**；**DTB 只能走 `--boot`/`--flash`**（file-load 无 DTB 形参）。kexec 只作为**待取证课题**，**任何驱动验证都不得假设 kexec 可用**。→ 排 **第 1 优先上机项**。
2. **发行版/磁盘**（R 裁决）：**不整体换成更大发行版**——~14 个用户态 bug 里 ~7 个是「会话/PAM/logind/busybox」类，**在现 Alpine 上加 `greetd+phrog+elogind` 会话即可一次清 U1–U7**（pmOS 25.12 已在 Alpine(musl) 上做到）。**boot_b 保持瘦身**（kernel + ~1 MB initramfs + DTB ≈ 20.8 MiB，rootfs/模块/固件放 `linux17`）。→ 排 **第 2 优先（会话 overhaul 为驱动收尾的前置；host-side 可先做）**。
3. **驱动补全**（D 采纳，受 ① 约束）：vk53 = NFC + CDSP + `TYPEC_MUX_FSA4480=y`（DP 前置）；**⚠️ 未上机验证**。vk54 = DP 的 `usb-role-switch` + `mdss_dp0` 单变量。**验证一律用 `fastboot boot`**（vk53=96.8 MiB > boot_b 96 MiB，**不可 flash**；要 flash 必须换 slim）。→ 排 **第 3 优先（等 ①② 的前提就位）**。

## 1. 三调查的独立结论（不重叠部分，原样保留）

### K — kexec（已提交）
- `kexec_file_load`（`kexec -s -l`）**装载成功**（RC=0）但 `kexec -e` **硬挂整机**：无 panic/无看门狗、pstore 空、USB/网络/fastboot 全消失，需物理复位。
- **旧证据无法定位分支点**：console 是 `ttyGS0` USB gadget，跳转必断；「串口戛然而止」不是证据。
- 主机侧查实两缺陷：① **`--dtb` 对 file-load 是空操作** ⇒ `iterate.sh dtb` 环不成立、`RUNBOOK §8` 原说法已改；② 本树缺上游 **`1537e55728ec`**（`VA_BITS_52`+`!LPA2` 的 `trans_pgd` 修复），本机配置正好命中（2 行、零风险，作为对照项先打）。
- **方案**：放弃 kexec 快环；上机最小取证（可逆 hotplug 预检 → 存活 console + `earlycon`/`tty0`/真 UART → 同源基线 + `maxcpus=1 nokaslr` → 单变量放开）。**需报备放行**。

### R — 发行版选择 + 硬盘布局（已落盘）
- **桌面栈新鲜度**：Alpine stable 3.24 = Phosh 0.55.0（上游 0.57.0；edge 已 0.57.0-r3）；Plasma Mobile stable 6.6.6（edge 6.7.5）。Phosh 不是「项目陈旧」，是**被发行版钉版**。
- **用户态 bug 单 U1–U14**：U1–U7（亮度/PIN/唤醒/fail whale/phoc-seatd/关机假成功/dconf）→ 换 `systemd+logind+greetd` 类方案**一次清**；U8/U9/U11 **换发行版无效**；U10/U12/U13 看打包/镜像；U14 硬件。**内核/驱动类另列，不与用户态混**（含 Q24、kexec 硬挂、deep suspend 等）。
- **方案**：现 Alpine + `greetd+phrog+elogind` 会话 overhaul（首选，照 pmOS 25.12）→ rootfs 升 Alpine edge（Phosh 0.57，可选）→ pmOS/Mobian 备选；**Ubuntu 不划算**；**Plasma Mobile 暂不换**。userland backlog **全部冻结**到驱动主线结束；只保留会话 overhaul 作前置。
- **硬盘布局（现状）**：`boot_a/b`、`dtbo`、`vbmeta`、`init_boot`、`vendor_boot`、`recovery` 在 **LUN4 `/dev/sde`**（`boot_b=sde45`），分区 **96 MiB**；rootfs/模块/固件在 **`linux17`=`/dev/sda17`（193.0 GiB）**。现 `boot_b` 里塞了整套 Alpine rootfs ramdisk（~62.6 MB）→ 应只留 **kernel `Image.gz` + ~1 MB busybox initramfs + DTB**（`out/boot-elden-vk52-slim.img`=20.8 MiB）。**内核版本必须与 `linux17:/lib/modules` 一致**。
- **UEFI**：**已搁置**（96 MiB 已由 slim/路线 C 解决，不构成主线依赖）。

### D — 硬件驱动补全（已提交，待上机）
- **G1-9 DP 根因链三闸**：① `FSA4480` typec-mux 模块未部署 → `pmic_glink.altmode` 永久 defer（**已在跑着的 vk47clean 上、insmod `fsa4480.ko` 后实测绑定成功**）；② `&usb { /delete-property/ usb-role-switch; }` → DWC3 不注册 role switch → UCSI defer → 无 `/sys/class/typec`；③ `mdss_dp0 status=disabled`。修复顺序 **mux → role-switch/UCSI → dp0**。
- **vk53**（`out/boot-elden-vk53.img`，内核 `7.2.0-debug-vk53-g2b5badef00fb`，分支 `elden/vk53-hw`）= NFC ST21NFCA + CDSP 启用 + `TYPEC_MUX_FSA4480=y`；**⚠️ 仅主机侧构建，无任何设备侧证据**。vk54 计划 = DP 单变量（只重编 DTB）。
- 剩余：G1-6 TF 卡 A/B、G1-7 BT H1/H2、相机 VCM/LED/iris —— 各需一次上机单命令；资产已就绪。

## 2. 冲突点 × 优先级裁决（★本文件核心）

| # | 冲突点 | K（kexec） | R（发行版/布局） | D（驱动补全） | **裁决（按优先级）** |
|---|---|---|---|---|---|

| **C4** | 设备时间分配 | 需上机取证（存活 console） | **不占设备**（host-side） | 需上机验 vk53/vk54/TF/BT | **K 胜**：上机次序 = **kexec 取证 → 驱动验证**；R 全部 host-side，随时并行 |
| **C5** | 「无输出硬复位」归因 | kexec 硬挂（独立） | Q24 熄屏复位有**内核 DSI blank** 与**用户态 UPower/logind** 两套假设，**须隔离** | 驱动测试被 Q24 干扰（设备自重启） | **交集**：Q24 隔离实验列入上机最小实验；驱动测试期间**禁止熄屏**、只用 `fastboot boot` |
| **C6** | 本轮范围 | （不涉及） | 发行版/会话决策优先于驱动 | 「本轮主线=硬件驱动」 | 保留 D 的硬件主线，但**第 2 优先的会话方案是前置**；驱动验证不得违反 C1/C2 |

### Phase 1 — 上机（**需报备放行**；kexec 取证排最前，遵守 C1）

### Phase 2 — 用户态收尾（驱动主线结束后）
