# 蓝牙（QCA WCN7861 / Brahma v2）断连调查 — 2026-09-30

> 入口 `INDEX.md`；驱动 `linux/drivers/bluetooth/{hci_qca.c,btqca.c}`（GEEKiDoS v7.2-elden 定制分支）。
> 任务：让主线 BT 稳定可用（当前"配对正常，连接几秒就断"）。

## 0. 一句话

**不是配对问题，是 BR/EDR 数据链路本身高延迟 + 低吞吐**：RTT 30–190 ms（正常 <10 ms）、
持续速率仅 ~1–2 包/秒，突发 20~50 包即掉。根因是**控制器侧 IBS 深度睡眠**（每包睡/醒 ~6 次）。

## 1. 现状（2026-09-30）

| 项 | 值 |
|---|---|
| 控制器 | `hci0`，MAC `22:22:62:9C:97:58`，`Bus: UART`，8 Mbps |
| 固件 | `qca/brhbtfw20.tlv` + `brhbtnv20.bin` + `brhperifw20.tlv` + `brhperinv20.bin` + `tmel_peach_20.elf`；成功标志 `QCA setup on UART is completed` |
| 用户态 | `bluez` + `bluez-deprecated` + `bluez-tools` + `bluez-btmon`（设备镜像已切 **aliyun**，ustc/tuna 对本热点 IP 403）|
| 开机自启 | `scripts/bt-up.sh` + `/init` 钩子（`scripts/patch-init-bt.sh`），`bluetoothd` 自动起 |
| 扫描/配对 | ✅ 正常 |

## 2. 断连证据（l2ping 压测）

- `-c 20/30 -i 1.0` → 20/30 sent，**0% loss**，RTT 60–165 ms。
- `-c 200 -i 0.05` / `-c 100 -i 0.2` → **约 20 包"Connection reset by peer"**。
- `-c 300/500 -i 0.05` → 约 20–54 包掉。
- HCI 断开事件：`Disconnect Complete Reason: Remote User Terminated Connection (0x13)`
  → MGMT `Reason: Connection terminated by remote host (0x03)`。**对端等不到就放弃**。
- 换多个对端均复现：本机 PC（Intel BT `8C:C6:81:EA:E1:69`）、vivo 手机。

## 3. 已排除

| 假设 | 结论 |
|---|---|
| 2.4G WiFi 与 BT 共存 | ❌ 关 WiFi 后照样掉（RTT 更差） |
| 链路层 SNIFF | ❌ `hcitool lp <bd> RSWITCH` 关掉后 RTT/丢包不变 |
| 主机侧 IBS 睡眠 | ❌ `tx_idle_delay` 2000→600000（主机 UART 不睡）无改善 |
| 固件未加载 / 波特率低 | ❌ 全加载；协商 8 Mbps；`hciconfig` RX/TX errors=0 |
| 配对/鉴权 | ❌ 正常 |
| 改固件字节绕开 IBS | ❌ 见 §5（破坏 peripheral setup）|

## 4. 根因（硬证据）

`btqca.c` `qca_tlv_check_data()`：
```c
case EDL_TAG_ID_DEEP_SLEEP:            /* tag 27 */
    /* WCN7861 stores the IBS enable bit in the second byte. */
    if (soc_type == QCA_WCN7861) {
        if (tag_len < 2) return -EINVAL;
        tlv_nvm->data[1] |= 0x01;      /* ← 强制开启控制器 IBS 深度睡眠 */
        break;
    }
    ...
```
`hci_qca.c` 的 peripheral 分支同样对 `brhperinv20.bin` 的 tag 27 执行 `data[offset+13] |= 1`。

IBS 计数器 `/sys/kernel/debug/bluetooth/hci0/ibs/`（20 包内变化）：

| 计数器 | 值 | 含义 |
|---|---|---|
| `ibs_recv_wakes` | 2248（+128） | 控制器**每包唤醒 ~6 次** |
| `ibs_recv_sleeps` | 2249 | 控制器每包睡一次 |
| `wake_retrans` | 100/113 ≈ **88%** | 主机唤醒设备需 100 ms 超时重传 |

**是控制器固件侧的自动睡眠在拖垮链路**；主机的 IBS 睡眠已排除，**设备侧睡眠主机管不到**。

## 5. 失败尝试：改固件文件关 IBS（勿重试）

把 `brhbtnv20.bin`（offset 0x145）与 `brhperinv20.bin`（offset 0x62）的 tag id `27 → 26`
（驱动 switch 无 26 分支 → 不置位）。结果：
```
Bluetooth: hci0: Peripheral setup failed: 5      (EIO)
Opcode 0x0c03 failed: -110
```
`hciconfig hci0 up` 卡死；已 `reboot -f` 恢复（`.bak` 还原，md5 一致）。
**结论：peripheral NVM 的 tag 27 是 peripheral 初始化必需，不能删/改。只能在驱动里改。**

NVM TLV 结构参考（`struct tlv_type_nvm` 12 字节头）：
`tag_id(le16) tag_len(le16) reserve1(le32) reserve2(le32) data[]`。
`brhbtnv20.bin` 是 `type=2` 头（4 字节）+ tag 列表；tag 17=HCI(baud)、tag 27=DEEP_SLEEP。

## 6. 下一步（需动内核）

**补丁**：`btqca.c` WCN7861 分支 `data[1] |= 0x01` → `data[1] &= ~0x01`（只清主 NVM 的 IBS 使能位，
peripheral NVM 不动）→ 重编 `Image.gz` → `scripts/flash-b.sh`。代价：待机功耗上升。
若无效，备选：改 `hci_qca.c` 让主机在收到设备 `SLEEP_IND` 后立即 `WAKE_IND`（保活），
或查厂商/上游是否发送了关闭 autosleep 的 VS 命令。

## 7. 补丁实测（vk25 / #20，2026-09-30 夜）

刷入含补丁的 vk25（`btqca.c` WCN7861 `&= ~0x01`）后：

| | 补丁前 | 补丁后 |
|---|---|---|
| 控制器睡眠 `ibs_recv_sleeps` | 2121（每包睡/醒 ~6 次）| **40**（10s 内 0 次）|
| l2ping RTT | 30–190ms | 44–97ms（**无改善**）|
| 突发（-c 150 -i 0.05）| ~20 包掉 | ~20 包掉（**无改善**）|

**结论**：补丁确实关掉了控制器的 IBS 深度睡眠（行为已变），但**链路高延迟/断连的根因不在睡眠**。
**决定**：保留补丁（消除睡眠风暴，对低速率 HID 可能更稳），蓝牙留待后续单独立项。
