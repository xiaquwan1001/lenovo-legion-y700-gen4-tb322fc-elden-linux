# G1-11 CDSP 修复 — split 固件 + initramfs（2026-10-07）

> 过程证据（archive，只增不改）；结论口径以 `TASKS.md` G1-11 / `PITFALLS` #127 为准。
> 设备 U2 `HA2EXB0E`。承接 `CDSP-PROBE-2026-10-06.md`（该文结论「PAS id 待定」被本次否证）。

---

## 0. 结论（数字）

- **CDSP 已起来**：`/sys/class/remoteproc/remoteproc1` → `name=cdsp state=running fw=qcom/sm8750/cdsp.mdt`；
  dmesg：`Booting fw image qcom/sm8750/cdsp.mdt, size 5084` → `remote processor cdsp is now up`（1.396 s）。
- **根因不是 PAS id**（原假设否证），而是**固件变体 + 载具**两点：
  1. DTS 用了**非 stock 的单文件镜像** `cdsp.mbn` / `cdsp_dtb.mbn`；单文件 `cdsp_dtb.mbn` 被 TZ 拒（PAS init `-22`）。
     stock SunP DTS 用的是 **split 镜像** `cdsp.mdt` / `cdsp_dtb.mdt`。
  2. 固件由 **initramfs 加载**（在 switch_root 之前，~1.16–1.19 s）；磁盘 rootfs 的副本**不生效**
     （原始 ramdisk 无 split 时，即便磁盘有，仍 `-2` ENOENT）。

## 1. 关键取证

### 1.1 `dtb_pas_id=0x25` 正确（反汇编 stock 模块）
`backup/stock-elden/vendor_dlkm/qcom_q6v5_pas.ko`（6.6.56-android15-8）反汇编出
`qcom,sun-cdsp-pas` → `sun_cdsp_resource`：

| 字段 | 值 |
|---|---|
| crash_reason_smem | 601 |
| firmware_name | `cdsp.mdt` |
| dtb_firmware_name | `cdsp_dtb.mdt` |
| pas_id | **18 (0x12)** |
| dtb_pas_id | **0x25** |

与主线 `sm8650_cdsp_resource` 完全一致 ⇒ **`-22` 与 PAS id 无关**。
（对照：`sun_adsp_resource`=1/0x24、`sun_modem_resource`=4/0x26，均与主线同名资源一致。）

### 1.2 stock DTS 用 split
`backup/stock-elden/dtb/10_dtbdump_...SunP_SoC.dtb` 解编译：
```
remoteproc-cdsp@32300000 {
    compatible = "qcom,sun-cdsp-pas";
    firmware-name = "cdsp.mdt", "cdsp_dtb.mdt";
};
```

### 1.3 单文件 vs split 内容确不同
`cdsp_dtb.mbn`（36664 B，ph1 filesz 29916）与 stock split `cdsp_dtb.mdt+b01`（filesz 29812）
在 29812 B 重叠区有 **17522 B 不同**；metadata（ph2/b02）也不同 ⇒ 是两个构建，单文件那个不是本机签名镜像。

### 1.4 固件来源 = initramfs（决定性）
| 实验 | ramdisk | 磁盘 rootfs | 结果 |
|---|---|---|---|
| A | 含 split（注入） | 无 split | **cdsp running** |
| B | 无 split（原始） | 含 split（已 scp） | **offline**，`Direct firmware load for qcom/sm8750/cdsp.mdt failed with error -2` @1.16 s |

⇒ 必须把 split 固件打进 **ramdisk**。

## 2. 修复

1. **DTS**（`linux/arch/arm64/boot/dts/qcom/sm8750-lenovo-elden.dts`，已提交 `c132a1bc7`）：
   ```dts
   &remoteproc_cdsp {
       firmware-name = "qcom/sm8750/cdsp.mdt",
                       "qcom/sm8750/cdsp_dtb.mdt";
       status = "okay";
   };
   ```
2. **ramdisk**：把 stock split `cdsp.mdt`+`cdsp.b00..b13,b15`、`cdsp_dtb.mdt`+`b00..b02`
   注入 initramfs 的 `lib/firmware/qcom/sm8750/`。
   （`scripts/build-initramfs.sh full` 已加注入步骤；`build-boot.sh` 自动带上。）
3. **磁盘 rootfs**（可选、非必需）：`/lib/firmware/qcom/sm8750/` 也已放入 split（持久系统一致性）。

## 3. 复现

```bash
# 1) 构建（DTS 改动已入库）
cd ~/y700-elden
bash scripts/build-initramfs.sh full out/boot-elden-cdsp-split-1.img   # 或等价 base
VERSION=cdsp-split-1 bash scripts/build-boot.sh
# 2) 零写盘验证
fastboot boot out/boot-elden-cdsp-split-1.img
ssh root@192.168.7.1 'cat /sys/class/remoteproc/remoteproc1/state'   # -> running
```
