## 0. 一句话结论

**WCD939x 编解码器成功枚举、声卡正常注册、播放不受影响；但 WCD 采集 `arecord` 报 `pcm_read I/O error`（APM 图启动无报错、无数据）** —— 卡在 ADSP 静态 tplg 的 WCD TX 图/数据面，未打通。

## 1. 做了什么

### 1.1 DTS（`linux/.../sm8750-lenovo-elden.dts`）

- **vk46**：镜像 `sm8750-mtp.dts` 新增
  - `wcd939x` codec 节点：`reset-gpios=<&tlmm 101 GPIO_ACTIVE_LOW>`（原厂 base dtb 证实=gpio101）、
    稳压 `vdd-buck/rxtx/io=<&vreg_l15b_1p8>`、`vdd-mic-bias=<&vreg_bob1>`、`vdd-px=<&vreg_l2i_1p2>`、
    micbias 2.0/2.7/1.8/2.0 V（照原厂 `qcom,cdc-micbiasN-mv`）、`qcom,rx-device=<&wcd_rx>`/`qcom,tx-device=<&wcd_tx>`
  - `sound` 新增 `wcd-capture-dai-link`：cpu `TX_CODEC_DMA_TX_3`(120)，codec `<&wcd939x 1>,<&swr2 0>,<&lpass_txmacro 0>`
  - `audio-routing` 加 `AMIC1–5→MIC BIAS*` + `TX SWR_INPUT1←ADC2_OUTPUT`
  - `&swr1`（RX master）挂 `wcd_rx`、`&swr2`（TX master）挂 `wcd_tx`（`sdw20217010e00`，端口映射照 MTP/原厂）
  - `&tlmm` 加 `wcd_default`（gpio101 reset pinctrl）
- **vk47**：移除 `va-dai-link` 与 4 条 `VA DMICx→vdd-micb` 路由（本机无 DMIC，硬件已证伪）。

### 1.2 tplg（`scripts/audio-tplg/`）

  `LPAIF_INTF_TYPE_RXTX`/`CODEC_INTF_IDX_TX3`，iid `0x4008/0x4008/0x6080`）→ 16860 B `3bd05394…`
- **vk47**：仅保留 TX3 子图（去 VA）→ 15380 B `53cc16fc…`

## 2. 实测结果（vk47 持久，2026-10-04）

| 项 | 结果 |
|---|---|
| `dmesg` | `wcd939x_codec audio-codec: bound sdw:2:0:0217:010e:00:4` + `…:3:0:0217:010e:00:3`（**RX/TX 均 bound**）；`input: Lenovo-Y700-Gen4 Headset Jack` |
| `/proc/asound/cards` | `Lenovo-Y700-Gen4`（sm8750）✅ |
| `aplay -l` | `MultiMedia1/2 Playback` ✅ |
| `arecord -l` | `device 2: MultiMedia3 Capture` ✅ |
| 播放 | `speaker-test -D hw:0,0` 正常 ✅ |
| **采集** | `amixer cset name='MultiMedia3 Mixer TX_CODEC_DMA_TX_3' on` → `arecord -D hw:0,2 …` → **`pcm_read:2285: read error: I/O error`**（wav 仅 44 B 头）❌ |

### 2.1 已排除项

- **不是 RAM 模式**：vk47 **持久** boot 仍 I/O error。
- **不是双采集 BE**：vk47（去 VA、单 WCD link）仍 error；vk47a（新 DTS + 旧 VA tplg）连 VA 采集也 error。
- **不是 DAPM mux 未设**：手工按序设置 `TX DECn MUX=SWR_MIC`、`TX SMIC MUX0=SWR_MIC1`、
  `TX_AIF1/2/3_CAP Mixer DECn=1`、`ADC2 MUX=CH2_AMIC2`、`ADC2 Switch/Volume` 后仍 error。
- **不是编解码器未枚举**：WCD939x RX/TX 两个 SoundWire 设备都 bound。
- APM 唯一超时 `GET_SPF_STATE (0x01001021)` 在 6.9 s（启动期，vk41 也有，良性）；采集时 **dmesg 无任何报错**。

### 2.2 值得注意

- `qcom-soundwire 7630000.soundwire: dout-ports (0) mismatch with controller (1)`（swr2/TX，MTP 同款 dtsi 默认，疑非致命）。
- 图启动**静默**（无 "Failed to Start Graph"）→ 疑似 ADSP 接受了 graph 但 TX3 数据面不产出。

## 3. 原厂权威参照：Android HAL 的 `mixer_paths_sun_*.xml`

原厂 **不用 ALSA tplg**，用 AudioReach HAL 的 `mixer_paths`/`resourcemanager` XML（`vendor/etc/audio/sku_sun/`）。
从 `/mnt/Samsung/l2/super.img.raw` 的 `vendor_a` 提取 `mixer_paths_sun_qrd_sku2.xml`，`primary-mic` 路径序列：

```
TX DEC2 MUX         = SWR_MIC
TX SMIC MUX2        = SWR_MIC4
TX_AIF1_CAP Mixer DEC2 = 1
ADC1 ChMap          = SWRM_TX2_CH1
ADC1 MUX            = CH1_AMIC1
TX0 MODE            = ADC_LP
ADC1_MIXER Switch   = 1
AMIC1_MIXER Switch  = 1
ADC1 Volume         = 12
```

⇒ 原厂主麦走 **ADC1/AMIC1 → SWR_MIC4 → SMIC MUX2 → DEC2 → AIF1**；而主线 MTP/我们走 `TX SWR_INPUT1←ADC2_OUTPUT` + TX3/AIF3。
索引不匹配可能是数据面不同的一个原因，但按 mux 手工设置仍未通 → 更可能在 ADSP 静态图的 TX3 支持。

## 4. 下一步（建议）

1. **对齐原厂 AIF/索引**：把 capture 设备的 cpu 由 `TX_CODEC_DMA_TX_3` 换成原厂对应的 codec-DMA（配合 `TX_AIF1_CAP`），
   并在 DTS 路由改成 `TX SWR_INPUT4 ← ADC1_OUTPUT`，按 `primary-mic` 序列设 mux。
2. **反向对照**：给设备刷回一个纯 vk45（旧 DTS+旧 VA tplg）确认 VA 采集**现在**仍工作，锁定"WCD 引入即破坏"的确切 DTS 元素。
3. **ADSP 侧取证**：抓 ADSP 日志（`remoteproc`/`qcom_stats`/pstore），看 TX3 容器是否被拒；必要时用 `AGM`/`resourcemanager` 语义重建图。
4. **兜底**：USB/Type-C 麦或蓝牙麦（不依赖 ADSP 静态图）。

  `boot-elden.img`=RAM 变体。曾据此 boot 到 RAM 镜像 → 无 `elden_root=LABEL=linux17` → 停在 initramfs（"没进桌面"）。
