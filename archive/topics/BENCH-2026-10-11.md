## 2. GL vs Vulkan

- **GLES** 测的是 `es2gears_wayland`（mesa-demos），15 s 稳定在 **~164 FPS = 面板 165 Hz 刷新上限** ⇒ 该工具被 vsync 卡住，**不能反映 GL 的真实算力上限**，只能证明 GLES/freedreno 通路可用。
- **Vulkan**（Turnip）`vkmark` 用部分场景（vertex/clear）绕开了 vsync 压力，**Score ~25500** 是更有信息量的数字。
- 结论：**Vulkan/Turnip 通路健康且可出分**；GLES 侧缺一个能突破 vsync 的离屏基准（`glmark2` Alpine 无包）⇒ GL vs Vulkan 的公平对比**未完成**（工具受限，非驱动问题）。

## 3. ⚠️ 观察到的渲染异常（用户 2026-10-11 现场，非阻塞）

跑基准时**大部分待渲染物体挤在屏幕左上角**。对数据的影响：
- `vkmark`/`es2gears` 是 wayland 客户端，**窗口/视口尺寸由合成器给定**；若被压成左上角小区域 ⇒ 渲染目标像素数偏小 ⇒ **填充型场景 FPS 偏高**。
- 因此 **GPU 绝对分（尤其 clear/vertex FPS）应视为「量级参考」，不宜当作同分辨率横向对比**；CPU/内存/磁盘数字不受影响。
- 该现象疑似与显示缩放/视口有关（可另立小任务查，不与本基准耦合）。

## 4. 复现命令

```sh
# 全套（设备侧）
DUR=15 sh scripts/bench-run.sh              # → /var/log/bench-<ts>/
# 补采（Wayland）
export XDG_RUNTIME_DIR=/run/user/1000 WAYLAND_DISPLAY=wayland-0
timeout 15 stdbuf -oL es2gears_wayland      # GLES fps
vkmark                                       # Vulkan score（约 2 min/轮）
sysbench cpu --cpu-max-prime=20000 --threads=8 --time=15 --events=0 run
# GPU 身份
vulkaninfo | grep -E "deviceName|driverName|apiVersion"
```
