# C1 — Waydroid 端到端复跑 / 「去掉 workaround」判定（U2 vk64，2026-10-11）

> 任务：`TASKS.md §2 C1` + `§5 Q2`。设备 U2 `HA2EXB0E`，b 槽 vk64（`7.2.0-debug-vk64-gd02658e63cf6`）。
> 结论：**容器能起了（修了一个真内核模块缺口），但 Q2 的答案 = 「netd 不能原生下发默认路由，旧 workaround 仍必需」**。
> 原始日志：`logs/c1-waydroid-20261011/`（`wdc*.log`、状态/路由输出）。

## 0. 结论

| 问题 | 答案 |
|---|---|
| 容器能否端到端起来 | ✅ 能：`waydroid status` = Session/Container RUNNING、IP `192.168.240.112`、`waydroid0` UP |
| **阻塞根因（本轮新发现）** | **venerable 部署的 vk64 模块目录缺核心网模块**：`CONFIG_BRIDGE=m` 但 **无 `bridge.ko`** ⇒ `waydroid-net.sh` 的 `ip link add type bridge` 报 **`Unknown device type`** ⇒ 容器起不来。**已修**（见 §2） |
| **Q2（去掉 workaround 是否仍通）** | ❌ **不通**。去掉 workaround 后容器内**只有链路路由**、**无默认路由**；`ip rule` → **`RTNETLINK answers: Operation not supported on transport endpoint`**（内核无多路由表）⇒ 根因 = `CONFIG_IP_ADVANCED_ROUTER` 未开，**旧 bind-mount workaround 仍必需** |
| 现役状态 | 已**还原 workaround**（`config_nodes` 恢复），容器回到 STOPPED（= 本轮起始态） |

## 1. 关键证据

**A. bridge 缺失（修前）**
```
$ sh -x /usr/lib/waydroid/data/scripts/waydroid-net.sh start
+ ip link add dev waydroid0 type bridge
Error: Unknown device type.
Failed to setup waydroid-net.
```
```
$ zcat /proc/config.gz | grep CONFIG_BRIDGE
CONFIG_BRIDGE=m            # =m，但模块目录里没有 bridge.ko
$ modprobe bridge
modprobe: FATAL: Module bridge not found in directory /lib/modules/7.2.0-debug-vk64-gd02658e63cf6
```
设备模块目录（1217 个 `.ko`）**完全没有 `kernel/net/` 或 `net/` 子树**（只有 `drivers/`）⇒ 部署时漏了核心网模块。

**B. Q2 / workaround 判定（单变量：去 workaround 后重启容器）**
```
# workaround 在（对照组，历史/复现）
$ waydroid shell -- ip route
default via 192.168.240.1 dev eth0
192.168.240.0/24 dev eth0 proto kernel scope link src 192.168.240.112

# workaround 去掉（实验组）
$ waydroid shell -- ip rule
RTNETLINK answers: Operation not supported on transport endpoint
Dump terminated
$ waydroid shell -- ip route
192.168.240.0/24 dev eth0 proto kernel scope link src 192.168.240.112     # ← 无 default
```

## 2. 修复：重编并部署核心网模块（vermagic 逐字节匹配）

设备 KV = `7.2.0-debug-vk64-gd02658e63cf6`；构建树 `geekidos-linux` HEAD=`d02658e63`（= vk64 源），`.config` sha = `a383cdb9…`（**与设备 `/proc/config.gz` 逐字节同**）。

```sh
cd geekidos-linux
. ../scripts/env-build.sh                 # ARCH=arm64 + ccache aarch64-linux-gnu-
LOCALVERSION=-vk64 kbuild modules_prepare
# MODVERSIONS 未开 ⇒ 跨目录符号用 KBUILD_MODPOST_WARN 放行（运行期由模块符号表解析）
for d in net/llc net/802 net/bridge net/8021q; do
  LOCALVERSION=-vk64 KBUILD_MODPOST_WARN=1 make ARCH=arm64 CROSS_COMPILE="$CROSS_COMPILE" -j8 M=$d modules
done
```
产物（vermagic 全部 = `7.2.0-debug-vk64-gd02658e63cf6`），已存 `out/netmods-vk64/`：
`llc.ko`、`stp.ko`、`bridge.ko`、`br_netfilter.ko`、`8021q.ko`。

部署到设备 + `depmod`：
```sh
KV=$(uname -r); M=/lib/modules/$KV
mkdir -p $M/net/{llc,802,bridge,8021q}
cp llc.ko $M/net/llc/; cp stp.ko $M/net/802/; cp bridge.ko br_netfilter.ko $M/net/bridge/; cp 8021q.ko $M/net/8021q/
depmod -a
```
修后：
```
$ modprobe bridge   → rc=0；lsmod: bridge 323584 0 / stp 12288 1 bridge / llc 16384 2 bridge,stp
$ ip link add name testbr type bridge → OK
$ waydroid container start → waydroid0 UP 192.168.240.1/24；status RUNNING / IP 192.168.240.112
```

## 3. 影响 / 后续

1. **部署管线缺口**：vk64（及同类）的模块部署**漏了 `net/` 核心网模块**（bridge/llc/stp/8021q）。需在 `scripts/build-modular-overlay.sh` / `deploy-*` 的 closure 或 `modules_install` 里补上 `net/bridge` 等，否则每次重装 rootfs 都会丢。（本轮已手工补齐在设备持久盘。）
2. **C1「去掉 workaround」仍未达成**：需 **`CONFIG_IP_ADVANCED_ROUTER=y`（连带 `CONFIG_IP_MULTIPLE_TABLES=y`）重编内核** 才能让 netd 原生下发默认路由（→ `TASKS §5 Q2`）。这是**内核 config 变更 + 重编/刷 boot**，本报告已把判据钉死。
3. 渲染/网络无关：本轮未动显示栈。
