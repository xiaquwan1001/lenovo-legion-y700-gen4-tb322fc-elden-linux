# 「过环境」（游戏环境检测绕过）研究 + 本机实测 —— 2026-10-02

> 支线任务。设备：Lenovo Y700 四代 TB322FC，ZUXOS 1.5.10.259 / Android 16 / kernel 6.6.118，
> KernelSU 3.2.5（**LKM 模式**，装在 `init_boot_a`）+ 解锁 BL。

---

## 0. 一句话结论

- **「过环境」= 让 App/游戏检测不到"你动过系统"**（root / Zygisk / 挂载 / 解锁 / 调试 / 非原厂指纹），
  从而不被拒登、踢下线、冻结或封号。它是**兼容性对抗**，不是外挂。
- 本机实测：装好 **Zygisk Next + Shamiko + PlayIntegrityFork + TrickyStore + 属性伪装**，
  并把 **KSU 管理器卸载**后，综合原生检测器 **Native Detector 判定 `Environment is normal`**；
  root 仍可用（`su -c` / MT 管理器）。
- 第二个检测器 Securify 仍报 2 项：`调试模式开启`（USB 调试，关掉即消）+ `指纹不一致`（内核级属性对抗，
  见 §6，未完全消掉）。**结论：软件层隐藏能过绝大多数"环境检测"；腾讯 ACE / 网易等硬核反作弊还需要内核级 SUSFS（§7）。**

---

## 1. 「过环境」到底在检测什么（检测方 taxonomy）

游戏/银行/支付类的"环境检测"通常分四层，由浅入深：

| 层 | 手段 | 典型信号 |
|---|---|---|
| L1 应用/包名层 | 扫已安装包名 | `me.weishu.kernelsu`、`com.topjohnwu.magisk`、爱玩机、GG、太极… |
| L2 文件/属性层 | 查文件、读 `getprop` | `/system/bin/su`、`/data/adb/modules`、`ro.boot.verifiedbootstate=orange`、`ro.boot.flash.locked=0`、`ro.debuggable=1`、`partition.*.verified=0` |
| L3 挂载/进程层（native） | `/proc/self/mountinfo`、`/proc/self/maps`、`/proc/*/status` | overlayfs 挂载、Zygisk 注入段、匿名可执行映射、`init.svc.adbd`、`/dev/socket/adbd` |
| L4 内核/完整性层 | 内核指纹、Keystore 证明 | 内核版本与 ROM 不符、Play Integrity（BASIC/DEVICE/STRONG）、key attestation 里 BL 状态 |

对抗思路与工具对应：

| 对抗 | 工具 |
|---|---|
| 隐藏 root / mounts / Zygisk | **Shamiko**（Zygisk 模块，白名单模式全局隐藏）、Zygisk Assistant |
| 给 KSU 提供 Zygisk API | **Zygisk Next** |
| 过 Play Integrity（指纹） | **PlayIntegrityFork**（旧 Android 指纹修复）、TrickyStore + keybox |
| 伪装 boot/verity 属性 | resetprop / 本文 `envpass_props` 模块、PIF 的 resetprop |
| 抹掉内核/mount 痕迹（最强） | **SUSFS**（必须编进内核；LKM 版不带） |
| KMP 级挂载隐藏 | SukiSU-Ultra 的 KPM（如 `zeromount`） |

## 2. 本机基线（改之前）

`Native Detector`（Reveny，原生 root/hook 检测）报 **Environment is abnormal**：

| 项 | 证据 |
|---|---|
| Bootloader Unlocked ×2 | `ro.boot.verifiedbootstate: orange`；`sys.oem_unlock_allowed` |
| Detected Risky App ×3 | 全部是 `me.weishu.kernelsu`（KSU 管理器包名，三种查法各报一条）|

注意：**root 本身（su、mount、Zygisk）当时没被测出** —— 官方 KernelSU 的默认隐藏已不错。

`Securify`（RootBeer + ReI 原生库）：报 2 项，`found_modified_system_files` + `found_debugging_mode`。

---

## 3. 我们做了什么（软件栈，全程未刷机）

1. **Zygisk Next 1.5.0** → 给 KernelSU 提供 Zygisk。
2. **Shamiko 1.2.5 (414)** → 隐藏 root/mounts/Zygisk。**白名单模式**：`/data/adb/shamiko/whitelist`。
   - ⚠️ Shamiko 1.2.5 的 `customize.sh` 用 `KSU_KERNEL_VER_CODE >= 20000` 判"版本异常"并 abort；
     官方 KSU 3.2.5 的版本号是 `32525` → **误判**。已打补丁绕过（见 §8 `Shamiko-...-patched.zip`）。
3. **PlayIntegrityFork v18** → Play Integrity 修复（未配 `pif.prop`，故不改指纹）。
4. **TrickyStore 1.4.1** → keystore 证书链 / BL 状态欺骗（自带软件 keybox）。
5. **`envpass_props` 模块（自写）** → resetprop 伪装：
   - `ro.boot.verifiedbootstate=green`、`ro.boot.flash.locked=1`、`ro.boot.vbmeta.device_state=locked`、
     `ro.boot.veritymode=enforcing`、`ro.secureboot.lockstate=locked`、`sys.oem_unlock_allowed=0`
   - `partition.{system,vendor,product,odm,...}.verified=1`
   - `ro.debuggable=0`、`ro.build.type=user`、`ro.build.tags=release-keys`、`ro.adb.secure=1`
   - 版本对齐：bootimage/vendor/vendor_dlkm/system_dlkm 的 `build.version.release=16`、
     `ro.build.version.incremental=ZUXOS_1.5.10.259_260611_PRC`（= fingerprint 第 5 段）
6. **卸载 KSU 管理器 APK**（`me.weishu.kernelsu`）—— 这是过 Native Detector 的临门一脚。
   - root 不依赖管理器：`/data/adb/ksud` + allowlist（`bin.mt.plus`、`com.android.shell`）仍在。
   - 需要 GUI 时用 `pm install` 重装即可（APK 见 §8）。

### 为什么管理器不能用"改名/伪装包"糊弄
官方 KernelSU 内核按 **APK 的 size+hash** 识别管理器（`.ko` 里有 `Crootning manager` /
`Found new base.apk ... is_manager`），不是按包名。改包名会导致内核不认管理器。
真正做到"隐藏管理器"的是 **KernelSU-Next / SukiSU-Ultra**（它们提供 `-spoofed` 管理器和内核侧支持）——需要换 root 方案（§7）。

## 5. 剩余项 1：调试模式（可解决，需你操作）

ReI `checkDebuggingModeState()` 的原生实现就是看：
- `getprop init.svc.adbd`（== running）
- `/dev/socket/adbd` 是否存在

→ 只要**关掉「USB 调试」**（自动 adbd 停、socket 消失）即可消失。
代价：关了 adb 我们没法远程，所以**放在最后做**。
`settings put global adb_enabled 0` 或 开发者选项里关。

## 6. 剩余项 2：指纹不一致（未完全解决）

Rei `detectInconsistentFingerprint()`（native，`librei.so`）做的事：把
`ro.build.fingerprint` 按 `/` 切成 6 段，再按 `:` 细分，与这些 prop 逐字段比对：

```
brand  ← ro.product.brand          name ← ro.product.name
device ← ro.product.device         release ← ro.build.version.release
id     ← ro.build.id               incremental ← ro.build.version.incremental
type   ← ro.build.type             tags ← ro.build.tags
```

本机 `ro.build.fingerprint` = `Lenovo/TB322FC_PRC/TB322FC:16/BQ2A.../ZUXOS_1.5.10.259_260611_PRC:user/release-keys`
→ 我们把上面 8 个 prop 全部对齐（含 fingerprint 里写 `:16` 但 bootimage/vendor 是 `15` 的原厂不一致），
**仍然报该项**。反汇编确认该函数只读上述 9 个属性、逐字节 `memcmp`，逻辑上应当通过 ——
疑为 Rei 在 Android 16 上的实现/逻辑瑕疵（或比对字段与我看到的不同）。
**不阻塞**：Native Detector（更硬核的原生检测）已 clean；Securify 此项属"指纹洁癖"。

## 7. 要"过"腾讯 ACE / 网易等硬核反作弊，下一步（需刷机）

现状的**天花板**：root 是 **LKM**（`/proc/modules` 里能看到 `kernelsu`，只是被隐藏给 App），
且内核**没有 SUSFS**。SUSFS 才能在内核态隐藏 mount/su 路径/`/proc/cmdline`，是"完美环境"的关键。

两条路：

### A. 换 SukiSU-Ultra（推荐，同一 KMI，机械上最省事）
- 本机 KMI = `android15-6.6`；SukiSU-Ultra v4.2.0 正好有 `aarch64-android15-6.6-lkm.zip`
  （已下载到 `assets/`）。其 LKM 的 `vermagic` = `6.6.127-4k-g46a034eca005-dirty`，
  **与本机现有 kernelsu.ko 的 vermagic 完全一致**（本机跑的就是这个字符串），所以能加载。
- 换法：用 SukiSU 管理器把 `init_boot_a` 重新 patch（ksuinit + kernelsu.ko）→ `fastboot flash init_boot_a`。
- 好处：**可隐藏/随机化管理器包名**（解决 §3 的包名泄露且保留 GUI）、支持 **KPM**（可上 `zeromount` 隐藏 mount）。

### B. 编带 SUSFS 的内核（最强，工程量最大）
- 仓库有内核源码 `stock-src/android_kernel_lenovo_sm8750`（402 MB）。
- 给内核打 SUSFS 补丁 + 重编 boot/init_boot，才能获得内核级挂载隐藏。
- 预期收益最大（腾讯 ACE 类），但有变砖/回退成本，且要配 AVB。

> 目前**不需要**马上做：软件栈已能让"普通检测器 + 大部分游戏"看到干净环境。

### 日常模式切换
```bash

adb shell su -c 'settings put global adb_enabled 0'        # 会立刻断 adb
# 需要管理 root / 装模块时（重新打开调试 + 装回管理器）
```

### KSU 模块 CLI（无管理器也能用）
```bash
adb shell su -c '/data/adb/ksu/bin/ksud module list'
adb shell su -c '/data/adb/ksu/bin/ksud module install <zip>'
adb shell su -c '/data/adb/ksu/bin/ksud feature get 4'   # selinux_hide
```

### 回退（任何一步）
```bash
cd ~/y700-elden
# 1) 删模块
adb shell su -c 'rm -rf /data/adb/modules/{zygisksu,zygisk_shamiko,playintegrityfix,tricky_store,envpass_props}'
# 2) 恢复 init_boot（如日后刷过）
adb reboot bootloader
fastboot --set-active=a
fastboot flash init_boot_a restore-259/KSU/init_boot.img
fastboot reboot
```
> KSU LKM 的安全模式：开机时按住音量下，可跳过模块加载（防模块导致不开机）。

## 9. 复现 Native Detector = normal 的最小步骤

1. 装 `repacked/*-deflate*.zip` + `envpass_props`（`scripts/envpass-ondevice.sh`）。
2. 建 `/data/adb/shamiko/whitelist`（白名单模式）。
3. `ksud feature set selinux_hide 1`。
4. 重启（等 Zygisk 注入）。
5. **卸载 `me.weishu.kernelsu`**。
6. 关 USB 调试（可选，给严格检测）。
→ Native Detector：normal。

## 10. 关键事实备忘

- KSU 是 **LKM**：`/data/adb/ksud` 与 init_boot 里的 `kernelsu.ko`；`ksud boot-info current-kmi` = `android15-6.6`。
- 该内核 **GKI 容忍 vermagic 与运行内核不一致**（现有 ko 的 vermagic `6.6.127-...`，设备 `6.6.118-...`，照常加载）。
- Shamiko/ZygiskNext/TrickyStore 的官方 zip 用 **xz(方法95)** 压缩，标准 `unzip` / KSU 的 Rust zip 可能读不了 → 用 `tools/repack_module_zip.py` 重打。
- 官方 KSU 3.2.5 没有"隐藏管理器"，也没有 SUSFS；`feature` 只有 su_compat / kernel_umount / sulog / adb_root / selinux_hide。
- `/proc/cmdline` 对普通 App 不可读（Android 16 SELinux 拒），所以 `androidboot.verifiedbootstate=orange` 不构成 App 侧泄露；但 `getprop` 可读 → 本模块解决。
