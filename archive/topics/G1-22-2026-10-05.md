## 0. 一句话结论

**vk40 原始内核（`gba28ec16f01f`）+ DPMS off 必硬复位（3/3）；不熄屏则稳定 ≥151s。**
二分：`vk34recon`、v1（仅热区）、v2（仅插桩音频）、**vk42（热区+干净音频）全部不复位**；
只有 **vk40 =「插桩音频 + 热区」组合**复现。**当前 boot_b（`g4c68eb5ed4e3`）10 轮 + 持续熄屏 90s 不复位 ⇒ 已被 vk42 的"干净重落"修复。**
崩溃源 = vk40 音频改动里的**调试插桩**（N1 有副作用阻塞调用 / N4 `print_hex_dump`）；**N2（APM 命令头）已被排除**（vk42 保留它却干净）。

## 1. 受控复现方法（可重复）

不依赖串口/不写盘：`fastboot boot <img>`（零写盘，RAM 内核 + 磁盘根）→ SSH `root@192.168.7.1` → 直接 DPMS off：

```sh
export XDG_RUNTIME_DIR=/run/phosh
P=$(pidof phosh)
export DBUS_SESSION_BUS_ADDRESS=$(tr '\0' '\n' < /proc/$P/environ | sed -n 's/^DBUS_SESSION_BUS_ADDRESS=//p')
wlr-randr --output DSI-1 --off
```

定量脚本：`scripts/g1-22-dpms-test.sh [cycles]`（输出 KEY=VALUE：vblank/PPM/DPU wait 计数 + uptime）。

判据：SSH 中断 + 重新读 `uname -r` 变为 **boot_b**（`g4c68eb5ed4e3`）= 复位回退；uptime 归零。

## 3. 源码二分（确定性）

分支线性历史（`geekidos-linux`）：`ba28ec16f → 6ef87e6a8(vk40) → e72a036ed(vk34-recon) → 4b643f169(vk41 psci) → eb432f18a(vk42 干净重落) → … → 5a70ade46(vk48 draft)`。

- `git diff 6ef87e6a8 e72a036ed` = **恰好 5 文件**（DTS 热区 + 4 音频）⇒ v1、v2 源码上互补，**v1+v2 == vk40**。
- DTB 校验：**原始 vk40 DTB == v1 DTB**（`38979201…`），v2 DTB == vk34recon DTB ⇒ 重建忠实，热区/音频隔离干净。
- `git diff e72a036ed eb432f18a`：音频 4 文件中 **`audioreach.c` 整文件回退**、`q6apm.c` 少 10 行、`q6apm-lpass-dais.c` 少 4 行 —— 即 **vk42 删掉了 vk40 的调试插桩**，但**保留了功能性的 N2（`alloc_apm_cmd_pkt`）**。

## 4. 根因

vk40 音频改动含三类插桩（`AUDIT2` §2 的 N1/N2/N4）：

- **N1（有副作用、会阻塞）**：`q6apm.c` 在 `dev_info` 实参里调用 `q6apm_get_apm_state(apm)`（`apm_probe` 与 `q6apm_graph_open` 各一处）⇒ 每次 probe/开图**额外向 ADSP 发 `GET_SPF_STATE` 并等待**（响应超时可达数秒）。日志不应有副作用。
- **N4**：`audioreach.c` 残留 `print_hex_dump` 整包 + DBG。
- **N2**：`GET_SPF_STATE / SHARED_MEM_*` 改用 `alloc_apm_cmd_pkt`（加 8 字节 APM 头；vk34 注释明确 GET_SPF_STATE 无头）。

**判定**：
- **vk42 = 保留 N2、删除 N1/N4 → 干净** ⇒ **N2 无罪**。
- v2 = 插桩音频、无热区 → 干净；vk40 = 插桩音频 + 热区 → 复位 ⇒ **需要「插桩 + 热区」组合**。
- ⇒ 崩溃源 = **N1/N4 插桩**（N1 的阻塞副作用最可疑：在 ADSP probe/开图路径上同步等待，与显示电源切换形成竞态）；热区 DTS 是**必需伴因**（改变启动/调频时序）。
- **修复 = vk42 的"干净重落"**（删除全部音频调试插桩）；当前内核已含此修复。

## 5. 取证限制（记录）

- 复位是**硬复位**：无 kernel panic / Oops / watchdog 打印；`pstore`/ramoops 挂载后**为空**（硬件复位未保留 ramoops）。
- ttyGS0 控制台被 `respawn` getty + 主机 ModemManager 的 AT 探测**刷屏污染**，串口未能抓到崩溃前内核消息；且我一次遗留的 `cat /dev/ttyACM0` 会占用设备（`Device or resource busy`）。
- 教训：`pkill -f '<pat>'` 会匹配到当前 shell（本条命令串里含目标串）→ 命令自杀 143；用显式 PID 或 bracket 且避免命令串本身含真实设备名。

## 6. 收尾 / 后续

- **G1-22 实质已解**：当前 boot_b 内核免疫。持久根的 `idle-delay=0` 规避可在一次长时空闲验证后解除（本轮因测试已足够，未改持久根）。
- 残留（非阻塞）：定位 N1 与 N4 谁为主（可再建「插桩音频 + 热区、只去 N1」变体）；DPU `vblank timeout` 在 vk40/boot_b 仍有、但不再致复位。
