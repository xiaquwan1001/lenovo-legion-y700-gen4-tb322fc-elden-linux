## 3. 卡点根因（图形）

设备 logcat crash buffer：

- 已试无效：`ro.hardware.gralloc=gbm`（被 find_hal 覆盖）、`vendor.gralloc.disable_ubwc=1`（未生效）。
- 未试：`ro.hardware.egl=angle`；换旧 vendor 镜像；把主机 Mesa 26.1.6 绑进容器；redroid 式打

## 4. 下一步候选（需用户定）

1. **换 vendor 镜像版本**（社区常见：某些版本 mesa 对某 GPU 坏；lineage-20-20250503 等）。
2. **`ro.hardware.egl=angle`**（vendor 有 `libEGL_angle.so`），或禁用 UBWC 的正确 prop。
3. **主机 Mesa 绑定**：把主机 `/usr/lib/libgallium-26.1.6.so` + `/usr/lib/dri/*` 与容器

4. **软件渲染**（`gralloc=default`+`egl=swiftshader`）——但本 vendor 无 swiftshader，且对游戏太慢。
5. **放弃 Waydroid 图形，转 Steam/Proton 路线**（见 HINDSIGHT：musl 上成本高，需 glibc 容器 + FEX）。

## 6. 更新（2026-10-01 下午）：图形根因锁定 + Mesa 26.1 构建

### 6.1 图形卡点真根因（已定位到底）
- 容器 `libgallium_dri.so` = **Mesa 26.0.8**，其 `fd_dev_info` 表 A830 只有 `chip_id=0x44050000`（**KGSL** 用）。
- 内核主线 DRM 上报 `chip_id=0xe844050000`；Mesa 的 `dev_id_compare` 有 fuse-id 通配规则：
  表项高 16 位为 `0xffff` 时按 `chip_id | 0x0000ffff00000000` 比。**`0xffff44050000`（DRM）是 Mesa 26.1 才加的**。
- 宿主 Alpine Mesa 26.1.6 → 正常；容器 26.0.8 → 查表失败 → `fd_pipe_new2: unsupported GPU id`。
- **临时绕过（已上机）**：改容器 `libgallium_dri.so` 偏移 `0x1f7bf90` 的 8 字节
  `0x44050000 → 0xffff44050000`（`/root/wd/libgallium_dri.so` + `config_nodes` bind-mount）。
  效果：SurfaceFlinger 由崩溃循环 → `running`，GBM/EGL 报错消失。
- 但仍 **GPU hang**：`[drm:hangcheck_handler] 44050000: hangcheck detected gpu lockup rb 0!`
  offending task = `RenderEngine` (/system/bin/surfaceflinger)。→ 26.0.8 的 **Gen8 主线 DRM 支持不完整**，
  必须 Mesa ≥ 26.1。

### 6.2 结论：需要一份新的 Android(bionic) Mesa ≥26.1
- 现成 ARM64 镜像都停在 Mesa 26.0.x（WayDroid-ATV 20260717 有 26.1.5 但**只有 x86_64**）。
- 故选 **自编**：源码树 `~/waydroid-build`（LineageOS 20.0），Mesa 指向
  `WayDroid-ATV/android_external_mesa3d@lineage-18.1-mesa-26.1`（**Mesa 26.1.8**）。
- 完整进度/恢复步骤见 **`~/waydroid-build/PROGRESS.md`**（含断点续传、清华 AOSP 镜像、
  `make vendorimage`、产物部署与回退）。
- **「是否必须全量装/编 AOSP」的审计结论**（会话 01a0f7cd）见
  **`WAYDROID-AOSP-AUDIT-2026-10-01.md`**：自编必要、但只需几十个工程 + 定向 make，
  `repo sync` 无须跑完；建议 freedreno-only 收窄后最小构建。

### 6.3 其他一起修好的前置项

## 7. 网络/DHCP 根因（2026-10-01 晚，实测）

设备 `waydroid status` → `Session/Container: RUNNING`，但 **`IP address: UNKNOWN`**。逐层排查：

| 层 | 状态 |
|---|---|
| 宿主 `waydroid0` | ✅ `192.168.240.1/24`，dnsmasq 已起（DHCP range `.2-.254`）|
| 宿主 NAT | ✅ `iptables-legacy -t nat` 有 `-s 192.168.240.0/24 -j MASQUERADE` |
| 容器 `eth0` | ❌ 只有 `fe80::...`，**没有 IPv4**；`dnsmasq.waydroid0.leases` 空 |
| 容器 `netd` | ⚠️ 在跑，但初始化各控制器时报错 |

容器 logcat 关键行（`waydroid shell -- sh -c "logcat -d -b all | grep -i netd"`）：
```
E IptablesRestoreController: ip6tables-restore v1.8.7 (legacy): unable to initialize table 'filter'
E netd: Failed to initialize RouteController (Operation not supported on transport endpoint)
E XfrmController: Could not get a new socket, line=240
E netd: Failed to initialize XfrmController ([Protocol not supported] : Could not open netlink socket)
E Netd: Unable to create netlink socket for family 5 / 12: Protocol not supported
W Netd: Unable to open qlog quota socket, check if xt_quota2 can send via UeventHandler
```

### 7.1 根因
- 内核 `IP6_NF_*` 全是 **`=m`**，而设备 `/lib/modules/<ver>/kernel/net/` 只装了 `802/ bridge/ llc/`
  → `ip6table_filter` 等 .ko 不存在 → `ip6tables-restore` 无法初始化 `filter` 表。
- **`CONFIG_XFRM` / `CONFIG_XFRM_USER` 未开** → netd 的 XfrmController 打不开 netlink socket。
- `CONFIG_NETFILTER_XT_MATCH_POLICY` 未开（netd 的 `bw_mangle` 用 `-m policy --pol ipsec`）。
- `xt_quota2` 是 Android 专有扩展，主线没有 → 仅告警，无碍。

### 7.2 修复（已备好，等重建内核）
- 片段：`patches/fragment-netd-ipv6-xfrm.config`（**全部 `=y` 内置**，免设备装模块）
- 合并脚本：`scripts/apply-kernel-fragment.sh`（已跑，快照 `patches/config-vk28-netd-ipv6-xfrm`）
- 重建：`sudo apt install -y gcc-15-aarch64-linux-gnu` →（应用片段）→
  `scripts/build-kernel.sh` → `scripts/build-boot.sh`
- ⚠️ 主机当前**没有** `aarch64-linux-gnu-gcc`（只有 binutils），重建前需装。

> 原始笔记里「IPv4 =y、IPv6 =m」的写法看起来完整，但**模块没随内核装到设备**，
> 所以只有 IPv4 规则生效；IPv6/RouteController/XFRM 全部初始化失败。
