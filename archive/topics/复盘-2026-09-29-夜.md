## 三、本轮确认的事实（重要，别丢）

- **a/b 两槽是两把不同密钥**：a 槽顶层 `vbmeta_a` = `2597c218…`（社区免签/KSU 包也是它）；
  b 槽 `vbmeta_b`/`vbmeta_system_b` = `8fcb864f…`（另一套固件）→ **b 槽原厂永远起不来**。
- **本机已 unlocked**：ABL 传 `verifiedbootstate=orange` + `veritymode=disabled`，所以
  **改过的 `abl_a` 不必刷**（唯一砖点），b 槽用自签 vbmeta（flags=3）就能引导自编内核。
- **`init_boot_a` 早已是 KSU 补丁版**、`init_boot_b` 是 Magisk 版；KSU 包与 `KSU/vbmeta.img` 严格配套
  （`sha256(salt‖init_boot[:2850816])` = vbmeta 描述符里的 Digest）。
- **熄屏 = phoc 关闭 DSI 连接器**（`connector DSI-1: Turning off`），不是挂起：
  `dpms=Off`、背光 511/4095、`bl_power=4`；内核活着（SSH 正常、0 条 `PM: suspend`）。
- **从系统外改不回 dpms**（`Permission denied`，DRM master 在 phoc 手上）。
- **busybox `pgrep/pkill -x` 不可靠**（`pgrep -x phoc` 匹配不到 comm 为 `phoc` 的进程），见 `PITFALLS §68`。
- **phoc 退出后 seatd 会卡**（`seat is VT-bound and has an active client`）→ 现场不要跟 seatd 缠，直接 `reboot -f`。

## 四、未解决问题 / 假设

### 4.1 ★ 熄屏后无法唤醒（本轮的核心未解问题）

观测：**主动按电源键熄屏 / 系统自动熄屏，之后无论如何都唤不亮**（无一次成功记录）。
最后一步的采样日志留在设备 `/root/dpms-watch.log`（**下次开机第一件事就是把它读出来**），
里面应该有"按键那一刻 dpms / brightness / phosh.log 末行"的完整时间线。

三种可能（用那份日志就能区分）：
1. phoc 收到了唤醒输入但**没有**发 `Turning on` → 输入/电源键处理路径问题（本机无 logind，phosh 的电源键动作可能失效）；
2. phoc 发了 `Turning on` 但面板仍旧黑 → **面板/DSI 的 disable→enable 重新使能路径坏了**（bring-up 常见）；
3. 面板亮了但背光停在 511/0 → 背光状态没恢复。

倾向 1+2。**下一步动作**：
- 读 `/root/dpms-watch.log` 定位（第一步）；
- 若"输入没到" → 用 `dd if=/dev/input/event0` 验证电源键有没有产生事件（`pmic_pwrkey` = event0）；
- 若是"重新使能失败" → 需要改内核（panel/DSI 的 disable/enable 或 DSI host 重初始化）；
- 临时规避：把空闲熄屏关掉（`org.gnome.desktop.session idle-delay 0`；本机 dconf 写入受 D-Bus 限制，
  建议改 `/usr/share/glib-2.0/schemas/99_elden.gschema.override` 后 `glib-compile-schemas`），
  并把电源键熄屏也一并禁掉（否则按一下照样黑）。

### 4.2 卡在 fastboot（收工状态）

`current-slot=b`，`fastboot reboot` 进不去系统。最可能的原因：
**A/B 槽的"启动失败重试计数"被耗尽** —— Android 侧每次成功启动会由 `bootcontrol`/`init` 写
`misc` 里的 `bootloader_control`（`successful_boot=1`、`tries_remaining=N`），而**我们的 Linux 镜像不会写**。
一晚反复重启后，ABL 认为 b 槽不可信 → 直接停在 fastboot。
（旁证：今晚每次用 `fastboot --set-active=…` 之后都能起来，而 `set_active` 会重置槽位元数据。）

**恢复（下次开工第一条命令，任选）**：
```bash
cd ~/y700-elden
fastboot --set-active=b && fastboot reboot        # 重置槽位元数据，回到 Linux
# 如果还回不去：
fastboot boot out/boot-elden-vk13.img             # RAM 方式，一定可用（不进系统分区）
# 想回 Android（注意 /data 还没重建，会走初始化）：
fastboot --set-active=a && fastboot reboot
```

**持久修复（下次做）**：在 Linux 的 `/init` 里启动后把当前槽标记为启动成功 ——
即写 `misc`（`/dev/disk/by-partlabel/misc`）偏移 2048 处的 `bootloader_control`
（`slot_suffix`、`slot_info[slot].successful_boot=1`、`tries_remaining=7`、`priority=15`），
或更省事：每次起来后跑一次 `fastboot --set-active=<当前槽>`（需要 fastboot，不理想）。
先把 `misc` 前后 4 KiB 读出来存档，再决定写哪些字节。
