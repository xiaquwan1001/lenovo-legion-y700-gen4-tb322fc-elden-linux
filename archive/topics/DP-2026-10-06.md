# G1-9 DP 输出 — DTS 链打通，卡在 ADSP UCSI/altmode（2026-10-06/07）

> 过程证据（archive，只增不改）；结论口径以 `TASKS.md` G1-9 为准。
> 设备 U2 `HA2EXB0E`，全程 `fastboot boot` **零写盘**。内核 vk53-hw `g2b5badef00fb`。

---

## 0. 结论（数字）

- **DTS/驱动侧已打通**：`card0-DP-1` 出现、`msm_dpu bound af54000.displayport-controller`、
  msm_drm_bind 正常、DSI 仍在（不黑屏）。
- **实际出图受阻**：`card0-DP-1/status=disconnected`。插 DP 线（含翻转方向）**全程零 HPD/altmode/USB-C 事件**。
- **根因定位**：`ucsi_glink.pmic_glink_ucsi pmic_glink.ucsi.0: PPM init failed, stop trying`（20.8 s），
  ⇒ ADSP 侧 UCSI PPM 未起来 ⇒ AP 侧 `pmic_glink_altmode` 收不到任何 connector/altmode 通知 ⇒ 无 HPD、不切 mux。
  与 audit 原判一致：**DP 是 ADSP bring-up，不是缺驱动**。

## 1. 单变量链（每步零写盘 boot 验证）

| 步骤 | DTS 改动 | 结果 |
|---|---|---|
| dp1 | 仅恢复 `usb-role-switch`（去掉 `/delete-property/`） | **启动失败 → 回退 boot_b** |
| dp1b | dp1 + `&i2c0 status disabled` | **启动成功**；typec 仍空 |
| dp2 | dp1b + `&mdss_dp0 status okay` | 启动成功、`card0-DP-1` 出现；插线无 HPD |

**关键副产**：主树 DTS 里 `&i2c0 { status="okay"; nfc@8{} }` 一直在——正是 **PITFALLS #108 的硬关机根因**
（文档曾记「已从驱动批次移除」，实际未落地）⇒ 由本树构建的任何 DTB 启动必失败。**已改 `disabled`**。
dp1 的「启动失败」即由此而来，与 role-switch/dp0 无关。

## 3. 剩余待解

- **ADSP UCSI PPM init failed**：需 ADSP 固件暴露/起来 UCSI owner。已知 PD 快充由 ADSP 独立完成（9.4V/5A），
  但 UCSI/altmode 服务未就绪。
- 与 #113 同型怀疑：`UCSI=y` 内置，ADSP glink 未就绪时首探失败即 `stop trying`，可试「UCSI 晚加载/重试」。
- 或 ADSP 固件版本不含该平台 UCSI 支持。
