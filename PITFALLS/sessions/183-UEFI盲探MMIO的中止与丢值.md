# #553 · UEFI 里盲探 MMIO：一次读多个字 + 一次打印 = 异常时整行值全丢；错误基址的代价是人工断电

- 日期：2026-11-07（深夜·二，G1-29，p56/p57）

## 现象

p56（R51）在交棒前读两处候选看门狗窗口的 6 个 32-bit 字，一次 `AsciiSPrint` 打印整行。
上机后屏上只有：

```
[K] FLT pc=CFC9FFA8 … esr=96000010 far=17410014
```

**没有任何 `[K] wdt…` 行** —— 一个字的读触发同步外部中止（DFSC=0x10，说明该偏移在总线上无实现），
整行参数值随异常丢失。且 fault handler 自旋不退出 ⇒ 设备卡死，**必须人工长按电源断电**。

p57（R52）改成「读一个、打一个」并避开 `0x14` 后，**第一个字**（`far=17410000`）就中止
⇒ `0x17410000` 整个窗口在本机不可访问（不是 `0x14` 的洞，是基址本身错）。

## 纪律

- **探测必须「读一个、打一个」**：每读一个字立刻 `SerialPortWrite` + `SerialPortLogPutString`，
   这样异常发生时之前的值已经在屏和环里。
- **盲探 MMIO 的成本 = 一次人工长按断电**（本项目里物理动作只能由用户做）⇒ 不做大范围地址扫描；
   先用「已知同族平台主线的 DTS 基址」缩小到一个，再逐字读。
- 读到的「寄存器值」要能自证：看门狗窗口的特征是 `EN` bit0 与 `BITE`(tick, 32.768 kHz) 的合理量级
   （4 s ≈ `0x20000`）；对不上就说明基址错，别硬解释。
- 平台相关地址（APSS wdt 等）**不要**照抄同族平台：SM8750 上 `0x17410000`（x1e80100 的 `apss_wdt`）
   与 `0x17C10000`（sm8250 的 `kpss_wdt`）都不可访问。
