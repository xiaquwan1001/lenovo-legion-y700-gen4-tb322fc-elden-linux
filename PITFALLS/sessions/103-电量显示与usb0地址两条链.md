# #429 电量显示缺的是 UPower（驱动一直正常）；#430 busybox applet 没符号链接 ⇒ udhcpd 不跑，宿主拿不到地址

- **日期**：2026-10-26
- **场景**：Debian 根（linux17）桌面已起，但①顶栏没有电量 ②主机必须手工 `ip addr add` 才能 SSH

## #429 `qcom-battmgr` 正常 ≠ 有电量显示；缺的是 **upower 包**

驱动侧一直是好的：

```
/sys/class/power_supply/qcom-battmgr-bat/{capacity,status}  →  86 / Charging
lsmod: qcom_battmgr 24576 0     (pmic_glink / pmic_glink_altmode 也在)
```

但 phosh 的电量指示**不走 sysfs**，走 **UPower over D-Bus**；Debian 包集合里没有 `upower`：

```
$ upower -i ...
bash: upower: command not found        ← 真实症状只有这一行
```

⇒ 现象是「电源管理模块不工作 / 无法显示电量」，很容易误判成 battmgr 或 PMIC 没驱动起来。

**修法**：
- `pkgmap.tsv` 加 `upower　add　upower`（apt-list 随之带上，第 100 行）；
- `stage.sh` 显式把 `upower.service` **挂进 `graphical.target.wants`**：Debian 的 upower 是
  D-Bus 激活型，`postinst` **不会** enable；不挂就可能出现"桌面已起但 phosh 拿不到 UPower 对象"。
- 门禁 G 增加断言（缺链接直接 FAIL，并在提示里写明"驱动正常也没用"）。

装上后：`upower -i …battery_qcom_battmgr_bat` → `present yes / state charging / energy 25.2 Wh / 86%`。

## #430 `udhcpd` 在 Debian 的 busybox 里**有 applet、没有符号链接**

`/init` 在 usb0 上起 DHCP（给主机发 192.168.7.2–20，**故意不发默认网关**，否则宿主上网流量
会走进平板）。Debian 根里 `/bin/busybox --list` 有 `udhcpd`，但 `command -v udhcpd` 失败 ⇒
直接调 `udhcpd -S /etc/udhcpd.conf` 静默失败 ⇒ **主机侧症状**是"USB 网卡永远没有 IPv4"，
而设备侧一切正常（usb0 有 192.168.7.1、sshd 在听）—— 这就是 #422 的同一类错误（能力在、名字不在）。

**修法**：
**①** `initramfs/init` 加 `usb0_dhcp()`：路径 → `$BB udhcpd` → `/run` 内联配置（配置文件缺失时），
   三处全都能用；两处调用点改用它。
**②** `/etc/udhcpd.conf` 由 `rootfs/debian/{build-rootfs.sh,stage.sh}` 都写一份（内容一致、无网关）。
**③** **主机侧**（一次性、可持久）：给 USB 网卡建一条 DHCP 的 NetworkManager 配置

```bash
nmcli connection add type ethernet ifname enx021e5eede102 con-name elden-usb-gadget \
      ipv4.method auto ipv6.method link-local autoconnect yes
```

（接口名由 usb-gadget 里固定的 host_addr `02:1e:5e:ed:e1:02` 决定，跨重启稳定。）

实测：冷起后主机 **10 s 自动拿到 192.168.7.9/24**，无需任何手工命令。
