## 三十六、构建落点（内存盘）与调试信息实测（2026-10-15 实测）

> 任务：把编译产物放进内存盘以加快重编译。实测结论 = **内存盘无效、关 DEBUG_INFO 有效**。
> 证据：`reports/rambuild-measure.tsv`、`logs/rambuild-*.{out,log,mem.csv}`；规划与裁决：`.pi/plans/2026-10-15_081500-内存盘构建区规划.md` §9。

---

266. **★把内核构建树放进 tmpfs（内存盘）不加速重编译**：增量环（改 1 个 `.c` → `Image.gz`）**31 s(ext4) vs 32 s(tmpfs)**，冷编 **560 s vs 566 s**。原因：日常编译受 CPU 与 ccache 支配；读路径本来就被 page cache 覆盖（`cached` 长期 25–40 GB），tmpfs 只省写路径/元数据，量级 <5%。**代价却是 7.3 GB 常驻内存**。⇒ 不要为「加速」建内存盘；要这么做只应为省磁盘。有 3 个 worktree 就因建在 `/tmp` 被清空成 `prunable`（`/tmp/dailyid`、`/tmp/vk125src`、`/tmp/vk125wt`），**别用 `/tmp` 当构建落点**。

267. **★关 `CONFIG_DEBUG_INFO` 是这套树最有效的迭代加速**：增量环 **32 s → 22 s（−31%）**、树体积 **−57%**、`vmlinux` **−88%**（669→80 MB）。默认别动，做成显式「迭代 profile」。
    - **坑中坑**：`DEBUG_INFO` 是 choice 成员，写 `# CONFIG_DEBUG_INFO is not set` **无效** —— `CONFIG_DEBUG_INFO_DWARF5=y` 的 `select DEBUG_INFO` 会把它拉回 `=y`（实测第一次片段就静默失败）。正确片段：`CONFIG_DEBUG_INFO_NONE=y` + `# CONFIG_DEBUG_INFO_DWARF5 is not set`；改完必须回读 `grep '^CONFIG_DEBUG_INFO' .config` 确认只剩 `DEBUG_INFO_NONE=y`。

268. **★冷编墙钟由 ccache 主导，换 config 的 A/B 必须让 ccache 状态同构**：p2a(566 s) 之所以不慢于 p0a(560 s)，靠的是热 ccache；L1 改 config 后 cache 全 miss，把 no-debug 的收益掩盖成 **+5.6% 劣化（598 s）**。⇒ 比较配置差异前，先确认两侧「同路径 + 同 config 已预热」或「两侧都清空 cache」，否则量到的是缓存不是变量。

269. **换树路径会使 `Image.gz` 的 sha 必变（GNU build-id 20 字节）**：同 commit/同 config 两份镜像 `cmp` 差 40 字节（build-id note 出现两次），而树路径本身**不在**镜像里（`grep -c` = 0）；DTB 的 sha 完全相同。⇒ **跨落点/跨 worktree 的「同源」判据不能用镜像 sha256**，只能用 `uname -r` + config 锚点 + `System.map` 符号（即 `scripts/assert-kernel-sane.sh` 的三件套）。要真字节一致得加 `-ffile-prefix-map` 或 `--build-id=none`。

270. **`set -o pipefail` + `grep -m1` = 假失败**：grep 命中即退出 → 上游（`strings` 等）收 SIGPIPE(141) → pipefail 判整条管道失败 → `x=$(producer | grep -m1 … || echo -)` 把兜底值也拼进变量（得到 `"#2 SMP … \n-"`），随后把这个含换行的值写进 TSV ⇒ **一行变两行、数据被静默污染**（曾据此把 4 行测量记录误删）。修法：`… | grep -m1 … || true`。

271. **快照「已编译的树」的未跟踪文件 = 把所有构建产物打包**（本案可达数 GB，会把仓库撑爆）：`git ls-files --others --exclude-standard | tar` 不适合内核树。护栏：未跟踪文件 > 2000 个即跳过打包（产物可重生，本就不该进快照）。

272. **`pi.bash` 里 `rm -rf` 对 tmpfs 一律 EXDEV 失败**（被重定向成「移入项目内 `~/.pi/trash`」，跨设备 rename 不可能）：删内存盘/`/tmp` 下的东西必须 **`/bin/rm -rf`**（实测 plain `rm` rc=1 且目录残留）。

273. **不要编辑正在执行的 shell 脚本**：bash 按块读文件，改了就可能在任意行报「未预期的记号」并把半个 `printf` 写进数据文件（本案第一次测量就撞上）。
