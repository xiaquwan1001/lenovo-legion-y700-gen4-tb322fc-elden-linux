## #514 探针判全局变量：`SbStopStage` 跨 fastboot 命令保留，且赋值点可能在你的探针之后

- **现象**：11-05 夜 10 发 `vs-stop20…25` / `pre-stop16/18/19` 全部「无应答」，被判成
  「崩在 N 之前」，于是把崩溃窗口收窄到 `LoadImageAndAuth` 前导 3 步并写进 SSOT。
  实际这 10 发**一次都没命中探针**，行为等于未加探针的对照件。
- **根因**：探针写成 `if (SbStopStage == (n)) { SbDiagAbort = (n); return EFI_ABORTED; }`，
  而 `SbStopStage` 的**唯一赋值点**在 `BootLinux()` 里；`CmdBoot` 的调用序是
  `LoadImageAndAuth()` → `BootLinux()` ⇒ 进 `LoadImageAndAuth` 时它恒为 `-1`。
- **第二形态（修第一形态时踩的）**：改成「入口解析」后加了 `if (SbStopStage < 0)` 守卫 ——
  该全局**跨 fastboot 命令保留**，同一固件会话连打第二发会沿用上一发的值
  （实测 `sbstop=18` 被打成 `vs-16`，判据直接错）。
- **对策**：① 停机点令牌**每次无条件当场从镜像头 cmdline 重解析**（与 `FastbootCmds.c` 的
  finebisect 同一做法），不要判全局；② 修完必须**反汇编核对**探针真的进了 `LoadImageAndAuth`
  （`llvm-objdump` + `LinuxLoader.map` 定位符号，看 `bl SbParseStopStage` / `cmp w0,#0x10` /
  `str …, [SbDiagAbort]`）；③ 每轮先打一发**入口对照**（`sbstop=0`）证明解析+回传+存活三件成立。

## #515 屏上调试输出会自己写穿帧缓冲：43 MiB 声明 ≠ 可写；`SCALE_FACTOR 3` 下一行就吃掉 274 KiB

- **现象**：`sbstop=17` 回话、`sbstop=18` 崩，中间源码上只剩一个 `if (Info == NULL)`；
  反汇编却显示那里有一次 `SbVProbe`。把探针通道做成开关后：`sbprobe=2`（全静默）不崩、
  `sbprobe=1`（只 `SerialPortWrite`）崩 ⇒ 崩溃由**屏显本身**造成。
- **机制**：`Display Reserved`/DT `splash_region` 声明 `0xFC800000` + `0x02B00000`（43 MiB），
  但实测**只有前 ~448 KiB 可安全写**（见 `PITFALLS #492`）；面板 1904×3040@32bpp，
  `SCALE_FACTOR 3` 下每行文字 = `3×FONT_HEIGHT(12)` = 36 像素行 = 36×1904×4 = **274 176 B**
  ⇒ 只装得下 **~1.6 行**，换行后继续画就越界。
  第二个未单独判别的可疑点：每次换行 `FbConFlush()` 对整块 `gWidth*gHeight*bpp/8`（22.08 MiB）
  做 `WriteBackInvalidateDataCacheRange`。
- **对策（本轮采用）**：新增 `sbprobe=3` = **只更新 `SbLastMark`、不写帧缓冲、不写 NV 变量**。
  标记照样经 fastboot 响应回宿主（`diag st=%r last=[%a]`），于是「不崩 + 仍能读到最后一条标记」
  同时成立，二分不再付断电代价。
- **另记**：`FbConScrollUp()` 用 `unsigned short *`（16 bit）搬 32bpp 帧缓冲，`count = gWidth*(gHeight-FONT_HEIGHT)`
  ⇒ 只搬一半字节、且行宽错位；真要用屏显通道得先修它。

## #516 「本地文件不存在」也会被读成设备回话：`fastboot boot` 的 rc=1 不能当「收到 diag」

- **现象**：mode-3 阶梯一次跑 5 档，5 档全被分类器判成 `REPLY`，但 `elapsed=0`、`marker=-`。
  看 run 文件才发现是 `fastboot: error: cannot load 'out/r21-sbstop/p7-m3-stop30.img': No such file or directory`
  —— 变体件根本没造（生成脚本只造了另一批编号）。
- **根因**：判据写成 `rc==1 ⇒ REPLY`。`fastboot boot` 在**本地读文件失败**时同样返回 1，
  于是「没发出去」被记成「设备回话了」。
- **对策**：① 判据必须**要求真的出现 `diag st=` 字符串**，rc 只作辅证；
  ② 造件脚本要在上机前打印/校验每个变体的 sha256 与字节数，并在阶梯脚本里先
  `[ -f "$img" ] || die`；③ `elapsed≈0` 的「回话」一律先怀疑本地失败（正常回话 1–2 s）。
