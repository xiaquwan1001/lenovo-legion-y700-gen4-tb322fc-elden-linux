## #664 ESP 满时 `esp-install-grub.sh --activate` 会「半成功」：备份 cp 失败但覆盖照做，跑的是上一版 EFI

2026-11-15 实测（ESP = `/dev/sda18`，512 MB，历史 GRUB 件把 `EFI/BOOT` 塞到 100%）：

```
cp: 复制 'EFI/BOOT/BOOTAA64.EFI' 到 'EFI/BOOT/BOOTAA64.EFI.shotB2-20261115.bak' 时出错: 设备上没有空间
```

脚本当时用 `set -e` 的 `&&` 串联，**这一句失败并没有中止**（`[ -f X ] && cp -a X X.bak` 里 `&&` 左边为真、右边失败 →
整句 rc≠0，但下一句 `cp EFI/grub/... EFI/BOOT/BOOTAA64.EFI` 仍被执行），于是 **BOOTAA64.EFI 被换成了新件、备份却没生成**；
更阴的是那次升级的意图是「新菜单多了两个中间标记」，结果跑的仍是上一版菜单 ⇒ 判决与上一发逐字相同，
差点被误读成「新标记没生效 / GRUB 缓存」。

**处置**：
- **装件前后各跑一次** `df -h /mnt/esp` 与 `sha256sum /mnt/esp/EFI/BOOT/BOOTAA64.EFI`，与「预期的件 sha」对齐再谈判决。
- **ESP 只留「当前件 + 1 份 loader 备份」；GRUB 世代件去 `EFI/grub/`，且同样只留最新一两份
   （本轮清掉 18 份 `>=6 MB` 的 `BOOTAA64.EFI.*.bak` 与 6 份 `EFI/grub/grub-v*`，从 100% 降到 60%）。
- **半成功后回滚链已断（没有这次的新 `.bak`）⇒ 回滚要显式指定件（本轮用了 `BOOTAA64.EFI.loader-r73.bak`，sha `6e51fc60…`）。

证据：`TASKS/sessions/2026-11-15-UEFI-ShotAB-读路径清白分配页存活.md` §4。
