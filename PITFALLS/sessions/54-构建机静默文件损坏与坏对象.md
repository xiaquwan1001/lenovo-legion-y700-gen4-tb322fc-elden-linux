## 五十四、构建机「静默文件损坏」与坏对象（2026-10-19/20 实受）

> 触发场景：`q24`/`n5b` 需要重建 `out/boot-elden-vk64.img`，内核编译反复失败。
> 起初判为「交叉编译器坏了」，实为**两个独立问题叠加**。

282. **★「编译随机 ICE/段错误」在这台机器上默认怀疑**工作树/产物被静默篡改**，不是源码、也不是编译器版本。**
    - 现象序列（同一晚）：
      1. `aarch64-linux-gnu-gcc -O2 -c hello.c` → `internal compiler error: in scev_initialize, at tree-scalar-evolution.cc:3017`（**连 hello 都编不过**）；
      2. 重装 `gcc-15-aarch64-linux-gnu` 包后 hello 恢复，但内核树里仍有 2~4 个文件 ICE/段错误；
      3. 之后 ld 报 `bad reloc symbol index (0x827 >= 0x60) ... in section '.debug_info'` / `member ... in archive is not an object`，**每次换一个文件**。
    - 真正的证据：逐文件比对 `sha1("blob <len>\0"+内容)` 与 git index 的 blob sha —— vk83-tree 报出 4 个 tracked 文件被**单字符改写**、大小与 mtime 都不变：
      `mmhub_9_4_1_offset.h`（多了一个反引号）、`nbio_7_11_0_sh_mask.h`、`bnx2x_reg.h`（`MSTAT_REG` → `M[TAT_REG`）、`trace_probe.c`；
      更早有 `nfstrace.h`（`__field(int, error)` → `__field(int( error)`）与 `serial_bcm63xx.h`（`UART_FIFO` → `IUART_FIFO`）。
    - ⇒ **git 不校验工作树内容**，`git status` 一直显示「干净」，只能逐文件 sha1 发现。工具：`scripts/verify-tree-integrity.py <tree> --allow-dirty`（并发 32，9.5 万文件约 2 s）。
    - ⇒ 编译脚本（`scripts/rebuild-vk64-image.sh`）已在**编译前后各做一次全树校验**，任一次不过即丢弃产物。
    - 未定性：现象跨多棵树、跨数天、发生在无 git 操作期间；`/tmp` 是 tmpfs 已排除；3×600 MB 写读回 sha 一致；无 MCE/EDAC 记录（本机 `EDAC ie31200: No ECC support` ⇒ **内存无 ECC，静默位翻转无法被硬件发现**）。参见 `reports/host-file-corruption-20261020.md`。

283. **★`ld` 报「bad reloc symbol index」时，被告的那个 `.o` 是坏的，但它**不代表**源码/编译器有问题 —— 删掉串行重编即可，且必须**逐个验证**才知道收敛没有。**
    - 手段：`aarch64-linux-gnu-ld -r -o /tmp/x.o <候选.o>`（对 aarch64 对象做局部链接）；报错即坏。
    - 全树批量检查要**排除 host 工具对象**：`scripts/` 下的 `.o` 是 x86-64（`Relocations in generic ELF (EM: 62)` 是误报），只校验 `readelf -h` 为 AArch64 的对象。
    - 破坏是**持续产生**的：一轮修好后下一轮链接又冒出新的坏对象（`libps2.o`）⇒ 必须按「链接 → 定位 → 删 → 串行重编 → 再链接」迭代到收敛，一次通过不代表干净。

284. **★`gcc -O0` 能过而 `-O≥1` 崩，且换同版本重装后行为改变 ⇒ 先查包完整性，再查输入文件，最后才怀疑源码。**
    - 判据顺序（省时间）：① `-O2` 编 hello（3 行）→ 崩则是工具链；② `dpkg -V <包>` / 包目录 mtime vs 上次成功构建时间；③ 换 `-O0`、`-fno-ipa-*`、`-fno-tree-*` 是否改变 —— 本例全部无效，说明不是优化选项交互；④ 逐文件 sha1 对 git index（见 #282）。
    - 反例警示：不要把「重装包后 hello 好了」当成根因确认 —— 本例重装只解决了**其中一个**（`cc1` 侧），内核树里的坏源文件仍在。

285. **★`m1-73` 的三处 `M`（`sm8750.dtsi` fastrpc `qcom,non-secure-domain`、`gc08a8.c`/`s5kjns.c` AGC 增益修）是**有意的未提交修改**，不是损坏。**
    - 判别方法：`git status` 里有的文件，用 `--allow-dirty` 让校验脚本读 status 豁免；**只有不在 status 里的不一致才是损坏**。
    - 已在 `patches/m1-73-worktree-20261020/0001-worktree-agc-fix-and-adsp-non-secure-domain.patch` 固化成补丁（sha256 `c0004ed4…`），避免下次被当成垃圾清掉。
