# PITFALLS #395 — 7.3 的 DTC_FLAGS 变量名按 `target-stem`（无 `.dtb`），旧写法被静默忽略 ⇒ 板 DTB 无 `__symbols__`

- 日期：2026-10-25
- 主题：内核 DT 构建规则改名后，`DTC_FLAGS_<board>.dtb := -@` 不再生效，运行时 overlay 全 `-EINVAL`
- 结论（一句话）：**7.3 起 `scripts/Makefile.dtbs` 用 `DTC_FLAGS_$(target-stem)`，而
  `target-stem = $(basename $@)` 已剥掉扩展名**；沿用老内核的 `DTC_FLAGS_foo.dtb` 写法不会报错、
  只是**不生效**——板 DTB 里没有 `__symbols__`，所有依赖 fixups 的 overlay（本机 = 厂商 hyp DTBO）一律 `-22`。
- 证据指针：`reports/gunyah-612-samebuild-20261025.md` §3

## 症状

`gunyah-dtbo: dtbo[0] … apply -> -22`，`/hypervisor` 不出现，`gunyah_rsc_mgr` 不绑、`/dev/gunyah` 不出现。
`dmesg` 里没有任何「找不到符号」类提示（overlay 只是 EINVAL）。

## 判据（两步都做，缺一不可）

① 直接查产物：`dtc -I dtb -O dts arch/arm64/boot/dts/qcom/<board>.dtb | grep -c __symbols__` → **0** = 本坑。
② 抓真实命令行：`make … dtbs V=1 | grep '<board>.dtb'`，看 `scripts/dtc/dtc` 参数里**有没有 `-@`**。

## 修法

```make
# arch/arm64/boot/dts/qcom/Makefile —— 7.3 正确写法（无 .dtb 后缀）
DTC_FLAGS_sm8750-lenovo-elden := -@
```

重编后 `grep -c __symbols__` = 1，`apply -> 0`。

## 为什么容易踩

- 老内核（≤6.x）的变量名是 `DTC_FLAGS_$(basetarget)`，`basetarget` **含** `.dtb`；把老补丁 rebase 到 7.3
  时编译器/make 都不报错，只在实际 overlay 时才暴露，且现场现象（`-EINVAL`）会被误归因到 SELinux、
  overlay 内容、`__fixups__` 写法等（`PITFALLS #389` 已有一条同型误判）。
- 迁移判据应是「产物里有 `__symbols__`」，而不是「Makefile 里有那行」。
