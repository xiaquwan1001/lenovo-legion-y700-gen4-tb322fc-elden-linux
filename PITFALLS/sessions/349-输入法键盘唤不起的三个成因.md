# #716「输入法键盘唤不起来」在 Phosh 栈上有**三个**互不相同的成因，其中两个是被部署造出来的

> 2026-11-24 二轮设备窗实测（TB322FC U2 / vk189 `7.3.1-debug-vk189-suspend-00005-g4bdf1711b5c0` / Debian trixie /
> phosh+phoc+osk-stub **0.46.0**，osk-stub = 我们 divert+hold 的 B 案自编件）。
> 用户报障原话：「之前有关中文输入法的配置似乎有两条路，现在的部署方案让输入法键盘无法唤起。」
> 本轮把三条成因全部定位到行级，并给出**单栈收敛**的脚本判据（`scripts/ime-single-stack.sh`）。

## 判据链（从现象到根因，全部可复跑）

现象：屏幕解锁、点输入框（Firefox 地址栏 / 应用网格搜索框都有光标），**键盘不出现**；
`sm.puri.OSK0 Visible` 甚至能读到 `(<true>,)`，但屏上什么都没有。

| 层 | 复跑命令 | 本轮实测 |
|---|---|---|
| ① 客户端真的在打字 | `WAYLAND_DEBUG=1 phosh-osk-stub`（自起一份）+ 点 Firefox 地址栏 | 收到 `zwp_input_method_v2#N.activate()` ⇒ **phoc 与客户端都正常**，链路断在 osk-stub 内部 |
| ② a11y 屏幕键盘开关 | `gsettings get org.gnome.desktop.a11y.applications screen-keyboard-enabled` | **`false`** ⇒ `phosh-osk-stub.c:221-238 set_surface_prop_surface_visible()` 里 `enabled = pos_input_surface_get_screen_keyboard_enabled()`，`enabled==FALSE` 时无条件 `visible=FALSE` ⇒ 收到 activate 也**永远不弹**。设 `true` 后同一动作立刻弹（截图 `grep` 之前的 `/tmp/s_ff5.png`、现行判据见下） |
| ③ IM 槽被抢 | `journalctl _PID=<osk-stub pid> \| grep -c 'Input method unavailable'` | fcitx5 以**默认参数**（`waylandim` 已加载）在跑时，`zwp_input_method_v2` 每 seat 只允许一个 client ⇒ osk-stub 只印 `pos-input-method-WARNING: Input method unavailable` + `Failed to acquire DBus name`，**layer surface 一直 `set_margin(0,0,-200,0)`（完全在屏外）**，而 D-Bus `Visible` 仍可被设为 true（这就是「读到 true 却没键盘」的指纹） |

## 两条都是**部署造出来的**

- ② 的默认值是 `false`：2026-11-19 重建 Debian 根后 dconf 里没有这一项 ⇒ 从那一刻起 OSK 就再也弹不出来，
  而 `daily-baseline.sh` / `deploy-desktop-shell.sh` 都**没有**任何判据覆盖它（今天加进 §14 第 ④ 项）。
- ③ 是**两套 IME 路径并存**的副产物：老路（fcitx5 + `fcitx5-ime-toggle` + `fcitx5-indicator` +
  `elden-ime-focusd`）与新路（osk-stub + B 案 RIME completer）都写在 `daily-baseline.sh` 里被"保住"。
  应用网格里 `Fcitx 5` / `Fcitx 5 配置` 图标仍可点，一点就等于「用默认参数起 fcitx5」= 主动抢槽，
  且它**不会自己退出**，此后键盘永久不弹、只有 osk-stub journal 里那一行提示。

## 处置（已落地，可回退）

- **单栈收敛**：`scripts/ime-single-stack.sh --check|--apply|--rollback`（7 条判据 C1–C7）。
   `--apply` = a11y key 置 true + `Completers=rime` + `user-data` 非空 + 停/禁/mask `fcitx5.service` +
   移除 `graphical-session.target.wants` 里的 fcitx5/indicator/focusd 链接 + 用 `NoDisplay` 覆盖隐藏
   `org.fcitx.Fcitx5.desktop`。`--rollback` 只反做这三件（不动 osk-stub 与 gsettings）。
- **日常门**：`scripts/deploy-desktop-shell.sh` §14 增加第 ④ 判据（`screen-keyboard-enabled=true`），
   FIX 分支同时写它。
- **设备现态**（本轮收尾时 `ime-single-stack.sh --check` 全绿）：osk-stub 在跑、持有 `sm.puri.OSK0`、
   本 boot 无 `Input method unavailable`、fcitx5 = `masked`、5 个 fcitx 启动项 `NoDisplay=true`。

## 反向纪律（下次别再从协议层开始查）

- `Visible=true` **不是**「键盘在屏上」的证据：它只是 D-Bus 属性，layer surface 可能仍 `margin -200`。
  判「屏上有没有」只认 `grim` 截图；判「有没有被抢槽」只认 osk-stub 的 `Input method unavailable`。
- 不要拿 `PITFALLS #615`「phoc 版本门」套现役栈：那道门是 **phoc ≥0.58** 才有的 return；**0.46 的
  `handle_text_input_enable()` 直接 `wlr_input_method_v2_send_activate()`**（`/tmp/p046/phoc-0.46.0/src/input-method-relay.c:224-243`）。
- `pkexec`/`loginctl unlock-sessions` 解不了 phosh 锁屏；`su -l <user> -c '...'` 里再套单引号会把
  `awk '$1=="..."'` 的参数吃掉（本轮把 `as_user` 改成 base64 传脚本才取到 osk-stub pid）。
- 频繁 `pkill -x phosh-osk-stub` 会把 gnome-session 的 required-component 重启预算打光，
  之后 `sm.puri.OSK0` 直接 `ServiceUnknown`（本轮一度把会话打成 "Oh no! Something has gone wrong." ⇒
  `systemctl restart greetd` 才恢复），**它没有 D-Bus service 文件可激活**（`/usr/share/dbus-1/services/` 里无 OSK 条目）。
