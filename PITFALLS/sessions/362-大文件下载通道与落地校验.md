# #729 大文件下载通道与「落地校验」（2026-11-25）

## 事实（同一天内实测）

| 通道 | 结果 |
|---|---|
| `curl --noproxy '*'`（直连 GitHub release） | **被限速/截断**：280 s 只拿到 901 120 B（目标 11 047 451 B） |
| `aria2c -x8 -s8 --all-proxy=http://127.0.0.1:7890` | 字节数**完全正确**（903293629 / 66862311 / 11047451），但 `zstd -t` 三件全 `Data corruption (36)` |
| `aria2c -x1 -s1 --all-proxy=…` | 同样损坏（排除「多连接拼段」这个单一解释） |
| `rayburst`(aria2-next, RPC `127.0.0.1:29100`) 下载 11 MB 小件 | **校验通过**（`zstd -t` 报解压后 34 478 080 B，无错） |
| `curl -x http://127.0.0.1:7890`（单流） | **校验通过**，11 MB 用时约 40–90 s |

诊断线索：aria2c 首轮日志里出现
`errorCode=8 Invalid range header. Request: 3145728-4194303/11047451, Response: 3145728-4194303/903293629`
—— 说明**该代理链路上 Range 请求的响应不总与请求对象对应**；aria2 的多连接/分片强依赖 Range，因此它最容易踩。

## 处置口径

- **下载后必须落地校验**：压缩包 `zstd -t`（或 `xz -t`/`unzip -t`）、普通文件 `sha256sum` 对上游公布值。
   **不要用文件大小当判据**——本次三件大小全对但内容坏。
- 通道优先级（本机）：`rayburst` RPC / `curl -x proxy` 单流 → `aria2c` 仅当能拿到上游 sha 并开 `--check-integrity`；
   `curl` 直连只适合小文件。
- **`curl -C -` 续传到已损坏文件 = 保留损坏**：发现校验失败要先删再下。
- 大文件（>500 MB）走后台 + `timeout -k`，并记录进度日志；完成后再校验。

## 关联
- 本机页缓存单比特翻转已有取证（PITFALLS #513、`~/hw-stability/`）⇒ 校验失败时**先换通道复现**，两次都坏再怀疑硬件。
- 相关技能：`aria2-rpc-downloads`（rayburst/aria2 RPC 用法与安全自检）。
