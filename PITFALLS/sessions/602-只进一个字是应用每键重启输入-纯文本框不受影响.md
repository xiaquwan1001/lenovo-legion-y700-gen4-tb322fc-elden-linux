# #763 「键盘只能输入一个字」是**应用每键重启输入**触发的 Android 侧丢弃，不是宿主键盘坏了；纯文本输入框不受影响

- 日期：2026-11-28（用户报「只能输入一个字，再输没反应」；父代理设备实测定位）
- 现象（小红书手机号框，T43 ①+② 都已装）：能唤出宿主数字键盘，**敲 1~2 位后继续敲没反应**；
  Android 侧日志 `DroidloomIME: start input restarting=true editable=true` **每敲一键一条**。
- 探针（`DROIDLOOM_TRACE=input`）同一时刻：`editor=Some((false, 0, 9, 1)) enabled=Some((75, 6)) focused_task=Some(75) entered=true held=true`
  ⇒ Android 发布的新 editor 记录是 **`active=false, task=0`**。
- 因果链（两处丢弃，第一处宿主救不了）：
  1. 应用（小红书手机号格式化）每键 `setText` → IMMS **restart input** → 重新下发 `EditorInfo`；
  2. framework 补丁只在 `mImeBindingState.mFocusedWindow` 非空时注入 task（`ro.vendor.droidloom.surfaceflinger_tasks=true` 已确认），
     restart 期间该窗口为空 ⇒ **`task=0`** ⇒ `HostInputMethod.publish()` 算出的 `active = active && task > 0` = **false**；
  3. `HostInputMethod.apply()` 开头就 `if (state == null || !state.optBoolean("active") || edit.session != session) return;`
     ⇒ **后续宿主提交全部丢弃**（发生在 Java 侧、到 `InputConnection` 之前，宿主补丁无法绕过）；
  4. 宿主侧还有第二处：`text_input.rs::done()` 的 `self.editor != Some(editor)` 在 `held` 期间也会丢（同一现象的另一半）。
- **对照实验（关键，别误判成全局故障）**：Android Settings 搜索框（纯文本、无每键格式化）`ydotool type "abcdef"`
  ⇒ `uiautomator` 读到 `text="abcdef"` **6 个字全进**，且 `DroidloomIME` **零** `restarting=true` 日志。
  同一宿主键盘、同一 droidloom 件 ⇒ **「只进一个字」是「每键重启输入的输入框」特有**。
- 判据/纪律：遇到「键盘能出、只能进一个字」，先 `adb logcat -d -s DroidloomIME | grep restarting`；
  有 `restarting=true` 连发 ⇒ 是应用 + Android IME 的 `active/task` 逻辑，不是宿主键盘/OSK 的锅。
- 出路（按代价排）：① 上游修 Android 侧（`HostInputMethod.apply()` 别拿 `state.active` 当门 + framework 在 restart 时沿用上一 task）；
  ② 重编 Android 镜像（用户 2026-11-28 已裁定镜像重编出列，仅作备案）；③ 本机绕开（该输入框改用 `adb shell input text`，
  或换纯文本输入框验证功能）。宿主侧唯一能做的是第 4 条（`held` 期间不丢 edit），但第 3 条仍在，**不足以修复**。
- 出处：`reports/phoc-046-edge-swipe-deploy-20261128.md` §2「追补 2」、`android/framework/droidloom-ime/src/com/android/droidloom/ime/HostInputMethod.java:150`。
