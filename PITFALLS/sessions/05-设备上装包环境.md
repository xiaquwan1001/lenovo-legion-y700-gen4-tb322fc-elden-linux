28. **早前"瘦身"Mesa/LLVM 时手删了文件但 apk 数据库还在** → `apk add` 不恢复（认为已装）。

## #538：`dpkg-query -f '${Status}'` 判「装没装」不能用 `*installed` 通配——`unknown ok not-installed` 也会命中

- 现场（2026-11-07，Debian 根盘查日用缺包）：审计脚本写的是
  `case "$s" in *installed) st=OK;; *) st=MISS;; esac`，结果 `sudo`（真缺）与 `bash-completion`
  （`unknown ok not-installed` = 已卸载但留着 conffile）**同时被判成 OK**，直接漏判。
- 正确判据：**精确等值** `[ "$(dpkg-query -W -f='${Status}' "$p" 2>/dev/null)" = "install ok installed" ]`。
- 同一个坑的第二种形态：`dpkg-query -W 'fcitx5*' | grep installed` 会把 `unknown ok not-installed` 也算进来
  ⇒ 盘「某前缀装了哪些」时要 `grep ' install ok installed'`，不能只 grep installed。

## #539：`debootstrap minbase` + `--no-install-recommends` 建出来的根「能起桌面，但没法当日常系统用」

- 根因不是掉包，而是**清单覆盖面**：`apt-list.txt` 源自 Alpine `apk-world`（硬件 bring-up + 调试），
  不含 `sudo` / `locales` / `man-db` / `bash-completion` / CJK 字体；而 `phosh-core`、Mobian
  `mobian-base` 是把这些写进 **Depends**（不是 Recommends）才兜住的。没有元包托底 ⇒ 全漏。
- 现象清单（2026-11-07 实测 1355 包）：`/usr/bin/sudo` 不存在、`/etc/locale.gen` 为空 +
  `locale` 报 `Cannot set LC_CTYPE`、`fc-list :lang=zh` = **0**、`fcitx5` 装了但**没有任何自启**。
- 处置口径：**不引入 `mobian-*` / `phosh-core` 元包**（会把 Mobian 整套策略与我们 greetd appliance /
  自维护 userland 打架），而是自建 `rootfs/debian/daily-baseline.tsv`（P0/P1 并进 apt-list，P2 只登记）
  + `rootfs/debian/daily-baseline.sh`（配置） + `scripts/mobian-daily-baseline.sh`（设备侧驱动）。
- **locale 判据的坑**：Debian 用 `locale-archive`，`ls /usr/lib/locale` **看不出** zh_CN 有没有生成
  （只有一个 `locale-archive` 文件）⇒ 必须 `locale -a | grep -i '^zh_CN\.utf-8$'`。
- **无口令账户的 sudo**：greetd appliance 账户 `passwd -S` = `NP`（无口令）⇒ sudo 无法用口令认证，
  只能 `/etc/sudoers.d/` 写 `NOPASSWD`。写规则前先判口令状态（`awk -F: '$1==u{print $2}' /etc/shadow`
  首两字符 `NP`/空 = 无口令），有口令时只入 `sudo` 组，别无条件 NOPASSWD。

## #540：Debian 的 fcitx5 没有用户级自启单元；`/etc/systemd/user` + `graphical-session.target.wants` 才是「构建侧和现场同一路径」

- Debian 包 `fcitx5` **不带 systemd user unit**（Alpine 时代靠 `/etc/xdg/autostart` + OpenRC 桌面链），
  装完 `pgrep fcitx5` 恒空 ⇒ 中文输入"看不见"的第一原因往往是**根本没起**，不是引擎坏。
- 落法（本工程）：`/etc/systemd/user/fcitx5.service`（`Type=simple` + `ExecStart=/usr/bin/fcitx5 -r --disable waylandim`，
  **不要** `Type=dbus`：fcitx5 会自己 daemonize 退出，systemd 立刻判 `inactive (dead)`）
  + **系统级** enable 链接 `/etc/systemd/user/graphical-session.target.wants/fcitx5.service`。
  用系统级而不是 `~/.config/systemd/user/default.target.wants`：**构建 chroot 里没有用户 home**，
  只有 `/etc` 下的路径能在「构建根」与「现场根」两处都生效。
- `--disable waylandim` 是必须的：Phosh 0.55 的 `phosh-osk-stevia` 占着 OSK/输入法槽位（见 #541）。
- **判活别只看进程**：`fcitx5-remote` 返回 `1` = inactive（新 IC 默认落到组内第一个引擎 `keyboard-us`），
  `-o` 激活、`-s rime` 切引擎；进程活着 + `org.fcitx.Fcitx5` 在总线上 ≠ 有输入上下文。

## #541：合成按键（`wtype`）不触发 IM 组词 ≠ 触摸 OSK 的路径也坏

- 2026-11-07 取证：GTK3 与 GTK4 各起一个会落盘回读的 Entry 窗口，`wtype` 注 `nihao`/`1`，
  `GTK_IM_MODULE=fcitx` 下窗口收到的是字面量 `nihao1`，`fcitx5-remote` 恒 `1`（inactive）；
  换 `ibus`+`ibus-rime` 对照臂同样字面量 ⇒ **不是 fcitx5 独有**。
- 已确认的是：`im-fcitx5.so` 确实被 GTK dlopen（`strace` 见到 `immodules.cache` → `im-fcitx5.so` → `libFcitx5GClient.so.2`），
  所以「模块没加载」这类结论会被 strace 直接否掉，别再往那个方向查。
- **边界**：合成虚拟键盘按键与 `phosh-osk-stevia` 真实触摸按键走的都是 `zwp_virtual_keyboard`，
  但**输入上下文是否建立**取决于窗口焦点/IC 生命周期，两者不等价 ⇒ 结论只能写「未证实」，
  必须在屏上真点一次才算判据（`TASKS` G1-37 的未收口项）。

## #573：`/etc/default/zramswap` 的 `ALGO=lz4` 在缺 `CONFIG_ZRAM_BACKEND_LZ4` 的内核上**静默回退**，服务仍 `success`

- 现象（2026-11-09，U2 `7.3.1-debug-vk184-00003`）：`zramswap.service` = `active` / `Result=success` / `ExecMainStatus=0`，
  但 `zramctl` 里 `ALGORITHM` 是 **`lzo-rle`**，而 `/etc/default/zramswap` 明写 `ALGO=lz4`。
- 真因：本工程内核只开了 LZO 后端（`CONFIG_ZRAM_BACKEND_LZO=y` / `FORCE_LZO=y`，
  `CONFIG_ZRAM_BACKEND_LZ4|LZ4HC|ZSTD|DEFLATE|842` 全 `not set`）⇒ `/sys/block/zram0/comp_algorithm` 只有
  `[lzo-rle] lzo`，zram-tools 写入 `lz4` 不被内核接受，被默认算法顶掉，**不报错**。
- 判据：`cat /sys/block/zram0/comp_algorithm`（方括号 = 当前生效档）比看配置文件/service 状态可靠。
- 处置：要 lz4 就开对应 backend 重编；不改内核就把 `ALGO` 写成 `lzo-rle`（消除"配置说的和跑的不一致"）。
  **已开（2026-11-09，配置侧）**：`patches/config-daily-c1` 与 `patches/config-vk163-modular-v2-20261026`
  都把 `# CONFIG_ZRAM_BACKEND_LZ4 is not set` 改成 `=y`（`select LZ4_COMPRESS/LZ4_DECOMPRESS` 本就 `=y`，无新依赖）⇒
  `olddefconfig` 两遍零变化（`=y 3499 / =m 1328` 不变）、`check-modular-config.sh` PASS、`zram.ko` 786 816 B。
  **在机内核仍是纯 LZO**，要等下一次重建镜像才生效。
  另：`PERCENT=50` 优先于 `SIZE=512`，实际盘 = 内存一半（7.3 G），不是 512 MiB。

## #576：`fcitx5-configtool` 只是薄壳 —— 缺 `fcitx5-config-qt` 时「点配置图标没反应」

- 现场（2026-11-09）：`fcitx5-configtool` 在（`/usr/bin/fcitx5-configtool`，`ldd` 无缺失），
  `.desktop` 的 `Exec` 也对，但点击后什么都不发生、也没有进程留下。
- 真因：配置界面在 **`fcitx5-config-qt`** 包里（连带拉 `libfcitx5-qt6-1` + `libkf6{dbusaddons,widgetsaddons,windowsystem,itemviews}`），
  `fcitx5-configtool` 只是转发器。装后 `org.fcitx.fcitx5-config-qt` 立刻出现在会话总线、窗口能开。
- 判据：`dpkg -l fcitx5-config-qt`；或 `busctl --user list | grep fcitx5-config`。
- 教训（与 #539 同族）：「命令在、ldd 干净」不等于「功能在」——GUI 类包要按**它实际启动的那个进程名**去装包。

## #577：`gtk4-layer-shell` 在 Python 里必须 `LD_PRELOAD`，否则每条 `set_*` 都警告且无 layer surface

- 现场：`gi.require_version("Gtk4LayerShell","1.0")` 成功、`init_for_window()` 也调用，但
  `gtk4_layer_shell_is_layer_window()` 仍 False，之后每次 `set_anchor/set_margin/...` 都打
  `GtkWindow is not a layer surface. Make sure you called gtk_layer_init_for_window()`；首次 init 时还有
  `Failed to initialize layer surface, GTK4 Layer Shell may have been linked after libwayland`。
- 修法：进程环境里预载 —— `Environment=LD_PRELOAD=/usr/lib/aarch64-linux-gnu/libgtk4-layer-shell.so.0`
  （发行版只装运行库时**没有** `.so` 符号链接，用 `.so.0`）。修后 `is_layer_window() = True`、无告警。
- 判据：脚本里打印 `is_layer_window()`；或看有没有那串 warning。

## #578：Phosh 没有 SNI 托盘；Wayland 的输入法槽位（`text-input-v3`）OSK 与 fcitx5 **二选一**

- Phosh/phoc 不实现 `StatusNotifierItem`：fcitx5 的 `kimpanel` 永远等不到宿主，`classicui` 在 Wayland 下只打
  `Created classicui for wayland display:` 而不出面板 ⇒ **想要顶栏指示只能自己画 layer-shell 小组件**
  （本工程做法：`rootfs/debian/ime/fcitx5-indicator.py`，GTK4 + layer-shell，右上一个胶囊，点击 `fcitx5-remote -t`）。
- `phosh-osk-stevia --allow-replacement` 与 fcitx5 的 `waylandim` 抢同一个槽位：
  - `fcitx5 -r`（waylandim 开）⇒ Wayland 原生应用（Firefox-Wayland/GTK4）能组词，但**屏幕键盘消失**（fcitx5 不画键盘）；
  - `fcitx5 -r --disable waylandim` ⇒ OSK 正常，但 Wayland 原生应用拿不到 `text-input-v3`，只剩字面输入
    （GTK3/XWayland 仍可经 `GTK_IM_MODULE=fcitx` 组词）。
- 附带：「`fcitx5-remote` 返回 0」不能从 SSH/systemd-user 作用域判活 —— 无输入上下文时它恒 0；
  只有从图形会话触发（点图标）才返回 1/2。取证请读 `~/.local/state/fcitx5-ime-toggle.log`。
