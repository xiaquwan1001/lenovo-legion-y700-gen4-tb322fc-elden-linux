# PITFALLS #396 — 6.12 的 `gunyah.ko` 是 `[permanent]`（无 `module_exit`）⇒ `rmmod` 永远 `Resource busy`

- 日期：2026-10-25
- 主题：换 Gunyah 驱动栈时不能用 `rmmod` 卸载旧 `gunyah.ko`
- 结论（一句话）：AOSP `android16-6.12` 的 `drivers/virt/gunyah/gunyah.c` 用 **`core_initcall(gunyah_init)`** +
  `MODULE_LICENSE`，**没有 `module_exit`** ⇒ 内核把它标成 `[permanent]`，`rmmod` 报
  `Resource busy`（不是被引用，refcnt 可以是 0）。换栈只能**改磁盘上的 `/lib/modules/<UTS>/…` 再重启**。
- 证据指针：`reports/gunyah-612-samebuild-20261025.md` §6

## 判据

```
grep gunyah /proc/modules
gunyah 12288 0 [permanent], Live 0xffff…      ← [permanent] = 无 exit，不可卸载
aarch64-linux-gnu-nm gunyah.ko | grep -c cleanup_module   → 0
```

## 正确做法

① `tar czf /root/ghmodules-6.x-backup.tar.gz -C /lib/modules/<UTS> kernel/drivers/virt/gunyah kernel/arch/arm64/gunyah`
② 新 `.ko` 覆盖到 **canonical 路径**（`kernel/drivers/virt/gunyah/`、`kernel/arch/arm64/gunyah/`），
   不要放 `extra/`——`depmod` 会优先解析 `extra/`，容易和新旧两套同名模块打架。
③ `depmod -a` 后确认解析路径：`modprobe -n -v gunyah_rsc_mgr | head`。
④ 重启（开机钩子 `modprobe` 即可），不要在运行中反复 `insmod/rmmod` 同一套 gunyah。
