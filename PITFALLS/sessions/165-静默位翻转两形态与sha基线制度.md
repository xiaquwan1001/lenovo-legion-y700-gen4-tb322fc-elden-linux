## 两种新形态（2026-11-05 实测）

| 形态 | 症状 | 判据命令 |
|---|---|---|
| **④ git pack 校验和不符** | 平时无感；`git diff`/`git show` 偶发 `error: inflate: data stream error (incorrect data check)`；只有被读到的那一次才报 | `git fsck --full`（会明确给 `pack checksum mismatch` + `cannot unpack <sha>` + 偏移）；`git fsck --connectivity-only` **不查 blob 内容，会漏** |
| **⑤ 文件名位翻转** | 目录里出现近形名（`testijg`/`ublj`/`vdSo`/`dr)vers`），`git status` 表现为成对的 `D` + `??`，`git diff` 报 `fatal: unable to read <base blob>` | `git status --porcelain \| grep -c '^ D\|^??'` 与 `git fsck --full` |

两者共同点：**长度/时间戳/mtime 都不变**，`sha256sum` 单次读也可能读到「一致」的假象 ⇒ 一次读通不代表文件好。

## 制度性对策（已落地）

- **镜像基线表**：`versions/out-images-sha256-20261105.tsv`（129 个 `out/*.img` 的 sha256 + 是否入账 + manifest 比对）。
   定期复算：`awk -F'\t' 'NR>3{print $1"  out/"$3}' versions/out-images-sha256-20261105.tsv | sha256sum -c --quiet`。
- **git 对象层**：收尾跑 `git fsck --full`（不是 `--connectivity-only`）；出现 pack 校验和不符时**先 tar 备份 `.git`，再按 `.pi/memory/MEMORY.md` 的配方全对象重写后 repack** —— 直接删坏 pack 会一次丢掉包内全部对象（本次 9599 个，远端 refs 全变「无效 sha1 指针」）。
- **校验要带重试**：同一命令/哈希重跑一次，区分「瞬时读错」与「真损坏」（本轮 85 条黄全部是「缺基线/引用文件不存在」，真损坏 0）。
- **诱因线索**：同一天三起事件（11-03 镜像静默损坏、今日 pack 与 b5-v2 文件名位翻转）在用户把 BIOS 改回保守设置前集中出现 ⇒ **先怀疑平台设置/供电/内存，而不是工具链**；替换件/BIOS 变更后重跑 `integrity-audit` 类校验再下结论。
