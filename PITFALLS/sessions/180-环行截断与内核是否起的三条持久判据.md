## #550 三条持久判据 + 环行截断

### 1. UEFI 日志环按 **200 字符/行** 截断 ⇒ 长 cmdline 的**末尾令牌看不见**

p49（R43 v2）唯一判据是「cmdline 末尾追加 ` elden_bootpath=uefi`」。但 UEFI 的 logfs 是日志**环**的
快照，而环里每行被截到 200 字符：

```
Cmdline: console=ttyGS0,115200 … elden_nocamera=1 androidboot.verifiedbootsta|Final RAM Partitions
                                                                      ↑ 第 200 字符处被切断，令牌在行尾
```

⇒ 上机后**根本看不到令牌到底写了没有**。p50 用 R44 补了一行**行首**判据才定案：

```
[K] cmdline len=293 tag=1 tail=no=51318dc0 androidboot.baseband=apq elden_bootpath=uefi.
```

**规则**：任何要跨启动判读的结论/令牌，都必须**自带一行短判据**（长度、布尔值、尾部片段），
不要指望它能从被截断的原始输出里读出来。

### 2. ~~`pstore/ramoops` 空 = 内核连 printk 都没跑到~~ **⛔ 本条错误，2026-11-07 20:20 撤回**

> **撤回理由**：`systemd-pstore.service` 在**每次 boot** 时把 `/sys/fs/pstore/*` 搬到
> `/var/lib/systemd/pstore/` 并清空源目录 ⇒ `/sys/fs/pstore` 空**不代表**上一次内核没写记录。
> 实测：被判「内核没跑到 printk」的那次尝试，其内核 console 完整躺在
> `/var/lib/systemd/pstore/console-ramoops-0`（64 858 B，从 `[0.000000] Booting Linux` 到
> `[4.122698] mmc0: sdhci: Host ctl2`），且 `Kernel command line:` 里带 `elden_bootpath=uefi`
> ⇒ **交棒其实成立**，内核真的起了，死在 4.12 s 的 `mmc0: ADMA error`。
> **正确用法**：读 `/var/lib/systemd/pstore/`（不是 `/sys/fs/pstore/`）；ramoops 控制台是 64 KiB 环，
> **文件头仍是 boot banner = 环没回绕 = 内核从此没再打印过**，这就是精确的「停在哪一行」。

### 2 原文（已作废，保留以便追溯）

本机 DT 有 `ramoops@c2000000`（4 MiB），内核启动 0.03 s 内就注册：

```
[    0.027355] printk: legacy console [ramoops-1] enabled
[    0.028016] ramoops: using 0x400000@0xc2000000, ecc: 0
```

⇒ 只要那个内核**执行过一条指令**，下一次引导在 `/sys/fs/pstore/` 里就该有 `console-ramoops-*`。
两次尝试（p49/p50）回读**全空** ⇒ 判「内核一条指令都没执行」，而不是笼统的「没起来」。

注意：2026-11-04 那条「ramoops 通道被证伪」说的是**UEFI 自己**往 `0xC2000000` 写记录
（被 PrePi/冷复位清掉）；**内核自己写 console**走的是同地址但由内核在启动时写、下一次引导读，
该路径不受影响（`reports/uefi-ramoops-channel-20261104R.md` §4 与本条不矛盾）。

### 3. `journalctl --list-boots` = 「有几个内核进过用户态」的计数器

每次 `fastboot boot` 尝试后，boot 列表只多 **一条** 记录（ABL 引导 `boot_b` 那一次）。
若 UEFI 交棒的内核曾进用户态，必然多出**第二条**（哪怕很短）。这条比 USB 事件稳
（`PITFALLS #549`：gadget 串是硬编码常量，对「哪台机」零信息量）。

### 4. 脚本层面的旧判据要一起改

`scripts/uefi-boot-trial.sh` 原把「fastboot 不再应答 / USB gadget 消失」记成 `HANDOFF` ——
那是**候选**而非结论（跳转后复位、ABL 自己引导同样如此）。已改为：
内核 cmdline 含 `elden_bootpath=uefi` ⇒ `HANDOFF_TAGGED`；内核起但无令牌 ⇒ `ABLBOOT_NOTAG`；
没起来 ⇒ `NOBOOT`。另修 `PRE/POST_BOOTID` 取到表头行（`head -1` → `sed -n 2p`）。
