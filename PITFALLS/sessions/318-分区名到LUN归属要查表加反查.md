# #686 分区名 → LUN 归属不是「猜」，是查表 + sysfs 反查（脚本审查 P1-3 落地）

## 现象（为什么要做）

本机是 **6 个 UFS LUN、每 LUN 一张独立 GPT**，而 Linux 的分区命名空间是**全局**的：

- `/dev/disk/by-partlabel/<name>` 只给你其中一个候选，**且不告诉你还有别的**；
- 仓库里多个脚本靠 `by-partlabel` 或**硬编码 `/dev/sde`** 定位（`slot-attr.py` 默认 `/dev/sde`、
  `flash-b.sh`、`uefi-flashed-trial.sh`、`slotboot-run.sh`）；
- `slot-attr.py` 在「条目找不到」时曾打印 `written + CRCs fixed (primary & backup)` 且 **rc=0**
  （脚本审查报告 P0-④ 的第二个洞）⇒ 对错 LUN 跑 `set a`/`mark-successful` 时，人看到的仍是成功。

⇒ 一旦换单元、换（精简）分区表、或 `--lun` 给错，就可能**静默写到错的分区**。
历史上最贵的一类事故（`PITFALLS` #308/#672：写 boot_a 写飞、槽属性写错导致「下一次注定失败」）。

## 处置（本轮落地）

- **`scripts/partlun.py`（新）**：分区名 → LUN 的**静态归属表** + 三类拒绝。
   - 表来源（证据，不是记忆）：`backup/HA2EXB0E-16+512/edl-20261118/gpt{0..5}-primary.bin`
     的 EDL 只读 dump 现扫（**112 个标签**，`--selftest` 会现场比对静态表 == dump）；
   - `resolve <label>`：唯一 → 打印 LUN；**同名多 LUN → rc=2（列出全部候选）**；未知 → rc=3；
   - `verify-dev <dev> --expect-lun N`：从 `/sys/class/block/<dev>` 的 realpath 里取
     `target0:0:<lun>`，与期望比 ⇒ 不符 rc=4；非 UFS（nvme/loop）判不出也 rc=4（**不猜**）；
   - `check-label <label> --dev <dev>`：标签、LUN、设备三者一致才算过（写前的一道闸）。
- **`scripts/slot-attr.py` 加 LUN 归属闸**：设备模式下先用 partlun 核对 LUN（默认期望 4），
   不一致**直接拒**（rc=4，并打印「加 `--allow-wrong-lun` 才能绕过」）；`--image` 离线模式不参与
   （离线件没有 LUN 上下文，靠尺寸/CRC 门）。
- **回归门**：`check-doctor` §19 增加 `partlun.py --selftest`（与槽属性自检同节），
   四类负例（未知/歧义/sysfs 解析/静态表漂移）任一破了就 FAIL。

## 判据（可复跑）

```sh
python3 scripts/partlun.py --selftest          # PASS，含「静态表 == dump 现扫（112 个标签）」
python3 scripts/partlun.py resolve boot_b      # -> 4 ；resolve nope -> rc=3
python3 scripts/partlun.py check-label boot_b --dev /dev/sde   # 设备上过；主机上 rc=4（不在 UFS 布局）
bash scripts/check-doctor.sh | tail -2         # FAIL=0
```
