# 287 — 待机资源采样器：`/sys/power/wakeup_count` 读会阻塞、`suspend_stats` 是目录

## #651 `/sys/power/wakeup_count` 一读就阻塞（把 systemd oneshot 服务永久挂住）；`/sys/power/suspend_stats` 是**目录**不是文件

- **现象（2026-11-13 实测）**：把采样器装成 `elden-resource-sample.service`（Type=oneshot）后，
  服务卡在 `cat /sys/power/wakeup_count` 上**永不返回**，TSV 里只有表头、`systemctl status` 显示
  `sh -c ... probe` 下挂着 `cat /sys/power/wakeup_count`。
- **机制**：`/sys/power/wakeup_count` 的读语义 = 「等当前 wakeup 事件计数可报告」才返回（内核为避免竞态故意阻塞读）；
  设备一直在处理 wakeup 事件时可能长时间不返回。⇒ 任何采样都必须 `timeout N cat …`，或干脆不用它。
- **同批第二个坑**：`cat /sys/power/suspend_stats` 报「是一个目录」——它是**每项一个文件**的目录
  （`success` / `fail` / `failed_*` / `last_failed_*`），旧写法按单文件 `awk '/^suspend_stats/'` 恒取空。
- **落地**：`scripts/suspend-resource-sample.sh` 已按这两条改（`timeout 2 cat wakeup_count`；`suspend_stats/success`+`/fail`），
  设备上以 `elden-resource-sample.timer`（30 min）追加到 `/var/lib/elden/suspend-resource.tsv`。
- **判据**：`systemctl is-active elden-resource-sample.service` 必须很快变 `inactive`（oneshot 完成），
  TSV 行数随周期增长；若服务长时间 `activating` 就是又踩到阻塞读。
