## #675 `qdl` 的会话生命周期：**一条 qdl 命令结束 = 设备离开 9008**；多目标必须写在同一条命令里，单独 `qdl reset` 必然报 `SAHARA: failed to read request`

**现象（2026-11-18，回滚官方 super 时）**：把 8 段 super + `vbmeta` + `vbmeta_system` 分几条 qdl 命令写，第一条写完后
设备**自己离开了 9008**（回到 fastboot 或直接复位），后续命令全部 `SAHARA: failed to read request`；
`qdl reset` 单独发也一样。最后把**全部目标塞进同一条 qdl 命令**才一次过。

**判据/口径**：

- qdl（`~/edl/qdl/build/qdl`）与 qfil 一样：**一次 Sahara/Firehose 会话内把该写的都写完**，会话结束即释放设备。
- 写多目标用一条命令：`qdl -s ufs <loader> write 0/90504 a.img write 0/... b.img …`（或直接用 `rawprogram*.xml` 批量）。
- **不要**指望「写完再 reset 再写第二个」；`qdl reset` 只在会话还活着时才有意义。
- 实测吞吐参考：8.3 GiB ≈ 3 min 24 s（41.6 MiB/s），14.5 GiB ≈ 5 min 56 s ⇒ 一条命令的超时要按体积给（`timeout -k` 至少 2× 预估）。
- 写前必备：目标 LUN + LBA 区间（4096 字节扇区）、分区存在性、区间覆盖冲突（见 #673）；写后必备：`qdl sha256 <lun>/<lba>+<n>` 与主机件比（见 #669）。

**同轮可用的两个正面事实**（省下次的时间）：

```sh
fastboot -s <SN> oem edl                     # 从 fastboot 进 EDL，实测可用
qdl -R -s ufs <loader> read 4/409595+2048 logfs.bin      # logfs 8 MiB，6 s 内可取
qdl -R -s ufs <loader> read 0/5939624+32768 pstore.bin   # pstoredump 128 MiB，6 s 内可取（本次全零）
```

`reports/edl-toolchain-survey-20261101.md`；`PITFALLS #669`（EDL 静默给错数据 / 用 `qdl sha256` 当第二把尺子）。
