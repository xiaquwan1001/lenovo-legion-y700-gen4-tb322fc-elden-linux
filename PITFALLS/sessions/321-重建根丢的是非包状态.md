# #689 重建最小根只恢复「包 + 桌面」，**非包状态**（公钥/sudo/WiFi 凭据/dconf）会静默丢 —— 症状是「ssh 不通」

## 现场（2026-11-19，11-18 wipe 后重建 minbase 根）

主机侧现象：设备 USB 已连、`lsusb` 有 `1d6b:0104 Multifunction Composite Gadget`，但 **`ssh elden` = `Permission denied (publickey,password)`**
⇒ 直觉是「设备又坏了 / 那次刷机把东西全丢了」。

实测反证（两条命令就分清）：

```
ssh elden-root 'id -un'            # → root          （一直好用）
ssh elden       'id -un; sudo -n true'   # → Permission denied
```

设备侧真因：`/home/xuqianhui1001/.ssh` **根本不存在**、该用户不在 `sudo` 组、`/etc/sudoers.d/` 只有 `README`。
即：重建时只把公钥装给了 `root`，而**文档默认入口**（`DEVICE/README.md` §1 的设备访问行、`~/.ssh/config` 的 `Host elden`）
走的是 `xuqianhui1001` ⇒ 默认入口失效、兜底入口正常。

## 判据与处置（已机械化）

- 判据不在「包是否齐」，而在接入面：`deploy-desktop-shell.sh --check` **§3b**（2026-11-19 新增）
  ① `sha256sum /home/xuqianhui1001/.ssh/authorized_keys` == 主机 `~/.ssh/id_rsa.pub`；
  ② `su -s /bin/sh xuqianhui1001 -c 'sudo -n true'` rc=0。任一不满足即 `MISS`。
- 处置（幂等）：`install -d -m700` + `install -m600 authorized_keys`（属主该用户）+
  `/etc/sudoers.d/010-xuqianhui1001` NOPASSWD + `usermod -aG sudo` + `visudo -c` 自检。
  实测修后：`ssh elden` 通、组含 `sudo`、`sudo -n true` OK。
- **同类的第二种非包状态 = WiFi 连接档**：`/etc/NetworkManager/system-connections/` 空（凭据不属包、也不许进仓）
  ⇒ 驱动/扫描全正常（`nmcli dev wifi list` 能看到 `ustcnet`/`eduroam`、`rfkill` 未封、`radio` 已启用），
  但状态栏没有 WiFi 图标，因为**没有任何已保存连接**。判据 = 该目录 `wc -l` = 0；修 = 人输凭据。
- 第三种 = 桌面用户 dconf（深浅色/IME/字体），在 `/home` 里，同在包外。

## 通则

**「镜像/包构建全绿」只保证「能起 + 有程序」，不保证「能登 + 能上网 + 界面是你要的」**。
以后每次重建根，收尾必须同时跑 `deploy-desktop-shell.sh --check`（MISS=0）**和**
`ssh elden`／`ssh elden-root` 两个别名各自验活，缺一个都不算恢复完成。
