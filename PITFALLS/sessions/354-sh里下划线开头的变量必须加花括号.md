# #721 POSIX sh 里 `$_cl` 不是「变量 _cl」——`$_` 是特殊变量，会被解析成 `${_}` + 字面 `cl`

> 2026-11-25 实测（`scripts/fix-ab-mark-successful.sh`，设备侧 `/bin/sh` = dash）。加了槽位交叉校验后
> 脚本报 `ab-mark-successful: 118: cl: parameter not set`，而上一行 `sh -x` 明明显示变量已赋值为 `b`。

## 机理

POSIX 的 `$_` 是**特殊参数**（上一条命令的最后一个参数），且不加花括号时变量名按「最长合法标识符」取——
`_` 本身是合法标识符首字符，所以 dash 里 `$_cl` = `${_}` 紧跟字面 `cl`；`_` 未设置 + `set -u`
⇒ 报错文本是 `cl: parameter not set`（把后面的字面量一起打出来，极具误导性）。
**同样的写法在 bash 里恰好正常**（bash 把它当 `_cl`），所以只在设备上炸。

## 判据

```sh
dash -c 'set -u; _cl=b; echo $_cl'      # => "cl: parameter not set"
dash -c 'set -u; _cl=b; echo ${_cl}'    # => b
bash -c 'set -u; _cl=b; echo $_cl'      # => b（bash 不报，故本机测不出来）
```

## 处置

- 下划线开头的变量**一律加花括号**：`${_cl}`、`${_s}`。
- 更稳：**不要用单个 `_` 开头的短名**，改 `_slot`/`_prev`/`_clslot` 这类多字符名（本脚本已如此）。
- 带 `set -u` 的设备侧脚本，`bash -n` / `dash -n` 全过**不代表**运行期没问题 —— 必须在设备
  （dash）上真跑一次，排障时加 `sh -x`。
