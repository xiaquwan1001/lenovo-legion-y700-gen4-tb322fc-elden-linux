# #706 安卓 a 槽「三发同现象」之后别再盲试：先拿日志通道；附恢复区「双清」作用域的实证

- 日期：2026-11-21 晚（上机 3 发，零写盘以外的写入只有 `vbmeta_a` 与 `/data` 格式化）
- 状态：已收口（按用户裁决「这条路走不通，暂不继续」）；判据可复跑

## 现象（三发逐字相同，不是巧合）

| 发次 | 单变量 | 结果（用户目视） |
|---|---|---|
| ① | 原厂 `vbmeta_a`（flags=0 ⇒ verity **on**）+ `/data` = ext4（只有 `lost+found`） | BL 警告 → 黑屏 → **安卓系统崩溃警告** → 联想 logo 一闪 → 黑屏 → Linux |
| ② | 同上 `vbmeta_a` + `/data` 换成 **f2fs 空**（`mkfs.f2fs -f`） | 完全相同 |
| ③ | 自签 `vbmeta_a`（flags=1 ⇒ verity **off**）+ `/data` f2fs 空 | 完全相同 |

每发之后设备侧现读：

```
qbootctl  → SLOT _a: Active 0 / Successful 0 / Bootable 0   ← 失败后 ABL 自动把 a 置不可启
            Current slot: _b                                 ← 回落 b，并把我方 -s a 的 active 改回
pstore    → 空 ⇒ 无内核 panic ⇒ 失败点在 kernel 之后（ramdisk / 上层）
usb 采样  → 4 min 内 /dev 上始终无 05c6/18d1 ⇒ **a 槽 Android 侧 gadget 不枚举 ⇒ adb 取证通道不存在**
```

## 判据（为什么这次可以判「别再盲试」）

- 「`vbmeta_a` 的 verity 位」与「`/data` 的 fs 类型」是两个能低成本单变量的旋钮，**都试过了、都不改变结果**；
  其余旋钮（`super` 内容、a 链缺件）都属十几分钟级写盘（S3 = 原厂 super 14.5 GiB）或需要日志才能定向。
- 而**日志通道当前不存在**：USB 不枚举 ⇒ `adb`/`ttyACM` 都拿不到；`pstore` 无 panic ⇒ 内核帮不上忙。
  在「没有日志」的前提下继续换变量盲试，每发只能得到一句「同样崩」，期望收益≈0。

## 附：恢复模式「双清」到底会动什么（本轮实证，回答「会不会误伤 Linux」）

解包原厂 `recovery_a`（`backup/official-rom-15.10.259/recovery.img`，sha `3807dd63…` = 在机值），
读 `system/etc/recovery.fstab`：

- 带 **`formattable`** 的只有两项：`/dev/block/bootdevice/by-name/metadata` → `/metadata`、
  `/dev/block/bootdevice/by-name/userdata` → `/data`。
- `system` / `vendor` / `product` / `odm` / `system_ext` / `*_dlkm`：全部 `ro` + `logical` + `slotselect`（只读挂载）。
- `boot`、`misc`：`emmc defaults`（可挂载，**非** formattable）。
- 全部 fstab 条目里**没有** `super` 物理分区、没有 `linux17`、没有 `boot_b` 的独立条目。

⇒ 「Wipe data/factory reset」作用域 = `userdata` + `metadata`；**`linux17`（Linux 根）与 `boot_b` 不会被它碰到**。
（注意：这是**原厂 recovery** 的 fstab；`backup/stock-259/recovery_a.img` 那份是 TWRP 形态（有 `twres/`），
不是本机在跑的件 —— 别拿它当判据。）

## 材料方法（复跑用）

- boot header v4（`header_size=1584`）解包：ramdisk 在 **offset 4096**，legacy LZ4 帧（magic `0x184c2102`）
  按 `[u32 size][block]` 逐块解，再 `cpio -idmu`。主机 `python-lz4` 缺 ⇒ `pip install --user --break-system-packages lz4`。
- 设备侧格式化需要 `f2fs-tools`（`apt install f2fs-tools` → `mkfs.f2fs` / `dump.f2fs`）；
  `dump.f2fs /dev/disk/by-partlabel/metadata` 能读出 `MKFS version`（本机 = Android 6.6）、features
  （`encrypt verity extra_attr project_quota quota_ino`）与 checkpoint state（= unmount ⇒ 干净）。
- 采样：`adb devices` / `fastboot devices` / `lsusb | grep -ciE '05c6|18d1'` 每 6 s 一行，共 4 min，
  落 `logs/h5-a-slot-20261121/observe.log`；三发的前置/后置态在 `logs/h5-a-slot-20261121/`。
