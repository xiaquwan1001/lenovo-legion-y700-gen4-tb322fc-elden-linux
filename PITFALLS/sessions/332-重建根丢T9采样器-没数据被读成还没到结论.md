# #700 重建根丢的是 T9 采样器（脚本 + 两枚手写 unit + `/var/lib/elden`）：「没有数据」会被读成「还没到下结论的时候」

- 日期：2026-11-21（设备在线轮次；设备 `up 9.1 h`、vk192、b 槽 Linux）
- 现象：T9（待机/唤醒资源趋势）自 2026-11-19 重建根起**一直没有数据**；本轮 `ssh` 查证 = 
  `/usr/local/sbin/suspend-resource-sample.sh` 不存在、`elden-resource-sample.{service,timer}` 不存在、
  **`/var/lib/elden/` 目录本身都没有**。而 `TASKS §4` 的 T9 行当时读起来像「在等样本攒够」。
- 判据：`deploy-desktop-shell.sh --check` 现在会打
  `MISS T9 采样器未就绪（缺件数=4，脚本 sha 设备=无 仓内=eed1d354…）`；
  手工判据 = `systemctl is-enabled/is-active elden-resource-sample.timer` + `ls -l /var/lib/elden/suspend-resource.tsv`。
- 成因：采样器**不是包**（自写 POSIX sh + 手写 unit），`apt`/`daily-baseline` 从不带它；
  11-19 的根走「minbase + deploy 脚本补桌面」，11-20 补的是音频/触觉（#698），T9 三件不在任何清单里 ⇒ 静默消失。
- 与 #689 的区别（所以要单独一条）：#689 的症状是「功能不可用」；本条的**症状是「看起来一切正常」**——
  桌面/音频/触觉全绿，只有数据缺，天然被误判成「样本不足」。
- 处置（已落地，四处）：
  1. `scripts/suspend-resource-sample.sh` 加 `tick [OUT]`（建目录 / 无表先写表头 / 追加一行），
     并修「表头用 `printf '%s'` 把 `\t` 写成字面两字节、整行不可分列」的真 bug（必须 `%b`）；
  2. `rootfs/debian/units-extra/elden-resource-sample.{service,timer}`（**手写**：render.py 无「timer 对」语义），
     `OnUnitActiveSec=30min`、`Persistent=false`；
  3. `rootfs/debian/stage.sh` **4d**：镜像构建也复制 `units-extra/*` + 建 `timers.target.wants` 软链；
  4. `scripts/deploy-desktop-shell.sh` **§12**（deploy + `--check` 四件判据）+ `check-doctor` **§22** 的四条非包资产锚点。
- 端到端证据：一次 `rtcwake -m mem -s 45` 前后各采一行，`suspend_stats` 3/0 → **4/0**、`fail` 恒 0、`uptime` 只涨 11 s。
- 通则：凡是「我们自己写的脚本/单元 + 运行时数据目录」的组合，**重建根前先问三件（脚本/单元/数据目录）在哪**，
  并把判据写进 `deploy-desktop-shell.sh --check`；否则丢掉的不是功能而是**观测能力**。
