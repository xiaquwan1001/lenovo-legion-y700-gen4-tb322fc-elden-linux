# 45 — 冷起「没有桌面」= greetd 崩；相机「出流成功」与「成像正确」是两件事

> 2026-10-18 实测（在机 vk127 / 7.3-rc7）。报告：`reports/camera-linux-vk127-20261018.md`。

## #318 冷起无桌面：`greetd` 崩了，而面板/DRM 是好的（别去查 Q28）

- 误导点：`/sys/class/drm/card0-DSI-1/status = connected`、面板 GOOD、SSH 正常 ⇒ 很像「Q28 坏发但显示驱动没报错」。
  真因：**display-manager 没起来**。
- 三行判据（按顺序）：
  ```sh
  rc-status | grep -i greet          # -> [crashed]
  loginctl list-sessions             # -> 空
  pgrep -af 'phoc|gnome-session'     # -> 空；且 ls /run/user/1000 | grep wayland 无 wayland-0
  ```
- 根因：上游 `/etc/init.d/greetd` 的 `depend()` 只有 `need localmount`，**缺 `after seatd elogind`**；
  且 `command_background=yes` 没有守护，崩了 openrc 不会重试（`rc-service greetd start` 还会回
  `WARNING: greetd has already been started / status: crashed`，必须先 `stop`）。
- 修法（已入库 `rootfs/persistent-overlay/etc-initd-greetd`，设备备份 `greetd.bak-20261018`）：
  ```sh
  supervisor=supervise-daemon
  respawn_delay_seconds=5
  respawn_max=10
  output_log=/var/log/greetd.log
  depend() { need localmount; after seatd elogind; provide display-manager; }
  ```
- 手工救场（不重启）：`setsid /usr/sbin/greetd --config /etc/greetd/config.toml &`，15 s 内 phoc+phosh 起来。
- ⚠️ 改 initd 后要 `rc-service greetd restart`；只 `start` 会被 openrc 的 crashed 状态挡住。

## #319 相机：`出流成功`（驱动级）≠ `成像正确`（画面级）——判据要分开写

- 驱动级判据（本轮 7.3 vk127 全过）：`cam -c<N> -C<帧数> --file=…` 打印
  **`seq` 连号 + 稳定 fps（30.06/30.26）+ `bytesused` = 满帧（4072×3072×4 / 3264×2448×4）**，且 `dmesg` 无
  `camss/vfe/csid/EPIPE/EINVAL`；`media-ctl -p` 里 sensor → `msm_vfe*_rdi*` 链路 ENABLED。
  ⇒ 这一层过了就**不能再写「STREAMON 失败」**（那是 2026-10-15 的 7.3 早期状态，vk127 上已不复现）。
- 画面级判据：必须**逐帧**看，而且**首帧非零会骗人**。
  - 反例（2026-10-18 实测，vk127）：`cam -c1 -C40` 帧 0 mean 15.9、**帧 1–39 全零**；只看首帧/只看「30 fps 满帧」就会误判「相机可用」。
  - 正确做法：`cam -c1 -C5 --file=x.bin` 后按 `bytesused` **逐帧**取 mean（本例 4096×3072×4 = 50 331 648 B/帧），
    再与**裸 V4L2 对照**：`v4l2-ctl -d /dev/video0 --stream-mmap --stream-count=3 --stream-to=b.raw`
    （pgAA 15 667 200 B/帧）——裸路径 3/3 帧都有数据（mean 25.6/20.5/20.7）就说明 **kernel/CSID/VFE/sensor 都好**。
  - 软件 ISP 的两个开关与 A/B：`LIBCAMERA_SOFTISP_MODE=cpu`（本例全零）与默认 EGL（本例只有首帧）；
    **换回 stock `ipa_soft_simple.so` 若现象不变 ⇒ 与自编 IPA 无关**。
  - 明亮场景 + AE 收敛仍是必要的（#303），但**不能替代逐帧判据**：本例 40 帧全是零，与场景亮不亮无关。
- 收尾纪律（Q24）：相机实验结束必须 `cam-mode.sh off` + `cam-mode.sh blank restore`；
  若 `/dev/video*` 残留，是 **wireplumber 持着 fd**（`fuser /dev/video0` 可见），
  `kill wireplumber` → `modprobe -r` 相机模块 → 节点归零 → 再把 wireplumber 拉回（`XDG_RUNTIME_DIR=/run/user/1000 setsid wireplumber`）。
  验证口径：`lsmod` 相机模块 **0**、`/dev/media*`+`/dev/video*` **0**、`cam-mode.sh blank show` 的 idle/lock 已回存档值。

## #320 libcamera `simple` + `SoftwareIsp`：只有第 0 帧被写进输出缓冲（2026-10-18，未解）

- 指纹：`cam -cN -Ck` 报 `30 fps`、`bytesused` = 满帧输出尺寸（ABGR8888），但**除帧 0 外全零**；
  `LIBCAMERA_LOG_LEVELS=*:DEBUG` 显示 `Debayer debayer_egl.cpp:446/453` **每帧都在跑**（参数 blackLevel 0.0627 / gamma 0.4545 正常）。
- 判别链（照抄即可）：裸 V4L2 对照 → `LIBCAMERA_SOFTISP_MODE=cpu` → 换 stock IPA → 换 libcamera 版本。
  本轮前三步已完成：裸 V4L2 好、cpu 模式全零、stock IPA 同现象 ⇒ 指向 `SoftwareIsp` 的**输出回写**（EGL `setOutput()` 多缓冲绑定/dmabuf→EGLImage 缓存最可疑）。
- 结论：**「出流成功」在驱动级成立，但「Linux 相机可用」不成立**；`TASKS` G1-5 已按此更正。

## #321 排查「ISP 只写第 0 帧」时，先用最小 EGL 程序排掉 Mesa/一致性 —— 三条假设的实测结论（2026-10-18）

- 最小复现器（设备侧 60 行，`/tmp/egltest.cpp`，只用 `dma_heap` + EGL + GLES2）：
  两块 dma-buf → 同一个 GL texture 依次 `eglCreateImage` + `glEGLImageTargetTexture2DOES` → 各 `glClear` 一色 →
  `glFinish` → **CPU mmap 读像素**。
- 实测（`GL_RENDERER=Adreno (TM) 830 / freedreno / Mesa 26.1.6`）：
  `buf1←red(255,0,0)`、`buf2←green(0,255,0)`、`buf1←blue(0,0,255)` **全部正确** ⇒
  ① 「同一 texture 重绑新 EGLImage 不生效」**否**；② 「GPU 写 dma-buf 后 CPU 读不到（一致性）」**否**。
- `egl.cpp` 的 `EGL_DMA_BUF_PLANE0_OFFSET_EXT, 0` 硬编码（libcamera 0.7.1 与 master 相同）在**我们的**场景无害：
  抓 `cam` 的 `/proc/<pid>/fd` 可见 **4 个独立 dma-buf**（`/dmabuf:frame-0…3`），每 buffer 一 fd、offset 全 0。
- 教训：这类「只剩首帧有数据」的问题，**先写 60 行最小 EGL 复现器**，比在 libcamera 里猜快一个数量级；
  而且要**每帧一个文件**（`cam --file='x_#.bin'`）来排除 app 侧拼接/映射疑点。
