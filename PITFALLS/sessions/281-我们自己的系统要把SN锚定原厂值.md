# #626 我们自己写的系统（Linux gadget / initramfs / UEFI…）必须把 SN 锚定原厂值，不能写死模板串

- 日期：2026-11-12
- pi 会话 id：本项目会话（11-12 晚）
- 主题：`PITFALLS #549` 的根因修复 + 用户口径「以后全部显式锚定原厂 SN」

## 问题

`rootfs/usb-gadget` 与 `initramfs/usb-gadget` 把 USB composite gadget 的 `iSerialNumber`
写死成常量 **`HA2CB1KY`**（模板值，**不是任何一台机器的 SN**）。真实 SN 由 ABL 经
`/proc/cmdline` 的 `androidboot.serialno=` 传入（本机 dt 里**没有** `serial-number` 属性）。

后果（#549 记过、2026-11-12 又踩）：同型号多台机 + 固定 `192.168.7.1` ⇒ 主机侧按
`lsusb` / `journalctl -k` 的 SerialNumber 判「是哪台 / 起没起来」**必错**；本轮据此把另一台
华为手机（`MDX5T20730009849`）当成了目标板。

## 修法（已落地，Linux 侧）

两份 gadget 脚本在写 `strings/0x409/serialnumber` 前**运行时取值**：

```
DT /proc/device-tree/serial-number  →  /proc/cmdline androidboot.serialno  →  /etc/elden-serial  →  TB322FC-unknown
```

设备侧判据：同一段取值逻辑输出 `SN=[HA2EXB0E]`（真实 SN）；`sh -n` 通过；已部署到
`/usr/local/sbin/usb-gadget`（回退件 `.bak-20261112`）。
⚠ initramfs 内的那份要**下次重建 ramdisk** 才生效（脚本已改，镜像未重打）。

## 口径（写给以后）

- **认设备的权威判据**：`fastboot getvar serialno`、内核 `/proc/cmdline` 的 `androidboot.serialno`；
   **`lsusb`/journald 的 gadget SerialNumber 永不作为身份判据**（修好之后也只能当辅助）。
- 我们在写的每个「系统」都要暴露原厂 SN：Linux gadget（已修）、initramfs gadget（脚本已改）、
   UEFI/Mu 的 SMBIOS `SerialNumber`（**未核**）、Waydroid/容器侧 `ro.serialno`（**未核**）。
- 别把 SN 写进仓库常量（会跨单元污染）；需要固定值时从设备现读。
