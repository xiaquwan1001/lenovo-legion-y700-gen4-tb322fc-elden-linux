# 122 · #459 容器相机的四个「静默」坑：bind 占位文件 / session start 身份 / `waydroid shell` 参数 / 守卫写死 uid

- **日期**：2026-10-28
- **场景**：C5/U7 容器相机（Waydroid + 主机 v4l2loopback 桥）。四个坑的共同点：**都不报错，只是静默不生效**。

## 坑 1：主机节点缺失时，LXC 的 `create=file` bind 会造一个 **0 字节普通文件**

```
容器内:  ---------- 1 root root 0 /dev/video100          ← regular file，mode 000
主机上:  crw-rw----+ 1 root video 81, 49 /dev/video100   ← 之后才 modprobe 出来的 char dev
```

`waydroid` 的 LXC 配置里是 `lxc.mount.entry = /dev/video100 dev/video100 none bind,create=file,optional 0 0`。
**容器启动时源不存在** ⇒ 容器里留下一个空占位文件；之后再 `modprobe v4l2loopback` 也不会自愈。
表现 = `dumpsys media.camera | grep Number` 永远是 **0**，但没有任何报错。

**正路**：先让主机节点就位（`modprobe v4l2loopback video_nr=100 max_buffers=8 exclusive_caps=1`），**再重启容器**。
判据 = 容器内 `ls -l /dev/video100` 必须是 `crw` 开头。

## 坑 2：`waydroid session start` 必须以**会话用户**跑，否则把 Session 打成 STOPPED

root 直接跑会：
```
WAYLAND_DISPLAY is not set, defaulting to "wayland-0"
Wayland socket '/run/user/0/wayland-0' doesn't exist …
```
然后 `waydroid status` = `Session: STOPPED`（可用 `setprop`/容器仍在，容易误判"没坏"）。

**正路**（后台常驻，ssh 退出不带走）：
```sh
setsid nohup runuser -u <user> -- env XDG_RUNTIME_DIR=/run/user/<uid> WAYLAND_DISPLAY=wayland-0 \
    DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/<uid>/bus waydroid session start &
```

## 坑 3：`waydroid shell` 传不了 `sh -c`（argparse 抢 `-c`）

```
waydroid shell sh -c "ls -l /dev/video100"
→ waydroid: error: unrecognized arguments: -c ls -l /dev/video100
```
`waydroid shell` 把参数直接交给 `lxc-attach`，子命令的 `-c` 被 waydroid 自己的 argparse 吃掉。
**正路**：直接用 lxc-attach：
```sh
lxc-attach -P /var/lib/waydroid/lxc -n waydroid -e -- /system/bin/sh -c "<cmd>"
```
（`-e` 保留环境；加 `--clear-env` 反而会让 `-e PATH=…` 这类写法被当成可执行文件而报
`Failed to exec "PATH=/system/bin:…"`。）

## 坑 4：守卫脚本把「会话用户 uid」和「提权工具」写死 ⇒ 静默空操作

`scripts/cam-mode.sh` 里写死 `pgrep -u 1000`、`/run/user/1000`、`sudo -u <user>`：
- Alpine 根是 `uid 1000/xuqianhui`，**Debian 根是 `uid 1001/xuqianhui1001`**；
- **Debian 根没有 `sudo`**（`command not found`）。

两者叠加的结果：`find_bus` 永远空 → `GS()` 里的 `gsettings` 一次都没跑过，而它把 stderr 吞掉、只留 stdout 最后一个字段
⇒ `cam-mode.sh status` 打印 `idle-delay = `（空）却仍报 CAM-ON/CAM-OFF，**blank 守卫等于不存在**。

**纪律**：任何"以会话用户执行"的封装都要
① 现查 uid（`loginctl list-sessions --no-legend | awk '$4=="seat0"'` + `id -u`）；
② 现查提权工具（`sudo` → `runuser` → **都没有就报错**）；
③ 判据回读真值（修后 `idle-delay = uint32 300`）。

## 附：本轮 C5/U7 的真卡点（换了人）
