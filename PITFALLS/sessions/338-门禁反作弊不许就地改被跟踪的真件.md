# #705 门禁「反作弊自检」不许就地改被 git 跟踪的真件：`trap` 兜不住 SIGKILL，门会自己制造假 FAIL

- 日期：2026-11-21（主机侧，零上机）
- 状态：已修并实测（改前/改后各一轮，含 SIGKILL 打断）

## 现象

`check-doctor` §24（`scripts/doctor/24-scripts-index.sh`，2026-11-20 立的 scripts 索引新鲜度门）在
反作弊 ①「改坏 README 头的结构指纹 ⇒ `--check` 必须 rc≠0」里 **`sed -i` 就地改 `scripts/README.md`**，
再靠 `mv -f "$_bak" "$README"` 还原、并把 `_bak` 清空交给 `trap` 兜底。

本轮实测后果（两次独立复现）：

| 观测 | 值 |
|---|---|
| 一次全量 `check-doctor`（外层带 `timeout -k 10 400`）后 | `git status` 多出 `M scripts/README.md`，首行停在 `结构指纹 fp=d34b0000`（= sed 改坏的形态） |
| 紧接下一轮 `check-doctor` | **FAIL=2**：`反作弊②收尾失败：撤掉探针后 --check 仍 rc=1（有残留）` + `scripts/README.md 过期` |
| 手工 `git checkout -- scripts/README.md` 后 | `--check` rc=0 ⇒ 真件本来没问题，FAIL 完全是门自己造的 |
| 直接 `timeout -k 0 1.0 bash scripts/doctor/24-scripts-index.sh` | rc=124/137，真件停留在 `fp=d34b0000` |

## 根因（两条，都成立）

- **还原点被自己消耗**：① 用 `mv -f "$_bak" "$README"; _bak=""` —— 还原的同时把备份删了；
  此后任何中断（`trap` 已无从还原，因为 `_bak` 空）。原实现的 `trap cleanup EXIT INT TERM`
  只有在「备份还在」时才有意义。
- **POSIX shell 的 `trap` 不打断前台子进程**：`timeout 60 python3 …` 在跑时收到 TERM，bash
  要等子进程返回才执行 trap；外层若带 `-k`（TERM 后再 KILL）或用户双击 Ctrl-C，**trap 根本不跑**
  ⇒ 被 `sed` 改过的真件永久留在盘上。所以「靠 trap 兜底」在这个形状里从一开始就不成立。

## 判据（怎么证明修好了，可复跑）

```
# ① 正常路径
bash scripts/doctor/24-scripts-index.sh        # 四行全 [ok]，退出 0
git status --short scripts/README.md           # 空（真件未被触碰）

# ② 打断路径（关键判据：真件必须仍然干净）
timeout -k 0 1.0 bash scripts/doctor/24-scripts-index.sh ; head -1 scripts/README.md | cut -c1-40
#   期望：fp=d34ba3c9…（正确值），而不是 fp=d34b0000
ls scripts/zz-doctor-probe.sh                  # 不存在；即便残留，下一轮开头无条件 rm

# ③ 副本口径自证（门用的就是这条）
cp scripts/README.md /tmp/probe-copy.md
sed -i 's/fp=\([0-9a-f]\{4\}\)[0-9a-f]*/fp=\10000/' /tmp/probe-copy.md
python3 scripts/gen-scripts-index.py --check --readme /tmp/probe-copy.md   # rc=1（门有效）
```

## 处置

- `scripts/gen-scripts-index.py` 新增 `--readme PATH`（默认 `scripts/README.md`，输出仍走 `rel()` 相对路径）。
- `24-scripts-index.sh` 反作弊 ① 改成**在 `mktemp -d` 副本上**改坏指纹、`--check --readme <副本>`：
  真件**全程只读**；临时目录与探针仍在 `trap` 里清，但即使 `trap` 不跑，残留也只是 `/tmp` 目录
  和一个**未跟踪**的 `zz-doctor-probe.sh`（本轮开头先 `rm -f`），不会再污染被跟踪文件。
- 顺带修掉实测暴露的第二个坑：`--check` 原本把「未追上引用计数」写成固定文案，改成 `rel(out_md)` 后
  曾把绝对路径打进 `OK` 行 ⇒ 已统一用 `rel()`。

## 通则（写给以后写门的人）

- **门禁的自检绝不允许就地改被 git 跟踪的文件**。「先备份 + trap 还原」在能被 `SIGKILL` 打断的
  环境里是假保证；正确形状 = 在副本/临时树上制造反例。
- 门的失败信息要能区分「真件坏了」与「门自己上次没收尾」：本轮 FAIL=2 的文案与真过期**完全同形**，
  第一眼会误判成文档过期 ⇒ 值是 `fp=xxxx0000` 这种「前 4 位保留 + 补 0」的形态，见到就直接
  `git checkout -- scripts/README.md`。
