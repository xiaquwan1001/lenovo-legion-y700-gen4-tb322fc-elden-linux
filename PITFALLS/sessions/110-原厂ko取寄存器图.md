# 110 · 原厂 `.ko` 未 strip ⇒ 寄存器表可直接从 `.data` 取出对账

> 2026-10-27（M4 camss 取证）。**#446**

## 现象

要判断「我们写的 CSIPHY 2.4.0 lane 表 / 状态块偏移是不是厂商原值」，第一反应是找厂商源码或文档——
本地 `stock-src/` 的 GPL drop **不含 techpack/camera**，`dsi.xml` 只描述部分位域 ⇒ 一度只能"猜 + 上机试"。

## 判据：厂商 vendor_dlkm 里的 `camera.ko` 是 **not stripped**

```sh
readelf -sW backup/stock-elden/vendor_dlkm/camera.ko | grep -E "csiphy_.*_v2_4_0|csiphy_v2_4_0"
#   a3d6c 1648 OBJECT  csiphy_2ph_v2_4_0_reg        ← lane 表：103 条 × 16 B
#   a4a4c 1152 OBJECT  csiphy_3ph_v2_4_0_reg        ← 3ph 变体（地址体系不同）
#   aab48   80 OBJECT  csiphy_v2_4_0                ← 每代参数（含状态块偏移 0x1138）
readelf -SW camera.ko | grep '\.data '              # 0x25fab8  ⇒ 符号地址 + 该偏移 = 文件偏移
```

- lane 表条目布局 = `{reg_addr, reg_data, reg_mask, param_type}`（各 4 B，与上游 `struct csiphy_lane_regs` 同形）；
- 参数结构里 `[ver+4]=0x1138`（= `0x1000 + 0x138`，common status 块）、`[ver+8]=0x1058`（mipi status），
  用法由 `cam_csiphy_common_status_reg_dump` 反汇编确认（`ldp w24,w10,[x25,#4]` → `add x27,x23,x24` → 12×`cam_io_r`）。
- **对账方法**：把两边表都化成 `(addr, data)` 多重集比较。实测 99/103 相同，
  4 条差异全是 SKEW_CAL 的 `0x5c` 偏移（我们 `0x54`、厂商 `0x00`），
  再扫完全部 **82 张** `csiphy_*` 表确认**没有任何一张含 `0x54`** ⇒ 该值是**我方偏离**，不是搬错。

## 可复用结论

① **先查 `backup/stock-elden/vendor_dlkm/*.ko` 是否 not stripped**：是则 `readelf -s` 拿符号、按 `.data` 文件偏移切、
   按已知结构体形状解码，比反汇编整段代码或猜快一个数量级；
② **"厂商一致" ≠ "上机验证"**：数据段一致只证明我们抄对了，运行期仍要单独取证（本例 `0x138` 只走错误上报路径，
   正常出流不经过）；
③ 差异要**反查全表**再定性（"82 张表里没有" 才能说"是我方偏离"），只看单张会误判成抄错。
