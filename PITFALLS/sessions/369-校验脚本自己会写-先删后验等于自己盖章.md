# #736 「校验」脚本自己会写/删 —— `--check` 必须只读，否则门在给自己盖章

**现场（2026-11-26 21:4x，T12 会话归档 gzip 轮）**：跑 `python3 scripts/gen-sessions.py --check`
想确认 171 篇 `SESSIONS/sessions/*.md` 与快照表一致，结果它**先把目录清空再重写**：

```
os.makedirs(SDIR, exist_ok=True)
for f in glob.glob(os.path.join(SDIR, '*.md')):
    os.remove(f)          # ← 清空
...
for r in rows:            # ← 重写 171 篇
    with open(os.path.join(SDIR, r['file']), 'w') as fh: ...
...
if '--check' in sys.argv: # ← 守卫在最后
    sys.exit(_check())
```

两个后果，第二个更危险：

- **① 内容被刷新**：模板里 `session_search` 已改成 `scripts/sess.sh`、`当日提交 N 条` 全刷成 **0**
   （那一步的 git log 取数失败于本轮无关原因）⇒ `git status` 出现 171 个 M。
- **② 校验对象被换成自己刚写的内容**：`_check()` 拿新写的文件去对源块，**必然 PASS**
   —— 这是「门在给自己盖章」，比没有门更糟。

**我修它的过程中还踩了一步**：只把写循环用 `_CHECK_ONLY` 跳过、漏了前面的 `os.remove` 循环
⇒ `--check` 变成「只删不写」，171 篇全变 `D`（`git checkout -- SESSIONS/` 恢复）。

**判据 / 处置**：

- 任何带 `--check` 的工具，先 `grep -n 'open(.*[\"'\'']w\|os.remove\|shutil.move\|os.replace'` 看写操作在不在守卫之前；
  有写操作就说明 `--check` 是「先改再验」，它的 PASS 不可信。
- 修法 = 在**第一个**写/删语句之前置 `_CHECK_ONLY = '--check' in sys.argv`，并让所有写/删分支 `if not _CHECK_ONLY`。
- 自证：跑完 `--check` 后 `git status --porcelain <被检查目录>` 必须为**空**（本次实测 0 行）。
- 同族（2026-11-26 同日修的三处）：`scripts/gen-scripts-index.py --check` 与 `scripts/reports-index.py --check`
  本来就是只读的，可作为对照范式。
