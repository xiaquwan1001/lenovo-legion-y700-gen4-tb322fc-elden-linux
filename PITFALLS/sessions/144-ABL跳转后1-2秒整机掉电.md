# #480 · ABL 跳转后 ~1–2 s 整机掉电（自旋/BRK 都掉）—— 异类载荷的观测窗口只有 1–2 s

- 日期：2026-11-01（上机实测，零写盘）

## 事实

两个**自写对照臂**（都只有 80 B，不含任何 UEFI 代码）：

- `shim-brk` = `brk #1`（同步异常）
- `shim-spin` = `b .`（纯自旋，无异常、无 MMIO）

**两臂表现完全相同**：`fastboot boot` → 0.05 s 内 `usb_read failed`（ABL 已跳）→ **用户目视「过联想 logo 立刻掉电，然后重启回落 Android」**，
USB 采样在 ~3 s 消失。⇒ 掉电**不是**载荷崩溃/异常造成的，而是 ABL 交棒后系统层的固定行为
（候选：ABL 跳转前 arm 的 PMIC/SoC boot watchdog，Linux 靠 `qcom_wdt`/SCM 早喂；Mu UEFI 没喂）。

## 推论（对 UEFI 线）

- 任何「屏上标记/串口打点」方案必须在**跳转后 1–2 s 内可见**，否则永远看不到 —— 这比「写 FB 会致命」更能解释
  J1（屏上出字）长期为 0。
- 想让窗口变长，第一候选动作 = **在 PrePi 最早期 pet/disable boot watchdog**（不是先改显示代码）。
- 复现方法：`reports/artifacts/uefi-rb-20261031/abortshims/{shim-brk,shim-spin}-v0.img` + `scripts/uefi-boot-trial.sh`。
