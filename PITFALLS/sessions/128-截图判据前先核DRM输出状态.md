# #464 「起没起窗口」的判据之前，先核 DRM 输出状态（G3/Steam 截图假阴性）

## 结论（2026-10-28，G3 Steam lane 设备实测）

Steam 确实到了登录界面（`SetLoginState: WaitingForCredentials - OK` ×3 轮、
`steamwebhelper` 恒 7 进程存活 130–301 s、CPU 38%→5.1%、0 SIGSEGV、
X 窗口树有 `"Sign in to Steam" 700x440`），但**截图判据 5/5 全失败**，原因不在 Steam：

- `/sys/class/drm/card0-DSI-1/enabled = disabled`、`dpms = Off` ⇒ `grim` 报
  **`no supported format found`**（`grim -o DSI-1` 同错），**不是** wlroots 截屏协议的问题。
- 旁路也全断：嵌套 weston 的 `wl-g3` 报 `compositor doesn't support the screen capture protocol`；
  `weston-screenshooter` 直接挂死；**设备根本没装 `xwd`**（`which xwd` 空 ⇒ 上轮 0 字节 `x.xwd` 的真因，
  不是「窗口不存在」）。
- 会话用户名是 **`xuqianhui1001`**（不是 `xuqianhui`），gdbus 调 ScreenSaver 唤醒时要带对
  `--address=unix:path=/run/user/1001/bus`（`--session` 与 `--address` 互斥，混用无效）。

## 定式

取证前先做三步前置检查，任一不满足就先把输出点亮，别去怀疑 App/合成器：

```sh
cat /sys/class/drm/card0-DSI-1/{status,enabled,dpms}    # enabled/enabled + dpms=On 才截得到
which grim xwd                                          # 设备端工具是否真的在
loginctl list-sessions --no-legend                      # 会话用户名/uid（Debian 根上是 <name><uid>）
```

## 附带（同轮已修）

- `cam-mode.sh` 与 `waydroid-cam-restart.sh` 写死 uid/`sudo`（Debian 根无 `sudo`）⇒ 相关守卫会静默空操作。
- `pkill -f "http.server 8080"` 会匹配到发起命令的 shell 自身 ⇒ 远程会话自杀（退出 255）；改用 `pgrep -af "http[.]server"`（见技能 `pkill-self-match`）。
