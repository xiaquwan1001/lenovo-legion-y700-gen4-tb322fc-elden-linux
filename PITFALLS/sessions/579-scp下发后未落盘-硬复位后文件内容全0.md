# #740 · `scp` 下发的文件若在**硬复位前没落盘**，复位后「尺寸不变、内容全 0」——看起来像"程序跑不起来"

- 日期：2026-11-27（`#692` 上机轮，连续踩到）
- 现象（实测）：`scp /tmp/hexagonrpcd-v elden-root:/usr/local/bin/` 之后**没 `sync`** 就跑了会触发整机硬复位的试验；
  复位回来后该文件**仍是 68912 字节**，但 `sha256sum` 与源不同、`file` 报 `data`、整份内容 `00`。
  直接执行的两种表现：① `bash: … 无法执行二进制文件：可执行文件格式错误`；② 静默 `rc=0` 什么都不打印（转人工查了半天）。
  `cat /usr/local/bin/<f> | cmp - <源文件>` 在第 1 字节就 DIFFER；`xxd` 头 64 字节全 0。
- 成因：ext4 延迟分配 + 硬复位/掉电 ⇒ 数据块未回写，只有 inode 尺寸落盘；内核随后给出全 0 内容（与 `PITFALLS` 里
  「DDR 内容不跨复位」是两件事，这里是**磁盘侧**没落盘）。
- 判据（照抄可用）：
  ```sh
  scp X elden-root:/usr/local/bin/ && ssh elden-root 'sync; sleep 1; sha256sum /usr/local/bin/X'
  # 本地 sha256sum X 必须一致；不一致就重发，不要"试着跑一下看看"
  ```
  - 只要**预期下一发会复位**（`-s`、ADSP stop、kexec、UEFI 试验…），下发后**必须 `sync`**；
  - 二进制"跑不起来但没有任何报错"时，先 `file <bin>` + `sha256sum`，再怀疑程序逻辑。
- 关联：`#737`（ADSP 复位）、`reports/sensors-692-file-root-20261127.md`（本轮全账）。
