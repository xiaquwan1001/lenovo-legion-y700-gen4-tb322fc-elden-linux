### 2.2 唯一需要本地适配的地方（不是冲突，是**缺一个上游已有符号**）

系列第 11 贴直接调用 `iris_vb2_signal_eos(inst)`，该 helper 是**另一个上游提交**引入的（本系列 11 贴里没有它的定义，`grep` 全文仅出现 2 次 = 调用 + 说明），我方树也没有 ⇒ 编译报 `implicit declaration of iris_vb2_signal_eos`。按上游语义本地补（4 行，与 `iris_vb2_buf_queue()` 里原有内联代码逐字等价）：

```c
void iris_vb2_signal_eos(struct iris_inst *inst)
{
	const struct v4l2_event eos = { .type = V4L2_EVENT_EOS };

	if (!v4l2_m2m_has_stopped(inst->m2m_ctx)) {
		v4l2_event_queue_fh(&inst->fh, &eos);
		v4l2_m2m_mark_stopped(inst->m2m_ctx);
	}
}
```

配套：`iris_vb2.h` 加声明、`iris_buffer.c` 加 `#include "iris_vb2.h"`，并把 `iris_vb2_buf_queue()` 里原内联块改为调用该 helper（保持单一实现）。

> 说明：`v4l2_m2m_clear_state` / `v4l2_m2m_has_stopped` / `v4l2_m2m_mark_stopped` 在本树是 **header 内 static inline**（`System.map`/`Module.symvers` 都查不到），所以不需要连 `v4l2-mem2mem` 一起重编 —— 任务书里「必要时连 `v4l2-mem2mem`」这条**不成立**，本树只编 `qcom-iris.ko` 就够。

## 3. 根因层更正（推翻 §静态判读的主因表述）

`reports/iris-decode-static-20261127.md` 的「`:393` 判 `LAST` 不判 `PSC_LAST` ⇒ 零尺寸 PSC_LAST 被误标 ERROR」**只是症状位置，不是修复点** —— 本轮 backport 后该行**仍然只判 `LAST`**（`git diff` 里它没被改）。真正的修复来自系列 09/10 引入的 `early_capture` / `drc_unsignalled` 分支：

- 驱动 CAPTURE 先 STREAMON（FFmpeg 就这德行）且首个 settings change **分辨率未变** ⇒ `iris_vdec_first_src_change_unchanged()` 置 `drc_unsignalled = true`、**不发 SOURCE_CHANGE**；
- 固件随后给的零尺寸 `PSC_LAST` 命中 `drc_unsignalled` 分支 ⇒ 走 `iris_vdec_src_change_complete()` + **把同一个 buffer 重新入队**（`iris_queue_buffer()`），根本不进「零尺寸 ⇒ ERROR」那条判断；
- 11 贴再补「带 ERROR 的 LAST 也要记 `last_buffer_dequeued`」，避免客户端再排capture 时冒出第二个假 LAST。

写法建议：后续引用根因时写「**首帧前 early-capture 的 DRC 未 signaling 路径**」，不要再写「`:393` 少判 PSC_LAST」当结论（该行在修复后依旧如此）。

## 4. T26 收口：开机不自动加载的真因是**我们自己**

排查顺序与判据（全部在设备上跑）：

| 步 | 命令 | 结果 |
|---|---|---|
| 1 | `cat /sys/bus/platform/devices/aa00000.video-codec/modalias` | `of:Nvideo-codecT(null)Cqcom,sm8750-iris`（正常） |
| 2 | `grep sm8750-iris /lib/modules/$(uname -r)/modules.alias` | 有两条 alias，含不带 `C*` 的那条 ⇒ **alias 覆盖没问题** |
| 3 | `udevadm test /sys/bus/platform/devices/aa00000.video-codec` | 确实排了 `RUN{builtin}=kmod load` |
| 4 | `modprobe -R 'of:Nvideo-codecT(null)Cqcom,sm8750-iris'` | 解析出 **`qcom_iris`** ⇒ kmod/索引都正常 |
| 5 | `modprobe 'of:Nvideo-codecT(null)Cqcom,sm8750-iris'` | **rc=0 但模块没加载** ⇒ 一定是「被 blacklist 掉」的那种静默跳过 |
| 6 | `modprobe -c \| grep -i iris` | **`blacklist qcom_iris`** ← 元凶 |

元凶文件：`/etc/modprobe.d/elden-blacklist-iris.conf`（内容 2 行，注释写着「2026-11-27 实验保险丝：iris 节点 enable 的 DT 上机时先不自动加载驱动」，来自 `reports/drivers-build-iris-20261127.md` 的实验 2 —— 那次失败其实是根 label fallback，与 iris 无关）。

处置：**改名为 `elden-blacklist-iris.conf.disabled`**（`modprobe.d` 只读 `*.conf`；留档不删，便于复查）。然后：

- `udevadm trigger --action=add --sysname-match=aa00000.video-codec` ⇒ 模块立刻加载，`/dev/video17` 权限从 `crw-------` 变成 **`crw-rw----+`（root:video + uaccess ACL）** ⇒ **普通用户可直接用硬件解码**（Moonlight/ffmpeg 不再需要 root）。
- `systemctl reboot` 冷启 ⇒ `lsmod | grep -c qcom_iris` 命中、节点自动出现、解码照常 ✅。

**判据满足**：T26 的「冷启后自动加载 + `/dev/video17` 直接可用」成立；且证明**不是** udev 缺陷、**不需要** `modules-load.d`（任务书要求「不要用 modules-load.d 掩盖」—— 本轮从头到尾没加任何 modules-load 配置）。
