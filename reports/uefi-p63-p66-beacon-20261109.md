**`logfs-beacon-p66.bin` 是短读、不是别的分区**（2026-11-10 复核更正）：它 8 355 840 B = 少尾 32 KiB（**记录区整个缺失**）⇒
作为 p66 的证据**作废**；但它**不是**「读到了 FAT12 分区」—— 本机 logfs 本身就是 vfat（正常 dump 在偏移 3 同样是 `MSDOS5.0`），
且该文件前 4096 B 与基准 logfs **逐字节相同**（同卷序列号）⇒ 是 ssh/dd 传输中断。
纪律：`dd` 后必须校验 `stat -c%s == 8388608`，不符立即重试；分析前先 `cmp` `0x7FC000` 头块确认读的是 logfs 本尊；
取件一律 `/dev/disk/by-partlabel/logfs` + 内容指纹 `SBLOG0` 自检（现状 `by-partlabel/logfs → sde68`，8 MiB ✓，无跨启动漂移证据）。

## 3. 「0 命中」不等于「没跑」

`logfs-run3.bin` 里 `esp in v=R64` 与 `pi n=` 都是 0 命中，但**同一次读到的镜像里 `[K] esp fs=1`/`[K] esp none` 在**——
原因是那两行来自更早的启动（记录区不是只增环形，尾部窗口只有 1 条）。所以：

- 判「补丁在不在执行的这份件里」→ 用 `scripts/uefi-fv-strings.py` 在 **FD 内层 FV** 里搜字串（本轮四个世代全命中：
  `esp in v=R64` / `pi n=` / `R66STG st=%d tag=%a` / `R67 blk=%d fs=%d`，p66 有 81 个补丁）；
- 判「这一发跑到哪」→ 只有**带世代/计数**的信标或**屏上 `Stall` 停留**能答（见 §4）。

## 4. 下发建议（下一发怎么设计，全部主机侧可完成）

1. **`p67` = 「一个明确的基线」 + `R66 v3` + `R67`**，信标改成**每 boot 唯一 nonce + 累积轨迹**：
   静态缓冲先读 `0x7FD000` 块，头部不是 `R66LOG` 就清零并写 `R66LOG boot=<nonce>`（nonce 取 DXE 期可用的
   `GetPerformanceCounter()` 或 `gRT->GetTime()` 微秒低 32 位），之后每个 stage **追加** `st=<n> tag=<t>` 再整块重写 ⇒
   一块里就是「本 boot 的唯一标识 + 完整轨迹」，残留歧义消失（这是复核给出的具体改法，见 `reports/beacon-recheck-20261110.md` §下发建议）。
   **同时修 stage 语义**：把 `st=8` 移进 `if (!Found)` 内（或改名 `tail`），并在 `LoadImage` 成功后加 `st=9 esp-ld-ok` ——
   「成功/回退」从此可判（本次复核已证明 `fallback` 标签在无条件位置，误导了两个会话）。
2. **屏上 `Stall` 是最便宜的硬判据**：R67 已实现 `[K] R67 blk=N fs=M` + 停 10 s；下一发上机时**只需人看屏**记两个数字
   （`N`/`M` 为 0 ⇒ 分区层没出来；`N>0 M=0` ⇒ FAT 没绑；`M>0` ⇒ ESP 在，问题在加载）。
   取值口径：`blk=N` = 第一次枚举（`[K] esp blk=`）的 `BlockIo` 句柄数（R67 用 `BlkCount` 存下来），
   `fs=M` = 紧接着第二次枚举（`SimpleFileSystem`）得到的卷数；两行都打不出来 ⇒ 崩在 `esp blk=` 之前。
3. **flashed 形态的对照件必须是 `p60`**（已证明 fastboot 形态可用）—— 本轮它同样失败，所以后续不要再把
   flashed 失败归因到某个新补丁上，除非对照件通过。
4. 若 `N/M` 都是 0：直接搬第三方 `StorageConnect.c`（`reference/retro98boy-y700-addon/`：非可发现 UFS 设备逐 LUN `ScsiIo` 连接 +
   `UFSDxe` 排到 `QRKSDxe` 之后），而不是继续在 BdsDxe 里加探针。
