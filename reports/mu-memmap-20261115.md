### 1.2 内存图的唯一真源（改哪一行）

| 项 | 事实 |
|---|---|
| 文件 | `Platforms/PakalaPkg/Device/lenovo-y700g4/Library/PlatformMemoryMapLib/PlatformMemoryMapLib.c` |
| 注入点 | `Platforms/PakalaPkg/Pakala.dsc:86` → `PlatformMemoryMapLib\|$(PACKAGE_NAME)/Device/$(TARGET_DEVICE)/Library/PlatformMemoryMapLib/PlatformMemoryMapLib.inf` |
| 表结构 | `ARM_MEMORY_REGION_DESCRIPTOR_EX gDeviceMemoryDescriptorEx[]`，字段 = `{Name, Address, Length, HobOption, ResourceAttribute, ResourceType(不显式用), MemoryType, ArmAttributes}`，`{"Terminator",0,…}` 收尾 |
| 消费方 | `Platforms/AndromedaPkg/MemoryInitPei/MemoryInitPeiLib.c:82` `GetPlatformMemoryMap()` → `AddHob()`：`HobOption==AddMem` ⇒ `BuildResourceDescriptorHob(ResourceType, ResourceAttribute, Address, Length)` + `BuildMemoryAllocationHob(Address, Length, MemoryType)`；同时 `InitMmu(MemoryTable)` 用 `ArmAttributes` 建恒等映射 |
| 条目上限 | `MAX_ARM_MEMORY_REGION_DESCRIPTOR_COUNT = 128`（`Platforms/AndromedaPkg/Include/Library/PlatformMemoryMapLib.h:14`）；本平台现有 44 条 ⇒ 加 1 条安全 |
| 现状缺口 | `DXE Heap 0xB90C0000 + 0x1D500000 = 0xD65C0000`，下一条是 `Display Reserved 0xFC800000` ⇒ **`0xD65C0000`–`0xFC800000`（0x26240000 B = 610.25 MiB）在表里根本没有条目**，因此不进 GCD、不进 EFI 内存图 |

⇒ **改法 = 在 `DXE Heap` 行之后插一行 `AddMem/SYS_MEM/SYS_MEM_CAP/Conv/WRITE_BACK_XN`**，与 pc2/R74 完全一致
（`Conv` 而非 `Reserv`：`Reserv` 只会让内核看到「不可用」，救不了 initrd；`Conv` 才让 `AllocatePages` 有地方可交付）。

### 1.3 AllocatePages / 内存图 插桩点

| 项 | 事实 |
|---|---|
| `AllocatePages` 真身 | `MU_BASECORE/MdeModulePkg/Core/Dxe/Mem/Page.c:1835 CoreAllocatePages()` → `CoreInternalAllocatePages()`；成功分支里已有 `CoreUpdateProfile()` 等收尾动作 ⇒ 插桩挂在这个成功分支 |
| 打印设施 | 现成的：pc1 配方第 10 条补丁（`patches/uefi/20261104-dxe/0001-dxemain-screen-serial-step-marks.patch`）**已经**给 `DxeMain.inf` 加了 `SerialPortLib` 类，并在 `DxeMain.c` 里定义全局 `SbMark(CHAR8 *Tag)`（tag ≤ 8 字符 + `\n\r`，走 `SerialPortWrite`）。dsc 侧 `SerialPortLib` 全局映射到 `Platforms/AndromedaPkg/Library/FrameBufferSerialPortLib`（屏上输出）⇒ **`Page.c` 里只需要 `#include <Library/SerialPortLib.h>`**，无需再改 INF |
| `DEBUG()` 不能用 | RELEASE 构建把 `DEBUG((...))` 整段编译掉（同类 前科：`patches/uefi/20261104-dxe/0001` 头部注释），所以插桩必须直接 `SerialPortWrite` |
| 初始化时序 | `DxeMain.c` 入口第一句就是 `SerialPortInitialize(); SbMark("[D00]")` ⇒ 任何 `AllocatePages` 发生时 `m_Initialized` 已 TRUE，不会触发 R21 的惰性初始化路径（那条路径要 `gST`） |
| 内存图判据行 | `Page.c:2527 CoreTerminateMemoryMap()`（= `ExitBootServices` 的最后一道关）里**已经**在遍历 `gMemoryMap` 做构造规则校验 ⇒ 在同一次遍历里顺便统计 Conv 总量，一行打出「内核将看到的 Conv 有多少 MiB」，这是判断 610 MiB 有没有真进图的最直接证据 |
| 日志量控制 | 分配行只在 `NumberOfPages >= 0x100`（1 MiB）时打印；内存图行只在 EBS 打一次 |

### 1.4 本轮与 pc1 的配方差异（两条）

1. **+ R74**（`patches/uefi/20261110R74-memmap-appsfree/0001-memmap-appsfree-conv.patch`，pc2 用过的原件，未改一字）：`Apps Free 0xD65C0000 + 0x26240000 Conv`。
2. **+ R75**（本轮新增 `patches/uefi/20261115R75-apm-trace/0001-dxecore-alloc-trace.patch`）：`Page.c` 里 `AllocatePages` 大块成功时打 `[A] t=… b=… p=…`，EBS 时打 `[M] ebs desc=… conv=…`。
3. **− R71**（`pc1` 的屏上静默）：R71 让 `SerialPortWrite` **不画帧缓冲**，本轮插桩的判读通道正是屏 ⇒ 这一代**必须**把屏显开回来（等同 p69 的通道形态）。代价 = 恢复 R2 的每字符忙等，启动变慢（p69 实测同形态 ~55 s 到 GRUB）；收益 = 不需要 SSH / 落盘就能读到插桩。**回退 = pc1 件**。

## 2. 实现（两处改动，逐行见 `out/mu-memmap-20261115/diff/changes.md`）

| # | 补丁 | 文件 | 位置（原文件行号） | 内容 |
|---|---|---|---|---|
| 1 | `patches/uefi/20261110R74-memmap-appsfree/0001-memmap-appsfree-conv.patch`（**pc2 原件，未改一字**） | `Platforms/PakalaPkg/Device/lenovo-y700g4/Library/PlatformMemoryMapLib/PlatformMemoryMapLib.c` | 34（`DXE Heap`）之后 | `{ "Apps Free", 0xD65C0000, 0x26240000, AddMem, SYS_MEM, SYS_MEM_CAP, Conv, WRITE_BACK_XN }` |
| 2 | `patches/uefi/20261115R75-apm-trace/0001-dxecore-alloc-trace.patch`（**本轮新增**） | `MU_BASECORE/MdeModulePkg/Core/Dxe/Mem/Page.c` | 12 之后 / `CoreAllocatePages` 成功分支 / `CoreTerminateMemoryMap` | `[A]` 大块分配行 + `[M]` EBS 内存图行 |

* 补丁文件本身是本轮唯一新增资产；配方 `patches/uefi/pc1m-recipe.txt` = pc1 配方 **−R71 +R74 +R75**，80 条 patch。
* 源树**没有**被永久改动：`uefi-build-variant.sh` 构建结束 `reset_tree` 还原，本轮结束后
  `git -C build/uefi-woa-prep/repos/7-mu-lenovo status --short` 只剩三条**开工前就有**的脏项
  （`m Common/MU_TIANO` 与两个 `.orig-mu` 未跟踪件）。
* `external/ext-repos/mu` 全程只读未动（它也不能构建本机，见 §1.1）。

### 2.1 为了屏上读得到的取舍：这一代**去掉 R71**

R71 让 `SerialPortWrite` 只进 `SbLogPut` 环形日志、**不画帧缓冲**。本代的判据是「上机一眼/一张照片看到 `[A]`/`[M]`」，
而落盘通道（logfs）要先能进系统才能读 —— 崩溃时就读不到。所以这一代把屏显开回来（≡ p69 的通道形态），
代价 = 恢复 R2 的每字符忙等（~1–3 ms/字符），启动时间预期回到 p69 量级（~55 s 到 GRUB 菜单）。
**这是唯一的「非最小」改动**，且是「取证换速度」，不是功能改动。

### 2.2 日志量控制（用户要求「别炸开」）

* `[A]` 行只在 `NumberOfPages >= 0x100`（**1 MiB**）时打 ⇒ 池/小缓冲一律不打；本平台启动期命中量级 = 个位数行。
* `[M]` 行只在 `ExitBootServices` 那一次打（且 GRUB 重试时最多重复几次）。
* 逻辑上只在 `CoreAllocatePages` 的**成功**分支、`CoreTerminateMemoryMap` 的 **MapKey 匹配**分支 ⇒ 不改变任何语义，
  异常路径也读不到半截输出。

```sh

```

**屏上应看到什么（按时间序）**：

1. 与 pc1 不同：**屏上重新开始刷 `[K]/[L]/[E]` 标记**（R71 已去；这是本代的取证通道，不是 bug）。
2. DXE 起来后陆续出现若干 `[A] t=… b=… p=…`（≥1 MiB 的分配）。GRUB 装载阶段应至少出现两条大块：
   `p=004000`（64 MiB initrd = 16 384 页）与 `p=00f000`（63 MB `/boot/Image` ≈ 15 750 页）。
3. GRUB `ExitBootServices` 前出现一行 `[M] ebs desc=… convMB=… allMB=…`。

**怎么判读（三条互不依赖）**：

| 观察 | 结论 |
|---|---|
| `[M] … convMB=` 比 pc1 同口径多 **≈ 0x262**（610 MiB）、`desc` +1 | **R74 生效**：610 MiB 真的以 Conventional 进了内核将看到的那张图 |
| `p=004000` 那行的 `b=` 落在 `0xd65c0000`–`0xfc800000` | 大块（initrd）**确实吃到了新增窗口** ⇒ 「内存图太小」这一支被正面证实 |
| `b=` 落在 `0xb90c0000`–`0xd65c0000`（老 DXE Heap 469 MiB 内）且内核仍起不来 | 新增窗口没被用上/不够，或病根不在容量 ⇒ 转向「交付页被复用」，需要用**同一件**的 `[A]` 基址 + 内核 oops 对照判 |
| 一行 `[A]` 都没有 | GRUB 用的是 <1 MiB 的分段分配（LoadFile2 逐块）⇒ 降阈值（`SB_APM_MIN_PAGES 0x100` → `0x10`）重打一发，别急着下结论 |
| 掉电/只剩背光（pc2 先例 §7） | 与本改动同一改动面 ⇒ 记为「内存图改动在 GRUB 路径上仍不安全」，回到 pc1 件继续别的方向 |

判读通道 = **屏**（可拍照/录像；这一代屏显有 R2 的每字符忙等，字会一行行慢慢出，属预期）。
若系统仍能起来，额外取证：`ssh elden-root 'cat /var/log/pstore/…'`（`pstore-catch` 归档）与 `/efi/loader.log`。

**失败怎么回退**：

```sh
fastboot boot out/r21-sbstop-pc1/uefi-preamblec1-r1.img     # 回已知可用件（零写盘）
```

* 本件**没有**改 boot_a/b、没有改 ESP、没有改槽位 ⇒ 最坏情况是 `fastboot boot` 后复位，ABL 会按现有槽位正常起回系统；
* 若 110 s 内没回系统且设备离线：物理长按电源 → 正常进 `boot_b`（**不需要** EDL，不写任何分区）；
* 不要在同一发里既换本件又改 ESP 上的 `BOOTAA64.EFI`（`PITFALLS #664`：ESP 满导致 install 半成功、跑的还是旧 EFI）。

* **未上机、未 flash、未动设备**；`build/daily`、`build/m3v2-7.3rc7`、`out/r21-sbstop-pc1/` 内的既有件均未改（只读了 pc1 件作 repack 基座）。
* 与 pc2 的差别只在**可观测性**：pc2 = R74 + R71（屏静默），本代 = R74 + R75 − R71（屏可读）。所以本代若出现「只剩背光→掉电」，
  也不能把上机结果与 pc2 直接等号，需按「有 `[A]` 行 / 无 `[A]` 行」分开判。
* 插桩的成本：`[A]` 每次调 `SerialPortWrite` 4 次（32 hex 字符）+ `SbApmHex`，全部走既有库，**不分配内存、不碰 gBS**
  ⇒ 在 `AllocatePages` 里调用不会递归（这是选 `SerialPortWrite` 而不是 `AllocatePool + AsciiSPrint` 的原因）。
* 6 位十六进制页数上限 = 0xFFFFFF 页 = 64 GiB，`convMB/allMB` 6 位 = 64 TiB，本机（12/16 GiB）远未触顶。
* 若下一发要「只验内存图、不掺分配打印」，把配方里 R75 那一行注释掉即可（`pc1m-recipe.txt` 的注释里已写）。
