## 1. 构建侧：所谓「内核二进制差」是什么

同一 `linux` 树（HEAD `d02658e63` clean）、同 config（`a383cdb9`）、同工具链
（`gcc 15.2.0-16ubuntu1` / `ld 2.46`），只改版本标签/构建号造镜像：

| 对比对 | 字节差 | `.rodata` 平移 | `.text` 差异 |
|---|---|---|---|
| `q28a` vs `q28aa`（仅 LOCALVERSION 长度差 1） | **466 B** | 无 | 1 个 word |
| Oct-8 `vk64` vs 新编 `q28a` | **19,861 B** | 无 | 少量 |
| Oct-8 `vk64` vs `vk64c`（22:20 构建） | **5,040,884 B** | **+4 字节**（区间 94.72% 满足 `b[i]==a[i-4]`） | 26 个 word |
| `q28a` vs `vk64c` | 5,060,451 B | +4 字节 | — |
| `vk64c` vs `vk64c` 复现（同版本号/时间戳重编） | 20,877 B | 无 | — |

- **`.text` 只有 26 个 word 不同，且全是 ADD/LDR 的立即数地址偏移**（Δ+1/+4/+12 B），**无一条指令语义改变**。
- **平移源头**：`linux_banner` 里的 `UTS_VERSION`（`#7`/`#92` + 时间戳）长度变化 → 8 字节对齐 padding 变化
  → 其后整段 `.rodata`（约 6 MB）整体平移 4 字节。
- ⇒ 所谓「8% 二进制差」是**构建元数据（版本串/构建号/时间戳）造成的布局平移假象**，不是功能代码分歧。
- 佐证：`q28a`/`q28aa` 只差 466 B 且不平移；Oct-8 `vk64` 与新编 `q28a` 只差 19,861 B 且不平移 ⇒ **Oct-8 内核可复现**。

复现命令（主机侧，无需设备）见 `reports/q28-binary-determinism-provenance-20261010.md` §8。

## 2. 设备侧：同路径同镜像即非确定

台架：`fastboot boot`（零写盘），判据 = `scripts/q28-devprobe.sh` 三态 + SSH 读 `card0`。
`reboot2` 暖复位通道**不可用**：STORM 态下 `reboot2 bootloader` 无效（无 fastboot），只能物理断电。

| 镜像（内核载荷） | 结果（按时间） | 说明 |
|---|---|---|
| `out/boot-elden-vk64.img`（Oct-8 `8efb2731`，旧 `/init`） | **STORM**（风暴 4→47）**存活 ≥226 s** | 与日常 boot_b 同一文件 |
| `boot-q28-oct8.img`（同内核 + 今天 ramdisk） | **GOOD(hang) → STORM → STORM → GOOD(hang) → STORM** | **同一镜像同路径非确定** |
| `boot-q28-oct8-ram.img`（同内核，RAM-only，无磁盘根/无桌面） | **HANG**（150 s 无 SSH，USB gadget 消失） | hang 与「桌面」无关 |
| `boot-q28-a.img`（`q28a`，与 oct8 仅差 19,861 B） | NOCARD ×4 | |
| `boot-q28-aa.img`（`q28aa`） | NOCARD ×3 | |
| `boot-q28-vk64c-repro.img`（`vk64c`） | NOCARD ×3 | |

**核心规律**：
- `storm=0` 的**干净 GOOD → 数秒内整机冻死**（disk-root ×2 + RAM-only ×1，**3/3**）。
- `storm>0` 的 STORM → **存活**（4/4）；NOCARD → 存活。
- ⇒ 「有 card0」**不等于**「能用」；`card0` 二元判据必须废除，改为
  **三态 + 存活门（GOOD 需 ≥60 s 存活/可交互）**。

## 3. 对原逆转台账的复核

- 原报告判据是**二值**（`card0` 在 = GOOD），**无法区分** 干净 GOOD / STORM / GOOD→HANG。
- 原「21 发」只有 **7 发**有仓库内原始日志；其余为口头观测且 `.img` 已删。
- 原台账里的 `GOOD×7` 因此是**混合态**：既可能含「STORM 存活」，也可能含「亮一下就死」。
  **不能一概说它们都是 hang**（有 storm-alive 存活反例，且当时循环靠 `reboot2` 连续进行），
  但**该标签不可用于任何结论**。

## 4. 结论（写入 SSOT）

1. **逆转说法（按内核二进制确定性）不成立**：同镜像同路径同晚即 GOOD/STORM 互现。
2. **构建侧「二进制差」= 版本串/构建号造成的 `.rodata` 平移**，功能代码实质相同。
3. **GOOD 判据加存活门**；`storm=0` 干净 GOOD 会 hang（与 #106 同签名的整机冻结）。
4. **`reboot2` 暖复位不可当 A/B 台架**（STORM 态下失效）。
5. 下一步：`storm=0 → hang` 的存活门统计；并尝试去掉 `console=tty0` 让 fbcon 不触发 modeset，
   看能否得到**免卡死**通道（否则每发 clean-GOOD 都要物理恢复）。
