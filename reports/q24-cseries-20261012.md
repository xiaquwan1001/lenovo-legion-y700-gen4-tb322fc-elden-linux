## 0. 一句话

Q28 **GOOD** 台架（面板真的 prepared、`l1=0 l2=0 storm=0`），**一次冷起内按序**做完三步：**C0（cam=0）blank→hold 60 s→wake 存活 +89 s**；**C1（`{camcc}`）blank→hold 60 s→wake 存活 +89 s**；**C2（`{camcc,cambist}`）熄屏后 ≤5 s 静默硬复位**（串口**无 panic/Oops/watchdog**，末票 `mmcx.lvl=2 / cx.lvl=5`）。⇒ 触发 = **配对 + 真实熄屏**；**`{camcc}` 单模块单独不致死**（在干净配对基线上首次确认）。

## 3. C2 死亡现场（决定性）

**串口**（`serial.log`，`grep -nE 'panic|Oops|BUG|watchdog|Unable to handle|Internal error'` = **0 行**）：
```
[ 202.215650][ T53] novatek-nvt36xxx-spi spi0.0: firmware version 1a.01 …   ← C1 唤醒后的面板重准备（正常）
[ 242.247801][ T5333] power_supply qcom-battmgr-usb: driver failed to report `online' property: -110
===== serial closed 11:36:08 =====                                        ← 无 panic，直接消失
```
**RPMh trace 最后一帧**：
```
phoc-1503  237.322322  mmcx.lvl (0x30080) = 0x2
phoc-1503  237.322347  cx.lvl   (0x30000) = 0x5
phoc-1503  237.322376  NoC/MC0 (0x50000…) 批
            → trace 静止 = 死亡
```
⇒ 与历史 `PITFALLS #173`「`mxc.lvl→0` 后硬复位」**同为静默硬复位**，但本台架 `mxc` 稳态本就 `off-0`、全程无 `mxc` 票 ⇒ **`mxc→0` 不是必要条件**（它是「本台架该轨原本为 0」的巧合，与 `#197` 同理）。

## 4. 与上一轮（L1FAIL 台架）的差异 —— **台架状态会移动「致死点」**

| 台架 | 面板 | 熄屏后 | 死亡点 |
|---|---|---|---|
| `q24-s123b`（11:07） | L1FAIL（从未 init） | **+11 s 仍存活** | **唤醒**（末票 `gfx=1/gmxc=1` GPU 上电） |
| **本轮 `cseries1`（11:32）** | **GOOD**（prepared） | **≤5 s** | **熄屏本身**（末票 `mmcx/cx` 降档） |

⇒ 结论：**触发集合 = `{camcc,cambist}` + 显示电源转换**；具体死在哪一步受台架显示栈状态影响。**取证必须 blank/hold/wake 三段分离**（`PITFALLS #201`/#204）。

## 5. 结论与边界

1. **确证（本轮新增、最干净的一次）**：配对在位 + 真熄屏 ⇒ 静默硬复位；`{camcc}` 单独 + 真熄屏 ⇒ 存活（在同一 GOOD 台架、同一加载顺序、同一硬门下）。
2. **与历史口径一致**：`{camcc,cambist}` 配对是触发集；「`{camcc}` 单独致死」的**唯一**反例（11:07 前的第 1 轮）来自「完整栈装载后卸载」的污染状态，本轮不重复。
3. **边界**：每相位 N=1；C2 死亡点落在熄屏（说明「配对 + 熄屏」在 GOOD 台架上是即时的）。
