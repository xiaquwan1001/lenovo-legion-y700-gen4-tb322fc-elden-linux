## §1 ★ 先纠正我自己上一轮的错判（重要）

上一轮的去重报告写成「**aw86927 的波形装载已被上游半路占据**，10-13 的结论两周就过时」。
**这是错的**，实际情况：

1. **上游的驱动内正弦表早就在了**，不是 linux-next 新加的：`aw86927_waveform[]` +
   `sram_waveform_header` + `aw86927_ram_init()` 由 **`df53055c540f`「Input: aw86927 - add support for
   Awinic AW86938」** 引入，**7.3-rc7（`24a19b953`）里就有**（`grep -c aw86927_waveform` = 3）。
   U4 报告写的「上游**无固件装载路径**」一直是对的 —— 它是「没有**固件**装载」，不是「没有波形装载」。
   我把这两个句子读成了同一个意思。
2. **`0003`/`0005` 套不上的真因不是功能冲突**，而是：
   - linux-next 相对 7.3-rc7 在这个文件上**只漂移 1 行**：新增 `#include <linux/interrupt.h>`，
     正好落在 `0003` 第一个 hunk 的上下文里 ⇒ `git apply` 严格匹配失败；
   - `0005` 的上下文包含 `0003` 新增的行（`u32 waveform_index;` 等）⇒ 系列内依赖，**本来就该最后才套**。
3. 所以「必须重构」的理由**不成立**（改成 3 行 include 就能套）。**重构的理由换成了另一条、
   而且更站得住**：把「替换上游内置正弦表为厂商固件」当第一炮打，是**最容易被否的一块**
   （要额外论证板级波形、DT 属性、校验格式），应当**先交无争议部分**。

**教训（已入 `PITFALLS` #449）**：① 读「没有 X」要连谓语读——「没有固件装载」≠「没有波形装载」；
② `git apply` 失败先看**失败 hunk 的行号与上下文**再归因，include 块漂移会伪装成功能冲突；
③ 去重核对仍要做（binding 404 / apply 检查），但**归因要分层**。

## §2 v1 → v2 的切除与重切

| 动作 | 内容 | 理由 |

| 删除 | `0003` 固件波形装载（+128 行、`select FW_LOADER`、`firmware-name` / `awinic,ram-waveform-index` 两个 DT 属性） | 替换上游内置正弦表属设计变更，需要独立 RFC；先交能被无条件接受的部分 |

| 保留 | AW8693X 寄存器布局（auto-boost / BST mode / VBAT / 两步 stop） | 与固件无关，且顺带修真 bug |
| 保留 | suspend/resume/shutdown | 与固件无关 |
