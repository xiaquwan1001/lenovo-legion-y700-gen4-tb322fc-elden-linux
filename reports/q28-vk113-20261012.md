## 1. 构造方法与单变量保证

现役日常 `vk94` 的结构（见 `out/boot-elden-vk94.manifest`）：内核 = Oct-8 的 `Image-vk64.gz`（`8efb2731`，源码 `d02658e63`）+ `geekidos-linux` 的 ADSP DTB（`5d658a2c`）+ 完整 ramdisk（`35823240`）+ 无相机 cmdline。

`vk113-dailyid` **只换内核**，其余三项取自 vk94 **原始镜像解包**（脚本逐步断言 sha）：

| 维度 | vk94（现役日常） | vk113-dailyid（候选日常） |
|---|---|---|
| 内核源码 | `d02658e63` | `d02658e63`（worktree `/tmp/dailyid`，detach） |
| .config | a383cdb9（`LOCALVERSION_AUTO=y`；= 由 vk64 内核 ikconfig 复验一致） | a383cdb9 → 仅把 `LOCALVERSION_AUTO=y` 改 `n` + 显式 `LOCALVERSION=-vk64-gd02658e63cf6`（PINUTS；只影响版本串） |
| 构建身份 | `#60 SMP PREEMPT Thu Oct  8 17:06:14 CST 2026`（**2 位**） | `#121 SMP PREEMPT Mon Oct 12 18:00:00 CST 2026`（**3 位**） |
| UTS release | `7.2.0-debug-vk64-gd02658e63cf6` | **逐字相同**（⇒ `/lib/modules/<KV>` 模块 vermagic 不变，无需重装模块） |
| ramdisk | `35823240…` | **同一文件**（vk94 镜像内解包） |
| DTB | `5d658a2c…`（含 ADSP non-secure-domain） | **同一文件** |
| cmdline | `… elden_root=LABEL=linux17 androidboot.slot_suffix=_b elden_nocamera=1` | **逐字相同** |
| 内核载荷 | `8efb2731…` | `834258c9…`（布局差异，见 §3） |

复现命令：

```bash
bash scripts/q28-build-daily-id.sh out/boot-elden-vk94.img vk113-dailyid
# 全新编译（丢弃 worktree）：WT_FRESH=1 bash scripts/q28-build-daily-id.sh out/boot-elden-vk94.img vk113-dailyid
```

脚本内置硬门（任一不过即 exit ≠ 0）：基准 DTB/ramdisk sha 断言 → worktree HEAD 断言 → 源 config = a383cdb9 → `CONFIG_ARCH_QCOM`/`CONFIG_DRM_MSM`/`CONFIG_DRM_MSM_DSI` 锚点 → `System.map` 符号（`gcc_sm8750`/`msm_dsi_host_bonded_cmd_trigger`/`qcom_rpmh`）→ UTS release 串比对 → **构建号必须 3 位** → 打包后解包复验 DTB/ramdisk 逐字节同 + 镜像 ≤ 96 MiB。

## 3. 证据：与 vk94 的内核载荷差异“只在布局”

对两镜像解包内核载荷（各 62 540 288 B，长度相同）逐字节比较：

- 差异字节总数 **5 129 077（8.20%）**，>=1 KiB 的连续差异段 157 个。
- **差异区间 [26.3 MiB, 41.0 MiB]** 与零星 >44 MiB 少量（44–50 MiB 266 B、58–60 MiB 59 B）；
  **0–26 MiB 与 42–44 MiB 零差异**（`.text` 与绝大多数驱动代码在此区间）。
- 分块直方图（每 2 MiB）：26–28 MiB 88 K；34–36 MiB 813 K；**36–38 MiB 2.04 M**；38–40 MiB 1.24 M；40–42 MiB 950 K。
- 该区间内容是绝对地址指针表与高熵串区（属链接/重定位与 `.rodata` 串布局），与 `#171/#195` 描述的「构建身份 → `.rodata` 平移」同机理。

结论（可复核）：vk113 与 vk94 的差异属**布局/重定位级**，不是代码、config、DT 或用户态改动；唯一受控变量即构建身份。

## 4. 副产物：vk94 载荷里存在**两份互不相同**的 UTS 串（→ `PITFALLS #216`）

解压 `vk94` 内核载荷并列出全部 `Linux version` 串：

| 偏移 | 内容 |
|---|---|
| 27 525 320 | `… ) # SMP PREEMPT `（**构建号与时间戳为空**） |
| 36 922 712 | `… ) #60 SMP PREEMPT Thu Oct  8 17:06:14 CST 2026` |
| 45 862 456 | `Linux version %s (%s)`（`linux_proc_banner` 模板） |

设备侧证据（`uname -v` / dmesg 第 2 行）用的都是**第二份**（`#60 …`），例如：
`logs/q28-cold-20261012-072449-q28storm-D2/dmesg.txt:2`、`logs/q28-forensics-20261010-125030/02-dmesg.txt:2`、`logs/q24-noc2-20261012-131918/s0-env.txt:1`。

含义：① Oct-8 那次构建的两个生成头（`init/utsversion-tmp.h` / `include/generated/utsversion.h`）不同步（陈旧态）；
② 「2 位 vs 3 位」判据应以设备可见的那份为准 —— `reports/q28-storm-bias-audit-20261011.md` §7.2 的口径**成立**；
③ vk113 由**干净 worktree + 固定身份**构建，两份串**逐字一致**（均为 `#121 …`），不再有该陈旧风险。

## 6. 诚实边界

1. **这是「构建身份」治法，不是机理修复**：`#195` 的证据是 `#60` 臂 4 坏/2 好 vs 3 位臂 0 坏/12+（Fisher p≈0.005，n 小）。vk113 = **1 个新身份**，其 GOOD 只能由 §5 的冷起验证证明；**不得**在验证前把 Q28 记为「已解决」。
2. **3 位 `#N` 与「rodata 布局」之间是相关性**（`#171/#175/#192/#195` 同族现象）；本报告 §3 给出的是「差异只在布局区」的**支持性**证据，不是因果证明。
3. vk113 的 config 树内 sha（`af8a2d69`）≠ 好档原件（a383cdb9），差 `LOCALVERSION_AUTO` 一行 —— 与 vk104（同一模式，已验证 GOOD）一致，不影响功能。
4. 本次**未**改动：根文件系统、`/lib/modules/<KV>`、相机运营口径（相机 ⇄ 熄屏互斥）、Q24 任何结论。
