## 1. 实现（`patches-userland/waydroid-sensord-udp/`）

复用上游 `waydroid-sensors`（GPL-3.0）的 **gbinder 注册与 HIDL 分发**，只把数据源从 sensorfw 换成 UDP：

| 文件 | 来源 | 说明 |
|---|---|---|
| `service.cpp` | 上游**未改** | `gbinder_servicemanager_new2(argv[1],"hidl","hidl")` + `add local object` + 全 HIDL 方法分发 |
| `Sensors.cpp` / `Sensors.h` | 上游**未改** | `getSensorsList`（含 `SENSOR_FLAG_DATA_INJECTION`）、`activate`、`poll`（`g_main_loop_run` 阻塞直到事件，**上游设计行为**，非自编 HAL 的无限 `condition_variable`） |
| `hybrisbindertypes.h` | 上游未改 | `sensor_t`/`sensors_event_t`/`SENSOR_TYPE_*`/`SENSOR_FLAG_*` |
| `SensorFW.h`/`.cpp` | **自写** | 同名类同签名（故 `Sensors.*`/`service.cpp` 零改动）；内部起 UDP 线程监听 `0.0.0.0:52012`，解析 `acc/gyr/mag/light/prox` 文本行 → 存值 + 回调 `sensor_event_cb` |
| `Makefile` | 自写 | `pkg-config glib-2.0 gio-2.0 libglibutil libgbinder`；无 cmake/Qt/sensorfw |

**关键点**：`service.cpp` 的 `main()` 取 `argv[1]` 作 binder 设备；Waydroid 的 `container_manager.py:170-172` 在 `which("waydroid-sensord")` 命中时**自动用 `/dev/hwbinder` 拉起它**（并 `images.py:154` 因此不再设 `waydroid.stub_sensors_hal`）⇒ **安装即自成服务，无需 OpenRC unit、无需手工起**。

## 3.5 真值数据源（SSC → UDP 中继）

`patches-userland/waydroid-sensord-udp/ssc-udp-relay.py`（+ `.openrc` 服务 `ssc-udp-relay`）：
每传感器一条 `ssccli --sensor <s> --timeout 3600` 流（accelerometer/gyroscope/magnetometer/light/proximity），
正则翻译成协议行发 `udp://127.0.0.1:52012`。实机验证（单 daemon 下）：

```
宿主 ssccli（真值）                   容器 dumpsys（消费端）
X=-3.007117 Y=0.076614 Z=9.169792  ->  -3.01, 0.08, 9.17   (wall 实时)
```

**踩坑（本会话）**：若同时存在**两个** `waydroid-sensord`（例如既写了 OpenRC unit 又让 Waydroid 自动拉起），
两者都用 `SO_REUSEADDR` 绑 52012，内核把 UDP 报文**分流**到其中一个 ⇒ 另一个收不到事件、看起来“HAL 不工作”。
**正解 = 只留一个**：Waydroid `container_manager.py` 自动拉起的那一个，daemon **不要**额外写 OpenRC unit。

## 7. 与其它路线的关系

- 路线 A（上游 sensorfw）：`waydroid-sensord` 依赖 `com.nokia.SensorService`，本机 Alpine sensorfw 无 SSC adaptor ⇒ 确定性不可用（`PITFALLS #188`）。
- 路线 B（自编 HIDL service 进 `/vendor`）：会让容器卡 boot（`PITFALLS #185`），已弃。
- **路线 C（本方案）= 上游注册设计 + 宿主数据源**：不碰 `/vendor`、不引 Qt/sensorfw，已端到端打通。
