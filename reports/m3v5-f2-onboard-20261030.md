## §1 本轮改动（1 行语义）

`build/m3v5-fix/drivers/usb/typec/ucsi/ucsi.c:1860`：

```c
con->usb_role_sw = fwnode_usb_role_switch_get(cap->fwnode);
if (IS_ERR(con->usb_role_sw)) {
        ret = dev_err_probe(ucsi->dev, PTR_ERR(con->usb_role_sw), ...);
-       con->usb_role_sw = NULL;          /* ← 删除：把 defer 降级成"这个连接器没有 switch" */
        goto out_put;
}
```

`out_put` 会 `ucsi_unregister_port(con)` 再把 `con->usb_role_sw` 置 NULL，两者对 `ERR_PTR` 都安全
（`usb_role_switch_set_role()` / `usb_role_switch_put()` 均 `IS_ERR_OR_NULL` 早退）。

**F3 不需要**（静态结论）：`ucsi_register()` 只读版本并排队 `ucsi->work`，真正的连接器注册在
`ucsi_init()`；而 `ucsi_init_work()` 本就有 `-EPROBE_DEFER` 重试环（`UCSI_ROLE_SWITCH_INTERVAL` = 100 ms，
`UCSI_ROLE_SWITCH_WAIT_COUNT` = 100 次 ⇒ ~10 s 窗口）。F2 上抛后，重试由既有机制承担，无需改 `ucsi_glink.c`。

## §2 构建与部署（命令级）

```
# 树：build/m3v5-fix（= m1-73 24223e44ad + M3-1 v4/v5 + A–J/F1 + 本轮 F2），.config 取自 build/m3v5-daily
env LOCALVERSION= make -C build/m3v5-fix -j22 Image.gz dtbs   # 0 warning / 0 error
env LOCALVERSION= make -C build/m3v5-fix -j22 modules         # 0 warning / 0 error
KDIR=build/m3v5-fix LOCALVERSION= VERSION=m3v5-f2 \
  RAMDISK=$PWD/out/initramfs-full-elden.cpio.gz \
  CMDLINE_EXTRA="elden_early_gadget=1 elden_q28_nowd" SLOT_SUFFIX=_b \
  bash scripts/build-boot.sh                                  # assert 全绿 + manifest
bash scripts/flash-b.sh out/boot-elden-m3v5-f2.img --reboot
```

- **UTS 的 `+` 陷阱（既有坑，`PITFALLS #468`）**：`CONFIG_LOCALVERSION` 已内嵌完整版本串；`scripts/setlocalversion`
  在 `LOCALVERSION` 环境变量**未设置**时会给脏树追加 `+` ⇒ UTS 变成 `…-debug-vk172+`，设备
  `/lib/modules/…-debug-vk172` 就匹配不上（`#468` 已记：多一个 `+` ⇒ 模块全丢 ⇒ 无 USB）。**构建必须 `LOCALVERSION=`（空但已设置）**。
- 模块必须一起部署：`CONFIG_USB_DWC3=m` / `CONFIG_TYPEC_UCSI=m` ⇒ F1（`usb-roles`，`=y`，在 Image 里）与
  F2/A–J（在 `.ko` 里）分居两处，只刷 Image 不换模块等于没测。
- 备份：设备 `/root/m3modbak-20261030/`（4 个原件）；回退 = 拷回 + `depmod -a` + 刷回
  `bootslot-b/boot_b-vk181-daily-signed-20261029.img`。

**判读**：
1. 两个 mux role switch 仍在（M3-1 v4 已成立的 per-connector 注册）。
2. `waiting_for_supplier` 在**刷写前后同名存在、读值都是 0** ⇒ 该属性**不能**当绑定信号（此前报告把它当信号的判读继续作废）。
3. **本轮唯一的判据** = 端口注册成功 + `PPM init` 0 条：F2 把任何获取失败变成「中止注册」，
   而端口确实注册完（还有 partner），所以获取必然成功。这一条**不再依赖** `connector` 软链（DT 平台永不创建）或 `role` 属性（mux switch 刻意不暴露）。
4. 仍未证明：**功能仲裁**（拔插时角色谁赢、port-select 是否切、充电是否按 §1.4 让位）。

## §5 拔插实测（用户换边两次，2026-10-30 13:26–13:35）——**绑定已闭环**

设备侧布点：`function_graph` + `set_graph_function=usb_role_switch_set_role`，插拔后统计：

```
usb_role_switch_set_role                   12 次（全部进入我们写的 mux 回调）
dwc3_mux_role_set [dwc3]                   12
dwc3_qcom_set_role_notifier [dwc3_qcom]    12
dwc3_qcom_vbus_override_enable [dwc3_qcom] 12
dwc3_set_mode [dwc3]                       12
```

典型调用链（trace 原文）：

```
usb_role_switch_set_role() {
  mutex_lock();
  dwc3_mux_role_set [dwc3]() {
    usb_role_switch_get_drvdata();
    mutex_lock(); _raw_spin_lock_irqsave(); _raw_spin_unlock_irqrestore();
    dwc3_qcom_set_role_notifier [dwc3_qcom]() {
      __pm_runtime_resume();
      dwc3_qcom_vbus_override_enable [dwc3_qcom]();
      __pm_runtime_idle();
    }
    dwc3_set_mode [dwc3]() { queue_work_on(); }
  }
  dev_uevent(); netlink_broadcast();    ← sw->role 已更新后发 KOBJ_CHANGE
}
```

**判据达成**：
- **UCSI → 我们的 mux switch 绑定成立**：到达 `dwc3_mux_role_set` 必需 `con->usb_role_sw` 非 NULL，且该回调只由 mux 形状的 `desc.set` 提供。
- **A–J 胶水路径也跑通**：`pre_set_role` → `dwc3_qcom_set_role_notifier` → `dwc3_qcom_vbus_override_enable`，**无自死锁**（12/12 完整返回，锁序符合 A 项设计）。
- **无异常后果**：`WARNING/Call trace/BUG/lockdep` = 0；设备全程 SSH 可达（USB 数据未丢）、电池 `Charging`。

**尚缺（仲裁明细）**：函数图不带参数，无法区分「哪个连接器 + 什么角色」；12 次里也**没有任何一次进入 HOST**（`dwc3_host_init` = 0、dmesg 无新 `xhci` 总线）。已按 arm64 语法布好带参 kprobe 并挂持久日志：

```
p:usbrole usb_role_switch_set_role sw=$arg1 role=$arg2  → trace_pipe
持续写入 /root/usbrole.log（setsid nohup，已实测存活）
```

下一次任何插拔都会自动记录 `sw` 指针与 `role`（0=NONE/1=DEVICE/2=HOST），据此直接判「oldest-wins」与每口角色；**不需要再专门安排一轮**。
