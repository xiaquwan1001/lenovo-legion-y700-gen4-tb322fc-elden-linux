## 2. 时间基线自愈（D1-④ / Q28 dossier T1）

### 2.1 问题与现态

- 硬件 RTC 断电归零且**不可写**：DOSSIER §t t-0 实测 RTC=1970-01-08；`hwclock -w` → `RTC_SET_TIME` 拒绝。冷启时钟停在假值 ⇒ TLS 全歪、journal 时间戳大面积失真（§t：watchdog 170 行里 162 行假钟）。
- 设备已愈一半：2026-11-16 手工装 fake-hwclock（load.service + save.timer enabled，§t t-2 T1「已执行」）。**但它不在任何基线表** ⇒ 重建根回归；构建器 chroot 实查：`dpkg status` 无 fake-hwclock、`/var/lib/fake-hwclock` 不存在。〔实测〕
- chrony 在两端都有且 enabled（chroot `/etc/systemd/system/chronyd.service` 别名 + multi-user.target.wants 链接；`chrony.conf` 默认 `makestep 1 3`，1970→now 属步进范围）。〔静态〕

### 2.2 既有配置为何不够（逐条）

1. **fake-hwclock 不进基线**：设备上的装法是一次性手工动作，pkgmap/apt-list/daily-baseline.tsv 均无 ⇒ 重建即丢。→ 本轮进 `daily-baseline.tsv`（P0，sid 索引实查 0.15 可解析，已并入 apt-list 151 包）。
2. **无 systemd 原生自愈闭环**：网络 UP 之后没有任何件「确保 NTP 开着 + 等 NTPSynchronized + 失败可见」。chronyd 自身 enabled 能覆盖「有网」场景，但 (a) 无网冷启时假钟无界持续（DOSSIER 实证）；(b) 失败不可见（chronyd 起了 ≠ 同步了，PITFALLS #573 同族教训：unit success ≠ 实际效果）；(c) 离线巡检无法判「现在到底同步没有」。
3. **time-sync.service（Alpine 期件，services.tsv:37）不接 Debian 渲染链**：构建 chroot 无该 unit、无 wants 链接（实查 /etc/systemd/system 全列）；其 chronyd -q 抢钟 + HTTP Date 兜底逻辑与本件**互补不重复**（HTTP 兜底仍归它，本件不做）。
4. **全仓查重**：`grep -rn "timesync\|set-ntp" packaging/ rootfs/ scripts/` 仅命中 time-sync.sh 家族（chronyd -q 一次性步进）、deps.tsv `time-daemon` 行、pstore-catch/init 的无关 mountpoint 行 ⇒ **无既有 systemd 原生件，不重复造件成立**。〔实测〕

### 2.3 新件与判据事实

- `rootfs/debian/units-extra/elden-time-baseline.service`：`Type=oneshot`，`Wants/After=network-online.target chrony.service`，`ConditionPathExists=/usr/sbin/chronyd`，`TimeoutStartSec=300`，`WantedBy=multi-user.target`。
- `scripts/elden-time-baseline.sh`（POSIX sh，dash/busybox 双解析器过）：
  - **run**：`timedatectl set-ntp true`（失败兜底 `systemctl enable --now chrony.service`）→ 轮询 `NTPSynchronized=yes` ≤180 s → 超时 **exit 1**（单元进 `systemctl --failed`，失败可见，不静默吞）；非 systemd 根直接退出 0（交给 openrc 期 time-sync.sh 家族）。
  - **--check [--root DIR]**：chrony 在 / NTP 入口 enable / fake-hwclock 在 / 启动入口 enable / 保存机制（cron.hourly 或 save.timer，缺→warn）/ 自愈单元在位+enable / （本地 root 时）NTPSynchronized 实时值（warn 级，容忍离线巡检）。
- 判据事实（为什么 `set-ntp true` 在本根成立）：
  - Debian chrony 4.9-2 提供 `/usr/lib/systemd/ntp-units.d/50-chrony.list` = `chrony.service`（chroot 实读）；
  - systemd 262.1-1 的 `systemd-timedated` strings 含 `context_parse_ntp_services_from_disk` + `/usr/lib/systemd/ntp-units.d` ⇒ 第三方 NTP 经此发现（不依赖旧的编译期单元名表）；〔静态〕
  - `NTPSynchronized=yes`：本机（systemd 259 + chrony 4.8 active、系统无 timesyncd、无 `/run/systemd/timesync/`）`timedatectl` 实测报 synchronized=yes ⇒ 该属性不依赖 timesyncd 私有状态文件；设备 262 为更新版本，同机制。〔实测·本机〕设备侧终证需上机。

## 3. 附带发现：build 侧 daily-baseline 配置段恒 no-op（已修）

`daily-baseline.sh` 原 `for a in "$@"` + 每轮尾部 `shift` 的解析惯用法：for 词表在循环开始时已展开，shift 不改词表 ⇒ **`--root DIR`（空格形）的 DIR 被当成下一个参数撞 `*)` exit 2**，且 stderr 被 `2>/dev/null` 吞掉。HEAD 复现：`git show HEAD:… | bash -s -- --check --root X` → rc=2（`--root=X` 形正常，MISS=19）。
而 `rootfs/debian/build-rootfs.sh:231` 恰用空格形 ⇒ 每次构建的 daily-baseline 配置段（sudo/locale/IME/zram 门）实际从没跑过，被 `|| say "warn: … 不阻塞构建"` 掩盖成一行 warning。设备侧不受影响（mobian-daily-baseline.sh 走 `bash -s` 无 --root）。已改为数组下标解析（对 `--root=DIR` 形零行为差异；空格形从 rc=2 变为正常）。回退 = `git checkout -- rootfs/debian/daily-baseline.sh`。
