# Q28 运营兜底看门狗（第 2 项任务）— 2026-10-12

> 目标：Q28 冷起坏发（~50%，按时间成簇）时**自动重启**，把日常可用性从 ~50% 提到 ~75%。
> 这条**不改根因**，只做运营兜底。根因现状见 `reports/q28-dsi-recover-20261012.md`、`reports/q28-dispcc-static-20261012.md`。

## 0. 结论（数字先行）

1. **已落地并在机上验证**：设备侧 `/usr/local/sbin/q28-boot-watchdog.sh`（判定 + 重启）+ `/etc/local.d/elden-bringup.start` 启动钩子（已加入 helper 枚举）+ `/usr/local/sbin/q28-watchdog.sh`（on/off/status）。主机侧管理 = `scripts/q28-watchdog.sh install|on|off|status|judge`。
2. **判据**：`bad = (无图形会话 OR 无 /sys/class/drm/card0) AND (无 card0 OR 命中 Q28 dmesg 特征)`；启动后 `Q28_WD_WAIT`（默认 75 s，需 ≥ #172 的 60 s 存活门）判一次；有会话+card0 ⇒ 计数清零。重启次数**跨启动**计数，上限 `Q28_WD_MAX`（默认 2）——防重启风暴。
3. **分支自检全过**（设备上、DRYRUN）：`nocard`→判坏发；`nosession`+特征→判坏发；`good`→清零；计数=2→「额度用尽，留在台架」；停用 marker→跳过。
4. **真实端到端通过**：`Q28_WD_SELFTEST=nosession`（不 DRYRUN）⇒ 持久日志落 `Q28 bad boot detected (attempt 1/2 …) -> normal reboot` ⇒ 设备**正常重启回 Linux（不是 fastboot）**、新 `boot_id`、随后 GOOD 启动把计数清 0。
5. **★顺带发现并修复一个潜伏地雷**：设备上部署的 `/usr/local/sbin/reboot2` 是 **2026-09-28 的旧构建**，其无参默认是 **bootloader ⇒ 进 fastboot**（源码 `44f464e` 已修，但**打包/部署的二进制从未更新**）。我的看门狗第一次真实重启就被它送到 fastboot。已装 `out/reboot2-fixed`（sha `0c68ee5f…`），并**替换仓库内打包件** `rootfs/alpine/usr/local/sbin/reboot2`；看门狗另有**能力自检**（`reboot2 -h` 必须含 `no argument = normal reboot`）+ **sysrq-b 兜底**。见 `PITFALLS #229`。

## 2. 开关与实验纪律

- 停用三选一：`q28-watchdog.sh off`（marker）、cmdline 加 `elden_q28_nowd`、`Q28_WD_MAX=0`。
- ⚠ **任何可能留下坏发台架的实验（Q28 A/B、Q24 台架）之前必须 `off`**——否则坏发 75 s 后被自动重启，台架/样本丢失。**停用期内好启动仍会清零计数**（判定顺序已排过：先 good-reset，后 disable-skip）。

## 3. 验收证据

- 分支自检日志（设备 `/var/log/q28-watchdog.log`）：
  ```
  Q28 bad boot detected (attempt 1/2 sess=yes card=no sig=yes selftest=nocard) -> normal reboot
  DRYRUN=1 -> not rebooting
  Q28 bad boot detected (attempt 2/2 sess=no card=yes sig=yes selftest=nosession) -> normal reboot
  selftest=good -> session+card present, count reset
  Q28 bad boot (sess=yes card=no sig=yes) but retry budget exhausted (2>=2) -> staying up for diagnosis
  disabled by /etc/q28-watchdog.disable
  ```
- 真实重启：`[uptime=250.36s] Q28 bad boot detected (attempt 1/2 … selftest=nosession) -> normal reboot`；重启后 `uname` = `#60`（boot_b=vk94）、`fastboot devices` 为空、`card0/DSI-1 connected`、phoc+phosh 起。
- `reboot2` 修复：`reboot2 -h` 现打印 `no argument = normal reboot`；实测无参 `reboot2` 正常回 Linux（未再落 fastboot）。
