## §3 阻塞项（每条都写清「缺什么 / 影响 / 下一步」）

### 3.1 **UTS 与在机不一致 ⇒ 在机模块树一个都用不上**

- 在机：`7.3.1-debug-vk189-suspend-00005-g4bdf1711b5c0`（`out/boot-elden-vk192.manifest:8`）。
- 本件：`7.4.0-rc3-g7-dwc3v11-20261121-dirty`。基线不同（7.3.1 vs 7.4.0-rc3）+ 哈希不可能一致 ⇒ **逐字相等的路是死的**，
  不做「伪装 UTS」：`CONFIG_MODVERSIONS` 确实没开（vermagic 只比 UTS 串），但 7.3→7.4 的结构体布局变化会让旧模块静默读错偏移，
  与 `scripts/assert-kernel-sane.sh:39-53` 记的实例同一类事故。
- **后果（必须写清）**：RAM 启动后 `/lib/modules/7.3.1-…` 全部不匹配 ⇒ `lsmod` 空（约 1 行表头），配置里 1337 个 `=m` 一个都装不上。
- **对本件判据的影响 = 无**（逐条证据，全部取 `config-g7.config`）：`USB_DWC3=y`、`USB_DWC3_QCOM=y`、
  `USB_DWC3_DUAL_ROLE=y`、`USB_ROLE_SWITCH=y`、`MUX_GPIO=y`(本轮改)、`USB_GADGET/LIBCOMPOSITE/F_NCM/F_ACM=y`、
  `DRM_MSM=y`、`ATH12K=y`、`EXT4_FS=y` ⇒ **G7 的整条链路 + 起机 + USB gadget(ssh) 全在内建范围**。
- 若还要 `fastrpc`/传感器/相机（`QCOM_FASTRPC=m` 等）：在本树 `make modules_install INSTALL_MOD_PATH=… INSTALL_MOD_STRIP=1`
  后**整包**部署到 `/lib/modules/7.4.0-rc3-g7-dwc3v11-20261121-dirty`（本轮未编、未部署：硬纪律禁设备动作，且判据不需要）。

### 3.2 **「DSI 起」在 7.4-rc3 上游骨架板上结构性不可达**

- 板 DTS（v8）**只描述**：板骨架 + WL2868C 稳压器 + USB mux/两连接器（241 行）。**没有** mdss/DSI/panel/touchscreen。
- 实测证据：把本件 DTB 反编译后 `display-subsystem@ae00000`、`dsi@ae94000`、`dsi@ae96000` **全是 `status = "disabled"`**，
  DTB 里 `panel@`/`touchscreen@` 节点数 **0**（`dtc -I dtb -O dts` + grep）。`dmesg` 里不会出现 `bound ae94000.dsi`/`fb0`。
- 缺什么：`build/daily`（vk192 那棵树）的板 DTS 是 ~1500 行的 payload 版（含显示/相机/触摸），它和上游骨架**同一路径**
  (`arch/arm64/boot/dts/qcom/sm8750-lenovo-elden.dts`) ⇒ 二者只能二选一。要连带判 DSI，下一步是
  「在 payload 板 DTS 上补 USB mux/两连接器节点（v8 的板级 hunk）」，而不是在本树上加显示 DT。
- 影响：本件上**不要**把「黑屏 / 无 `/dev/dri`」当回归；那是缺件，不是坏件。

### 3.3 **「wlp1s0 UP」同样不可达**

- `sm8750.dtsi`（7.4-rc3）**没有** WCN7861/wifi 节点（`grep -n 'wcn\|wifi' sm8750.dtsi` = 空），板 DTS 也没描述；
  DTB 里 `pcie@1c00000` = `disabled`。`ATH12K=y` 只是驱动编进去了，没有设备可绑。
- 下一步：同 3.2——WiFi/PCIe/regulator 描述都在 payload 板 DTS 里。

### 3.4 **没有 Type-C 消费者 ⇒ 「换口」需要 rolehook 变体**

- 7.4-rc3 的 `sm8750.dtsi` **没有** `pmic-glink`/UCSI/TCPM 节点（`grep -n 'pmic-glink\|ucsi\|typec' sm8750*.dtsi` = 空），
  而 v11 的 per-connector role switch 的消费者是 connector/port-manager 驱动（`fwnode_usb_role_switch_get()` 的调用者：
  `cros_ec_typec`、`extcon-*`、TCPM/UCSI 一类）。
- 板 DTS 里的两个 `usb-c-connector` 只是被动描述（`power-role/data-role="dual"`），**不会**自己发 `set()`。
- 且 per-port switch 默认**不出现 `role` 属性**（`usb_role_switch_is_visible()` 见 `allow_userspace_control`）；
  dwc3 自己的那个 `role` 是 RW，但 `dwc3_set_mode(dwc, mode)` 带 `port=-1` ⇒ 只换角色、**不换连接器**
  （`dwc3_queue_mode()`：`if (dwc->role_mux && port >= 0) …desired_port = port`）。
- ⇒ 想看「HS 数据线真的切到另一个口」，只能用 `boot-with-rolehook.img`（`echo host|device > /sys/class/usb_role/<dev>-portN/role`）。
  这是**测试钩子**，不是 v11 的行为结论；纯 v11 的行为结论只能从 `boot.img` 的 §4.3 只读项里拿。

### 3.5 `build-kernel.sh` 的打包后守卫对 pristine 7.4-rc3 假阳性（rc=1）

- 守卫要求 `System.map` 里有 `msm_dsi_host_bonded_cmd_trigger|msm_dsi_host_bonded_cmd_xfer|dsi_bonded_cmd_trigger`
  之一；那三个名字来自 **daily payload 的 B5 重构**（`patches/local/b5-resoc-20261027`），7.4-rc3 原树没有。
- 于是脚本在**编译成功、Image.gz/DTB 已落盘之后**打印 `ERROR: … MISSING in System.map -> This Image is DEAD` 并 `exit 1`
  （`out/g7-20261121/build-2.log:36`）。**这是误报**：同一条守卫的另两个锚点 `gcc_sm8750`/`rpmh` 都在（13 / 53 处），
  `msm_dsi_modeset_init`、`dsi_dev_probe` 也在。
- 本轮**没有改脚本**（产物边界约定）。下一步（另立一轮）：给守卫加「上游等价符号」分支
  （如 `msm_dsi_modeset_init`），否则任何 pristine 上游树都会被判死。

### 3.6 `willsemi,wl2868c` 驱动不在 7.4-rc3（`dtbs_check` 唯一一条诊断）

- 树里**没有** `drivers/regulator/wl2868c*` 文件、**没有** Kconfig 符号，`CONFIG_REGULATOR_WL2868C` 在归一后消失
  ⇒ 板 DTS 的 `i2c10/pmic@2f` 永远不会 probe；`dtbs_check` 因此有 1 条
  `failed to match any schema with compatible: ['willsemi,wl2868c']`（`out/g7-20261121/dtbs-check.log`）。
- 对 G7 无影响（USB 不用这颗 PMIC）。它是**板件系列（v9 投递前）**要处理的：binding 已进 `regulator.git for-7.5`，驱动补丁 `wl2868c-v12` 还在飞。

### 3.7 板 DTS 末尾多一个空行

`git apply` 对 v8 `0002` 报 `new blank line at EOF`（文件以 `};\n\n` 结尾）。纯样式，不影响编译；
建议随 v9 投递时顺手删掉（`checkpatch` 的严格模式对尾部空行不敏感，但维护者会挑）。

## §事件：一次不可复现的 `gen_header.py` SIGSEGV（按全局规则 12 处理，未深挖）

### 4.3 G7 判据（逐条「期望 / 判负」）

| # | 判据 | 命令 | 期望 | 判负（= 上报，不要自行解读成回归） |
|---|---|---|---|---|
| 1 | 两个 port 注册 | `ls /sys/class/usb_role/` | **2 个** `<dev>-port0`、`<dev>-port1`（v11 的 per-connector switch），外加 1 个 dwc3 自身的 `<dev>` | 只有 1 个 ⇒ `dwc3_role_mux_init()` 没走 mux 路径（先查 `&usb` 的 `mux-controls`、两个 endpoint 的 `usb-role-switch`/`mux-state`、`MUX_GPIO` 是否 `y`） |
| 2 | 初始选口 | `cat /sys/class/usb_role/*/role` | 两个 port 均 `none`（没人请求过），dwc3 自身 `device`（默认 role = peripheral ⇒ gadget 起得来） | dwc3 自身为 `host` ⇒ `role-switch-default-mode` 被误设，USB lifeline 会断 |
| 3 | 首次换口（**需 rolehook 版**） | `echo host > /sys/class/usb_role/<dev>-port1/role` | dmesg 出现**一次** mode switch + mux 切到 state 1；无 `failed to select USB port` | `-EBUSY`/`-ENODEV`（mux 未 ready）、反复 select/deselect、`mux_control_select` 超时 |
| 4 | 单次跳变（不回跳） | 接着 `cat /sys/class/usb_role/*/role`；再 `echo host > /sys/class/usb_role/<dev>-port0/role` | 每次请求只引起**一次** select；port1 保持它所请求的角色（`dwc3_mux_role_get` 语义） | 角色被反复打回 `none` ⇒ 仲裁/发布顺序坏了（对应 sashiko 3/3 那条） |
| 5 | unbind 期间无「实例还在跑、线已被切走」 | `echo <dev> > /sys/bus/platform/drivers/dwc3/unbind`（或 rmmod 路径）；`dmesg -w` 同步看 | `dwc3_host_exit`/`dwc3_gadget_exit` 在前，`mux_control_deselect` 在后；无 WARN/BUG | 出现 deselect 先于 teardown 的窗口（= v11 修的那条又回来了） |
| 6 | 无 deselect 竞态 | `dmesg | grep -i dwc3` | 无 `WARNING:`/`BUG:`/`deselect` 报错、无 gadget 起停乱序 | 任一出现即记录原文与时间点 |
| 7 | gadget 存活 | `ls /sys/class/udc`；`ip -br a show usb0` | 有 UDC、`usb0` 有地址（ssh 通本身已证） | UDC 消失 |
| 8 | tool 自证 | `cat /sys/kernel/debug/<dwc3>/mode` 写入 | **返回 `-EBUSY`**（v11 刻意拒绝：connector provider 才有权决定角色+数据路径） | 写入成功 ⇒ 补丁没生效/树不对 |
| 9 | DSI / wlp1s0 | — | **不判**（§3.2/§3.3：缺件，非回归） | 把它当回归 = 误判 |

> 判据 3/4/5 是 v11 的真考点；判据 1/2/7/8 是「功能面在不在」的静态确认。
> 采集口径沿用 `patches/upstream/dwc3-v11-20261121/GATES-v11.md` §G7 与 `reports/dwc3-v11-20261121.md` §5 的 ①②③④。

### 4.5 回退（必须先想好）

- **本件零写盘**：`fastboot boot` 不写任何分区，`boot_b`（vk192）与 ESP 都未被触碰 ⇒ **一次冷/热重启即回 vk192**。
  证据：本轮主机侧零设备动作（无 `flash`/`dd`/`scp`），产出只有 `out/g7-20261121/` 下的文件。
- 若起机后 60 s 无 SSH：先看宿主 `lsusb`/`fastboot devices` 是否还看得到设备——
  - 还看得到 ⇒ `fastboot reboot`（回 _b = vk192）；
  - 看不到 ⇒ USB 物理层已挂（`panic=15` 只救 panic，救不了 hang），需要**用户**长按电源+音量进 bootloader；
    这也说明 dwc3 v11 在真板上确实有病，直接转取证（`dmesg`/pstore 取不到就靠 `elden_early_gadget=1` 变体补一发：
    `CMDLINE_EXTRA` 里加这个 token 可让 usb0 在 `switch_root` **之前**就起来，`PITFALLS` #468 的同源判据）。
- 不要为了「看得见」去 flash boot_b（那会把 vk192 换掉，是本项目明令的分阶段操作，且本轮未被授权）。
