## 2. ★待核查项（按优先级，下一会话）

1. ~~**`to_primary_dsi()` DSI0 vs DSI1（最高优先）**~~ **← 2026-10-12 静态核查证否，本项作废（`PITFALLS #196`）**：上游 mainline 与本树属**两套不同 MSM 实现**——vanilla 7.2 的 `dsi_manager.c` 无 `bonded_cmd_xfer` 且 `DSI_ENCODER_MASTER=DSI_1`；本树有整套 `dsi_mgr_bonded_cmd_xfer`，注释明写「**DSI0** 才是 broadcast master / completion source」，DT `qcom,master-dsi` 两树都在 dsi0。该 bonded 路径**忽略消息来自哪个 host**，而面板驱动无 RX / 无 REQ_ACK ⇒ 全部命令走此路径 ⇒ `dsi[0]`/`dsi[1]` 在本硬件上 **no-op**。**不要改成 `dsi[1]`**（会与本树 dsi_manager.c 冲突），也不要为此上机。详见 `PITFALLS #196`。
2. **★Method B 校准上游（现在的最高优先）**：把 `2028280686f4`（byte-clk reparent 后取整）按 generic 落点移植（本树 NOT-IN-TREE），用 PINUTS + 已知 GOOD 身份做冷起 A/B（见 `reports/q28-community-cases-20261012.md`）。
3. **refgen 线索**：Pengyu 原话「sm8750 上要反复重启才点亮」——与本机 STORM 同症状（lore `sc8280xp use refgen regulator for DSI` 线程）。已核：本树/上游 `sm8750.dtsi` **无 refgen 节点**、DSI 无 `refgen-supply`；refgen 驱动已编为模块。⇒ 向 Pengyu/Dmitry 确认 sm8750 是否走硬件线。
4. **日常替换候选 `vk112`（可选）**：`5d01d3324`（含 ADSP DT）+ PINUTS + 3 位 `#N` + 模块化 R，冷起确认后刷 boot_b（写盘，需用户点头）。
5. **可选**：到 `dri-devel` / nt36536 线程报告本机冷启 `-110` 现象。

## 3. 方法学纪律（务必遵守）

- **冷起 A/B 必须 PINUTS**（`CONFIG_LOCALVERSION_AUTO=n` + `LOCALVERSION=-vk64-gd02658e63cf6`），并**记录 `#N` 位数**——否则构建身份混淆结果（观察者效应，#192/#195）。
- 判据用 **`q28-devprobe2.sh`**（三态 + L1/L2 拆分 + session 门 + 65 s 存活门）；不要只数 v1 的 `storm_sig`。
- 冷起 = 物理 POR（用户动作）→ fastboot → `fastboot boot`；`reboot2` 暖复位粘 NOCARD，不可当 A/B 台架。
- 每样本走 `scripts/trial.sh`（记录 reset 类型/镜像 sha/verdict）。
