## 1. 为什么换台架（不是复刻 vk64）

N5 在 vk64（`fastboot boot` RAM 内核）上第 2 发致死，n=2；M1-7.3 同配方 12/12 存活。继续在 vk64 上
采样需要先重建 `out/boot-elden-vk64.img`（换机后 MIGRATION-LOST）。本轮改在 **vk127** 做，理由：

1. **决策相关**：日常策略针对 7.3 线；vk64 的死活不改变「日常零相机模块」的口径。
2. **可迭代**：vk127 在 git 里（`replay/m1-73-vk127` + tag），177 文件 payload 是 cherry-pick 进来的
   ⇒ 一旦复现死亡，N6 二分能在**同一棵可编树内**做。
3. **零成本**：设备当时就活在这颗内核上（`uptime` 已 2800+ s、Q28 签名 0），不需要重启。

## 2. 实验设计与实现

```
A 臂（对照）：CAM_FORCE=1 camera-modules-load.sh → 19 模块 / 17 video / 1 media → 不熄屏 600 s
B 臂（主测）：同一栈在位 → gdbus org.gnome.ScreenSaver.SetActive(true) → 校验 dpms On→Off
             → 保持 30 s → 读 boot_id → SetActive(false) 唤醒 → 下一发
K 臂（备选）：内核 DPMS（写 /sys/class/drm/card0-DSI-1/dpms）——**本机不可用，见 §4.1**
判据（PITFALLS #288/#209）：boot_id 变 = 死；硬复位另查 powerlog 有无本次 id + pstore 是否空 + uname 是否回落 boot_b
```

- 每发都**读回** `dpms` 并打印跃迁（`On -> Off`），NO-BLANK 会记 `INVALID` 而不是 `ALIVE`
  （防 `sleep-sweep.sh` 那种假阳性，`#288`）。
- 每次测试前 `gsettings idle-delay = 0`，确保熄屏只由我们触发；测试后 `cam-mode.sh off` 还原。

## 3. BAD 显示态那一轮（关键）

- 设备由用户**断电真 POR** → fastboot → `fastboot boot` vk127 ⇒ 本次 boot `Q28sig=3`、`dsi_isr=0`、
  `command DMA timeout: status=0x2200200` + `bonded command DMA failed: master=-110 peer=-110` + `ff 20` `-110→-5`：
  **教科书级 L1 坏发**。
- 坏发 boot 上 `phoc`/`phosh` **crash-loop 约 3 分钟**（`drm_crtc_wait_one_vblank` trace + greetd 反复重启），
  `loginctl` 初始为空；到 `uptime≈190 s` 会话才稳定可用，之后 B 臂 6 发正常完成。
- **每次熄屏→唤醒都会重新走一遍失败的板端初始化**：`Q28sig` 逐发递增 **4→5→6→7→8→9**。
  这既证明「坏发是持续性 down-state」而不是一次性瞬态，也说明唤醒路径真的被执行了（不是 no-op）。
- 结果：**6/6 存活**（`boot_id` 全程 `26262eee…` 不变）。

## 4. 方法学收获（已登记 PITFALLS #294/#295）

### 4.1 `/sys/class/drm/*/dpms` 是本机**只读**的（`-r--r--r--`）

`echo Off > …/dpms` 直接 `Permission denied`（root 也是）。⇒ **内核 DPMS 路径不可用**，
设备侧自动熄屏只能走会话总线（`org.gnome.ScreenSaver.SetActive`）或 `modetest`。
K 臂因此 6 发全部 `INVALID-NO-BLANK (On->On)` —— harness 正确拒绝判 ALIVE（这就是要校验跃迁的原因）。

### 4.2 坏发 boot 上的会话是「先崩后稳」

`phoc` 起来又死、greetd 反复拉起，约 3 分钟后才稳定。若在 `uptime < 120 s` 就抓总线，
会拿到**另一个** `DBUS_SESSION_BUS_ADDRESS`（旧 phoc 的）而全部调用失败。
⇒ 坏发上做任何会话侧实验，必须**等 `pidof phoc` 稳定 + 用当前 pid 的 environ 取总线**。
