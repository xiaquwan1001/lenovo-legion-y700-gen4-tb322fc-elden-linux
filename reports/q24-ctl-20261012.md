# Q24 受控复现（第 1 轮）：干净台架 + 对照熄屏（2026-10-12）

> 承接 `reports/q24-stageA-20261012.md`。设备 U2(HA2EXB0E)。原始数据：`logs/q24-ctl-20261012/`、`logs/serial-q24-20261012.log`。

## 0. 一句话

在 **GOOD 台架**（`-vk64` PINUTS 内核）上，把相机栈清到 **`{camcc}` 单模块**后执行一次**真实熄屏** ⇒ **静默硬复位**（串口**无 panic**、USB 重枚举、回落到日常 `#60` 内核并进入 STORM）。⚠️ 但该对照的**状态是「装载过完整相机栈后再卸载」**，不是历史的「干净启动 + 只 camcc」，**不能**据此否定历史「{camcc} 3/3 存活」。

## 2. 死亡现场（自串口 + RPMh trace）

### 2.1 串口：无 panic（无痕硬复位）
```
[   37.629760][ T3909] NOTICE: Automounting of tracing to debugfs is deprecated ...
===== serial closed 09:33:45 =====      ← USB 消失（硬复位）
===== serial opened 09:34:17 =====      ← 32 s 后重枚举 = 重新开机
[    0.000000][    T0] OF: reserved mem: ...
```
**复位前没有任何 panic / Oops / BUG / 看门狗消息** ⇒ 与历史 Q24「无痕硬复位」同型；本轮**不是**我在阶段 A 遇到的 hang 型。

### 2.2 RPMh trace：最后一笔是 **phoc 降 MMCX/CX**
```
phoc-1839  [007]  283.113361  rpmh_send_msg ... addr: 0x30080 data: 0x2   ← mmcx.lvl → 2（降）
phoc-1839  [007]  283.113388  rpmh_send_msg ... addr: 0x30000 data: 0x5   ← cx.lvl  → 5（降）
<idle>-0   [000]  ...         rpmh_tx_done ack 0x30080 data 0x2 / 0x30000 data 0x5
                               ← 之后 trace 完全静止（内核已死）
```
（`cmd-db`：`mmcx.lvl`=0x30080 / `cx.lvl`=0x30000；实测稳态为 `mmcx` 高 corner、`cx=6`。）
⇒ **区别于「配对死」的最后一笔（`mxc.lvl→0`）**：本轮（camcc 单模块）最后一笔是 **MMCX 下折**。两种终态的最后投票**不同**，值得单独记。

## 3. 结论与边界（必须并列写清）

1. **确证**：`{camcc,cambist}` 在位（ramdisk 自动加载）经数分钟**不熄屏**稳定 ⇒ 与阶段 A 一致，**「在位」本身不即时致死**，死亡需「真熄屏」这一动作。
2. **新观测**：装载过完整栈后再卸到 `{camcc}` 单模块，**真实熄屏仍硬复位**（无痕）。最后一笔 = `mmcx↓ / cx↓`。
3. **⚠️ 混淆项（不可当结论）**：本对照的状态 = **「完整栈装载→卸载后」**（且 `wireplumber` 被杀、`/dev/video0` 释放）。这与历史「干净启动 + 只加载 camcc，3/3 存活」**不是同一状态**（PM 投票/genpd refcount 已扰动）。**因此本轮不能否定历史结论，也不能断言「camcc 单模块即致死」。**
4. **终态并存**：Q24 已见 **hang 型**（阶段 A：USB 仍枚举）与 **无痕硬复位型**（本轮）。取证必须并列多判据。
