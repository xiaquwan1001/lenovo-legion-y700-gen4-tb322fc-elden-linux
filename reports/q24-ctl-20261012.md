## 0. 一句话

在 **GOOD 台架**（`-vk64` PINUTS 内核）上，把相机栈清到 **`{camcc}` 单模块**后执行一次**真实熄屏** ⇒ **静默硬复位**（串口**无 panic**、USB 重枚举、回落到日常 `#60` 内核并进入 STORM）。⚠️ 但该对照的**状态是「装载过完整相机栈后再卸载」**，不是历史的「干净启动 + 只 camcc」，**不能**据此否定历史「{camcc} 3/3 存活」。

## 2. 死亡现场（自串口 + RPMh trace）

### 2.1 串口：无 panic（无痕硬复位）

**复位前没有任何 panic / Oops / BUG / 看门狗消息** ⇒ 与历史 Q24「无痕硬复位」同型；本轮**不是**我在阶段 A 遇到的 hang 型。

### 2.2 RPMh trace：最后一笔是 **phoc 降 MMCX/CX**
```
phoc-1839  [007]  283.113361  rpmh_send_msg ... addr: 0x30080 data: 0x2   ← mmcx.lvl → 2（降）
phoc-1839  [007]  283.113388  rpmh_send_msg ... addr: 0x30000 data: 0x5   ← cx.lvl  → 5（降）
<idle>-0   [000]  ...         rpmh_tx_done ack 0x30080 data 0x2 / 0x30000 data 0x5
                               ← 之后 trace 完全静止（内核已死）
```
（`cmd-db`：`mmcx.lvl`=0x30080 / `cx.lvl`=0x30000；实测稳态为 `mmcx` 高 corner、`cx=6`。）
⇒ **区别于「配对死」的最后一笔（`mxc.lvl→0`）**：本轮（camcc 单模块）最后一笔是 **MMCX 下折**。两种终态的最后投票**不同**，值得单独记。

## 3. 结论与边界（必须并列写清）

1. **确证**：`{camcc,cambist}` 在位（ramdisk 自动加载）经数分钟**不熄屏**稳定 ⇒ 与阶段 A 一致，**「在位」本身不即时致死**，死亡需「真熄屏」这一动作。
2. **新观测**：装载过完整栈后再卸到 `{camcc}` 单模块，**真实熄屏仍硬复位**（无痕）。最后一笔 = `mmcx↓ / cx↓`。
3. **⚠️ 混淆项（不可当结论）**：本对照的状态 = **「完整栈装载→卸载后」**（且 `wireplumber` 被杀、`/dev/video0` 释放）。这与历史「干净启动 + 只加载 camcc，3/3 存活」**不是同一状态**（PM 投票/genpd refcount 已扰动）。**因此本轮不能否定历史结论，也不能断言「camcc 单模块即致死」。**
4. **终态并存**：Q24 已见 **hang 型**（阶段 A：USB 仍枚举）与 **无痕硬复位型**（本轮）。取证必须并列多判据。

## 7. 执行记录

| 步 | 内容 | 结果 |
|---|---|---|

## 8. S3 失败的根因：**该台架是一台「暖复位路径」启动的坏仪表**

1. `org.gnome.ScreenSaver.SetActive(true)` / `Lock()` 均返回 `()`，但 `GetActive` **恒 false**、`DPMS` 恒 On、`bl_power` 恒 0 ⇒ **屏没有真关**。
2. 原因是 **phoc 已卡死**：`/proc/<phoc>/status: State: D (disk sleep)`，`wchan=rpm_resume`，栈 = `adreno_get_param → __pm_runtime_resume → rpm_resume`；同时 `a6xx_gmu_set_oob`、`msm_gpu_fault_crashstate_capture` 也在 D 态 ⇒ **GPU 处于故障捕获态**。`kill -9` 无效（D 态不可杀）。
3. dmesg 佐证显示栈已坏：`dpu_encoder_phys_vid_prepare_for_kickoff … ctl 1 reset failure: -22`、`frame done timeout`、`vblank timeout: 204208c0`、`wait for commit done returned -110`（t≈135 s 起）。
4. 因此 `modetest -M msm -w 36:DPMS:3` 始终 `Permission denied`（DRM master 被卡死的 phoc 持有），**无法执行 DPMS-off 路径**。
5. **第 1 轮的 trace 段（MARK 2404 起）为空** ⇒ 从头到尾没有任何 DPMS/熄屏 RPMh 事件，坐实「S3 从未发生」。

**⇒ 归因**：本轮是经 **`reboot2 bootloader`（暖复位）** 进的 fastboot，正落在 `PITFALLS #166`（暖复位粘坏态，不可当台架）上。第 1 轮那次**有效**的对照（真熄屏 → 硬复位）是用户**物理 POR 后**的冷路径。

## 9. 本轮有效/无效判定

| 结论 | 有效性 |
|---|---|
| 「`{camcc,cambist}` 在位、不熄屏 → 不即时致死」 | **有效但弱**（在坏仪表上测得；与阶段 A、第 1 轮一致，三处一致） |
| 「真实熄屏 → 硬复位」 | **本轮未复现**（S3 未执行）——**不能**据此否定第 1 轮的硬复位 |
| 「无相机 cmdline（`elden_nocamera=1`）本身会把启动弄坏」 | **不成立/未判**：混淆文是暖复位路径 |
| 干净台架 `lv64-nocam` 的**正确性** | **未验证**（唯一一次启动走的是暖路径） |
