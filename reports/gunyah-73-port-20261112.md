## §2 API 适配逐条

### 2.1 `vm_mgr.h`：`vma_interval_tree_foreach` → `mapping_rmap_tree_foreach`（唯一代码改动）

- 现象：`vm_mgr.h:180 error: implicit declaration of function 'vma_interval_tree_foreach'`（gcc 还提示 `mapping_rmap_tree_foreach`）。
- 根因：7.3 把 `folio_mmapped()` 用的反向映射遍历宏重命名并改了签名：
  6.12 `vma_interval_tree_foreach(vma, &mapping->i_mmap, start, last)`
  → 7.3 `mapping_rmap_tree_foreach(vma, mapping, start, last)`（`build/daily/include/linux/mm.h:4191`，第二参数从 rmap 树头改为 mapping 本体）。

### 2.3 `hypervisor_kobj` 未定义 → 重链 vmlinux（非代码改动）

- 现象：`MODPOST ERROR: gunyah_rsc_mgr.ko: symbol 'hypervisor_kobj' undefined!`
- 根因：piano Kconfig `select SYS_HYPERVISOR`；build/daily 的 `.config` 里 `CONFIG_SYS_HYPERVISOR=y` 是本次 olddefconfig 才打开的，
  而**已链接的 vmlinux 是在它关闭时构建的**，`drivers/base/hypervisor.c` 的
  `EXPORT_SYMBOL_GPL(hypervisor_kobj)` 不在内核里 → 模块 modpost 解析失败。
- 处置：`make -j26 vmlinux` 增量重链（ccache 命中，分钟级），之后 `nm vmlinux | grep -w hypervisor_kobj` 有 `B hypervisor_kobj`，modpost 通过。
- 未改任何 7.3 核心文件。

## §4 下一步上机方案（喂违规 DTB 看 RM 错码 0xA→8）

目标：验证 piano parcel 修复是否把 `VM_INIT` 的 `MEM_INVALID (0xA)` 变成可判定的别的错码（如 `0x8 = NVMGID_INVALID / DT 无效`类），从而定位 10-25 轮的根因。参照 `reports/gunyah-pvm-attempt-20261025.md` 的矩阵与 `tools/gunyah-modules/vmmtest/vmmtest.c`。

1. **前置（设备侧）**：等 vk189-suspend 基线内核在 U2 上跑起来（vermagic 一致），或临时 `modprobe --force-vermagic`（仅诊断用，正常做法是重编统一基线）。
2. **模块装载顺序**：`gunyah_hypercall gunyah_timer → gunyah → gunyah_platform_hooks gunyah_qcom → gunyah_rsc_mgr gunyah_vcpu`（qcom 需要 `/proc/device-tree` 里的 gunyah-hypervisor 节点 + QCOM_SCM）。
3. **最小探针**：沿用 vmmtest（4 MiB LEND + 1 vCPU + 16 B payload，`SET_FW_CONFIG` auth=NONE 路径），复现基线 `VM_INIT Error: 10 (0xA)`。
4. **违规 DTB 实验**：在 VM_CONFIGURE 喂故意违规的 DTB（vmmtest 支持 dtb 参数；可先用 `tools/gunyah-modules/dtbo/guest-v2.dtb`，再逐级破坏：去 `/gunyah-vm-config` 节点、坏 GIC phandle、超范围 IPA），
   观察 dmesg `RM rejected message 5600000b` 后的错误码：
   - 若从固定 `0xA` 变为随 DTB 内容变化的错码（如 `0x8`/`0x3 DENIED`）⇒ 说明 parcel 生命周期已修好，0xA 的旧根因确实是 g612 的提前 reclaim/unpin；
   - 若仍恒为 `0xA` ⇒ 违规点不在 VMM 侧 parcel 状态，转向查 RM 对 LEND 布局（pvmfw/DT 尺寸对齐）的要求。
5. **取证**：每轮 `dmesg | grep -E '5600000|gunyah'` 存档；错码 `%d` 打印，按 PITFALLS #393 口径十进制读。
6. **安全**：诊断前 `scripts/q28-watchdog.sh off`；模块可 `rmmod` 逆序卸载，不动槽位与 boot 分区。
