# 在文件管理器侧栏隐藏只读 Android / 持久化分区 — 机制调研 + 脚本 + 上机判据

- 日期：2026-11-19（主机侧；**全程未接设备**：无 adb / fastboot / qdl / ssh，本会话不用 sudo）
- lane：`hide-android-partitions`
- 产物：`scripts/hide-android-partitions.sh`、`scripts/hide-android-partitions-selftest.sh`、
  证据原文 `out/hide-android-partitions-20261119/evidence.txt`
- 一句话结论：**在 udisks2 层用 udev `UDISKS_IGNORE=1` 做「PARTLABEL 白名单」是最好的单点**——
  Nautilus 侧栏、GTK 文件选择器侧栏、`gio mount -l` 三者都源自同一个 `GVolumeMonitor`
  （`gvfs-udisks2-volume-monitor`），而该 monitor 的 `should_include_volume()` **第一条判断**就是
  `Block:Ignore`；Nautilus 自身在 GNOME 50 里**已经没有任何相关 dconf 键**，fstab 的 `x-gvfs-hide` 只覆盖
  「已在 fstab 里挂了」的条目，对未挂载的 Android 分区无效。

## 2. 机制（四层，各给权威引用）

### a) udisks2：`UDISKS_IGNORE` / `UDISKS_AUTO` / `UDISKS_SYSTEM`（★主修点）

- **权威文档（本机已装，宿主 udisks2 2.10.91，设备 2.11.2 同语义）**：
  `man 8 udisks` → 段 **DEVICE INFORMATION**（gz 行 123）：三个属性「If set, this overrides the value of the
  `HintSystem` / `HintIgnore` / `HintAuto` property」。
- **源码位置（上游 storaged-project/udisks，本轮实拉 master 核对）**：
  `src/udiskslinuxblock.c:919-927` —— `g_udev_device_has_property(...,"UDISKS_SYSTEM")` → `hint_system`，
  同段 `UDISKS_IGNORE` → `hint_ignore`、`UDISKS_AUTO` → `hint_auto`；
  随后 `udisks_block_set_hint_ignore (iface, hint_ignore)`。
- **本机已装行为实证**：`strings -a /usr/libexec/udisks2/udisksd | grep -x 'UDISKS_.*'`
  → `UDISKS_SYSTEM` / `UDISKS_IGNORE` / `UDISKS_AUTO` 三个都在二进制里。
- **现成用法样例**（照抄语法用）：
  `/usr/lib/udev/rules.d/80-udisks2.rules:121` `ENV{ID_PART_ENTRY_SCHEME}=="gpt", ENV{ID_PART_ENTRY_TYPE}=="426f6f74-…", ENV{UDISKS_IGNORE}="1"`；
  `/usr/lib/udev/rules.d/96-e2scrub.rules:2` `ENV{DM_LV_NAME}=="*.e2scrub", ENV{UDISKS_IGNORE}="1"`。
- **覆盖方式**：**不要改** `/usr/lib/udev/rules.d/`（包升级会覆盖，文件头第 2 行就写 "Do not edit this file"），
  在 `/etc/udev/rules.d/` 放同名排序位之后的规则。`60-persistent-storage.rules` 提供 `ID_PART_ENTRY_NAME`（来自 GPT 名字 / PARTLABEL），
  所以我们的文件取 **`79-`**（在 60 之后、80 之前都安全；udev 属性是累积的，`80-` 只对特定设备再置 1）。
- **为什么 `UDISKS_IGNORE` 而不是 `UDISKS_AUTO`**：`HintAuto` 只影响「插上就自动挂」，而内部分区的 HintAuto 本来就是 FALSE
  （`src/udiskslinuxblock.c` 里 system drive 默认 auto=FALSE），我们要的是「别出现在列表里」= HintIgnore。

### b) gvfs：`x-gvfs-hide` / `x-gvfs-show` / `x-gvfs-name`（fstab 层，覆盖「已挂载」条目）

- **权威源码（本轮实拉 gvfs master 核对；设备 = gvfs 1.62.0-3）**：
  - `monitor/udisks2/gvfsudisks2volumemonitor.c:1052` —— `should_include_volume()` **首条**：
    `/* Block:Ignore trumps everything */ if (udisks_block_get_hint_ignore (block)) goto out;`
  - 同文件 `should_include()`（约 850-880 行）—— fstab 选项解析顺序：
    `x-gvfs-show` **优先级最高**（"The x-gvfs-show option trumps everything else"）→ `x-gvfs-hide` → 然后才是
    `g_unix_is_mount_path_system_internal()`、`/.`、`$HOME`、`/media`、`/run/media` 启发式。
  - `monitor/udisks2/gvfsudisks2utils.c:103` `gvfs_udisks2_utils_lookup_fstab_options_value()`：**前缀无关的 strstr 匹配**
    （源码注释自认这是 bug，并可被 `comment=x-gvfs-hide` 利用，见 gvfs issue #348）⇒ 不要把 `x-gvfs-show` 和
    `x-gvfs-hide` 同时写在一行。
- **本机已装行为实证**：`strings -a /usr/libexec/gvfs-udisks2-volume-monitor | grep '^x-gvfs'`
  → `x-gvfs-hide` / `x-gvfs-show` / `x-gvfs-name=` / `x-gvfs-icon=` / `x-gvfs-symbolic-icon=`；
  且 `ldd` 显示它链 **`libmount.so.1`**（fstab 就是这么进来的）。
- **注意（重要）**：`man 5 fstab` 与 `man 8 mount` 里**没有** `x-gvfs-*`（实测 zgrep 0 命中）——
  这些是 gvfs 私有约定，权威只在 gvfs 源码/二进制里。**别去 man 页找它。**
- **对未挂载分区无效**：Android 那堆分区根本不在 `/etc/fstab` 里 ⇒ 这层**单独解决不了**用户的问题。

### c) Nautilus 自身：**没有可用的 dconf 键（2026 现状）**

- 实测（宿主 nautilus `1:50.2.2-0ubuntu0.2`）：`/usr/share/glib-2.0/schemas/org.gnome.nautilus.gschema.xml`
  的 6 个 schema **总共 11 个键**，全文如下：
  `recursive-search, search-filter-time-type, show-directory-item-counts, click-policy, show-image-thumbnails,
  default-sort-order, default-folder-viewer, date-time-format, default-compression-format, default-zoom-level(×2)`
  ⇒ **没有任何 volumes/mounts/places 相关的键**。老版本的 `org.gnome.nautilus.desktop volumes-visible`
  已随 desktop-icons 拆分删除（本机 `org.gnome.nautilus.desktop` schema 不存在）。
- 「其他位置（Other Locations）」列表**不是** dconf 驱动的，它来自 `GVolumeMonitor`：
  `gtk/gtkplacessidebar.c:1228 volumes = g_volume_monitor_get_volumes(...)`（GTK main 实拉核对；
  Nautilus 的 side bar 用同一个 GTK places 组件）。
- 推论：**想在 Nautilus 里做，只能从 GVolumeMonitor 的数据源（udisks/gvfs）剪**——这正印证 §a 的选择。
- 附带利好：整盘（`/dev/sda`）不会因为它自己冒出来——`gtkplacessidebar.c` 只在
  `g_drive_is_media_removable(drive) && !g_drive_is_media_check_automatic(drive)` 时才把「无卷的 drive」放侧栏
  （内部 UFS 盘不满足）；而 gvfs 的 `should_include_drive()` 注释明确「目前无条件包含 drive」但 UI 侧不显示。

### d) Phosh 自己有没有设备/挂载入口：**没有**

- 上游 phosh（本轮实拉 master）只有 `src/gtk-mount-manager.c` —— 那是 **GtkMountOperation 的 D-Bus handler**
  （`org.gtk.MountOperationHandler`，即「插入加密卷时弹密码框」），**不是**卷列表 UI。
- `grep -rn -i mount phosh-src/data/*.gschema.xml.in` → 0 命中（没有任何挂载相关设置键）。
- ⇒ Phosh 不提供需要单独治理的挂载列表；它同样经由 GTK/GIO → §a 一层就够。

## 3. 我们的选择与理由

采用 **规则文件 `/etc/udev/rules.d/79-hide-android-partitions.rules`（PARTLABEL 白名单 + `UDISKS_IGNORE=1`）为主，
`/etc/fstab` 补 `x-gvfs-hide` 为辅**，由 `scripts/hide-android-partitions.sh` 幂等生成。

| 层 | 用不用 | 理由 |
|---|---|---|
| udisks/udev（§a） | **用（主）** | 唯一能覆盖「未挂载的 Android 分区」的层；一次生效于 Nautilus / GTK 文件对话框 / `gio mount -l`；重启、升级都保留（`/etc/udev` 不被包管理覆盖）；不影响内核分区表、不 umount、不动权限 |
| fstab `x-gvfs-hide`（§b） | **用（辅）** | 我们有 `/mnt/persist` 这类**已挂载**条目；这类条目若未加 `x-gvfs-hide` 仍会出现在侧栏。只改我们自己条目、逐字节保留其余行 |
| Nautilus dconf（§c） | **不用** | 键不存在（11 个键里 0 个相关），无法实现 |
| Phosh 私有入口（§d） | **不用** | 不存在此类入口 |

**设计约束（都写进脚本了）**：

1. **白名单制**而不是黑名单：只「显示我们要的」（默认 `linux17`、`eldenesp`，以及 11-18 新根镜像用的 fs label `linux`），
   其余全部 `UDISKS_IGNORE=1`。这样以后原厂固件改分区名（本项目已经遇到 GPT 被原厂件覆盖）也不会漏。
2. **不动可移动介质**：默认给 `ID_DRIVE_FLASH_SD|ID_DRIVE_FLASH_MMC|ID_BUS=="usb"` 开例外（TF 卡/U 盘是「用户感兴趣」的卷，
   不属于本脚本要治的固定分区）；要全隐藏加 `--no-keep-removable`。
3. **fstab 只改能解析到「隐藏分区」的条目**；解析不出（例如 TF 卡按 UUID 写、当前没插卡）就**不动**并在 dry-run 里报 `UNRESOLVED`
   ——宁可不改，不误伤。
4. 系统内部挂载点（`/`、`/boot`、`/boot/efi`、`/usr`、`/var`、`/home` 等）一律跳过。
5. 只写规则 + fstab 选项 + 可逆状态文件；`--apply` 前逐文件备份 `*.bak-hideandroid-<时间戳>`；`--revert` 删规则并精确撤掉我们加的那几行选项。

## 4. 脚本

### 4.1 文件

| 文件 | 作用 |
|---|---|
| `scripts/hide-android-partitions.sh` | 主脚本（POSIX sh）。`--check` / `--apply` / `--revert`；**默认 dry-run** |
| `scripts/hide-android-partitions-selftest.sh` | 离线自测，全在 `/tmp` 沙盒，不碰 `/etc`、不碰设备 |

### 4.2 用法

```sh
scripts/hide-android-partitions.sh                 # 默认 --dry-run：打印将写什么 + 每个分区 keep/HIDDEN 预演
scripts/hide-android-partitions.sh --check         # 只读；rc=0 = 已符合期望（适合进 check-doctor）
sudo scripts/hide-android-partitions.sh --apply    # 需 root（本会话拿不到 sudo ⇒ 由主代理执行）
sudo scripts/hide-android-partitions.sh --revert   # 撤销
# 追加白名单：
sudo scripts/hide-android-partitions.sh --apply --keep mydata
```

### 4.3 生成的规则长这样（默认白名单）

```udev
ACTION!="add|change", GOTO="hide_android_partitions_end"
SUBSYSTEM!="block", GOTO="hide_android_partitions_end"
ENV{DEVTYPE}!="partition", GOTO="hide_android_partitions_end"

ENV{ID_PART_ENTRY_NAME}=="linux17|eldenesp|linux", GOTO="hide_android_partitions_end"

ENV{ID_DRIVE_FLASH_SD}=="1", GOTO="hide_android_partitions_end"
ENV{ID_DRIVE_FLASH_MMC}=="1", GOTO="hide_android_partitions_end"
ENV{ID_BUS}=="usb", GOTO="hide_android_partitions_end"

ENV{UDISKS_IGNORE}="1"

LABEL="hide_android_partitions_end"
```

### 4.4 离线自测结果（`sh scripts/hide-android-partitions-selftest.sh`）

**22 项 PASS / 0 FAIL**（全文 = `out/hide-android-partitions-20261119/evidence.txt` 末段），要点：

- `sh -n` 通过；
- `--dry-run` **一个文件都没写**，且正确把 `sda1 system` 判 `HIDDEN`、`sda18 linux17` 判 `keep`；
- `--check` 在干净状态 **rc=1**，apply 后 **rc=0**；
- `--apply` 后 fstab 恰好 3 行加 `x-gvfs-hide`；`/boot/efi` 与「按 UUID 写的 TF 卡」**未被改**；
- `udevadm verify <规则>` → `1 udev rules files have been checked. Success: 1 / Fail: 0`（**语法级已验证**）；
- 二次 `--apply` = 幂等（规则「已是最新」、fstab 未变）；`--revert` 后 fstab **逐字节**回到原始、规则文件被删。

### 4.5 一个踩到的坑（写在这里免得再踩）

`case` 的模式里**不能**用 `|`：`case "|$LIST|" in *"|$x|") …` 在 dash 与 bash 下**永不匹配**
（实测 `K="linux17|eldenesp|linux"; case "|$K|" in *"|linux17|") → nomatch`，即使加了引号）——
`|` 在 case 模式列表里始终被当备选分隔符。脚本因此维护两套表示：`KEEP_CSV`（逗号，shell 比对）与
`KEEP_ALT`（`|`，只给 udev 规则用）。

第二个坑：`lsblk` 的 **`-l` 与 `-P` 互斥**（`互斥参数： --pairs --tree --list --raw`），且 `-o NAME,PARTLABEL,TYPE`
在 `PARTLABEL` 为空时列会被辞崩（分区行只剩 2 个字段 ⟹ `$3` 拿不到 `part`，全部误判成整盘）。
改法：`lsblk -pno NAME,PARTLABEL,TYPE -P` + awk 解 `key="value"` 对；已实测主机 nvme 上 `TYPE="part"` 过滤正确。

## 5. 上机验证判据（Linux 起来之后）

> 前置：Linux 根已在机（当前设备在 fastboot/Android，`linux17` 数据仍在、GPT 条目待重建 ⇒ 本 lane 的判据**现在无法执行**）。

### 5.0 先确认「是哪个 app 在画侧栏」（可选，1 条）

```sh
dpkg -l | grep -E 'nautilus|portfolio|thunar|nemo|pcmanfm'   # 期望：有就用它对照；空 = 说明是 GTK 文件对话框侧的 places
```

### 5.1 apply 后立刻跑（3 条，含期望输出）

```sh
# ① 分区与 PARTLABEL（对照白名单）
lsblk -o NAME,PARTLABEL,SIZE
```
期望：`sda` 下能看到 `system`/`vendor`/`persist`/`metadata`/`modem`/`linux17`/`eldenesp` 等名字**照旧**（脚本不动分区表）；
只有 `linux17`、`eldenesp`（和 `--keep` 的项）在下一步里 HintIgnore=FALSE。

```sh
# ② udisks 眼里谁被忽略（逐分区打印 HintIgnore）
for d in $(lsblk -lno NAME,TYPE | awk '$2=="part"{print $1}'); do
  printf '%s HintIgnore=' "$d"; udisksctl info -b "/dev/$d" | sed -n 's/^ *HintIgnore: *//p'
done
```
期望：**非白名单分区全部 `true`**（`system/vendor/persist/...`），`linux17`/`eldenesp` 为 `false` 或**不打印**（udisks 对
HintIgnore=true 的块可能不列 `HintIgnore` 行——两种都算通过，判据是「白名单项不出现 true」）。
若全是 `false` ⇒ 规则没生效：看 `udevadm info -q env -n /dev/sda5 | grep UDISKS` 是否为 1，
再 `udevadm control --reload-rules && udevadm trigger -s block -a change`。

```sh
# ③ 文件管理器那一侧（与 Nautilus 侧栏同源）
gio mount -l
```
期望：**不再出现** `system` / `vendor` / `persist` / `metadata` / `modem` 等卷；只剩
`/`（root，本来就算 system-internal 不显示）、可能的 `/mnt/Samsung`（TF 卡，我们不动）、以及已挂载的 `linux17` 相关项。
`gio mount -l` 的说明就是 "List user-interesting volumes, drives and mounts"（`glib/gio/gio-tool-mount.c:76`），
与 GTK places sidebar / Nautilus 走同一个 `GVolumeMonitor`。

### 5.2 图形侧目视（需人）

打开文件管理器（或任一 GTK 应用的文件对话框）→ 侧栏「其他位置 / Other Locations」：**只剩白名单 + 可移动介质**。
这一步是**最终验收**；①②③ 是它的机制级代理判据。

### 5.3 回退

```sh
sudo scripts/hide-android-partitions.sh --revert
# 或手工：
sudo rm -f /etc/udev/rules.d/79-hide-android-partitions.rules
sudo udevadm control --reload-rules && sudo udevadm trigger -s block -a change
# fstab 若是本脚本改的：脚本会留 /etc/udev/hide-android-partitions.state（行号）与 /etc/fstab.bak-hideandroid-<ts>
```
回退**不影响任何分区内容**（脚本从头到尾不写设备、不 umount、不改 GPT）。
