## §1 提交 1：bonded 全局态收进 `struct msm_dsi_manager`

commit `5a3edf6e2`（内核树）· `drivers/gpu/drm/msm/dsi/dsi_manager.c` 净 +5/−4。

- 删除文件级 `static bool dsi_bonded_cmd_failed;`，改为 `struct msm_dsi_manager` 的成员 `bonded_cmd_failed`（正好落在 `msm_dsim_glb` 那一族结构里）。
- 三处读写随之变成 `READ_ONCE/WRITE_ONCE(msm_dsim_glb.bonded_cmd_failed, …)`：`msm_dsi_manager_cmd_failed()`、`dsi_mgr_bridge_enable()`（panel 未 prepare 的拒绝路径）、`dsi_mgr_bonded_cmd_xfer()`（DMA 失败置位）。
- 保留 `dsi_bonded_cmd_lock`（那是锁不是状态），注释补一句说明“它保护的失败标志已进 glb”。
- 现有 `is_sync_needed` / `is_bonded_dsi` / `master_dsi_link_id` 本来就在该结构里，本轮不动（它们的语义收编属于设计稿第 4 步，会变行为）。

判据（原始输出见 §4）：`grep -c "static bool dsi_bonded_cmd_failed" dsi_manager.c` = **0**。

> 续跑说明：这份改动是上一轮被中断时留在内核树里的未提交 diff，本轮先 `git diff` 逐行复核确认等价（无残留 file-static、读写点齐全）后直接沿用，再补跑编译门才提交。


## §2 提交 2：per-SoC `msm_dsi_bonded_cfg` + 常量参数化

commit `fb8f38d95` · 三文件 +26/−6。

**`dsi_cfg.h`**：新增 `struct msm_dsi_bonded_cfg`（字段与设计稿 §3 逐条对齐：`master_link_id` / `cmd_dma_ctrl` /
`err_clear_bits` / `err_cleanup_bits` / `poll_timeout_us` / `needs_link_clk_bump` / `needs_sw_reset`），
并在 `struct msm_dsi_config` 加 `const struct msm_dsi_bonded_cfg *bonded;`（`NULL` = 无 bonded 能力）。

**`dsi_cfg.c`**：新增 `sm8750_dsi_bonded_cfg`，值**逐字取自现状**：

| 字段 | 值 | 来源 |
|---|---|---|
| `master_link_id` | `DSI_0` | DT `qcom,master-dsi` 挂在 `&mdss_dsi0`（`sm8750-lenovo-elden.dts:2376`）⇒ 现状实际主链 = DSI0 |
| `cmd_dma_ctrl` | `DSI_CMD_DMA_CTRL_BROADCAST_EN \| FROM_FRAME_BUFFER` | `dsi_bonded_cmd_stage()` 原有置位（`dsi.xml.h` 有定义） |
| `err_clear_bits` | `0x001f0200` | `dsi_cmd_error_prepare/cleanup()` 原字面量 |
| `err_cleanup_bits` | `0x44440400` | `dsi_cmd_error_cleanup()` 原字面量 |
| `poll_timeout_us` | `5000` | 原 `for (i = 0; i < 500; i++) … udelay(10)` = 500×10 us |
| `needs_link_clk_bump` / `needs_sw_reset` | `true` / `true` | 现状 SM8750 走 `dsi_cmd_link_clk_set_rate()` 特判与 `dsi_sw_reset_v2_9()` |

表项挂在**既有 `sm8650_dsi_cfg`** 上，而不是新增一张 SoC 表：SM8750 的 DSI 版本寄存器报 **V2_9_0**，
`dsi_cfg_handlers[]` 里 V2_9_0 指向 `&sm8650_dsi_cfg`（`io_start` 也正是本机 `ae94000/ae96000`，只有它能匹配），
所以 bonded 数据必须跟这张表走。用仍然由 `of_device_is_compatible("qcom,sm8750-dsi-ctrl")` 闸门，因此真正的 SM8650 设备行为不变。
文件里已写明这一点的注释。

**`dsi_host.c`**：新增 `dsi_bonded_cfg(msm_host)` 取表助手；`dsi_cmd_error_prepare/cleanup()` 改读 `bonded->err_*`；
`dsi_bonded_cmd_stage()` 的 `BROADCAST_EN|FROM_FRAME_BUFFER` 改为 `val |= dsi_bonded_cfg(...)->cmd_dma_ctrl`；
`dsi_bonded_cmd_poll_slave()` 改成按 `poll_timeout_us` 以 10 us 步长计时的循环。

判据：`grep -c 0x001f0200 dsi_host.c` = **0**，`grep -c 0x44440400 dsi_host.c` = **0**（都搬进了表）。

> `needs_link_clk_bump` / `needs_sw_reset` 本轮只是**登记数据**，`dsi_cmd_link_clk_set_rate()` / `dsi_sw_reset()`
> 仍用 compatible 判断（那两处属设计稿第 5 步的隔离层，本单不动）。


## §3 提交 3：十个直调 → 两个 host ops

commit `768b7c11d` · 5 文件 +107/−74（`dsi_manager.c` 净 −42）。

- `dsi_cfg.h` 的 `struct msm_dsi_host_cfg_ops` 新增两个回调：
  `.bonded_cmd_xfer(host, peer, msg)`（跑一次广播命令）与 `.bonded_wait_video(host)`（等视频引擎空闲）。
- `dsi_cfg.c`：只在 `msm_dsi_6g_v2_9_host_ops` 上挂实现（SM8750 报的就是 V2_9_0，是当前唯一的 bonded 代）。
- `dsi_host.c`：十个 `msm_dsi_host_bonded_*` 改名为 `dsi_bonded_*` 并降为 **file-static**；
  事务主体从 manager **原位搬入** 新的 `msm_dsi_host_bonded_cmd_xfer()`（步骤顺序、`wmb()` 位置、master/peer 触发顺序均逐行不变）；
  新增 `msm_dsi_host_get_cfg_ops()` 供 manager 取 ops。
- `dsi_manager.c`：`dsi_mgr_bonded_cmd_xfer()` 只剩“查 master link → 取 peer → 调 ops”，
  失败置位改走新的 `msm_dsi_manager_mark_cmd_failed()`（提交 1 的 glb 字段仍是唯一存放处）。
- `dsi.h`：十个原型的 **10 → 2**（`msm_dsi_host_bonded_cmd_xfer` / `msm_dsi_host_bonded_wait_video`）。

判据：`grep -c "msm_dsi_host_bonded" dsi.h` = **2**（≤ 3 达标）；
`git grep -n msm_dsi_host_bonded_ -- dsi_manager.c` = **无命中**（只剩 `ops->bonded_cmd_xfer(...)`）。

> 注意：master 仍由 `msm_dsim_glb.master_dsi_link_id`（probe/bind 顺序）决定，这是“行为中性”的前提；
> 改成读 `bonded_cfg->master_link_id` 是设计稿第 4 步，会变行为，本单不做。

## §5 剩余风险与未做

**未做（按派工单范围）**：
1. 设计稿第 4 步「master 改由 `bonded_cfg->master_link_id` 决定」—— 会变行为，必须上机，本单不做。
   当前 `master_link_id` 字段只是**登记**了现状值（DSI0），未参与判断，所以改了也不会生效。
2. 第 5 步隔离层（`err_*` 的 `TODO(doc)`、`dsi_sw_reset_v2_9()` 细节）—— RFC-SCOPE R1 阻断项，不进上游包。
   同理 `needs_link_clk_bump` / `needs_sw_reset` 目前**只是数据**，两处兼容判断未改。
3. 未上机（本 lane 零设备）。

**剩余风险**：
1. **bonded 表挂在 `sm8650_dsi_cfg` 上**：SM8750 与 SM8650 撞 DSI 版本 V2_9_0、只有这一项能匹配本机 `ae94000/ae96000`，
   所以贴在这里是唯一正确选择；但真正的 SM8650 设备将**看到** `cfg->bonded != NULL`。现有代码访问 bonded 的三处
   （error prepare/cleanup、cmd_dma_ctrl、poll_timeout）**全部位于 SM8750 兼容闸门内**的 bonded 事务里，所以不会触发；
   后续如果有人拿 `cfg->bonded` 当“这个 SoC 支持 bonded”的判据，需记得先把闸门搬进表。
2. **`cmd_dma_ctrl` 只包含原来无条件置的两位**：`init_trigger` 里清 `BLOCK_DMA_WITHIN_FRAME`/`DMA_TRG_MUX`
   等仍留在代码里（它们是“清除”而非“配置”，带语义，未入表）。
3. **`msm_dsi_host_get_cfg_ops()` 是新导出的访问器**，放宽了 manager 对 host 内部的可见面；若上游更倾向
   把该判断放进 manager 自己持有的 cfg 指针，这里还可再收。
4. **行为等价未经设备验证**：三步都是搬移，判据是 grep + 编译，按设计稿即是静态口径；时序/亮度/反复熄亮需上机（设计稿 §5）。
