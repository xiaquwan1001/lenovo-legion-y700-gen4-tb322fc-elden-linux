## 2. ★两个失败与一个真结论

### 2.1 真结论：18:19 的卡死**不是** m8v5 内核造成的 —— 那一发根本没跑到测试臂

排查（设备恢复后从 journal 取）：

```
boot -1：Linux version 7.3.1-debug-vk189-suspend-00005-g4bdf1711b5c0   ← vk192，不是 00008
        Kernel command line: … elden_bootmenu=grub-daily              ← 臂 0 的标记（臂 1 会写 grub-mb8v5）
        末尾 8 行 = Waydroid android init：init.waydroid.rc 的 `boot` action
kernel 侧诊断计数：soft lockup / hung task / RCU stall / watchdog BUG = **0**
```

⇒ 症状 = **`PITFALLS #106`「进 GUI 后整机卡死，无 panic、网络不通」的复发**（本机 APSS 硬看门狗被永久禁用，
这类死挂不会自复位），时间点与 **Waydroid 容器 bootstrap** 重合（最后一行日志就是 Waydroid 的 `boot` action）。
与 m8v5 内核、与本次实验件均无关。

同时排除「脚本」假设（用户怀疑的那条）：该 boot 里没有任何自研脚本被执行，`/etc/local.d/` 为空，
设备侧无人值守项只有 `pi-tablet-night.timer`（23:00 才跑，且脚本默认 `DRY_RUN=1`、`needs_device=false`、带 `timeout -k`）、
`elden-bootlog` / `elden-powerlog` / `ssc-udp-relay` / `hexagonrpcd-*`（均在本 boot 早期正常启动，无异常输出）。

### 2.2 失败一：**grubenv 选臂完全不生效**（所以两台都是臂 0）

现象：ESP 上装的确是 v11b（sha `07558bde…`，18:10），但两次 a 槽 boot 都是臂 0，且**一个 `elden_dbg_*` 键都没写进 grubenv**
（v11b 在 cfg 顶部有 `save_env … elden_dbg_loadenv/elden_dbg_arm/elden_dbg_default` 打点）⇒ 顶层的
`search --label linux17` + `load_env -f ($root)/boot/grub/grubenv` + `save_env` 这一组**在 menuentry 之外没有生效**。
`grubenv` 里那条 `51-daily-vk192-initrd-ok-booting` 是 18:06 那发（臂 0）留下的旧值，不是本发写的。

处置（已改）：**放弃 grubenv 选臂**，改成**编译期固定 default 的两枚 EFI**，切臂 = 换 ESP 上那一个文件（8 MB，5 s）：

| 件 | sha256 | 用途 |
|---|---|---|
| `out/grub-arm64-arming-20261116/grubaa64-ab-arm0.efi` | `6a8d2595…` | 基线臂（vk192 现役） |
| `out/grub-arm64-arming-20261116/grubaa64-ab-arm1.efi` | `60037bc7…` | 测试臂（M8 v5） |

### 2.3 失败二（次要）：`grubenv-set.sh` 首版会把整块 key 清掉

我的 `scripts/grubenv-set.sh` 第一版按 `data.split(b"#")` 取正文 ⇒ 文件首行注释 `# GRUB Environment Block` 让正文变空，
把 10 个旧键全丢了。**已修**（改为逐行跳过 `#` 开头）并从 `/boot/grub/grubenv.bak-20261116` 恢复。

## 3. 关键纪律（下次开台架前照做）

1. **按电源前先起 `scripts/serial-tap.py`**：本机 `ttyACM0` 是内核 console（`console=ttyGS0`），
   硬冻结时它是唯一能拿到尾部的通道；18:19 那次没起 tap ⇒ 只剩「journal 停在 Waydroid boot action」。
2. **实验期间 `q28-watchdog.sh off`**（本轮已 off）——否则看门狗会在 100 s 处把台架重启掉。
3. G1 侧已知干扰项要 mask：`systemctl mask waydroid-container ssc-udp-relay`（重、且与显示/ADSP 强耦合），
   A/B 只留 phosh 栈，判据才干净。
4. `boot_a` 的 ESP 菜单必须始终有一条「vk192 基线」臂，且默认指向它；测试臂只能靠换 EFI 或菜单手选。
