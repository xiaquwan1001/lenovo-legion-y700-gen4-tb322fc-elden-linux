# Q32 · 首份 W1 样本（暖复位，vendor 0x80010001）—— pstore 通道验证成立

> 日期：2026-10-24 凌晨 · 设备 U2 `HA2EXB0E`（在机 `boot_b` = vk152）
> 前序：`reports/q32-kickoff-20261023.md`（工具落地）、`reports/q32-warm-vs-cold-preresearch-20261023.md`（预研）
> 产物：`reports/trials/20261024T021347Z-q32w1-r1/`（含 `pstore-prev-boot.log`、`serial-delta.log`、`probe.txt`、clkdiag）
> 纪律：**1 发样本，不足以出结论**（判据要求同臂 ≥2 发一致）；本文只固定「通道可用 + 这一发的量」。

## 0. 结论先行

1. **pstore/ramoops 通道验证成立**：本次启动读到了上一个内核在复位路径上的决定性打印 ——
   ```
   [  110.947437] reboot: Restarting system with command 'bootloader'
   [  110.947437] psci: SYSTEM_RESET2 vendor reset_type=0x80010001 cookie=0x2 (cmd=bootloader)
   ```
   ⇒ **W1（暖 vendor 复位）在证据上是可自证的**，不必依赖用户口头声明，也不必依赖串口。
2. **串口在这条路径上会丢这一行**（同一发 `serial-delta.log` 249 246 B 里 0 命中）：
   本机 console 是 USB gadget（`console=ttyGS0`），`pr_info` 后立刻 `invoke_psci_fn()` ⇒ 主机还没轮询就断链。
   ⇒ **复位深度证据以 pstore 为准，串口只作辅助**（更正 `TASKS §5 Q32` 早先「串口/或只有 dmesg」的含糊写法）。
3. **这一发（W1 r1）的量**：`VERDICT=GOOD`（card0 + DSI-1 connected + 0 风暴）、
   `FW_LIVE_FB=yes`（`silent_boot.mode=nonsilent` + msm 记录 boot FB IOVA）、`SIMPLEDRM=0`、
   `disp_cc_mdss_pclk0/1_clk_src` 均 `172972734 Hz` / parent `dsi0_phy_pll_out_dsiclk`（两路一致 ⇒ Q28 判据 1 通过）。
4. **pstore「空」的三种含义要分清**（本机已实测）：① 真 POR/断电 ⇒ 空（本轮 3 次）；
   ② 已知暖复位 ⇒ 有 `SYSTEM_RESET2 vendor` 行（本例）；③ 已被读过一次 ⇒ 也空（**读后即删**）。
   所以只有「读到行」是强证据，读不到不能反推冷起。

## 2. 本发流程（可复现）

```
scripts/q32-arm.sh w1 1
  → 就绪门（uptime≥90 s + phoc/phosh 在）        # 见 §3 的坑
  → sync; eldroid-bootctl reboot bootloader       # RESTART2 reason="bootloader"
  → 等 fastboot（出现 = vendor 路径的结果级证明，架构 SYSTEM_RESET 只会正常启动）
  → fastboot reboot（单条，不接管道）
  → 新 boot：先取 pstore（读后即删）→ clkdiag → devprobe → trial record
```

## 3. 本轮踩到的两个坑（已修进脚本）

1. **就绪门只过了一次**：Round 2 在上一发刚起来 ~35 s 时又发 `reboot bootloader`
   ⇒ **USB 全不枚举**（无 fastboot、无 `ttyACM*`、无 SSH），只能人物理断电 —— 正是 `PITFALLS #368` 的形态。
   **修法**：`q32-arm.sh` 每发之前重新过就绪门（`PITFALLS #376`）。
2. **`grep -c` 失败时返回两行**（`0` + `0`），把 `set -u` 的整数比较打崩 ⇒ 取证中断、样本作废。
   **修法**：`| head -1` + `${VAR:-0}` 兜底。
