## 3. 索引行统一模板（最小设计）

### 3.1 模板

```markdown
| NN | 一句话主题（≤ 30 字，动词开头） | [NN-文件名](sessions/NN-文件名.md) |
```

- `NN` = **文件名前导数字**（不是中文"三十八"）——现在是"三十八 → 38-*.md"要靠人脑换算，
  且中文数字让排序无法机械进行（实测 `L75`(五十) 排在 `L77`(四十五) 前）。
- 三列而不是两列：加中列后，「一句话主题」有了固定落点，避免再次退化成"结论堆"。

### 3.2 单元格长度上限（建议值）

| 项 | 上限 | 理由（可机器校验） |
|---|---|---|
| **中列（主题）** | **≤ 80 字符 / ≤ 200 字节** | 一行终端/一屏表格可读；超过就要问"这是正文还是索引" |
| **整行** | **≤ 800 字节** | 现值中位数 ~150 B，超长行 ≥800 B；800 B 正好是"9 个问题行"的下沿，改完不会有行贴着上限 |
| **单格内 `#NNN` 引用数** | **≤ 2** | 现值 L78 达 12 个 ⇒ 一行 = 一个节的目录 |

### 3.3 如何"不丢信息"地收缩（三选一，按优先级）

1. **搬正文**（默认）：内容属该节细节 ⇒ 已在 `sessions/NN-*.md`，索引直接删，只留主题词。
2. **搬 TASKS 的 Q 行**（仅 Q28/Q24/Q26 相关）：如果这条其实是**任务状态**（如「未解 / n=2 / 待 N5b 扩样」），
   SSOT 是 `TASKS/README.md` §5 的 Q 行（对照 `TASKS/README.md:34-37` 已有完整 #349 口径更正），
   索引里改为「见 `TASKS/README.md` §5 Q24」。
3. **丢弃**（纯枚举）：把 8–12 个编号压进一格只为证明"我这节有这些条"——正文目录天然具备该功能，
   直接丢。

### 5.2 加两条规则（改 `COUNT_RULES` + 一条新正则）

**(a) 让 `#1–#N` 受管**（`check-doctor.sh:313-315`）：

```python
COUNT_RULES = [
    ('INDEX.md', r'PITFALLS[^\n]*?(\d+)\s*节', 'PITFALLS'),
    # 新增：PITFALLS 抬头的条目号上界必须 = 正文实际最大编号
    ('PITFALLS/README.md', r'条目编号\s*#1\s*[–-]\s*#(\d+)', 'PITFALLS'),

```
但第二条的"真值"不是行数，而是**最大编号**，所以要在循环里按 `pat` 分派。
最小改法（不重构）：给 COUNT_RULES 元组加第 4 项 `truth_kind`：

```python
COUNT_RULES = [
    ('INDEX.md',          r'PITFALLS[^\n]*?(\d+)\s*节',          'PITFALLS', 'rows'),
    ('PITFALLS/README.md', r'条目编号\s*#1\s*[–-]\s*#(\d+)',      'PITFALLS', 'maxid'),
]
# …循环内：
nums = []          # 所有正文条目号
for f in glob.glob(os.path.join(root, ang, 'sessions', '*.md')):
    for ln in open(f, encoding='utf-8', errors='replace'):
        m = re.match(r'^(?:##\s*#?|)(\d{1,3})[.\s]', ln)   # 同时吃 `NNN. ` 与 `## #NNN `
        if m and ln.startswith(('##', ) + tuple(str(d) for d in range(10))):
            nums.append(int(m.group(1)))
real = len(set(nums)) if kind == 'rows' else max(nums)
```

**(b) 顺手修 DUPNUM 的盲区**（`check-doctor.sh:292-295`）——这条**比计数更重要**，
因为 `#337/#338/#339` 的缺口正是它漏掉的：

```python
# 现状（只认 `NNN. `）：

```
改完后立刻会暴露的既有问题（**这就是收益**）：
- `#337/#338/#339` 只在 `README.md:71`，正文无定义 ⇒ 应报「引用但未定义」（可再加一条 NEWREF 规则）；
- `28-上游邮件通道.md:9` 用 `218.`，而 `28-*.md:3` 是 `257.` ⇒ 该文件条目号已乱序（人工确认后再定是否重编）。

**(c) 抬头改成不写死数字**（`PITFALLS/README.md:6-7`）：

这样 `#1–#353` 这个必漂移的数字从文档里消失，`check-doctor` 也就无需为它维护真值。
