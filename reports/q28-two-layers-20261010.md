# 显示"背光无画面"实为两层故障（2026-10-10 串口实测 + 源码核实）
> ⚠ 已被取代：`reports/q28-DOSSIER.md` §b B2 + `PITFALLS #164`（根因=L1 cmd-DMA hang，L2 仅下游；本文正文「建议下一步」主张 L2 为主因已被推翻，见 DOSSIER g-6） — 仅历史留痕，当前口径以领域层/ q28-DOSSIER 为准。

## ★根因确认（2026-10-10 日志差分铁证，覆盖下文初判）
同 log(15 boot) 分段分类：GOOD 4 次 `commandDMA=0/initfail=0/ctlreset=0/framedone=0`；BAD 11 次**全部**先有 `ae94000+ae96000 command DMA timeout status=0x2200200 master=-110 peer=-110`（面板首条 DCS `dcs data ff 20` 即超时），init 重试 3 次仍失败(-110→-5)，**4ms 后**才 `dpu_encoder_phys_vid ctl 1 reset failure -22`/frame done/vblank 风暴→自发重启。
**完美共现 ⇒ L2(DPU CTL 卡死) = L1(bonded 双 DSI 首条 DCS 命令 DMA hang) 的下游。根因 = L1。** delay/byte-clk 方向正确，之前暖起 A/B 测不到才误判。修复靶点：`msm_dsi_host_bonded_cmd_trigger` 写 REG_DSI_TRIG_DMA 前后（settle / 取整 byte-clk）。冷起才复现。

## 结论先行
之前把 Q28 当单一问题（bonded DSI CMD DMA / PLL re-lock / byte-clk）**以偏概全**。现场 + 源码证明是**两层独立故障**，都能造成"纯背光无画面"，且**面板是 VIDEO 模式**（非 CMD）：

| 层 | 现象/签名 | 子系统 | 现状 |
|---|---|---|---|
| **L1 面板初始化** | `panel-novatek-nt36536 ae94000.dsi.0: panel init attempt 1/2 failed: -110/-5`；注释"bonded 首条 DCS 写 **~60% 启动**超时" | DSI 命令 DMA（init 用 DCS） | 已有 retry 缓解（`d02658e63`，重试≤2）；仍失败→`Failed to init panel: -5` |
| **L2 视频流式（当前"背光无画面"主因）** | `dpu_encoder_phys_vid_prepare_for_kickoff: enc35 intf1/intf2 **ctl 1 reset failure: -22**` + `dpu_encoder_frame_done_timeout` + `wait for commit done returned -110` + 反复 `vblank wait timed out on crtc 0` | **DPU** video 编码器 / `dpu_hw_ctl` / DSC+bonded intf | 未定位 |

## 关键源码事实（逐条核实）
- 面板 `csot,pp8807hb1-1`(=`novatek,nt36536`)，`drivers/gpu/drm/panel/panel-novatek-nt36536.c:530`：
  `mode_flags = MIPI_DSI_MODE_VIDEO | MIPI_DSI_CLOCK_NON_CONTINUOUS | MIPI_DSI_MODE_NO_EOT_PACKET | MIPI_DSI_MODE_VIDEO_BURST | MIPI_DSI_MODE_LPM | MIPI_DSI_MODE_DSC_ALL_SLICES_IN_PKT`
  → **VIDEO_BURST + DSC，双 DSI（is_dual_dsi / bonded，enc35 intf1+intf2）**。
- `novatek_prepare()` 顺序：reset → **init_sequence（DCS，L1 在此 -110）** → DSC PPS → compression_mode → **backlight_enable** → return 0。
  ⇒ **背光是在 init 成功之后才开**的。故"看到纯背光"= init 已过 = 当前坏发属 **L2（DPU 视频 CTL）**，不是 init 层。
- `ctl 1 reset failure: -22`（EINVAL）在 `dpu_encoder_phys_vid_prepare_for_kickoff`：多为 encoder 的 ctl/pp 控制路径未正确 assign 或 CTL reset 握手失败——**DPU 内部配置/状态问题**，与 DSI 时钟取整无关。

## 对既有路线的影响（重要）
- **Method B（byte-clk 取整 / 上游 2028280686f4）针对的是 DSI 时钟 re-lock，属 L1 侧**，且本树是 7.2 基线、上游逐字移植无效（见 q28-upstream-diff 报告）。**它不解决当前 L2 的"背光无画面"**。
- L1 已有 retry 兜底（虽丑但能出 init）；真正让面板"黑/背光"的是 **L2 DPU CTL reset -22**。

## 建议下一步（待用户裁决方向）
1. **转向 L2 DPU 线**：查 `dpu_encoder_phys_vid_prepare_for_kickoff` 的 `ctl reset -22` 来源——
   `cur_ctl`/`cur_pp` 是否 assign、DSC+双DSI(intf1+intf2) 的 CTL/PP blk 分配、`dpu_hw_ctl_reset_claim`/`_reset_control` 为何 EINVAL；与 vk 哪版引入相关（对比能点屏的历史 vk）。
2. **区分实验**：一次干净启动里，先看 `panel init` 有没有 -110/-5（L1），再看 modeset 后有没有 `ctl 1 reset failure -22`（L2）。已知坏发还会**自发重启**（DPU commit 卡死→看门狗/panic）。
3. 若 L2 是主控因，L1 的 byte-clk/delay 全都不是优先级；先坐实 L2 根因（可能需要 dpu_encoder/dpu_crtc/dpu_hw_ctl 侧 DT/驱动 diff 或上游 DSC+bonded 补丁）。
