# Q24 受控复现（2026-10-12 第 3 轮）：干净无相机台架 + 三值仪表硬门 + 首例硬门有效死亡

> ⚠️ **2026-10-12 晚更正（第 8–9 轮）**：本文中「起点必须是物理 POR / 需物理 POR」类表述**已被取代**——Q24 致死 = **SoC 级复位**，USB 掉线后约 30 s **自动重启回日常 boot_b**（当日 6/6 复现），**不需要物理 POR**；「POR 起点」只约束「进 fastboot + RAM 镜像」这条路，而**当前首选台架 = 日常 boot_b 自身**（`SKIP_BOOT=1` 复用活台架）。见 `PITFALLS #209`、`reports/q24-noc-20261012.md` §3。

> 承接 `reports/q24-ctl-20261012.md`（§10 的下一步）。原始数据：`logs/q24-s123b-20261012-110712/`、`logs/q24-instr-20261012-110545/`。设备 U2。

## 0. 一句话

在**干净无相机**（cam=0）RAM 台架上：**仪表硬门 3/3 通过**（真实熄屏 ⇒ `GetActive=true` + `DPMS=Off` + RPMh mmcx/cx 降档票）后：**S1（`{camcc}`，不熄屏 60 s）存活**、**S2（`{camcc,cambist}`，不熄屏 300 s）存活**；**S3 真实熄屏成功、且 +11 s 未立即致死**，但在随后的**唤醒（`SetActive false`）** 时设备**硬复位**（USB 11:15:04 断开 → 11:15:37 回落日常 boot_b）。死亡前最后 RPMh 票 = **`gfx.lvl`(0x30050)=1 / `gmxc.lvl`(0x300d0)=1（GPU 域上电）+ NoC 批** —— 与历史「熄屏即死、末票 `mxc.lvl→0`」**不同型**。

| 项 | 值 |
|---|---|

| cmdline | `… elden_nocamera=1`，`cam=0` 门控生效 |

## 2. 仪表硬门（本轮新方法，与会话可用性分开判定）

`cam=0`，`SetActive true` ⇒ **3/3 通过**：

```
GATE_BEFORE active=(false,) dpms=On bl_power=0 bright=511
SETACTIVE_true=()
GATE_AFTER5 active=(true,) dpms=Off bl_power=0 bright=511   ← 屏真关
mmcx/cx 票 = 4 条                                            ← 内核侧真降档
```

⇒ **不再需要「Q28 GOOD 台架」**：L1FAIL 台架照样能给出有效的熄屏仪表（`PITFALLS #198` 的三值判据升级为「台架准入」）。

## 4. 死亡前 RPMh trace（逐行）

```
739.799832  mmcx.lvl (0x30080) = 0x2      ← blank（phoc）
739.799959  cx.lvl   (0x30000) = 0x5      ← blank
747.09x     一批含 irq/229-dwc3 的票（0x429xx/0x40xxx/0x41fxx）  ← ⚠️ USB 控制器，疑似本会话 SSH 活动
752.698510  gfx.lvl  (0x30050) = 0x1      ← GPU 域上电（wake 路径）
752.699391  gmxc.lvl (0x300d0) = 0x1      ← GPU 域上电
752.701760  NoC/MC0 (0x50000…) 批
           → trace 静止 = 死亡
```

**归因候选**：死亡点在**唤醒 → GPU 域 resume** 路径；`mxc.lvl`(0x300a0) 全程无票（与本台架稳态 `mxc=off-0`、消费者只有 dispcc 一致）。

## 5. 对照与不确定性（必须并列）

1. **同台架 cam=0 对照**：11:07 仪表检查做过 `wake → blank → wake` ×1 轮（`logs/q24-instr-20261012-110545/`），**存活** ⇒ 「相机对在位与否」是差异项。**N=1，不足以下因果结论**。
2. **本轮无串口记录**：runner 的 `SKIP_BOOT=1` 分支漏启 `serial-logger`（已修）⇒ 无法判定 panic / 看门狗 / 纯 hang。**下轮必须带串口**。
3. **死亡点与 `PITFALLS #198` 的「坏台架」同路径**：那次是 phoc 卡在 `adreno_get_param → __pm_runtime_resume`（**GPU resume**）。本轮死亡同样落在 GPU 域上电之后 ⇒ 下轮必须把「blank」「wake」「GPU resume」三者分离。
4. **台架本身是 Q28 L1FAIL**（面板从未 init，l2 风暴 456）⇒ 显示栈处于异常态；虽然仪表硬门证明「熄屏指令真的下去了」，但不能排除异常态改变了死亡路径。

## 8. 工具链教训（已固化）

1. **`fastboot` 客户端不得接 `head`/`grep -q`**：SIGPIPE 半途掐断 bulk 传输会**卡死设备 fastboot gadget**（`getvar` 全部超时）⇒ 只能物理 POR。同理任何 `timeout` 掐断 fastboot 传输都有此风险。
2. **`kill 0` 自杀**：`${LOGPID:-0}` 在未设时等于 `kill 0`（杀整进程组）⇒ runner 静默自毁、丢收口日志（本轮 `=== marks ===` 缺失即此因）。
3. **root 连会话总线**：`/tmp/dbus-XXXX` 直连报 `Connection is closed`，必须 `setpriv --reuid=1000 --regid=1000 --init-groups env HOME=… XDG_RUNTIME_DIR=… DBUS_SESSION_BUS_ADDRESS=…`。
4. **`org.gnome.ScreenSaver` 的 `GetActive` 是方法不是属性**：`gdbus … --method org.gnome.ScreenSaver.GetActive`（`Properties.Get` 会报 `No such property`）。
5. **始终开 `serial-logger`**（含复用台架模式）：死亡现场唯一记录。
