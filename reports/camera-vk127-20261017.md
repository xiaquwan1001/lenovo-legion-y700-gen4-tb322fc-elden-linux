## 1. 前摄：真实画面（判据）

- libcamera 输出 `4096×3072` XRGB8888（内存字节序 B,G,R,X），3 帧 30 fps。
- 帧统计（末帧）：B/G/R 均值 **48.3 / 58.0 / 40.5**，max 195/248/180 → 有结构、有层次。
- 缩略图目视：桌面 + 台灯横臂 + 纸袋 + 桌沿，**确认真实场景**。
- **偏绿**是 AWB 未标定（`s5kjns.yaml` / `gc08a8.yaml` 缺失 → IPASoft 回退 `uncalibrated.yaml`，
  且 `Failed to create camera sensor helper`）⇒ **标定缺口，不是驱动/链路故障**。

## 2. 后摄：链路通、场景无光

- 首轮（相机未对光）：RAW10 p50 = **64**（= black pedestal）、p99 = 65、max 66 ⇒ 全黑。
- 对光后重采：末帧 RGB 均值 **37.5/38.3/37.4**、max 49/50/42，**均匀无结构**；
  且 AE 拉到极限 ⇒ 帧率掉到 **0.5–0.75 fps**。
  ⇒ 结论：**后摄镜头仍对着暗面**（不是链路问题；同一内核前摄同时正常出图）。
- 另记：`v4l2-ctl -d /dev/video3 --stream-to` 在使用过 libcamera 之后会 `STREAMON … Operation timed out`；
  同一时刻 `cam -c1` 正常。⇒ 两者对 media pipeline 的占用/配置互相干扰，测 raw 前先让 libcamera 退出。

## 4. 容器侧：真正的缺口是 camera provider（不是 /dev 节点）

实测（容器 RUNNING）：

| 检查 | 结果 |
|---|---|
| `getprop ro.hardware.camera` | **`v4l2`** |
| `service list \| grep camera` | `media.camera`、`media.camera.proxy` **在** |
| `ps -A \| grep camera` | `cameraserver`（pid 121）在跑 |
| `/vendor/bin/hw/` | **无 camera 项**（audio/cas/configstore/drm/gatekeeper/graphics/health/keymaster/light/memtrack…） |
| `find /vendor /system /apex -maxdepth 4 -name '*camera*'` | **空** |
| `/vendor/etc/vintf/manifest.xml` | **无 camera 条目** |
| `/dev/video*`（容器内） | **不存在**（`config_nodes` 未绑定） |

⇒ **C5 的真实成本不是“绑设备节点”，而是容器里没有 camera HAL/provider**。
Waydroid 1.6.2 也没有任何 camera 相关 CLI。

### 建议的实现拆分

1. **主机侧（可独立验收）**：为 `vk127` UTS 编 `v4l2loopback`；用 libcamera 软 ISP 出 YUV（YUYV/UYVY）
   → 写 loopback 节点。验收 = 主机上 `v4l2-ctl -d /dev/videoN --stream-mmap` 出 YUV 帧，且该节点可被任意消费者读取。
2. **容器侧（重活）**：提供 v4l2 external camera provider（AOSP `android.hardware.camera.provider@2.4-external`
   一类），把 loopback 节点映射成 `camera id 0`；需要 Android 侧构建/或找现成预编译。
3. 中间可先用一个“最小证据”验证方向：把主机 `/dev/video0..16` 绑进容器，看 `cameraserver` 是否
   报 `external/0`（预期不会，因为没有 provider，但可留证）。

## 6. 后摄：链路已通，"黑"是曝光问题（libcamera AE 缺口）

| 实验 | 结果 |
|---|---|
| 后摄 `test_pattern=2`（Color bars） | libcamera 输出 mean **123.6**、max **248** ⇒ **整条数字链路（sensor→CSIPHY→CSID→VFE→软 ISP）完好** |
| `test_pattern=4`（PN9） | mean 110.2、max 175 ⇒ 同上 |
| `test_pattern=0` + 默认 `exposure=372, gain=32` | 输出 mean 0.0、max 28 ⇒ 黑 |
| `test_pattern=0` + **手动 `exposure=3100, gain=1500`** | 输出 mean **61/69/51**、max **230** ⇒ **真实画面**（`logs/.../rear7.png`：桌面+台灯底座+鼠标+线缆） |
| 手动曝光下再跑 libcamera（AE 接管前设好） | 同样真实画面，29–30 fps 报告 ⇒ 曝光值被沿用 |

**结论**：后摄不是坏，是 **libcamera 无法控制 s5kjns 的曝光/增益**——
`cam --list` 已警告 `Failed to create camera sensor helper for 's5kjns'`（gc08a8 同样警告），
于是 AE 停在低曝光（372/32）→ 黑；AE 试图拉长时又退化成 0.37 fps。
**修法在用户态**：给 libcamera 补 sensor properties/helper（`sensor_properties.yaml` 的
`black_level` / `gain` 模型 / `exposure` 范围），或应用侧显式给手动曝光。
**另**：`v4l2-ctl -d /dev/video3 --stream-to` 在用过 libcamera 之后会 `STREAMON … timed out`；
真正卡住的是 **csid1 路径**（`dmesg: CSID reset timeout` + `Failed to power up pipeline: -110`），
用 `media-ctl -r` 重置后走 **csid0/vfe0** 路径即可正常抓 raw（本节的 raw 就是这么拿的）。

## 8. 容器侧：镜像里根本没有 camera HAL 二进制（C5 的真实缺口）

| 检查 | 结果 |
|---|---|
| `ro.hardware.camera` | `v4l2` |
| `pm list features` | 报出 `android.hardware.camera.*`（框架默认值，不代表有 HAL） |
| `/vendor/bin/hw/` | 15 项，**无 camera**（audio/cas/configstore/drm/gatekeeper/graphics×3/health/keymaster/light/memtrack/power/sensors/vibrator） |
| `/vendor/lib64/hw/` | **无 camera 项** |
| `/system/bin/hw/`、`/system/lib64/` | **无 camera provider** |
| `persist.vendor.camera.external.enabled` | 未设置（`waydroid prop set` 报 session 状态问题，未生效） |

**上游事实**（检索确认）：Waydroid 一直是通过**把 V4L2 设备透传给 Android 的 external camera HAL**
来"支持相机"的（waydroid#519：被称为 "extremely limited external webcam"，
供二维码这类用途）；做法是 `ro.hardware.camera=v4l2` + external provider 二进制 +
`/vendor/etc/external_camera_config.xml`；而且已知 **external HAL 常见"0 devices"**（waydroid#2365，2026-07）。
**我们的镜像 `/vendor`、`/system` 里都没有这个 provider**（可能是自定义 arm64-only 镜像构建时裁掉了）。

⇒ 结论不变但更具体：C5 容器侧需要 **(a)** 提供 external camera provider（二进制 + config + vintf manifest 条目）
**(b)** 把 `/dev/video100` 通过 `config_nodes` 绑进容器。**(a) 是主要工作量**；
最短路径是换/补一个带 external provider 的 vendor 镜像，而不是自建 AOSP 树。

# 续二：让 AE 真正工作（增益单位 + 黑电平），前摄已达标

## 9. 根因拆解（为什么 AE 不工作）

`IPASoftSimple::configure()`（libcamera 0.7.1, `src/ipa/simple/soft_simple.cpp:227`）在**没有 sensor helper** 时：

```c
/* helper 缺失分支 */
agc.againMax = againMax;   /* 直接用 V4L2 原始增益码 2048 */
agc.againMin = againMin;   /* 32 —— 被当成 "32 倍增益" */
agc.again10   = againDef;
agc.againMinStep = 1.0;
black.level 默认不设（=0）
```

我们两个驱动把 `V4L2_CID_ANALOGUE_GAIN` 的码值**原样写寄存器**（s5kjns 32..2048、gc08a8 1024..16384），
所以软 ISP 把「码 32」读成「增益 32×」，进而压曝光；同时 **黑电平 64(10bit) 没被扣掉**，
AGC 直方图把 pedestal 当成环境光。两条一起导致「AE 收敛到很暗的画面」。

## 10. 两步修复（已上机验证）

**① 驱动侧：让 V4L2 增益单位 = 真实增益**（`patches/camera-ae-fix-20261017/0001-…patch`）
- `s5kjns`：控制范围 `32..2048` → **`1..64`**，写寄存器时 `val = ctrl->val * 32`
- `gc08a8`：`1024..16384` → **`1..16`**，写寄存器时 `val = ctrl->val * 1024`
- 只重编这两个模块（`make -C build/m1-73 M=drivers/media/i2c modules`，vermagic 逐字保持
  `7.3.0-rc7-debug-vk127-00002-g24223e44ad80-dirty`），备份旧 `.ko` 在设备 `/root/cam-ko-bak-20261017/`。
- ⚠ 这是**本地临时措施**（上游正确做法是给 libcamera 加 sensor helper，见 §11）。

**② 用户态：补每传感器 tuning 文件**（`/usr/share/libcamera/ipa/simple/{s5kjns,gc08a8}.yaml`）
```yaml
version: 1
algorithms:
  - BlackLevel:
      blackLevel: 4096      # 64 @10bit << 6
  - Awb:
  - Adjust:
  - Agc:
```
`BlackLevel` 算法读 tuning 文件（`src/ipa/simple/algorithms/blc.cpp:29`），**不需要重编 libcamera**。

## 11. 结果与遗留

| 相机 | 修复后 AE | 画面 |
|---|---|---|
| **前摄 `gc08a8`** | `ExposureTime=32836 µs, AnalogueGain=5.0` | **达标**：mean **114/117/116**、max 255（正常亮度） |
| **后摄 `s5kjns`** | `ExposureTime` 单调爬升（3228→5151→6843→17699 µs）、`Gain` 停在 1.0 | 仍偏暗：软 ISP 输出 mean ~1（该场景确实暗，raw p50≈92 @10bit ≈ 黑电平+7/8bit）|

**后摄遗留**：AGC 在 1 fps 下收敛极慢（软 ISP 4096×3072 只有 ~1 fps），且该场景需要高增益才够亮；
需要继续调 AGC 目标/收敛速度（tuning `Agc` 段）或等 libcamera 侧 helper 落地。
**实用口径**：后摄用**手动曝光**（`v4l2-ctl -d /dev/v4l-subdev28 --set-ctrl exposure=3000,analogue_gain=32`）
可以立刻得到正常画面；`scripts/cam-loopback.sh start rear …` 已内置这一步。

**上游正确修法（待做，两处）**：
1. `src/ipa/libipa/camera_sensor_helper.cpp` 加 `CameraSensorHelperS5kjns`
   （`gain_ = AnalogueGainLinear{1, 0, 0, 32}`、`blackLevel_ = 4096`）与 `CameraSensorHelperGc08a8`
   （`{1, 0, 0, 1024}`、`blackLevel_ = 4096`），注册名 `"s5kjns"` / `"gc08a8"`；
   同时把驱动改回原样（增益码语义不变）。
2. `sensor_properties.yaml` 补这两颗的 `blackLevel`/`testPatternModes`。
   **构建受阻**：设备（Alpine aarch64/musl）当前**无外网**（wlan0 有 IP 但 ping/HTTP 全失败），
   需先给设备做代理/直通（主机做 HTTP 代理）再 `apk add` 构建依赖；也可换 aarch64-musl 交叉工具链在主机编。
