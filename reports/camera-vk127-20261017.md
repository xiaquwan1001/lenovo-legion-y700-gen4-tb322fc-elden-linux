## 1. 前摄：真实画面（判据）

- libcamera 输出 `4096×3072` XRGB8888（内存字节序 B,G,R,X），3 帧 30 fps。
- 帧统计（末帧）：B/G/R 均值 **48.3 / 58.0 / 40.5**，max 195/248/180 → 有结构、有层次。
- 缩略图目视：桌面 + 台灯横臂 + 纸袋 + 桌沿，**确认真实场景**。
- **偏绿**是 AWB 未标定（`s5kjns.yaml` / `gc08a8.yaml` 缺失 → IPASoft 回退 `uncalibrated.yaml`，
  且 `Failed to create camera sensor helper`）⇒ **标定缺口，不是驱动/链路故障**。

## 2. 后摄：链路通、场景无光

- 首轮（相机未对光）：RAW10 p50 = **64**（= black pedestal）、p99 = 65、max 66 ⇒ 全黑。
- 对光后重采：末帧 RGB 均值 **37.5/38.3/37.4**、max 49/50/42，**均匀无结构**；
  且 AE 拉到极限 ⇒ 帧率掉到 **0.5–0.75 fps**。
  ⇒ 结论：**后摄镜头仍对着暗面**（不是链路问题；同一内核前摄同时正常出图）。
- 另记：`v4l2-ctl -d /dev/video3 --stream-to` 在使用过 libcamera 之后会 `STREAMON … Operation timed out`；
  同一时刻 `cam -c1` 正常。⇒ 两者对 media pipeline 的占用/配置互相干扰，测 raw 前先让 libcamera 退出。

## 3. 命令（可复现）

```bash

sh /usr/local/sbin/cam-mode.sh on
sh camera-stream-up.sh rear  stream 4      # /dev/video3
sh camera-stream-up.sh front stream 4      # /dev/video0
cam -c1 --capture=3 --file=/tmp/back2.bin  # 4096x3072 XRGB8888/帧，50 331 648 B
cam -c2 --capture=3 --file=/tmp/front2.bin # 3264x2448? -> 实际 4096x3072? 见下

# 主机侧：RGBA(4B/px, BGRX) -> PNG 缩略图，统计各通道 min/max/mean
```

## 4. 容器侧：真正的缺口是 camera provider（不是 /dev 节点）

实测（容器 RUNNING）：

| 检查 | 结果 |
|---|---|
| `getprop ro.hardware.camera` | **`v4l2`** |
| `service list \| grep camera` | `media.camera`、`media.camera.proxy` **在** |
| `ps -A \| grep camera` | `cameraserver`（pid 121）在跑 |
| `/vendor/bin/hw/` | **无 camera 项**（audio/cas/configstore/drm/gatekeeper/graphics/health/keymaster/light/memtrack…） |
| `find /vendor /system /apex -maxdepth 4 -name '*camera*'` | **空** |
| `/vendor/etc/vintf/manifest.xml` | **无 camera 条目** |
| `/dev/video*`（容器内） | **不存在**（`config_nodes` 未绑定） |

⇒ **C5 的真实成本不是“绑设备节点”，而是容器里没有 camera HAL/provider**。
Waydroid 1.6.2 也没有任何 camera 相关 CLI。

### 建议的实现拆分

1. **主机侧（可独立验收）**：为 `vk127` UTS 编 `v4l2loopback`；用 libcamera 软 ISP 出 YUV（YUYV/UYVY）
   → 写 loopback 节点。验收 = 主机上 `v4l2-ctl -d /dev/videoN --stream-mmap` 出 YUV 帧，且该节点可被任意消费者读取。
2. **容器侧（重活）**：提供 v4l2 external camera provider（AOSP `android.hardware.camera.provider@2.4-external`
   一类），把 loopback 节点映射成 `camera id 0`；需要 Android 侧构建/或找现成预编译。
3. 中间可先用一个“最小证据”验证方向：把主机 `/dev/video0..16` 绑进容器，看 `cameraserver` 是否
   报 `external/0`（预期不会，因为没有 provider，但可留证）。
