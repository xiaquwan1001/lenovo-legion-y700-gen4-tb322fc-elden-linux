Q28 **GOOD** 台架 + 上游 `power-domains=<MMCX>,<MX>` 的 cambist DT 臂上，**C0（cam=0）/C1（`{camcc}`）各自 blank→hold 60 s→wake 存活 +89 s**；**C2（`{camcc,cambist}`）真熄屏后 3 s 内静默硬复位**，熄屏末票 `mmcx.lvl=2 / cx.lvl=5` **与 MX-only 基准逐字相同** ⇒ **DT 电源域绑定（H1）被否证**。

## 3. 死亡现场

```
GATE_BEFORE active=(false,) dpms=On  bl_power=0 bright=511
SETACTIVE_true=()                                   ← 熄屏指令成功
GATE_AFTER3  active=(false,) dpms=Off bl_power=4    ← 屏真的关了（DPMS Off + 背光断电）
Timeout, server 192.168.7.1 not responding          ← 3 s 内整机失联
```
- blank 段 RPMh 票：`0x30080(mmcx.lvl)=2`、`0x30000(cx.lvl)=5` —— 与 C0/C1 的熄屏票**完全相同**（票本身不区分死/活，`PITFALLS #204`）。
- 串口：末段止于 C1 唤醒后的面板固件重上传（uptime 202.6），随后 `===== serial closed 12:37:35 =====`，**无 panic/Oops/watchdog**。
- 死亡前 trace 尾部新现象：**`disp_snapshot-814`** 在 NoC（`0x50034`）投票后静止（基准那轮末段是 `phoc` + NoC）——留作机制轮线索。

## 4. 判定与边界

1. **H1 否证**：上游 mainline 的 `MMCX+MX` 绑定与实验性 `MX-only` 绑定在**同一台架、同一相位、同一签名**下同样致死 ⇒ **cambist 的 power-domain 绑定不是杠杆**（其提交 `be79b256d` 既不是因、也不是解）。
2. N=1（每相位一次）；但本次 C2 的死亡签名与 `logs/q24-cseries1-*` 的基线 C2 **逐项一致**（票、`active=false/dpms=Off`、~3 s、无 panic）。
3. 因此 DT 空间只剩 **H3（camcc 去 MXC）** 一个明确变量；纯猜臂的边际价值已低。
