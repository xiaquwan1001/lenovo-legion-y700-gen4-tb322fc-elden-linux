## 1. 复现步骤（全部可重跑）

```bash
# 0) 设备进 fastboot（用户侧物理动作或 reboot2 bootloader）
fastboot devices                      # HA2EXB0E
# 1) 零写盘启动生产根（vk163 是模块化实验件，已在生产 f2fs 根验证全绿）
fastboot boot out/boot-elden-vk163.img
# 2) 设备起来后：卡被 exfat 自动挂载 ⇒ 先卸掉再格（本轮卡是空卡：仅 System Volume Information）
ssh root@192.168.7.1 'umount /mnt/tf; umount /run/media/xuqianhui1001/<UUID>; mkfs.ext4 -F -L tftest /dev/mmcblk0p1; mount /dev/mmcblk0p1 /mnt/tf'
# 3) 压测（脚本 201 行，仓库内权威副本）
ssh root@192.168.7.1 'cat > /tmp/tf-stress.sh && chmod +x /tmp/tf-stress.sh' < scripts/tf-stress.sh
ssh root@192.168.7.1 '/tmp/tf-stress.sh --fsck -r 3 -t 800 /mnt/tf'
# 4) 收尾 fsck（脚本 --fsck 已做前后两次，这里再独立确认一次）
ssh root@192.168.7.1 'umount /mnt/tf; e2fsck -fn /dev/mmcblk0p1'
```

证据：`reports/trials/20261026T070115Z-tf-g16-card2-3r.json`（`reset=warm`, `deploy=fastboot-boot`, `verdict=PASS`）。

## 2. 与本轮其它线的交界

- **驱动模块化**：MMC 栈在 vk163 的 `=y` 集合里，**不需要模块化**（模块树缺失时 TF 仍能枚举，已实测）。
  ⇒ 后续若把 `MMC_SDHCI_MSM` 改成 `=m`，必须把「TF 可枚举」加入 `mod-loop` 回归清单。
- **Mobian 迁移**：`/mnt/tf` 的自动挂载来自桌面会话（udisks/gvfs），Debian 根上是否同样自动挂载
  **未验证**；`tf-stress.sh` 不依赖自动挂载（自己 mount），迁移后可直接复用。
- **`err_stats` 通道**：依赖 `debugfs` 挂到 `/sys/kernel/debug`；最小 Debian 根若无 `debugfs` 命令需补
  （`e2fsprogs` 已含），否则 `snap_attrs` 静默退化（脚本对缺失是 WARN 而非 FAIL）。
