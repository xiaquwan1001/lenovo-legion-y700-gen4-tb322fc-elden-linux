**1.3.3 主进程信号处置（已证）**

```
$ grep -E 'SigIgn|SigBlk|SigCgt' /proc/1240/status     # 主进程(当前 boot MainPID=1240)
SigBlk:	0000000000000000
SigIgn:	0000000000001000
SigCgt:	0000000000016442
$ grep -E 'SigBlk|SigIgn|SigCgt' /proc/1251/status     # session-worker
SigIgn:	0000000000001000
SigCgt:	0000000000000440
$ grep -E 'SigBlk|SigIgn|SigCgt' /proc/1561/status     # phoc
SigBlk:	0000000000000200
SigIgn:	0000000000001000
SigCgt:	0000000100004000
$ cat /proc/1240/wchan   → do_epoll_wait
$ cat /proc/1251/wchan   → do_wait
```

位解读（SIGTERM=15 ⇒ mask `1<<(15-1)=0x4000`）：

| 进程 | `SigCgt` | 含 SIGTERM? | 结论 |
|---|---|---|---|
| greetd 主 1240 | `0x16442` | `0x16442 & 0x4000 = 0x4000` ⇒ **是** | 主进程**捕获** SIGTERM（tokio `signal(SignalKind::terminate())`）⇒ 不会默认动作致命，只能靠它自己退出 |
| session-worker 1251 | `0x440`（bit7=SIGBUS, bit11=SIGSEGV，Rust 栈溢出守卫） | 否 | worker 收到 SIGTERM **会直接死** |
| phoc 1561 | `0x100004000` | 是 | phoc 自己处理 SIGTERM |

`SigIgn=0x1000` 三者都有 = SIGPIPE 被忽略（Rust 运行时标准行为），**不是** SIGTERM（父会话提的
「SigIgn 含 bit15 ⇒ 被忽略」在这里**不成立**）。

⇒ 主进程「杀不死」不是信号被忽略/阻塞，而是**它能收到 SIGTERM 但退出路径被卡住**（§2.1 给出源码级机制）。

### 1.6 全历史统计：这是每次都发生，不是偶发（已证）

脚本（**设备侧只读**，全文内联在此，可原样复跑；用 `journalctl -o short-unix` 取精确时间戳）：

```bash
cat > /tmp/greetd-bootstats.sh <<'EOS'
#!/bin/bash
printf '%-6s %-18s %-18s %-10s %s\n' BOOT STOP_EPOCH STOPPED_EPOCH DELTA_S NOTE
for b in $(journalctl --list-boots --no-pager -o short | awk '{print $1}' | tail -40); do
  j=$(journalctl -b "$b" --no-pager -o short-unix 2>/dev/null | grep -E "greetd\.service")
  [ -z "$j" ] && continue
  s=$(printf '%s\n' "$j" | grep "Stopping greetd.service" | head -1 | awk '{print $1}')
  e=$(printf '%s\n' "$j" | grep -E "Stopped greetd.service" | awk -v s="$s" '$1>s{print $1; exit}')
  to=$(printf '%s\n' "$j" | grep -c "stop-sigterm' timed out")
  sk=$(printf '%s\n' "$j" | grep -c "Killing process.*(greetd) with signal SIGKILL")
  if [ -z "$s" ]; then
    printf '%-6s %-18s %-18s %-10s %s\n' "$b" - - - "no-stop(掉电/异常关机)"
  elif [ -z "$e" ]; then
    printf '%-6s %-18s %-18s %-10s %s\n' "$b" "$s" "(none)" INF "journal截断"
  else
    d=$(awk -v a="$s" -v b="$e" 'BEGIN{printf "%.3f", b-a}')
    printf '%-6s %-18s %-18s %-10s timeout=%s sigkill=%s\n' "$b" "$s" "$e" "$d" "$to" "$sk"
  fi
done
EOS
bash /tmp/greetd-bootstats.sh        # 设备上跑；纯 journalctl 只读
```

- `0.001 s` 的 2 个 boot **不是**反例，是 greetd 根本没起来：

### 2.1 ★ 根因 R1（已证，机制 + 现场双重吻合）：`check_children()` 持写锁 await `start_greeter()` ⇒ SIGTERM 处理死锁

**源码（`greetd/src/context.rs`，0.10.3 行号；master 对应 344/380 行）**

>`start_greeter()`→`start_unauthenticated_session()`（context.rs:78-108）在 `loop { match scheduled_session.get_state().await }`
> 里**阻塞等 session-worker 通过 unix datagram 回 `Success`**。也就是说：
> **只要 worker 不回话（哪怕只是慢），持锁方就无限期占着锁；此时来的 SIGTERM 只能挂在 `terminate()` 的 `write().await` 上。**

**为什么本机必然踩到**（现场时序，§1.4）：

1. 关机事务里 `session-c1.scope`（用户会话）先/同时被停 → phoc 收 TERM 退出
2. 内核发 SIGCHLD 给 greetd → `check_children()`：`current` 是 **User 会话（`is_greeter=false`）** ⇒ 走 `None` 分支
   → **持锁** `start_greeter().await` → fork `greetd --session-worker` → 该 worker 打开 PAM 会话
   （`pam_unix(greetd-greeter:session): session opened ... by (uid=0)`，时间戳比 `Stopping greetd` **早 0.16 ms**）
3. 同一瞬间 systemd 下发 SIGTERM → `term.recv()` 到期 → `ctx.terminate()` → **`inner.write().await` 永久阻塞**
4. `user@1001.service` / `run-user-1001.mount` 在 15:01:11.x 被拆掉，worker 侧环境（`XDG_RUNTIME_DIR` 等）已消失，
   `Success` 永远不会到 ⇒ 死锁固化
5. systemd 按 `Type=simple` + 无 `TimeoutStopSec` 等满 **90 s** → `stop-sigterm timed out` → SIGKILL

**判别命令（本次输出是否支持）**

| 判别 | 命令 | 本次结果 | 支持? |
|---|---|---|---|
| 主进程能收 SIGTERM（不是被忽略/阻塞） | `grep SigCgt /proc/$(systemctl show -p MainPID --value greetd)/status` | `0x16442` 含 `0x4000` | ✅ 支持 R1（若是默认动作早就 0 s 退出） |
| 主进程在 90 s 内**没走退出/报错路径** | `/var/log/greetd.log` mtime、`journalctl` 中 greetd 行 | mtime 停在 10-27 10:02；90 s 窗口 greetd 零日志 | ✅ 支持 R1（`Err(...)` 分支会写 `error: ...` 到 stderr=该文件） |
| 会话进程不是「顽固子进程」 | journal 里有无 `Killing process N (phoc)` | 只有 `Killing process 1273 (greetd)` | ✅ 支持 R1、否定候选 (b) |
| 死锁入口正是「刚起 greeter」 | `pam_unix(greetd-greeter:session)` vs `Stopping greetd` 时间差 | −0.16 ms | ✅ 强支持 |
| 上游 master 是否已修 | 对比 master `context.rs` | **未修**（仍 `inner.current = Some(... start_greeter().await? ...)`） | ✅ 说明这是上游缺陷，不是 Debian 补丁引入 |

**若成立的最小修复**（三级，详见 §3）：

- 止血（系统级，0 代码）：`TimeoutStopSec=10` + `ExecStop` 先杀 `--session-worker`（让 worker 侧 socket 关闭 ⇒
  `get_state()` 收 `ECONNREFUSED` ⇒ `check_children` 返回 Err ⇒ 主进程在 ms 级退出）
- 根治（上游）：`check_children()` 在 `start_greeter()` 前 `drop(inner)`，成功后再取锁写回（与同函数 `scheduled` 分支
  已有的 `drop(inner)` 写法一致）
- 生成链：`services.tsv` 增 `stop` 语义 + `render.py` 渲染（§3.2）

### 2.2 R2（未证实，但**必须一起修**）：`session-c1.scope` 与 `greetd.service` 无顺序约束 ⇒ 每次关机都在「刚重启 greeter」的窗口里

- 机制：`session-*.scope` 由 logind 动态创建，`greetd.service` 的 `After=seatd.service systemd-logind.service` 只约束
  **开机**顺序；关机时两者**并行**停（实测 14 ms 间隔）。R1 的死锁窗口 ≈「spawn worker + PAM 开会话 + worker 就绪」
  = 数百 ms 到数秒，而关机恰好会触发一次该窗口（会话死 → SIGCHLD → 起 greeter）。
- 判别：`systemctl show elogind -p Before` 是否含 `session-c1.scope greetd.service`（**已证：含**，两者同级并行停）；
  `journalctl -b -1` 里 `Stopping session-c1.scope` 与 `Stopping greetd.service` 的 Δ（**已证 0.0142 s**）。
- 现状支持度：**支持**「并行停」，但**不能**证明「若强制先停 greetd 再停会话就一定 0 s」——
  按源码应当是（`terminate()` 抢到锁 → `child.term()` → `break` → 退出），但**未上机验证**，标 `未证实`。
- 最小修复：**不需要**动 order（改 `Before=session-c1.scope` 不可行，scope 名动态；用 `Conflicts=` 反而会牵连 phosh）。
  用 R1 的止血 + 根治即可；顺序问题只是**放大**死锁概率，不是原因。

### 2.3 候选 (b) `KillMode` / 顽固 greeter 子进程 —— **已否定（已证）**

- `KillMode=control-group`、`SendSIGKILL=yes` 都已是缺省生效值（§1.1），显式写只是冗余；
- 会话进程在 `session-c1.scope`，**根本不在** `greetd.service` 的 cgroup（§1.3.2），`KillMode` 家族对它无效；
- 若真是「子进程顽固」，journal 会出现多个 `Killing process N (phoc/…)`；实测只有 1 条主进程（§1.4）。
- 唯一**仍然值得保留**的部分是 `TimeoutStopSec`：它不修原因，但把用户可见的 90 s 变成有界值。

### 2.4 候选 (d) PAM 会话 close 阻塞 —— **未证实（本轮无法区分，且被 R1 覆盖）**

- 机制上成立：`common-session` 含 `pam_systemd`/`pam_elogind`，session close 需要 logind 的 D-Bus 往返，
  而 logind 在本机是 **最后**才停（`Before=greetd.service session-c1.scope`，实测 logind 在 greetd 之后 0 s 才 `Stopping`），
  所以「等 logind 回应而对方已停」在本 boot **时序上不成立**。
- 更重要的是：**greetd 根本没走到 PAM close**——它卡在 §2.1 的写锁上，连 `terminate()` 的第一行都没过。
- 判别（需用户在场）：`journalctl -b -1 | grep 'pam_unix.*closed'` 看会话关闭是否被记录、以及 worker 是否残留。
  本轮 `-b -1` 里 greetd 侧的 `session closed` **未出现**（`/var/log/greetd.log` 亦无），与「没走到」一致。
- 结论：**不是根因**，但若修完 R1 仍 >2 s，应作为第二顺位复查项。

### 2.5 候选 (e) `StandardOutput=append` 写日志阻塞 —— **已否定（已证）**

- root = `/dev/sda17 ext4 rw`（§1.8），`/var/log/greetd.log` 在 root 上；
- `greetd.service` `Requires=local-fs.target` 且 `Before=shutdown.target` ⇒ 停机时 root 仍 rw、未 unmount；
- 关机窗口内该文件 mtime 无变化（§1.7），也没有「写到一半」的痕迹；
- 反证：历史上 greetd 在同类 fs 上大量正常写 `error: ...`（`greetd.log` 780 B 全为 stderr 错误行）。

### 2.6 候选 (a) 的**另一半**：`terminate()` 自身逻辑是否还会再卡一次 —— **未证实，需源码补丁后复测**

- `terminate()` 里 `sess.session.cancel().await` 与 `Session::cancel()`（`session/interface.rs:181`）会
  `send(&mut self.sock).await`——若对端 worker 已死，unix datagram 发送通常立刻 `ECONNREFUSED`，够快；
  但若对端 socket 缓冲区满/无人收，`send` 可能阻塞。
- 这不是本次 90 s 的原因（没走到），但**修完 R1 后**要确认「SIGTERM 路径整体 ≤2 s」可用 §4.2 的
  `systemctl kill -s TERM` 快速复测。

## §3 修复方案（落生成链，不改生成物）

### 3.0 设计原则

1. **不改设备上的 `/usr/lib/systemd/system/greetd.service`**（文件头 `GENERATED ... DO NOT EDIT`，
   `verify.sh` F2 段会拿 `out/units/` 与设备逐字比对，手改必然 FAIL）。
2. 修复分三级，**互不依赖**，可以只做 P0 就能止住 90 s：
   - **P0（今天就能上设备）**：drop-in，系统级，不碰仓库生成链；用于**先取证再改链**。
   - **P1（仓库根治）**：`stop.tsv` + `hooks/greetd.stop` + `render.py`，让「停止语义」进唯一真源。
   - **P2（上游）**：greetd `check_children()` 释放锁，把死锁本身消掉（上游 master 至今未修，见 §2.1）。
3. **不采用**的写法（逐条给理由，避免下一个人重复走）：
   - `KillMode=`：已是缺省 `control-group`，且**会话不在 cgroup**（§1.3.2）⇒ 无效（§2.3）。
   - `Before=session-c1.scope`：scope 名是运行时动态的（c1/c2/…），写死必然漂移。
   - `Conflicts=phosh.service` 反向加：已存在（§1.2），再加 `Conflicts=session-*.scope` 不存在通配语义，
     且会把「停 greetd」变成「停所有会话」，停机顺序更难控。
   - 在 `greetd` 外面套 wrapper 让 SIGTERM 变 SIGKILL：等于把 90 s 变成「立即杀」，但会连带杀掉
     仍未退出的 worker/会话，且 `Type=simple` 下 wrapper 才是 MainPID，日志/退出码全部错位。

```sh
#!/bin/sh
# greetd.stop — 解除 greetd 关机 SIGTERM 死锁（R1）
#
# 机制（greetd 0.10.3 greetd/src/context.rs:338-383 / 405-406）：
#   check_children() 在 **持有 inner 写锁** 的情况下 await start_greeter()，
#   而 start_greeter() 会一直等 session-worker 通过 unix datagram 回 Success；
#   SIGTERM 处理 terminate() 要拿同一把写锁 ⇒ 永久阻塞 ⇒ 主进程不退 ⇒ 90 s 超时。
# 对策：在本单元被 stop 时先把所有 session-worker 杀掉 ⇒ worker 端 socket 关闭
#   ⇒ 持锁方 get_state() 立刻 ECONNREFUSED ⇒ check_children 返回 Err ⇒ 主进程立即退出。
#
# 注意（PITFALLS: pkill 自杀）：模式用 ^ 锚定绝对路径，不会匹配本脚本自身 cmdline；
# 另加 [ "$c" = "$$" ] 兜底。不要改成 pkill -f 'session-worker'（会匹配外层 shell）。
set -u
_kill() {
	pgrep -f -- '^/usr/sbin/greetd --session-worker' 2>/dev/null | while read -r c; do
		[ "$c" = "$$" ] && continue
		kill -TERM "$c" 2>/dev/null || true
	done
}
_kill
# 给一次机会：worker 死后主进程应在毫秒级退出；1 s 后仍在则再补一次（幂等）
sleep 1
_kill
exit 0
```

### 3.5 为什么 `TimeoutStopSec` 不是「掩盖问题」

- 它**不修**死锁（P2 才修），但它把「系统停机被单服务挂住 90 s」变成有界故障——这是 systemd 单元设计里
  `TimeoutStopSec` 的本职（任何 `Type=simple` 守护进程都可能卡在 `write()`/`fsync()`/驱动 ioctl 上）。
- 与 P1 组合后的最坏情况：**5 s**（内核/用户态都失效时）→ 正常情况 **≤2 s**（判据见 §4.4）。

### 4.2 低风险死锁探针（**确认 R1，不需要关机**）

> 风险等级：**D 级（可恢复）**。`systemctl kill -s TERM greetd` 直接给主进程发 SIGTERM：
> - 若 R1 成立（当前正在起 greeter 的窗口内）→ 主进程不退 → 命令**立即返回**但进程还在 ⇒ 探针成立；
> - 若不在窗口内 → `terminate()` 拿到锁 → 杀掉会话子进程 → 主进程退出 → `Restart=always` 5 s 后重启
>   ⇒ **桌面会黑一下再自动恢复**（auto-login）。
> 不管哪种结果，`ssh` 都在，最坏 `systemctl kill -s KILL greetd` 兜底。

```bash
ssh root@192.168.7.1 '
  t0=$(date +%s.%N)
  systemctl kill -s TERM greetd
  for i in $(seq 1 20); do
    pid=$(systemctl show -p MainPID --value greetd)
    if [ "$pid" = "0" ] || [ ! -e /proc/$pid ]; then
      echo "EXIT after $(echo "$(date +%s.%N) - $t0" | bc) s"; break
    fi
    sleep 0.5
  done
  pid=$(systemctl show -p MainPID --value greetd)
  echo "still alive: $pid ($(cat /proc/$pid/comm 2>/dev/null))"
  cat /proc/$pid/wchan 2>/dev/null; echo
'
```

**判据**

| 观测 | 判定 | 下一步 |
|---|---|---|
| 10 s 内 `MainPID` 变 0 或进程消失 | 该次没有踩到死锁窗口（**不能据此否定 R1**，只说明窗口窄/此刻不在窗口） | 重复 3 次；仍全过 ⇒ 记「探针未命中」 |
| 主进程 **存活 ≥10 s** 且 `wchan` = `do_epoll_wait`/`futex_wait_queue` | **R1 命中**（SIGTERM 被处理但退出不了） | 立刻 `systemctl kill -s KILL greetd` 收尾，记 `已证` |
| 主进程 0 s 退出但 desktop 没回来 | greeter 重启失败（另一个已知问题，§1.7 的 `greeter exited without creating a session`） | `systemctl restart greetd`，记 `未解` |

**收尾（无论结果）**：`systemctl is-active greetd` → `active`；`loginctl list-sessions` 有 1 个会话；否则 `systemctl restart greetd`。

| `TimeoutStopSec=5` 在慢 eMMC/fs 上过短（本机 root 是 ext4/`noatime`，实测其它单元 ≤1.5 s 停完） | 极少数情况被 SIGKILL（greetd 无状态，无数据丢失风险） | 5 s 是实测停等（1.9 s 用户会话 + 0.2 s logind）的 2.5 倍余量 |
| 仓库与设备同批次落地要求 | 只部署一半 ⇒ `verify.sh` F2 FAIL | §3.2 部署段把「仓库改动 + 设备覆盖」写成同一批次，回滚也成对 |
