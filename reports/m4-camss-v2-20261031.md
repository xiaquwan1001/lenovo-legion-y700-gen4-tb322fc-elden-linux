## 1. 为什么 2/3 必须整枚撕掉（三条独立理由，任一成立）

1. **判据错位**：代码查 `sg_dma_address()`（IOVA），commit message 却声称「physically contiguous」；若真改成 `sg_phys()` 会**拒绝所有正常 video buffer**（V4L2 不保证物理连续）。
2. **实测反证**：Bryan 的 plane0 = 11 677 696 B / 6 CPU entry / **5 处物理断裂**（最大物理 run 8 MiB）/ **1 个 DMA 段 / 0 IOVA 断裂**，管线正常。与 `dma-iommu.c:1325-1328 __finalise_sg()` 的合并行为一致 ⇒ 补丁想防的「写穿第一个 scatterlist」在 IOMMU 路径上不存在。
3. **钩子是死代码**：`prepare_buffer` 整树 0 实现者 / 0 调用者；删除无依赖。

> 若将来仍要「非连续 buffer 可观测性」，LaneB 给的最弱形态 = `dev_warn_once()` 告警、**不拒绝**、不用新钩子；本系列不做（A 方案：什么也不做）。

## 2. 3/3 的形态（对应 Loic 10-29 15:00 的建议）

- 起流/停流共用 `camss_video_subdevs_set_stream(video, bool)`；start 失败时反向 disable 已启的子设备。
- 源 pad 用 `media_entity_remote_source_pad_unique()` 取，不再假设 `pads[0]`。
- 用 `v4l2_subdev_enable_streams()/disable_streams()`；camss 子设备目前只实现 `.s_stream()`，helper 自动回退——这是它能不改子设备驱动就工作的原因（commit message 写明）。
- 已在请求状态上的流返回 `-EALREADY`，因此「失败的那个（未标记 enabled）」与「其上游（未启动）」都不被误关。
