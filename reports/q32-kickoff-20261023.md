## 0. 结论先行

1. **判据必须更正一处**：`psci: SYSTEM_RESET2 vendor reset_type=…` 是**被复位的那一个内核**在关机前打印的，
   本次启动的 dmesg 里**永远不会有**。复位深度的内核侧唯一证据渠道 = **pstore/ramoops**
   （在机已注册：`ramoops@c2000000` 4 MiB、`CONFIG_PSTORE_CONSOLE=y`、`printk: legacy console [ramoops-1] enabled`），
   而 pstore 语义是**读后删除** ⇒ 必须「先归档、后分析」。预研 §2 的「判据 = dmesg 有该打印」按此改写。
2. **试点实测推翻了预研 §3 的一个推论**（不是结论）：在机 DT **有** `reserved-memory/splash_region`
   （43 MiB @ `0xfc800000`、`no-map`），msm 打印 `boot framebuffer mapped before SID switch` 与
   `[drm] reserved boot framebuffer IOVA 0xfc800000+0x2b00000`，cmdline `silent_boot.mode=nonsilent`
   ⇒ **本次启动 ABL 确实留了活显示**；但 `simpledrm/efifb` 计数 = **0**、`chosen/` 无 `framebuffer`。
   ⇒「**没有 simpledrm**」≠「**没有交接 framebuffer**」：7.3 树删掉 `chosen/framebuffer` 只关掉了「内核把固件 FB 当 fbcon」这条路，
   固件 FB 仍被 msm 以 **IOVA 保留**方式显式记录（`msm_iommu_record_boot_framebuffer()`，读 `&mdss { memory-region = <&splash_mem>; }`）。
3. **UEFI 结论不变（维持搁置），且与 Q32 不互补**：UEFI 链会把 Q32 的自变量「固件有没有留活显示」**推向恒为 yes**
   （UEFI 自己点屏/GOP），同时把复位入口收窄到架构 `SYSTEM_RESET`（W1 臂消失）⇒ 先用 UEFI 会同时放大风险并抹掉对照臂。
4. 三臂**均未执行**：W1/W2 需复位（agent 可做）、C1 需人物理断电。Q32 状态仍是**未上机**。

## 2. 试点原始证据（在机 vk152，稳态，只读）

```
===== summary =====
RESET_DECLARED=unspecified
PSTORE_PRESENT=no                 # 本次启动 ramoops 无上个启动记录（真 POR/断电 或 已被读过一次）
RESET_DEPTH=unknown               # 无声明 + 无 pstore ⇒ 内核侧不可判定（预期行为）
SPLASH_NODE=yes                   # /proc/device-tree/reserved-memory/splash_region（no-map）
BOOTFB_RECORDED=1                 # [drm] reserved boot framebuffer IOVA 0xfc800000+0x2b00000
BOOTFB_MAPPED_PRE_SID=2           # boot framebuffer mapped before SID switch（两次：attach 前后）
FW_LIVE_FB=yes
SILENT_BOOT=nonsilent             # ABL 点了屏（splash）
SIMPLEDRM=0 / CHOSEN_FB=no        # 7.3 树无 chosen/framebuffer ⇒ simpledrm 全程未参与
FB0_NAME=msmdrmfb
DSI_STATUS=connected/enabled
STORM_SIG=0
```

时间线（dmesg）：`0.000` `OF: reserved mem: 0xfc800000..0xff2fffff (44032 KiB) nomap non-reusable splash_region` →
`0.296` `boot framebuffer mapped before SID switch` → `8.868` `msm_dpu … bound` + `reserved boot framebuffer IOVA`
→ `9.152` `Console: switching to colour frame buffer device 119x95` → `9.175` `fb0: msmdrmfb`。

**读法**：`splash_region` 由 DT 声明、ABL 填内容；msm 在 **attach SID 之前**就把它按 IOVA 原样记录，且**不接管内容**
（`msm_iommu_destroy()` 时才 unmap）。所以「ABL 有没有留活显示」在**任何一次启动**都能从 dmesg 直接读出，
不需要 probe 前快照 —— 这是本轮对预研 §3「需加一版 probe 前快照」的简化：**用 `BOOTFB_RECORDED`+`SILENT_BOOT` 代替**。

### 2.1 第二个稳态快照（收尾后自动采集，非实验臂）

设备在本轮收尾期间**自行**换了一次启动（boot_id `b6211ab4` → `3c3c06e3`，**不是本会话发的复位**），
随即又采了一份同口径证据（`reports/artifacts/q32-boot-3c3c06e3.txt`）：

```
PSTORE_PRESENT=no / PSTORE_RESET_PRINT=0 / RESET_DEPTH=unknown   # 复位类型未声明，无可判定证据
SPLASH_NODE=yes / BOOTFB_RECORDED=1 / SILENT_BOOT=nonsilent      # ⇒ FW_LIVE_FB=yes（与首份一致）
SIMPLEDRM=0 / CHOSEN_FB=no / FB0_NAME=msmdrmfb / DSI_STATUS=connected/enabled / STORM_SIG=0
```

**两次稳态快照在「固件活显示」上一致（2/2 `FW_LIVE_FB=yes`、2/2 `simpledrm=0`）** —— 这是判据基线，
不是结论：它只说明「日常线上每次启动 ABL 都留了活显示」这个前提到目前为止成立。
另外注意 **pstore 连续两次为空** ⇒ pstore 渠道本身尚未被「已知暖复位」验证过，W1 臂跑完必须看到
`PSTORE_RESET_PRINT=1`，否则说明该渠道不可用（而不是「这次是冷起」）。

## 3. UEFI 交叉评估（与 Q32 的关系，落盘版）

| 面 | 现状（ABL 直起 boot_b） | UEFI 链下 |
|---|---|---|
| 复位入口 | 三个不同固件入口：vendor `0x80010001` / `SYSTEM_RESET(0x2)` / `SYSTEM_RESET2(type 0)`，钩子有 fallthrough 可静默降级 | 重启由 UEFI `ResetSystem` 承担（一般落 PSCI `SYSTEM_RESET`，【待核】复起时 grep `ResetSystemLib`）⇒ **W1 臂消失**；`reboot bootloader/edl` 语义要 UEFI 自己实现（=G1-29 想要的 BDS 菜单） |
| 显示交接 | `splash_region` + msm 记录 IOVA 保留；simpledrm 不参与 | UEFI 自己点屏（GOP）⇒ 固件活显示**恒为 yes**，必须同时带 `chosen/framebuffer` 语义与 `DISP_CC_MDSS_CORE_BCR` 撕 FB 的处理，否则 Q28 类「撕正在扫描的显示」从偶发变常态 |
| 继承态风险 | 见 `reports/kexec-vk147-display-inherit-20261023.md`：继承「display 全活、PLL 全锁」⇒ 目标核静默挂死 | 同族：UEFI→Linux 也是继承态，Q32 判据（同深度内一致性）适用但需重采 |

⇒ 决策顺序维持：**Q32（零成本）→ kexec → UEFI**；UEFI 的阻塞（Q25 两层：`0x402` 运行期注册表 + `UFS.c+2326` `UFSSmmuConfig`）与本轮无关、无变化。
