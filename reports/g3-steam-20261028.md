## 4. 路线决策：改走**官方 ARM64 Steam 客户端**（不走 Box64+Wine 起 Steam）

依据（全部本轮实测/仓内已有）：

1. **x86 路线要从零重建**：PoC 环境 `/root/glibc-rootfs`、box64、wine 全部不存在（§2），
   而 box64 0.4.3（Debian sid 候选）在 PITFALLS/归档里有「与 Wine 不兼容触发 explorer fork 风暴」的旧账，
   Wine 9 需 dpkg 加 amd64 架构并装 `wine64:amd64`，Steam 客户端本体是 32 位引导（归档 §5 已列「32 位支持」为未解决项）。
2. **官方 ARM64 通道确实存在且可用**：`client-update.steamstatic.com/steam_client_steamdeck_stable_linuxarm64` → HTTP 200，12582 B manifest，
   manifest `version=1792618285`，合计 **967 MB / 279 条**（`file`+`zipvz` 双份）。
3. **本机是原生 aarch64 + glibc**（Debian sid），跑 ARM64 客户端是**原生执行**，无转译层；
   x86 游戏留给后续 FEX/box64（G3 第二阶段），与本批「起到登录界面」解耦。
4. 参考实现（armadaos-freedom `packages/steam-bootstrap/`）的 `fetch.py`/`generate.sh` 已取回并在本仓落地为
   `reports/artifacts/g3-steam-20261028/{fetch.py,bootstrap.sh}`（GPL-2.0-or-later，保留出处），去掉其容器/离线 feed 部分。

Steam Runtime 取最新已发布 tag：`3c.0.20261021.266024`（`repo.steampowered.com/steamrt3c/images/`，
`steam-runtime-steamrt-arm64.tar.xz` 52 469 712 B，sha256 见 `SHA256SUMS`）。

### 6.3 截图为何拿不到（已证，非 Steam 问题）

设备当前 DRM 输出状态（本轮三次运行前后一致，未因 Steam 改变）：
```
/sys/class/drm/card0-DSI-1/status  = connected
/sys/class/drm/card0-DSI-1/enabled = disabled      <- 输出未启用
/sys/class/drm/card0-DSI-1/dpms    = Off           <- 面板 DPMS 关
backlight brightness = 1024, mode = 1904x3040
```
三条截图路径全部失败，原因各不相同（均为环境，不是 Steam）：

| 路径 | 命令 | 原始输出 |
|---|---|---|
| phoc 整屏 | `runuser -u xuqianhui1001 -- env XDG_RUNTIME_DIR=/run/user/1001 WAYLAND_DISPLAY=wayland-0 grim …png` | `no supported format found` |
| phoc 指定输出 | `grim -o DSI-1 …` | `no supported format found`（`-o card0-DSI-1` → `unknown output`） |
| 嵌套 weston (`wl-g3`) | `XDG_RUNTIME_DIR=/tmp/g3-steam/rt WAYLAND_DISPLAY=wl-g3 grim …` | `compositor doesn't support the screen capture protocol` |
| weston 原生 | `weston-screenshooter`（`wl-g3`） | **挂死**（pid 227801 不动，已 `pkill -9`）；weston 未编 `screenshooter.so` 模块 |

补充事实（排除上轮「用户不存在」干扰）：会话用户真名是 **`xuqianhui1001`**（uid 1001），
不是 `xuqianhui`——上轮 `runuser -u xuqianhui` 报 `user xuqianhui does not exist` 因此不成立，是拼写错误。
`grim` 的 `no supported format found` 与本仓 `PITFALLS` 里记录的「输出关闭/modeset 失败」同一签名（§251 段）。
另：`xwd` **未安装**（`which xwd` → 空），上轮 `/root/g3-shots/x.xwd` = **0 字节**原因即此；本轮已随证据拉回。
