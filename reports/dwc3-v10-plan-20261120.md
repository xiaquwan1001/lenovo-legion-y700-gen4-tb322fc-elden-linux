### 3.2 `mux_control_*` 与 `role_switch` / `port-select-gpios` 的关系

| 对象 | v8（旧） | v10（目标） | 语义分工 |
|---|---|---|---|
| `port-select-gpios`（私有属性） | 有：控制器节点上直接一根 GPIO | **删除**，binding 与 driver 零引用（只在 changelog 说明文字里出现，`v10-0001:44`） | 私有属性被通用 mux 框架取代 |
| `mux-controls`（标准） | 无 | `properties.mux-controls` → 指向 `compatible = "gpio-mux"` 控制器（`Documentation/devicetree/bindings/mux/gpio-mux.yaml`，`#mux-control-cells = <0>`） | 「哪条总线被切」由 **mux consumer API** 表达：`devm_mux_control_get()` 取控制器，`mux_control_select(ctrl, state)` 持锁选中 |
| `usb-role-switch`（控制器级，原有） | 有 | 保留，且在 mux 分支里 **required** | 让 `dwc3_drd_init()` 走 OTG role-switch 路径（G1-9 的既有前提） |
| `usb-role-switch`（**endpoint 级**，新增） | 无 | `$defs.hs-endpoint` 布尔属性，两 endpoint 均 required | 声明「该连接器自带 role switch」，由 `usb_role_switch_at_endpoint()` 按 endpoint 找；**这是 2/3 存在的理由** |
| `mux-state`（endpoint 级，新增） | 无 | `uint32` enum `[0,1]`，两 endpoint 互斥（schema `oneOf` + driver 拒绝同值） | 即 mux 的 **state 号**，`mux_control_select(ctrl, mux_state)` 的第二个参数 |
| 谁来 select | `gpiod_set_value()`（读得回电平） | **只有 `__dwc3_set_mode()`**（`system_freezable_wq` 工作线程，可睡眠）+ `dwc3_drd_exit()` drain 之后 deselect | role-switch `set()` 回调**从不直接碰 mux**，只登记 `desired_dr_role` + `desired_port` 后 `queue_work()` |
| 代价（必须在 cover 写清） | 启动时能读 GPIO 电平判断「开机插在哪个口」 | **mux 控制器不可读回** ⇒ 启动时无法探测，首个 mode 请求把 mux select 到 state 0 | 行为差异，v9/v10 正文已如实披露 |
