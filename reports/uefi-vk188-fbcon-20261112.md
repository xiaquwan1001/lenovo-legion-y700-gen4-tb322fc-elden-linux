## 一、一句话结论

| 问题 | 结论 |
|---|---|
| GRUB 菜单字太小 | **已解决**：v3b/v5 件三档字体（96/72/40 px）自动降级，用户实测「菜单显示正常，字大小正常」 |
| 选完菜单黑屏/无字 | **一半解决**：`SYSFB_SIMPLEFB` 单开**不够**；条目里必须带 `earlycon=efifb keep_bootcon`（A 臂无字 / A2 臂 0.000000 起有字，同内核同 DTB 以外的单变量） |
| 「十多秒掉电」 | **其实是 `panic=15` 自动重启**。改 `panic=0` 后不再重启，屏上停在最后状态 ⇒ 可以稳定拍/读 |
| 为什么一直只能拍屏 | 两个原因叠加：① UEFI/GRUB 阶段**没有串口**（ttyGS0 是 Linux gadget）；② `/boot/initrd.img` 是坏的（`no cpio magic`）⇒ 没有 initramfs 就没有 gadget/SSH |

## 二、本次上机实测（全部零写盘，`fastboot boot` UEFI 载荷）

| 轮次 | 件 | 结果 |
|---|---|---|
| 1 | v3b GRUB（96 px + 三档降级）+ vk188 内核 + 真 DTB | 菜单大字正常（用户目视）；选 A → **立刻全白、无任何内核字**、十几秒后重启（= `panic=15`） |
| 2 | v4 GRUB（真值 + grubenv 留痕，默认 A2）+ `elden-nopstorecons.dtb` | 同样进不去；回落到 b 槽后 `grubenv` 证明「A2 被选中并执行」 |
| 3 | v5 GRUB（每步 ok/FAIL 留痕）+ vk188 + A2（`earlycon=efifb keep_bootcon panic=0`） | **屏上从 0.000000 有字**，滚到 `37.09 s`；`Initramfs unpacking failed: no cpio magic`；不重启、挂在原地 |

## 三、三条硬结论（都已写进 PITFALLS）

1. **GRUB `gfxterm` 有字号上限**：`cols ≥ 40` 且 `rows ≥ 12`（反汇编 `gfxterm.mod` 得判据），
   本机 160 px 物理不可能；现役 96 px（横屏）/72 px（竖屏）/40 px（兜底）三档 `if terminal_output gfxterm` 降级。
2. **「内核有字」= `earlycon=efifb keep_bootcon`**：`simpledrm`/`fbcon` 接管太晚，`msm` 接管 DPU 后
   GOP buffer 不再被扫描 ⇒ 只开 `SYSFB_SIMPLEFB` 仍然全程无字。
3. **`out/ramdisk-vk181-daily.cpio.gz` 前 602 字节全 0**（boot.img 里也一样）⇒ `no cpio magic` ⇒
   无 `/init`、无 gadget、无 SSH，且**不会 panic**。已换 `ramdisk-vk181-working.cpio.gz`（同尺寸、偏移 0、
   `gzip -t` 过、181 MB newc），并重打 `out/boot-elden-vk188b.img`、把设备 `/boot/initrd.img` 换掉（旧件留 `.zeros602.bak`）。

## 五、QEMU 侧（子代理调研已落 `reports/qemu-usage-survey-20261112.md`）

对这条线直接可用的三条：

1. **`-device ramfb` 才能让本内核 fbcon 出字**（`virtio-gpu` 在本内核**完全不出字**，`DRM_VIRTIO_GPU` 未开）；
   GRUB 阶段只能用 virtio-gpu ⇒ **两阶段要换显示设备**。
2. `-M virt` 默认 ACPI 会让本内核（无 `CONFIG_ACPI`）在 `build_all_zonelists` 空指针 panic ⇒ **必须 `acpi=off`**。
3. GRUB 菜单/字体/cfg 语法可以 **30 s 一轮**在 QEMU 上验（本轮 96/72/40 三档就是这么定的），
   并且已经抓出两个真 bug：模块集缺 `disk/part_msdos` 会让 `search --file` 静默失败；`ramoops` 的 `reg` 越界会永远 0 条 pstore。

**未完成**：把「GRUB → vk188 → 串口 dmesg」整链在 QEMU 上复刻（本轮卡在 GRUB 从 ext4 读 64 MB Image 的慢读上，
没等到 `Linux version`）。这是下一步最值得补的一块（配方见调研报告 §3）。
