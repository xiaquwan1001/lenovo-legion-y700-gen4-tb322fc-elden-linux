## 1. 增量盘点（逐 hunk 分类）

### 1.0 分类口径

| 代号 | 含义 |
|---|---|
| **HW** | 上游缺失的**硬件事实**（寄存器序列/时序/电压/时钟比）——按 Q3 应进 DT/数据表/固定 cfg 数据 |
| **BRD** | **板级差异**（本板/本面板特有）——应进板 DTS |
| **DBG** | **调试插桩**（打印/诊断）——不出发行树 |
| **Q3** | **Q3 违例**（策略或未定根因被写成硬件事实）——发上游前必清 |
| **Q28** | **Q28 实验钩子**（bonded 命令协议、超时/轮询/状态机）——根因未定，只能带 RFC/quirk 说明 |
| **STR** | **结构性偏离**（scattered compat / 跨模块全局 / 生命周期重构）——B5 要收进 cfg |
| **MECH** | 纯机械改动（可空引用/注释/变量提升，无行为变化） |

## 2. per-SoC cfg 重构方案

### 2.1 现状（为什么 compat 判定散落）

上游 `dsi_cfg.c` 的 select 机制是**按硬件版本寄存器**（不是按 compatible）：

```
// drivers/gpu/drm/msm/dsi/dsi_cfg.h
struct msm_dsi_cfg_handler { u32 major; u32 minor;
	const struct msm_dsi_config *cfg; const struct msm_dsi_host_cfg_ops *ops; };
const struct msm_dsi_cfg_handler *msm_dsi_cfg_get(u32 major, u32 minor);
```
`dsi_get_config()` → `dsi_get_version(ctrl_base,&major,&minor)` → `msm_dsi_cfg_get(major,minor)`（dsi_host.c:218-256）。
上游表（dsi_cfg.c:299-347，本树与 base 一致、**无改动**）关键两行：
```
{MSM_DSI_VER_MAJOR_6G, MSM_DSI_6G_VER_MINOR_V2_9_0,  &sm8650_dsi_cfg,   &msm_dsi_6g_v2_9_host_ops},   // dsi_cfg.c:344
{MSM_DSI_VER_MAJOR_6G, MSM_DSI_6G_VER_MINOR_V2_10_0, &kaanapali_dsi_cfg, &msm_dsi_6g_v2_9_host_ops},   // dsi_cfg.c:346
```
**根因**：SM8750 的 DSI 版本寄存器报 **V2_9_0**（Q28 侧静态取证见 `reports/q28-upstream-static-20261012.md`；见 §3.1），与 **sm8650 撞 minor** ⇒ 上游表里两者共用一个 handler；vendor 又需要 SM8750 特有行为，于是**只能用 `of_device_is_compatible` 逐处兜**。
→ 这正是 B5 说的"收进 per-SoC cfg 结构"的可解之处：**把 select 从"仅版本号"扩展为"版本号 + compatible"**，并把差异变成 cfg 字段/ops 指针。

对照：**PHY 侧已经是对的做法**——`dsi_phy.c:580-584` 用 `of_device_id` 的 `.data` 指向 `&dsi_phy_3nm_8750_cfgs` / `&dsi_phy_3nm_kaanapali_cfgs`（按 compatible 选 per-SoC cfg 数据）。B5 就是把 host/manager 侧改成同样的姿势。

### 2.2 目标结构

**(A) cfg 数据（`dsi_cfg.c` 静态表，C 里放硬件事实）**——给 `struct msm_dsi_config` 增字段（示例）：
```
struct msm_dsi_config {
    ...  /* 既有 io_offset/regulators/bus_clk/io_start */
    bool cphy_only;         /* SM8750：C-PHY 三 trio，无时钟 lane */
    bool bonded_cmd;        /* 启用 broadcast bonded 命令路径 */
    ...
};
```
新增 **`sm8750_dsi_cfg`**（io_start 用 0xae94000/0xae96000，与 sm8650 同基址、regulator/bus_clk 同集），并把 select 从"仅 minor"扩为：
```
const struct msm_dsi_cfg_handler *
msm_dsi_cfg_get(struct device_node *np, u32 major, u32 minor);   /* np 用于同 minor 消歧 */
```
（或用 `of_device_id` 表 + `.data`，与 PHY 侧一致；兼容旧调用可保留一个只按 minor 的 wrapper。）

**(B) ops 函数表（`dsi_cfg.c`）**——新增 `msm_dsi_6g_v2_9_sm8750_host_ops`，把 `of_device_is_compatible` 分流改为函数指针：
```
struct msm_dsi_host_cfg_ops {
    ...
    int  (*link_clk_set_rate)(...);          /* sm8750 专属实现，替代 H28 compat */
    int  (*clk_init_ver)(...);               /* 已有；替代 H07 compat */
    void (*sw_reset)(struct msm_dsi_host *); /* 新增；NULL=通用 dsi_sw_reset，替代 H14 compat */
    int  (*cmd_link_clk_set_rate)(...);      /* 合并 H23 的 dsi_cmd_link_clk_set_rate */
};
```
- **H07 / H28 直接变冗余**：sm8750 已走 v2_9 ops（`clk_init_ver`/`link_clk_set_rate` 就是那两个函数），这两处 compat 可**行为等价删除**（§4 已实证编译通过）。
- **H14**：`void (*sw_reset)` = NULL 时走通用，sm8750 ops 填 `dsi_sw_reset_v2_9`。
- **H35 / H34（manager 的 `is_sm8750`）**：manager 不应自己 compat；改由 `cfg->bonded_cmd`/`cfg->cphy_only` 表达（manager 可通过 `msm_dsi_get_dsi(...)->host->cfg_hnd->cfg` 或一个小 helper 取）。

**(C) 哪些值应来自 DT 而非 C（Q3 正解）**：
| 值 | 归属 | 理由 |
|---|---|---|
| `cphy_timing_ctrl[14]`（H48/H56） | **DT**（`qcom,cphy-timing-ctrl` + binding） | 每板/每面板 C-PHY 时序，厂商按板配 |
| `vreg_ctrl_0/1`（H55）、DSICLK_SEL（H54）、sw_reset 序列（H14）、PLL-skip（H52） | **C（per-SoC cfg）** | SoC/PHY 代次事实，不随板变 |
| `io_start/regulators/bus_clk` | **C**（既有） | 同左 |
| 面板 DCS 时序 / 刷新率 / force_hz | **DT/panel mode data** | 见 §3（不是驱动参数） |

### 2.3 hunk → 重构落点（汇总）

## 3. 与 Q28 的关系（哪些重构会改 Q28 现场行为）

### 3.1 Q28 现场一句话（引自 `archive/topics/UPSTREAM-REPORT-q28-bonded-dsi-2026-10-12.md`）

冷起首条 DCS 的 command-DMA 间歇超时，坏发签名逐字一致：
```
msm_dsi ae94000.dsi: command DMA timeout: status=0x2200200
msm_dsi ae96000.dsi: peer command DMA timeout: status=0x2200200
msm_dsi ae94000.dsi: bonded command DMA failed: master=-110 peer=-110
```
- **根因未定**：已排除构建身份/ramdisk/DTB/POR 时长；上游 byte-clk 取整补丁 `2028280686f4` 移植后**仍坏**；坏发率随**时间窗**漂移（0/20+ ↔ 4/7）。
- **寄存器级否证（vk125-resetterm）**：DSI 侧复位+强制 `ctrl_reset()` 终态后，`CLK_STATUS` 的 DYN 位被清（`0x3743→0x1403`），但 `link_power_on` 后立刻回 `0x1743` ⇒ **动态像素时钟请求在 power-on 阶段被重新拉起，请求源在 DSI 控制器之外**。
- 上游报告（v2 发送版 `out/q28-bonded-dsi-2026-10-13.mail.txt`）**待用户发送**；问题含"bonded 路径是否上游支持、超时是否应由驱动可恢复"。

### 3.2 会改变 Q28 现场行为的重构（**必须与设备试验配对，不能只做静态重构**）

| hunk | 对 Q28 现场的影响 | 处置 |
|---|---|---|
| **H45/H46（bonded 配对/触发序）** | 直接决定"DSI0=master、DSI1=peer、谁拥有完成 IRQ"——坏发就发生在此 | P4 原样搬运，**不改语义**；改一行都要重跑 Q28 冷起风暴 |
| **H12/H20（IRQ mask 与 `dma_submit_seq`）** | 影响 `CMD_DMA_DONE` 的 ACK/等待——坏发时 `TRIG_DMA` 不自清 | 同上 |
| **H39/H40/H42（`msm_dsi_host_enable` 时机从 pre_enable 挪到 enable）** | 改变"首条命令时链路/LP11 状态"，**最可能移动 Q28 概率** | P4 内保留原时序；**不要**在 P2 里顺手改 |
| **H11/H24/H52（clk rate/parent、拒绝陈旧配置）** | Q28 报告已试过 byte-clk 取整路径；这些也在动时钟 | P2 归为"硬件事实"，但改动后**必须**跑 Q28 对照（否则可能把已知坏发率调成未知） |
| **H14（`dsi_sw_reset_v2_9`）** | Q28 的 `q28-resetterm` 实验正走此路径 | P2 保留行为；**魔数需 stock 佐证** |
| **H19/H37/H38/H41（坏发即放弃）** | 定义"坏发后不再恢复"的语义 | 属 Q28 策略，P4 门控；上游若认为应"可恢复"，这里要改成 RFC 提交 |

### 3.3 **不得**写进 cfg 的"未定根因"（否则把 Q28 实验当硬件事实）

以下均为**反汇编 Lenovo stock 得到 / 为绕开未定根因引入**，根因定案前**禁止**作为 per-SoC 硬件事实并入 P1–P3：
1. `dsi_cmd_error_prepare()` 的 `REG_DSI_ERR_INT_MASK0 |= 0x001f0200` 与 `dsi_cmd_error_cleanup()` 的 `0x44440400`（H23 内）。
2. `dsi_sw_reset_v2_9()` 的 force-on 时钟位 `BIT(8)|BIT(9)|BIT(11)|BIT(21)`（H14）。
3. `bonded_cmd_init_trigger()` 的调度行算式 `vtotal-(vsync_start-vdisplay)+1`（H23）。
4. "reject stale link configuration"→`-ESTALE` 的**语义**（H24）；`link_configured` 状态机（H04/H27/H29/H30/H32）。
5. 超时常量：master 200 ms、slave 500×10 µs（H23）。
6. `dsi_bonded_cmd_failed` 全局 + bridge 各处 early-return（H34/H37/H38/H41）。

→ 这些都只允许出现在 **P4**，且带 `cfg->bonded_cmd` 门控 + 注释标明"下游实验/RFC，根因见 <Q28 报告>"。

### 3.4 实验钩子该放哪

| 钩子 | 现状 | 建议 |
|---|---|---|
| `dsi_cmd_delay_us` cmdline（`patches/q28-cmd-dma-delay.patch`） | **不在 M1 树**；实验层 | 若证明是**面板时序事实**→进 **panel mode data**；否则保留为**实验层**、以 quirk + 上游 RFC 说明（policy §3 原文） |
| D1 timing `dev_info`（`patches/0006-dsi-timing-diag.patch`） | **不在 M1 树**；实验层 | 永不进上游；B5 各补丁**不得**顺手加回 |
| bonded 协议本体 | **在 M1 树内**（H45 等） | 短期：P4 门控保留，M1 继续可跑；上游反馈若"非上游模型"→整组移入 **M5 下游 patchset**，M1 树删除（届时 M1 命令路径回退到上游 `need_sync` 双写） |

**结论**：**B5 与 Q28 合并做的正确姿势** = 先做 P1（+P0），再 P2/P3（数据/DT），最后 P4（行为，门控+试验）。P1–P3 必须对 Q28 **行为中性**（不改 bonded 时序/时钟调用序），否则 Q28 的"时间窗漂移"统计会被重构引入的新变量污染。
