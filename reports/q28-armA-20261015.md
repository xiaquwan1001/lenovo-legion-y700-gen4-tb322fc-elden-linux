# Q28 arm A 实验报告：vendor bonded 命令协议的否证与「可分离性」的证实（2026-10-15）

> 状态/样本数 SSOT = `TASKS/README.md` §5 Q28；协议 = `.pi/plans/2026-10-15-armA-采样协议.md`。
> 原始证据 = `logs/armA-sampling-20261015/`（每发一个子目录）+ `reports/trials/20261015T*`。
> 纪律：全部 5 发均为**真实物理 POR**；判定最终一律以**用户目视**为准（`PITFALLS #251/#255`）。

## 0. 一句话结论

**arm A（删掉 vendor bonded 命令协议、改走标准 `need_sync` 双写路径）不是 Q28 的解**
（0 GOOD / 3 BAD，与 baseline 无显著差异），
**但它证明了 Q28 的 `-110` 命令 DMA 超时签名与「面板不亮」是可分离的两件事** ——
不变量是**面板黑**，不是 `-110`。这把后续靶点从「命令路径」彻底推开。

### 1.1 arm A 的三处改动（已核对为真单变量）

1. `dsi_mgr_uses_bonded_cmd()` → `return false`（停用 vendor bonded 写路径）
2. `msm_dsi_manager_cmd_xfer_trigger()` → 还原上游（`need_sync` 双写、`DSI_0` 早退返回 0）
3. `msm_dsi_manager_cmd_xfer()` → 补 `if (need_sync && id == DSI_0)` 早退

**立论前提**：旧否证（P2b/P2c「上游 DSI 点不亮」）取证于 **2026-10-13/14 上午**，
而 M1 树的显示回归 **2026-10-14 12:40 才由 E1b 修复** ⇒ 那批结论**被污染**、从未在 E1b 后复测。
arm A 即补这一课。（**前提成立，但结论是反向的**——见 §3。）

## 3. 统计与裁定（**不过度声称**）

**Fisher 精确检验**（双侧，`[[armA 0G,3B],[base 2G,2B]]`）：**p = 0.43 ⇒ 无显著差异**。
arm A 打出 0/3 在真值 p=0.5 下的概率 = **12.5%**，**毫不意外**。
（baseline 本会话自测恰为 50%，与该先验一致。）

⇒ **不能说 arm A 更差，也不能说更好。**
⇒ **裁定：arm A 作为「修复」= 否定（无可测收益）。**

（早期「s1+s3 0/2 ⇒ arm A 更差」的方向性读法，在 s4 出坏发时**已撤回**——
这正是必须取对照臂坏发样本的理由。）

## 4. ★ 本实验真正的产出：可分离性（定性结论，不依赖率）

| | `-110` 签名 | 面板 |
|---|---|---|
| **baseline 坏发**（s4） | **在**（`l1=5`，`command DMA timeout status=0x2200200` + `master=-110 peer=-110`） | 黑 |
| **arm A 坏发**（s1/s3/s5） | **不在**（`l1=0`，panel "prepared"） | **仍黑** |

⇒ **arm A 改变了失败的「模式」，没有改变「结果」。**

**推论（本项目本轮最重要的机制结论）**：

1. **不变量 = 「面板黑」**；`-110` 命令 DMA 超时**不是**不变量（arm A 证明它可以缺席）。
2. ⇒ **「Q28 的 `-110` 签名」与「面板不亮」是两个可分离的层**。
   过去所有工作（七臂 vk116–vk125、B5 命令路径分析）都盯着 `-110` 那一层；
   **而真需求（`local-cleanup` §1 需求 a）是「面板有内容」这一层。**
3. ⇒ 这同时**解释了 P2b/P2c 的命运**：上游命令路径也是「DRM/合成器全 GOOD、面板无内容」——
   **与 arm A s3/s5 完全同类**。P2b/P2c 当初的「1 发 GOOD」是**判据错误**（只查 `card0`+session），
   不是真的点亮。

| 亚型 | 背光可控（电源键） | 签名 | 样本 |
|---|---|---|---|

⇒ **亚型是可观测的新维度**，建议后续每发都记录「背光是否可控」。

## 6. ⚠️ 方法论定论：`q28-devprobe2.sh` 会**误报 GOOD**

本会话 **s3、s5 两次**，探针把**用户确认的黑屏**判成 `VERDICT=GOOD`：

```
s3/s5: l1=0  l2=0  session=1  phoc=1  phosh=1  wayland=1  connected=1  →  VERDICT=GOOD
       但用户目视 = 黑屏
```

**原因**：其规则（`l1==0` + connector `connected` + session 起来）**不充分**。
坏发时 `card0-DSI-1=connected`、phoc/phosh/wayland、DPMS On、背光开、
`disp_cc_mdss_pclk0/1_clk_src=172991986 Hz` 被 DSI 认领、`crtc intf_mode=2` —— **全部照常**。

**❌ 我已验证为无效的「软件侧点亮代理」（重要，勿再用）**：
- **`grim` 出图**：抓的是**合成器自己的 buffer**，不是面板输出。
  arm A s3 实测 `grim` 出 1904×3040、解码 151 个不同字节值（真桌面内容），**而屏幕是黑的**。
- **受激 `core_irq` delta**（我本轮提出）：s3 实测 +8/次重绘、与 GOOD 台相同，**但屏幕是黑的**。
  它只证明 **DPU 在跑**，不证明面板收到有效视频。
- **`DSI PLL(0) lock failed status=0x0` ×4 + `orphan reparent failed -110` ×4**：
  在**三发样本（含 GOOD 的 s2）中完全相同** ⇒ 早期 probe 伪影，**无判别力**。

**✅ 辅助量（5/5 与目视一致，但仍不能单独作数）**：
**`dsi_isr`（`/proc/interrupts` 的 mdss IRQ 4）** —— 亮 = **41**；坏 = **0 / 0 / 0 / 0**。

> **定论：唯一可信判据 = 用户目视**（`PITFALLS #251/#255` 完全正确）。
> agent 不能自证「点亮」；**采样与判定必须配合用户在场**。

## 7. 与「用户亲述症状」的呼应

用户对两类坏发的现场描述（本轮最硬的证据）：

- **s3 / s5（A 型）**：*"电源键能控制背光亮暗，音量键和音频正常，但是屏幕无显示"*

## 8. 方案 C：静态调查 + 只读判别（本轮补完）

### 8.1 ❌ GDSC `HW_CTRL_SKIP_DIS` 候选：只读判别**否证**

子代理静态调查挖到一条此前无报告涉及的 delta：`dispcc-sm8750.c` 全文仅 2 行差异 ——
`mdss_gdsc`/`mdss_int2_gdsc` 被 payload 加了 `HW_CTRL_SKIP_DIS`（全 mainline 仅此一处、原厂无），
使 `gdsc_disable()` 永久跳过 `gdsc_hwctrl(false)`。其建议的**零成本只读判别**已在机执行：

| 启动 | 判据 | `mdss_gdsc` | `mdss_int2_gdsc` |
|---|---|---|---|
| **GOOD**（s7，用户确认亮，`dsi_isr=41`） | `l1=0` | `on` | `off-0` |
| BAD（s4） | `l1=5`（`-110`） | `on` | `off-0` |
| BAD（s6） | `l1=4`（`-110`） | `on` | `off-0` |

**三方完全一致 ⇒ 零判别力 ⇒ 该候选收口，不建臂。**

**⚠️ 口径（不可过度解读）**：`/dev/mem` 被 `CONFIG_STRICT_DEVMEM=y` 挡住 ⇒ 只能走 `pm_genpd`。
而这否证的是「**用 `pm_genpd` 可观测状态做 Q28 判别**」这条路，**不是** `HW_CONTROL_MASK` 位本身——
`pm_genpd` 暴露的是 genpd **状态机视图**（且 `mdss_gdsc` 因 `ae00000.display-subsystem` 持有而**恒为 `on`**），
**不是 `gdscr` 寄存器原值**。要读寄存器位须写内核侧 debugfs 钩子 = **引入新变量**，性价比不成立。

### 8.2 Pengyu 指路（`dsi clk source select`）：前提**反转**

Pengyu 指路的落点 = PHY `DSI_7nm_PHY_CMN_CLK_CFG1.DSICLK_SEL` + 它决定的
`disp_cc_mdss_pclk{0,1}_clk_src` 输入频率，**不在 DPU**（DPU 全目录 `CLK_SEL|clk_sel|clk_src` 命中 0）。

**三方对照**：

| | C-PHY 选择 | `pclk_div` |
|---|---|---|
| pristine `24a19b953e` | `DSICLK_SEL(3)` / `pll_post_out_div` | 4/7（不可达） |
| **本树** | **`SEL(0)` / `pll_bit`**（payload `640b0e49db`） | **2** |
| **原厂** `dsi_pll_3nm.c:1196-1217`（bpp=30, lanes=3） | **`sel=0`** | **2** |

**数值闭环**：`756839941/2 × 16/35 = 172991986 Hz` = 实测 `pclk0/1_clk_src` **逐位吻合**
（`{16,35}` 在上游 `clk-rcg2.c:1120`）。

⇒ **前提反转：本树已 = 原厂；pristine 7.3-rc7 才是错的那侧。**
⇒ **与 Q28 不吻合**（DSICLK_SEL 是 probe 期一次性静态 mux；坏发首命令前寄存器与好发**逐字相同**、
好坏发 pclk rate 全同；若它错，症状是上电期 `Failed to set rate pixel clk -22`，**走不到发 `ff 20`**）。
⇒ 该轴**停止投 Q28 工时**，改记为**高价值上游化 patch**（pristine 的 `SEL=3` 对 elden 这类
30bpp/3-lane C-PHY 是错的）→ M3 显示片。
