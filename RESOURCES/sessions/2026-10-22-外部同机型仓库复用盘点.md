### `0154`+`0155` 为什么算 Q28 真候选（不是重复劳动）

- `0155`（Baryshkov 上游系列）机理：`dsi_pll_7nm_vco_prepare()` 只清 `PLL_SHUTDOWNB`、不抬 `DIGTOP_PWRDN_B` ⇒ **PLL 锁不上**；
  自 `acf7a91d0b0e` 起时钟框架会在 PHY 使能前去锁 PLL（`of_clk_set_defaults` 应用 `assigned-clock-parents`），
  失败时 `CMN_CTRL_0` 读到 `0x20`，打印 `DSI PLL(0) lock failed, status=0x00000000`，并使 pixel clock 使能计数失衡。
- 本仓历史记录里，冷起 **NOCARD** 模式的原话就是「`DSI PLL(0) lock failed status=0x0`×4 + `Failed to create device link … for panel@0`×6 ⇒ 无 card0」，
  当时被判为「组件不聚合的下游伪影」（`PITFALLS` #277 / M1-7.3 会话 #31）。那条判定在**缺模块**场景下成立，但**没有穷尽**这条独立成因。
- `0154` 补的是另一半：某些 bootloader 退出时把 dispcc 留在全活状态（PLL 已锁、三个 BCR 已出复位），内核的 `mdss_reset()` 叠在活状态上 ⇒ kickoff timeout / encoder reset failure。
  与「热复位粘态」「cold-only」的经验吻合（**同一方向，未证实**）。
- 与 2026-10-22 另一份 Q28 结论**不冲突**：软件闩锁（`dsi_bonded_cmd_failed` 只置位不清零）与 `link_configured` 误清解释的是**坏发后不可恢复**；`0154/0155` 解释的是**首次坏发**。两者可并存。
- 落地方式（未做）：打两补丁 → 用现成 `scripts/q28-devprobe.sh` 三态判据 **冷起 ≥10 发**；单变量 = 只有这两补丁 vs 当前基线，其它不变。

## 3. Mu-Silicium：从「系统性缺口」降级为「换一个二进制」

- 现状取证：`Status.md` 的 **Snapdragon 8 Elite（SM8750）** 段有 OnePlus 13 `dodge`，`Internal Storage ✅ / Mass Storage ✅ / Linux Boot ✅`；SM8850 段另有 OnePlus 15。
- **UFS 成功的原因有据可查**：`Device-Binaries/dodge/README.md` 明写 UFSDxe 两条补丁——「sleep 调用换成 wakeup」「gear check 前强制 link 唤醒」（作者 `sunflower2333`/N1kroks），
  且 `UFSDxe.inf` 确实指向 `UFSDxe.patched.efi`（155648 B，sha256 `e76b555f…3c85ef`；未打补丁版 151552 B，`0b32d924…d41aac`）。
- 我们 2026-10-05 试的是 **`mu_wide_platforms` 自己那版** `PatchedBinaries/UFSDxe.efi`（另一套补丁，反把 32 位配置值当指针解引用 ⇒ `UFSDxe+0x13224` 硬崩）。
  ⇒ 与「上游答复：需 UFSDxe 专用补丁」对齐，**这只是没试对版本**，不是平台不可救。
- ⚠ 本机已无 `mu_wide_platforms/`、`uefi-firmware-backup/`（2026-10-17 换机未随迁）⇒ 重试须先重取；配方写在 `reference/upstream-mu-silicium/README.md` §3（未执行、未上机）。

## 4. 明确「不取」的

| 东西 | 原因 |
|---|---|
| kShimC 启动菜单源码（5.4 MB） | **GPL-3.0**；且引入即等于替换本仓「单槽 `boot_b` + kexec」架构，属立项级决策 |
| kshim-tools（packer/unpacker/avbtool） | 与 `bootslot-b/` 打包功能重叠，先比再取 |
| hv-haptics（`1000`，194 KB）/ rsinput FF（`1002`） | 本仓触觉与手柄链路不同（无 RSInput 驱动），不引入新驱动栈 |
| SM8750 基础设施补丁（gpucc/GPU/UART15/CPU capacity/热/ufshc/PCIe suspend opp） | 本仓 `sm8750.dtsi` 已更全 |
| ArmadaOS 的 DTS 处理方式（禁 `memory@a0000000`/`ramoops`/`splash`、内存由 kShimC 交接重建） | 与我们的引导链相反，**不要照搬** |

## 5. 复用清单（按性价比）

1. **`0154`+`0155` → Q28 冷起 A/B**（成本 = 32 行 + 一轮 ≥10 发冷起）。
2. **dodge `UFSDxe.patched.efi` → G1-29 零写盘重试**（成本 = 重取 1 G 设备包 + 换 1 个文件 + 1 次 `fastboot boot`）。
3. **`0146` 的 `arm_smmu_boot_fb_range()`**：只在出现「splash 区被覆盖/花屏」时对照，不主动加。
4. **Steam ARM64 客户端 pin + FEX/gamescope 配方**：G3 的备选路线评估材料（本仓现走 Box64+Wine）。
5. **设备配置事实**：触屏名 `NVTCapacitiveTouchScreen`、`ARMADA_GAMESCOPE_USE_ROTATION_SHADER=1`、`ARMADA_BUILTIN_GAMEPAD=0`（仅当上 gamescope 时用得上）。
