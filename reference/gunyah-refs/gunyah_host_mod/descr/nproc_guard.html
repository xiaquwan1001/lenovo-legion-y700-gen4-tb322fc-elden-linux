Why it's needed

To reach the camera, microphone and app-scoped files, DroidVM briefly switches a helper thread's real user ID between root and the app, over and over. The kernel keeps a per-user count of running processes (RLIMIT_NPROC), and its bookkeeping can drift a little on each of those switches — sometimes one too many, sometimes one too few.

Once that count drifts below zero (or, far more rarely, past the ceiling), the kernel refuses to start any new process for the app's user. The symptom is unmistakable: DroidVM stops opening, often right after reinstalling or after many VM start/stops — and only a reboot clears it, because the bad count lives in the kernel.

What it does

It recomputes that count from the truth — the number of the app's processes actually running right now — and writes it back, so the kernel starts the app again without a reboot. A count below zero is always wrong, and while the app is closed the correct value is simply zero.

The app's user ID is different on every phone, so it is not built in: the DroidVM daemon passes it when it loads the module. Loaded on its own, the module does nothing.

If the app still won't open

Run this once from a root shell (e.g. Termux), then reopen DroidVM:

su -c 'echo 1 > /sys/kernel/nproc_guard/reset'

Check what happened with su -c 'cat /sys/kernel/nproc_guard/status'. The lasting fix is on the DroidVM side (switching only the effective/filesystem user ID, which never touches this count); this module is the no-reboot rescue in the meantime.

原因

为了访问摄像头、麦克风和应用私有文件，DroidVM 会把辅助线程的真实用户 ID 在 root 和应用之间来回切换，而且非常频繁。内核为每个用户维护一个正在运行的进程计数（RLIMIT_NPROC），每次这样切换，它的记账都可能偏一点点——有时多算一个，有时少算一个。

一旦这个计数掉到负数（或极少数情况下超过上限），内核就会拒绝为该应用的用户启动任何新进程。症状很明确：DroidVM 打不开了，常发生在重装之后、或反复开关 VM 之后——而且只有重启才能清除，因为坏掉的计数在内核里。

功能

它按真实情况重新计算这个计数——也就是该应用当前真正在跑的进程数——再写回去，让内核不用重启就能重新启动应用。负数一定是错的；应用关闭时，正确值就是 0。

应用的用户 ID 每台手机都不同，所以不写死：由 DroidVM 守护进程在加载模块时传入。单独加载时，模块什么都不做。

如果应用还是打不开

在 root shell（例如 Termux）里执行一次，然后重新打开 DroidVM：

su -c 'echo 1 > /sys/kernel/nproc_guard/reset'

用 su -c 'cat /sys/kernel/nproc_guard/status' 查看结果。根治要在 DroidVM 端（只切换有效/文件系统用户 ID，就不会碰到这个计数）；这个模块是过渡期的免重启急救。

為了存取相機、麥克風和應用程式私有檔案,DroidVM 會把輔助執行緒的真實使用者 ID 在 root 和應用程式之間來回切換,而且非常頻繁。核心為每個使用者維護一個正在執行的行程計數(RLIMIT_NPROC),每次這樣切換,它的記帳都可能偏一點點——有時多算一個,有時少算一個。

它按真實情況重新計算這個計數——也就是該應用程式當前真正在跑的行程數——再寫回去,讓核心不用重開機就能重新啟動應用程式。負數一定是錯的;應用程式關閉時,正確值就是 0。
