Why it's needed

For GPU acceleration the virtual machine and the phone must work on the same graphics memory, instead of copying every frame back and forth.

Qualcomm's Gunyah virtualization layer can in fact share memory with a VM while it is running — but the phone kernel does not expose that ability. There is simply no interface to call, so GPU acceleration cannot work.

What it does

The module adds the missing interface, /dev/gunyah_share. While the VM runs, it lets the VM program (crosvm) hand a graphics buffer to the VM on the fly.

Nothing in the kernel is patched or reflashed: the module reaches the kernel's internal helpers by resolving them at load time.

原因

GPU 加速需要让虚拟机和手机使用同一块绘图内存，画面数据才不必来回复制。

高通的 Gunyah 虚拟化底层其实具备「对运行中的 VM 动态共享内存」的能力，但手机内核并没有把这个能力开放出来——根本没有可以调用的接口，因此 GPU 加速无法运作。

功能

这个模块补上缺少的接口 /dev/gunyah_share：在 VM 运行中，让虚拟机程序（crosvm）把一块绘图内存即时交给 VM 使用。

全程不修改也不重刷内核：模块在加载时自行解析内核内部的相关函数。
