- **结论**：

1. **vk189 零写盘上机全绿**（`fastboot boot out/boot-elden-vk189.img`）：`uname -r` = `7.3.1-debug-vk189-suspend-00002-g4da9a8b69fc8-dirty`；
   `/sys/power/state` = `freeze mem`、`mem_sleep` 默认 `[s2idle]`；`lsmod` 非空；`/dev/dri/card0`；DSI `bound ae94000.dsi`；
   `wlp1s0` UP；无 arm-smmu fault / xHCI 错误。**s2idle 3/3 成功**：`rtcwake -m mem -s 45` 三发，
   `suspend_stats/success` 0→3、`fail=0`、`uptime` 连续；唤醒后面板重下发 novatek 固件、WiFi 重关联（`PM: suspend entry/exit` 成对）。
   附：每次入睡/唤醒会打一条 `qcom-pcie 1c00000.pcie: Timeout waiting for L2 entry! LTSSM: 0x12`（WCN PCIe L2 已知面，WiFi 仍工作，T9 线口径）。

2. **发现真回归 → vk190**：vk189 上 `hexagonrpcd` 失败（`/dev/fastrpc-adsp` 不存在）、`iio-sensor-proxy` inactive。
   根因 = 日常线（vk184/188/189）**从来没有** ADSP fastrpc 的 `qcom,non-secure-domain`；该修复 11-07 已投上游，
   但当时只落进 **vk185 的独立三提树**。判据陷阱见 `PITFALLS #639`（不能用 `strings dtb | grep -c`：属性名在 strings 表按名去重，恒为 1）。
   处置 = `build/daily` apply `patches/upstream/sm8750-adsp-nonsecure-20261107/` → 只重编 DTB（`dtbs` + `CHECK_DTBS=y` 零新诊断）
   → 重打包 `out/boot-elden-vk190.img`（sha `54e84588…`，dtb `89c9336d…`）。**UTS 与 vk189 逐字相同**（刻意复用机上 1499 `.ko`；
   身份由 `kernel_payload_sha256` 锚定：vk190 `511e16a1…` vs vk189 `cab6a5c3…`），known-issues 已登记 `uts_dup2`。

3. **vk190 判据全绿**（零写盘 1 发 + 持久 1 轮）：`/dev/fastrpc-adsp` 在、`qrtr-lookup` 有 `400 Snapdragon Sensor Core service`、
   `iio-sensor-proxy` active、`HasAccelerometer/HasProximity = true`、`monitor-sensor` 出 `+++ iio-sensor-proxy appeared`；
   s2idle 2/2 success；WiFi/DSI/Waydroid/zramswap 正常。**持久化**：`boot_b` 自签+流式 dd，**readback sha 逐字一致**（`4f020cb3…`）；
   ESP `/boot/boot.img` 换同件（`54e84588…`，`menu.cfg` 首项改 `Elden vk190`，FAT `fsck` 干净）；**重启实测回 vk190**，
   `boot_id` 换新、cmdline 无 `elden_bootloader=esp` ⇒ 实际走 **`boot_b` 槽**（`getvar current-slot` 也是 `b`），UEFI/ESP 链降为备用。

4. **两条门禁欠账收口**：① ABI 参考从 10-18 的 `patches/config-vk127-working-*` 换到 `patches/config-daily-c2-suspend-20261113`
   （`scripts/check-abi-config.sh` 默认序反转，先 `config-daily-*`），`build/m3v2-7.3rc7` 同步开 SUSPEND（`patches/config-m3v2-suspend-20261113`）
   ⇒ 两树都是「27 项一致」，**打包不再需要 `SKIP_KERNEL_ASSERT=1`**（vk189 那条红门的解除条件兑现）。
   根因与规则见 `PITFALLS #640`（含「vk189 的 config 快照其实是 vk188 状态」的事实：`config-vk189-suspend-20261112` 的
   `CONFIG_LOCALVERSION` 是 `-debug-vk188-sysfbfb` 且无 GUNYAH 符号，与 vk189 manifest 的 `config_sha256=feefc38b…` 不符）。② `scripts/to-fastboot.sh` 的复位 ssh 加 `timeout -k 5 12`（`PITFALLS #638`，用户现场指出「ssh 还挂着连接」）。
