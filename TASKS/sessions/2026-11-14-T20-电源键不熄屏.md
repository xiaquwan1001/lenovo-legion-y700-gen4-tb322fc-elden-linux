# T20 电源键不熄屏（2026-11-14 用户报回归）

**日期**：2026-11-14
**pi 会话 id**：01a1d8a6-9861-7308-aa73-7b014fc47dfe
**主题**：电源键短按不再熄屏/挂起（用户：「之前是可以的」）；本轮定位到桌面层，未做修复。

**结论（截至本轮）**：

1. **不是内核没编挂起**：

   | 判据 | 实测（本 boot） |
   |---|---|
   | 挂起能力 | `rtcwake -m mem -s 60` → `PM: suspend entry (s2idle)` 14:45:56 / `exit` 14:46:47（51 s），`suspend_stats` success **3→4**，fail 0 |
   | 唤醒后显示 | `card0-DSI-1` connected、dpms On、背光 1197，SSH 立即可达 |

2. **按键确实到达，但没人处理**：
   - `systemd-logind` 记录 `Power key pressed short.`（用户 14:29:11/12、14:30:11 三次均记录）；
   - `systemd-inhibit --list` 里 phosh（`handle-power-key`，**block**）与 gsd-media-keys（`handle-power-key…`，block）
     都声明"我来处理"⇒ logind 让位；
   - 但按下后 **phosh / gsd-power / gsd-media-keys 零日志、journal 里 0 条 `Reached target sleep`、0 次 suspend 尝试**。
   - 输入链路本身正常：`pmic_pwrkey` 绑 `/dev/input/event0`（IRQ 23 有计数）；phoc、seatd、logind 都持有该设备 fd。
   - phosh 二进制含 `Failed to get power button inhibit fd` / `Inhibited logind power button handling` /
     `Power button released, activating screensaver` ⇒ 设计路径 = logind inhibit-fd → phosh → screensaver；
     `gsd-media-keys` 读 `power-button-action`（用户值 = `suspend`）。

3. **关键异常：phosh 的屏幕保护状态卡在 active**：

   | 查询 | 结果 |
   |---|---|
   | `org.gnome.ScreenSaver.GetActive` | **`true`**（屏幕亮着、用户在正常使用） |
   | `GetActiveTime` | **0**（自相矛盾：active 但计时 0） |
   | `SetActive true` | 空回包，状态不变 |
   | `SetActive false` | 空回包，**仍 `true`** ⇒ 无法解除 |

   ⇒ 推断（未证）：电源键 → screensaver "activate" → **已经是 active** ⇒ 空操作 ⇒ 屏不灭。
   启动期日志有对应残留：`phosh[…]: Failed to send locked hint: … Session does not support lock screen.` +
   `pam_unix(phosh:account): setuid failed: 不允许的操作` + `gkr-pam: no password is available`
   （桌面账户 `xuqianhui1001` 为**无口令**账户）。

4. **版本线索**：aph history 显示 phoc/phosh/libphosh/phosh-common/xdg-desktop-portal-phosh
   在 **2026-11-05～11-07 从 0.58.0-1 升到 0.59~rc1-1**（同一批 packagekit 升级），
   与用户「之前是可以的」时间吻合；但**未做**降级对照，不能当结论。

5. **本轮已布置的取证开关**（可回退）：

   - `busctl --user set-property mobi.phosh.Shell.DebugControl … LogDomains as 1 "*"`（原值 = 空列表）
     ⇒ phosh 的 `g_debug` 会进 journal，按电源键即可看到它走到哪一步。
     复原：`… LogDomains as 0`。
   - 备选判别：把 phoc/phosh 降回 `0.58.0-1` 复测（需重启桌面会话）。

**下一步（按顺序）**：

1. 用户在 debug 已开启状态下按电源键 2 次 → `journalctl -b --since "-2min" | grep -i phosh` 看是否有
   `Power button …` / `activating screensaver` 行：
   - 有 ⇒ 断点在 screensaver/blanking（状态机卡 active），修 screensaver 状态或解锁路径；
   - 无 ⇒ 断点是**事件没到 phosh**（logind inhibit-fd / phoc 输入转发），查 `phosh` 的 inhibit fd 与 phoc 的 key 分发。
2. 若 1 无定论：降级 phoc+phosh 到 0.58.0-1 复测（可逆，需会话重启）。
3. 任何情况下**不要**为了"试出来"去改 `HandlePowerKey=`/`logind.conf`：logind 侧本来就是让位语义。

## 6. 收尾状态（2026-11-14 晚，用户叫停）

- **仍未解决**。本轮排除项已写进正文：内核挂起/恢复（4/4 成功）、按键到达 logind（7 次记录）、
  greeter 类会话假设（改 PAM service 无效）、**野 `phoc -v` 抢 `/dev/input/event0`**（已清除，现象不变，用户确认昨晚就坏）。
- **未做的判别（留给后续，按代价排序）**：
  1. `phosh` 侧事件链：phosh 用 logind **inhibit-fd** 接电源键（二进制字符串 `Failed to get power button inhibit fd`），
     可在会话启动时用 `strace -f -e trace=read,epoll_wait -p <phosh>` 看该 fd 是否被读、是否有事件；
  2. 通道排除：临时把 `power-button-action` 改 `nothing`/`interactive` 看 gsd 是否动（区分 gsd 与 phosh 谁该动）；
  3. 版本对照：`phosh 0.58.0-1` 已装未解决 ⇒ 下一档是 `phoc 0.59~rc1 → 0.58.0-1`（未做）；
  4. 会话类：把桌面从 greetd greeter 会话改为 **user 类会话**（需要改登录路径，非 PAM service，风险高）。
- **纪律**：不要再为了试而重启 greetd（会关掉用户全部 app，且已证实与现象无关）；改包一律留 0.59~rc1 的 deb 回滚路径。
