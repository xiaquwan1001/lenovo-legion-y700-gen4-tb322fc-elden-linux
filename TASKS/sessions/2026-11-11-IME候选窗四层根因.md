- **主题**：用户实测「键盘能弹、中文能上屏，但无候选窗」；本轮定位并修复第 4 层根因。
- **结论**：
  1. **层 A（UI 后端）**：`CurrentUI=classicui` 在 phoc 上建不出候选窗（classicui 需要的窗口协议 phoc 不提供）
     ⇒ 必须 `SetAddonsState "[('classicui',false),('kimpanel',true)]"`，kimpanel owner = `elden-ime-focusd`。
  2. **层 B（直接原因）**：**新 IC 恒拿 `keyboard-us`**。判据 = **新窗口有焦点时** `fcitx5-remote -n`
     （全局看着是 `rime`，新 IC 却是 `keyboard-us`）。机制 = fcitx5 新 IC 取 `profile` 的 **`Items/0`**，
     `DefaultIM=rime` 改不了它。原 profile 是 `Items/0=keyboard-us` ⇒ Rime 不参与 ⇒ 候选恒空。
  3. **三个坑（都踩过）**：① fcitx5 退出时把内存态**写回** `profile`（运行期改文件被覆盖）；
     ② `pkill -x fcitx5` 杀不掉（systemd user unit 立刻拉起；`mask` 后仍另有实例）——判据 `pgrep -x fcitx5 | wc -l` 必须 = 0；
     ③ `AddInputMethodGroup` 会新建 `[Groups/1]` 而 `GroupOrder` 只有 `0=默认` ⇒ 顺序错乱且读回仍是旧值，**不要用它改顺序**。
  4. **正解**：停 unit + `kill -9` 残留 → 写 profile 把 rime 放 `Items/0` → 起 unit →
     `InputMethodGroupInfo 默认` 读回 `('us', [('rime',''),('keyboard-us','')])`。
  5. **判据全绿**：新 IC `fcitx5-remote -n`=`rime`；`dbus-monitor` 抓到 `SetLookupTable` 真实候选
     `["你","那","呢","能","年"]`（打 `ni`）；截图 `reports/artifacts/ime-candidates-20261111.png`；
     **用户目视确认「现在能看到候选词」**。
