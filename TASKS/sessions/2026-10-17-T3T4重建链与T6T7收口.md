## 关键判断与教训（★ 供并入 `PITFALLS`/`TASKS` SSOT）

1. **★ 下游「最终态」不能取 `v7.2-elden` tip**（`ba28ec16f`）：它是 GEEKiDoS 上游分支，**不含**我们自己的 12 个运行期提交（温控分级 / WCD939x 音频 / aw86927 / psci reboot / dpu GC / cdsp split / 相机 rotation / fastrpc non-secure-domain）。用它会得到 **DTB 140537 B**，缺 `passive0..3`、`audio-codec`、`wcd-capture-dai-link`、`splash_region`。
   ⇒ 判别法：**用「在机镜像里的 DTB 指纹」反查下游 tag**（pstore 大小 / audio-codec / wcd dai link / splash 命名 / cambist 电源域）。命中 `vk64`；`vk53` 差 3 项；`vk83` 带 Q24 FIX-1。
2. **Q24 的实验性 DT 会污染日常镜像**：`vk64` 的 cambist 是 H2（只挂 MX）、`vk83` 是 FIX-1（只挂 MXC），而**在机基线是上游 parity（MMCX+MX 双域）**。重放时必须回退，否则日常镜像悄悄带上未收口的 Q24 变体。
3. **payload 基点对象丢失后的替代重建**：`linux-7.2.tar.xz`（USTC 镜像 6 s，160 MB）→ `git init` 提交作 pristine 基点 → 用 cherry-pick 做三方合并（保留 7.3 上游新增节点，如 coresight `tmc/replicator`）。比 `diff -rq` + 手工贴回可靠。
4. **`mkbootimg` 的 sha1 id 字段不可盲信**：AOSP 的 `id = sha1(section + "<len>" …)`，但工程内历史镜像是**事后重打过**的，其 id 不服从任何标准序 ⇒ 自校验应**屏蔽 576..608** 再比结构。另：往 32 字节切片写 20 字节 digest 会**静默缩短 header 12 字节**（正是我第一次自校验失败的原因）。
5. **浅克隆限制**：geekidos 仓是 shallow，`git fetch` 拒收新 root；加 `--update-shallow` 才能把 7.3-rc7 基座接进来——这也是让 `vk-identity.py` 认 vk127 源提交（`replay/m1-73-vk127` + tag `vk127`）的前提。
6. **`assert-kernel-sane.sh` 原本硬编码 `$ROOT/linux`**：已加 `KDIR=`，否则重放树无法过打包闸门。
7. **`/tools/` 在 .gitignore 里**：这正是 `mkbootimg` 上次随换机丢失的结构性原因 ⇒ 重建后迁到 `scripts/mkbootimg.py`（受管）。
