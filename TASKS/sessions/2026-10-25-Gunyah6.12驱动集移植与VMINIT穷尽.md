## 1. 为什么选「移植 6.12 驱动集」而不是再调 VMM

两条候选（① 移植 6.12 分层 ② 直接用 crosvm 跑差值）里选 ①，因为它是唯一**同时**服务
「让 RM 接受本 VM」与 G1 上游化（主线 `drivers/virt/` 至今无 `gunyah/`，6.12 Android 分支是最接近上游的形状）。

## 2. 硬证据：厂商 RM 消息集 ≠ 我们 6.6 移植

`gh_rm_drv.ko` 反汇编按函数聚合消息 ID：

- 厂商**有** `VM_AUTH_IMAGE = 0x5600000a`；
- 厂商**没有** `SET_FIRMWARE_MEM(0x32)` / `SET_DEMAND_PAGING(0x33)` / `SET_ADDRESS_LAYOUT(0x34)`；
- 6.12 上游把这三条拆成 `config_image` 结构 + `gunyah_auth_vm_mgr` 插件 + 新增 `gunyah_qtvm.c`。

**但**：`gh_rm_vm_auth_image` 报文 = `{u16 vmid; u16 n; {u32 type; u32 param}[n]}`，
6.12 只在 QTVM（`AUTH_QCOM_TRUSTED_VM`）发它，普通 pVM 不发 ⇒ **缺 `VM_AUTH_IMAGE` 不能单独解释 `0xA`**；
真正的结构性差异是 `image_size`/`dtb_offset` 语义与「bind + demand paging」vs「整块急切 LEND」的内存模型。

## 3. `VM_INIT` 穷尽（干净启动后逐条单变量，全部同一个错误码）

`rm-rpc` vdevice（crosvm 写法，从未有过）／只 LEND 不建 fw 区／fw 放 crosvm 的 `0x7fc00000`／
DTB 独立出 RAM／提前建 vCPU／内核侧跳过 `0x33` `0x34`（新增两个 module_param，A/B/C/D 四臂）／
DTB v10–v13（无 `gunyah-vm-config`、无 `memory`、`reg` 代替、`size-max`=RAM）
⇒ **8 项全部 `0xA MEM_INVALID`，DTB-only 路线正式穷尽**。

实测 RM 序列（`kprobe:gunyah_rm_call id=%x1`）：

```
01 → 12(MEM_LEND ×1 页, 只有 DTB) → 09 → 33 → 34 → 0b ← 0xA
cleanup: 15 → 06 → 02
```

**只有 DTB 那 1 页真正 `MEM_LEND`，guest RAM 全靠 `SET_DEMAND_PAGING`** —— 与 crosvm 的「整块急切 LEND」不同，
这是唯一还没测过的内存模型变量。

## 4. 移植与编译

`build/gunyah-port`（原件备份 `build/gunyah-port-6.6-backup-20261025-1406.tar.gz`）；
替换 17 文件 + 5 头文件；**真实 API 漂移 7 处**全部语义等价、逐处 `ELDEN PORT` 注释；
9 个 `.ko` 0 error，vermagic 与日产树逐字一致（含新增 `gunyah_qtvm.ko`）。

## 5. 上机失败（本轮最重要的一条教训）

加载新栈后出现 `list_del/list_add corruption`，且 `reboot` 卡在 `device_shutdown`（电源键无效，只能硬断电）。
根因不是 Gunyah：设备自报 `g2d223a4d0-dirty`，而**所有模块**按 `g24223e44ad80-dirty` 构建 ⇒ 不是同一构建。
`vermagic` 只比 UTS release 串 ⇒ 同串 ≠ 同构建 ⇒ 结构体一变就随机踩内存。已记 `PITFALLS #394`。

⇒ 6.12 栈**未通过上机验收**，但本轮也**未证伪**它。

## 6. 下一步（按收益）

1. 上机前把「构建身份逐字一致」做成硬门禁（`/proc/version` vs `modinfo vermagic`，含 `-dirty`）。
2. 在同一构建的内核上重跑 6.12 栈 + vmmtest；判据 = 无 `corruption`/`BUG`，再看错误码是否变化。
3. 若仍 `0xA`：把 guest RAM 改成**整块急切 LEND**（对齐 crosvm），这是最后一个未测的内存模型变量。
4. 上游化：按 6.12 的分层拆补丁（先 `vm_mgr`/`vm_mgr_mem`，再 `gunyah_qtvm`）。

`build/gunyah-port` 已切到 6.12 驱动集；`/root/ghnew/` 存有 9 个新 `.ko`；`build/vk151` 日用树未改动。
