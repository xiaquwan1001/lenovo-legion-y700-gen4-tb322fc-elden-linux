# 2026-10-28 UEFI 同芯片平板亮屏回挖（lane 会话记录）

## 0. 一句话结论

用户记忆**部分不准**（平板亮屏**未证实**），但**换来了一个更大的发现**：
**我们自己的 Y700g4 UEFI 在 2026-10-05 就已经亮过屏**，且**亮屏通道不依赖 GOP、不依赖 UFS**。
⇒ 「早期可见性」在本仓是**已实现**的，不是待开发项；真正要做的是**复现 10-05**（1 个变量）。

## 2. 三条推翻/更正

| # | 旧结论 | 裁决 |
|---|---|---|
| 1 | 「本机无早期可见性，屏幕输出依赖 GOP」 | ⚠️ **部分推翻**：NoSb 用 `USE_SCREEN_FOR_SERIAL_OUTPUT=1` ⇒ `FrameBufferSerialPortLib` 直写 `Display Reserved`，**不需要 GOP**。10-05 已实测出字 |
| 2 | 「UFSDxe 代次差（159 744 B / KaanapaliLAA 26310）是本机根因」 | ❌ **已否证（本机）**：Mu 件与厂商件只差 **6 字节**（全在 build 路径串 `mp250526` vs `mp251201`）；159 744 B 那版只在 `plk110`/`salami` |
| 3 | 「v3 header 本机 ABL 静默忽略」（10-24/10-26） | ⚠️ **待澄清**：10-05 用的正是 `header_version=3` 且**能真跳并出字** ⇒ 矛盾 |

## 3. 上游新方向（B 项，已评估）

上游 issue #12（2026-10-28T04:27:34Z）：「UFS 问题是 **Link State 处于 Sleep**，写个 tiny DXE 把 link 拉起来」。
**等级 = 上游主张，我方未证实。**

- 能解释 `ufs_error_log 11/3b/55`（`UFS.c+2326`，link/gear 层）；
- **解释不了** 10-05 抓到的 `ESR 0x96000005 / Data abort: Translation fault, second level / FAR=0x0`（SMMU 页表缺项）。
- ⇒ 两层独立。**tiny DXE 成功也可能仍卡在 SMMU 层**。
- 取舍：**先做 E-1（可见性）→ E-2c（注释 UFSDxe，证显示独立）→ E-2a（换厂商件）**，只有 E-2a 仍报 `11/3b/55` 时才做 E-3（tiny DXE）。
- 不推荐先换 dodge `UFSDxe.patched.efi`（`e76b555f…`）：上游 README 自标 **「These Patches are Outdated & Unstable!」**，且是 OnePlus 13 的 PHY/供电配置。
