# 2026-11-10（第七段）— UEFI 干净世代 pc1 + loader 菜单 R72 + GRUB 双层菜单定案

- **日期**：2026-11-10（同日第七段）
- **pi 会话 id**：本段会话（关键词「去掉 debug 的 UEFI + 装载 grub」/「grub 8s 不倒计时、按键后仍进入下一阶段」）
- **主题**：① 构建**去掉 debug 输出与人为停留**的 UEFI 世代 `pc1` 并上机量时；② 修 **loader 启动菜单**的两个真 bug；
  ③ 把 **GRUB 双层菜单**的结构性约束与可用件定案（含「为什么 GRUB 倒计时修不了」）
- **结论**：
  1. **pc1（干净世代）**：p69 − R64/R66/R67/R68/R69/R70 + **R71-quiet**（`SerialPortWrite` 单一收敛点早退：
     只进 `SbLogPut`、不上屏、不做 R2 的每字符忙等）。件 `out/r21-sbstop-pc1/uefi-preamblec1-r1.img`（`40d43397…`）。
  2. **实测（暖复位，零写盘）**：`fastboot boot pc1` → **+39 s** 到 SSH（含 fastboot 11.7 s + 菜单 8 s），
     `elden_bootloader=esp`、内核 `vk184-00002`、`boot_b` 未动；对照 p69 = 128.7 s（R70 的 74 s 停留已去掉）。
     与「p67 = 54.5 s」的严格差值需同法复测（旧条目测法可能不同）。
  3. **用户报的 GRUB「bug」拆成两件事**：
     - GRUB 侧倒计时**看不见是结构性**的：其倒计时文字走 `ConOut`，本平台 `ConOut` 被 R7 设成 no-op ⇒
       交互件改 `set timeout=-1`（永不自动跳），另备 `timeout=1` 的无人值守件。
     - **真正的 bug 在 loader**：`LMenuSelect()` 的倒计时只画一次 + `Start` 不因按键重置 +
       结尾 `if (mLMenuTimeout==0) Sel=0` 强拉回第 0 项 ⇒ 「按键后 8 s 仍启动」「启动到非预期条目」。
       已修 **R72**（`out/espboot-20261110/Loader-r72.efi`，`566cb12d…`，已装 ESP 两处）：标题每秒重画、
       **任何按键即取消自动启动**（`[L] menu autoboot off`）、删掉强拉回逻辑。
  4. **GRUB 双层菜单定案**：arm64 GRUB 的 `linux`=EFI-stub ⇒ 撞 `PITFALLS #558` 墙 ⇒ 选内核只能由我们的
     `LinuxLoader` 做 ⇒ 菜单**必然两层**（GRUB 选 loader/重启/关机，loader 选内核）。件在 ESP `/EFI/grub/`，未替换 `BOOTAA64.EFI`。
