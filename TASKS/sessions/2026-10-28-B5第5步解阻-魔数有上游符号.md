# 2026-10-28 · B5 第 5 步解阻：「魔数无上游描述」被证否，改名补丁落地

- **日期**：2026-10-28
- **pi 会话 id**：`$PI_SESSION_ID`
- **主题**：按顺序继续的三项里第 1 项 **B5 第 5 步**（原判：`0x001f0200`/`0x44440400` 涉及 bit30/29「上游无描述」⇒ 永久隔离）。
  本轮不靠猜：把「有没有上游描述」这条判据本身重做了一遍。
- **结论（数字）**
  - **`0x44440400` 全部有上游符号**：`DSI_FIFO_STATUS_CMD_DMA_FIFO_UNDERFLOW`(bit10) +
    `DLN0/1/2/3_HS_FIFO_OVERFLOW`(bit18/22/26/30)，定义在 `drivers/gpu/drm/msm/generated/dsi.xml.h:166,178,180,182,184`；
    五者 OR **逐位相等**（`0x44440400`）。
  - **「bit30/29 无描述」不成立**：bit30 = `DSI_CMD_DMA_CTRL_BROADCAST_MASTER`（`:320`）、bit29 = `DSI_CMD_DMA_CTRL_WC_SEL`（`:321`）。
  - **真正没描述的只有 `ERR_INT_MASK0` 的字段布局**（生成头只有 `REG_DSI_ERR_INT_MASK0 = 0x108`，`:597`）⇒
    写成 `GENMASK(20,16) | BIT(9)`（= `0x001f0200`，逐位相等），注释写明「bits16..19 = 四条 lane 的 HS FIFO overflow、
    bit20 与组同掩、bit9 = CMD DMA FIFO 下溢」，并与厂商 GPL 源码
    `dsi_ctrl_hw_cmn.c:1796 dsi_ctrl_hw_cmn_mask_error_intr()` 的 `reg |= (0x1f << 16); reg |= BIT(9);` 同形对上。
  - 落地补丁 `patches/local/b5-resoc-20261027/0005-dsi-name-fifo-error-bits.patch`（**+24 −9**，注释改成上游口径、去掉 "Stock" 措辞）。
  - **等价证明（最硬的一条）**：改前/改后各编一次 `dsi_host.o`，用 `aarch64-linux-gnu-objcopy --only-section=.text` 抽出
    `.text` 后 `cmp` ⇒ **逐字节相同（23 048 B / 23 048 B）** ⇒ 不是「看着一样」，是**机器码零差异**。
    另：`make drivers/gpu/drm/msm/dsi/dsi_host.o` rc=0 / **0 warning**；补丁 `-p1` 应用后目标文件**逐字节一致**。
- **方法学落点**（`PITFALLS #458`）：判「上游无描述」必须**两头都查** —— `generated/*.xml.h`（生成头，符号在这里）
  + `registers/*.xml`（源头），并在报告里写命中**文件:行号**；只查 `dsi.xml` 正文会把**已命名的位**当魔数，
  把可提交的改动误判成「永久隔离」。
- **对 M6 口径的影响**：第 5 步从「永久隔离」改为「**可评审**」；RFC 文本需把原 R1 的措辞换掉
  （保留的唯一风险 = 「`ERR_INT_MASK0` 无公开寄存器手册」，而上游 `dsi_host.c:990` 本来也写裸常量 `0x13ff3fe0`，
  属可争辩而非不可提交）。
