# 2026-11-11（第三段）— A 持久化落地 + GRUB 直启三次取证与三处自我纠正

- **日期**：2026-11-11 下午
- **pi 会话 id**：本段会话（关键词「做 a 后 c，后台开 b」）
- **主题**：① 把 nftables 内核（vk187b）写进 `boot_b` 做持久化；② GRUB 直启 EFI-stub 路线的 E2/E2'/E3/E4 四发取证；
  ③ 三处推翻自己先前结论的纠正。
- **结论**：
  1. **A 完成并验证**：`bootslot-b/boot_b-vk187b.img`（100 663 296 B，AVB 公钥 sha1 `1e54e86e…` 与在用件同键）
     → `fastboot flash boot_b` → **设备侧 `dd` 读回 sha `8ab357ed…` 与主机件逐字相同**；当前 slot 本来就是 b（无需切槽）。
     回滚件 `bootslot-b/boot_b-device-20261111.img`（sha `4e38bc2c…` = 原 vk185）。
     重启后自动：`nft list ruleset` rc=0、`droidloom-doctor` = `Result: READY (0 blockers)` ⇒ **nftables 常驻**。
  2. **GRUB 直启（EFI-stub）死法是「硬件级掉电」，不是内核 panic**（本轮三发一致）：
     - 用 E4（`initcall_debug` + `softlockup_panic=1` + `panic_on_oops=1` + `panic=1` + **给 ramoops 补了 `record-size`** 的 DTB）跑完 →
       **`/sys/fs/pstore/` 仍为空**（开机前已清空）；且本机 `dmesg` 明确 `watchdog: Hard watchdog permanently disabled`、**无 `/dev/watchdog`**
       ⇒ 「≈85 s 硬件看门狗复位」也不成立；
     - 起机后 `uptime` 显示**重新上电**（不是 panic 复位后的连续 boot），用户所述「掉电后靠 USB 自动开机」正是这个特征。
     ⇒ **没有任何内核侧落盘证据，说明电源在 panic 之前就被切掉了**。此前「≈15 s = `panic=15` 计时」的定性**收回**。
  3. **E3 的反向证据（重要）**：`initcall_debug` 那一发文字持续 100 s 量级（每行 ~45 ms 是 `earlycon=efifb` 逐行写像素的速度），
     说明内核在 EFI 路径下**能活着走完数百个 device_initcall**（`vmlinux` 里 device_initcall 共 **1297** 个）。
     因此「死点很早」也不成立；真正的窗口是 **~60–70 s 之后**、且无任何 panic 记录。
  4. **三处自我纠正（都写明白，避免下次重踩）**：
     - ⚠️ **E2a 那发「一个字都没上屏」是我自己的 GRUB 配置 bug**：那一版把 cmdline 拆成 `set base_args=…` / `$efi_dsi` 再在 `linux` 行展开，
       实测展开失效 ⇒ 内核拿到的是残缺 cmdline（缺 `root=`/`earlycon=`）⇒ 无 earlycon、秒死。
       **因此「白闪与 msm 无关」这条推论作废**（它建立在一次无效实验上）。后续世代一律**写字面量**，不用 GRUB 变量。
     - ⚠️ 「死法 = `panic=15` 复位」作废（见 §2）。
     - ⚠️ 仓里 `reports/grub-direct-vs-secondstage-20261110.md` §1 的「EFI 只给 469 MiB Conv ⇒ 必然死」在本世代**不成立**：
       实测该发 `Total pages: 3037793`（≈11.6 GiB）、`Memory: 14229904K/15351172K available`、`Remapping and enabling EFI services`、
       `efivars: Registered` ⇒ EFI 内存地图与 runtime 都正常。
  5. **转录不可信度已量化**：VLM 给出的 `gcc_ao_clk_driver_init`、`clk_mt8195_topck_drv_init` 等名字在 `vmlinux` 里**根本不存在**
     ⇒ 拍屏 OCR 只能用来读「形态/顺序」，**不能用来取驱动名**；要名字就得落盘（本轮 pstore 证明这条路对「掉电」无效）。
