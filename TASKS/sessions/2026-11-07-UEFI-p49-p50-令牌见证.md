# 2026-11-07（夜）— UEFI p49/p50：令牌见证（`tag=1`）但内核拿不到

- **日期**：2026-11-07（夜，接 `2026-11-07-UEFI-撤回误判与交棒判据.md`）
- **pi 会话 id**：见 `.pi/sessions/*.jsonl`（关键词「p49 p50 cmdline witness / ramoops 空」）
- **主题**：用户「请继续UEFI任务」⇒ 把 p49 上机，并补一枚「令牌到底写没写」的持久判据（p50）
- **结论**：
  1. **p49 上机**（零写盘）：UEFI 的 logfs 链到 `preeb` 转储（与 p47 同型），内核回来
     `/proc/cmdline` **没有** `elden_bootpath=uefi`。
  2. **p50 = p49 + R44**：在 `UpdateCmdLine()` 之后、`LoadAddrAndDTUpdate()` 之前打一行
     `[K] cmdline len=… tag=… tail=…`（`SerialPortWrite` 上屏 + `SerialPortLogPutString` 进环）。
     上机读到 `len=293 tag=1 tail=… androidboot.baseband=apq elden_bootpath=uefi.`
     ⇒ **R43 生效**，令牌确实在 `FinalCmdLine` 末尾（随后由 `UpdateDeviceTree()` 写进 DTB，`BootLinux.c:766`）。
  3. **交棒仍未成立**：内核 cmdline 无令牌（p49/p50 两次）；`journalctl --list-boots` 每次尝试只多
     **一条**记录；`/sys/fs/pstore/` 空而本 boot 的 `legacy console [ramoops-1] enabled` 已在
     ⇒ 交棒的内核**连 printk 都没跑到**。故障窗口收窄到 `JUMP-BANNER` → `LinuxKernel()`/最初几条指令。
  4. **两发都自恢复**：payload 接管后 45–54 s 自己回 `boot_b` → Linux，**无需长按断电**；`boot_b`/槽位未动。
  5. **判据纪律顺手修**：`scripts/uefi-boot-trial.sh` 不再把「USB gadget 消失」记成 `HANDOFF`（改为
     必须看 cmdline 令牌：`HANDOFF_TAGGED`/`ABLBOOT_NOTAG`/`NOBOOT`），并修 `PRE/POST_BOOTID` 取表头行的 bug；
     p49/p50 两条旧 record 补 `verdict_tag/verdict_final/correction`。
