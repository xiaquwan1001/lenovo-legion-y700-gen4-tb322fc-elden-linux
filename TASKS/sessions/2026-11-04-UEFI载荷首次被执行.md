# 2026-11-04 — UEFI 线：载荷首次被真正执行（屏上可见性达成、死点定位到 cache 维护）

- 日期：2026-11-04
- pi 会话 id：见 `$PI_SESSION_ID`（同批提交）
- 主题：接着 11-03 下午「头对齐假设」做上机验证；把 UEFI 线从「载荷从未被执行」推进到「载荷执行、FD 拷完、只差跳入 Mu」
- 结论（先数字）：
  1. **载荷被执行（本线首次）**：`v2 base0` 打包 + Image 头对齐后，ABL 从 `0.056 s usb_read failed` 变成 `Sending 1.49 s` + `Booting OKAY 10.108 s`，且 DRAM 被大量改写。
  2. **屏上可见性达成（J1）**：shim 直涂设备 DT 里的 `splash_region`（`0xFC800000`/`0x02B00000`）；实测**只有前 ~448 KiB 可安全写**，整屏 43 MiB 填充会挂死（屏上红到 ~137 行后无响应）。
  3. **FD 4 MiB 已全部拷到 `0xFF300000`**（进度色带 4/4 绿 + M2 绿带，绿带宽度 = 红带 2 倍）；**死点在 M2 之后、M3 之前** ⇒ 唯一可疑步骤 = 对 FD 区的 `dc civac` 4 MiB 扫描。
  4. **DDR 标记通道在本类场景失效**：载荷跑过后低 4 GiB 出现 ~1.9 GB `0xFF` 大填充（`0x82600000`–`0xf37fffff`），把 shim 的 stage 页一起抹掉，三窗读回恒 100% `0xFF`。
  5. **该大填充经两次对照确认来自我们自己的载荷**：① 清零后纯重启 → 四窗仍 `0x00`；② 同一 `fastboot boot` 路径启动**真内核** → 三窗仍 `0x00`。⇒ 指向 Mu PrePi/内存初始化（下一轮在 Mu 侧插桩确认）。
  6. `0xFF300000` 是真 DRAM（写 `0x42` 读回 `0x42`，三处抽检全过），拷贝目标本身没问题。
