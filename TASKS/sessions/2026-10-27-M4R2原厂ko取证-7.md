- **结论（数字）**：
  1. **R2 解决**：原厂 `camera.ko` **not stripped**，符号 `csiphy_v2_4_0`（80 B，`.data`）= `{0x1028, **0x1138**, 0x1058, 0, 0, 0, 0x400, 0xb, 0x14, 5, 1, 3, 0x67, 0x48, …}`；
     `cam_csiphy_common_status_reg_dump` 反汇编证实 `[ver+4]` 即 common status 基址（`x27 = base + [ver+4]`，随后读 12 个 status 寄存器；第二块 `[ver+8]=0x1058`）
     ⇒ **`0x1138 = 0x1000 + 0x138` 与我们取值逐位一致**（仍属「数据段一致」，非运行期实测）。
  2. **R1 降级**：`lane_regs_sm8750`（103 条）vs 厂商 `csiphy_2ph_v2_4_0_reg`（1648 B = 103×16）：**地址/掩码/类型 103/103、`data` 99/103**；
     4 条差异全是 SKEW_CAL `0x5c`（我们 `0x54`、厂商 `0x00`），且**扫遍 82 张 `csiphy_*` 表 0 命中 `0x54`** ⇒ 我方偏离，需 A/B 决策。
  3. **新事实**：厂商另有 `csiphy_3ph_v2_4_0_reg`（72 条、地址体系完全不同：`0x294/0x2f4…`）⇒ 该 PHY 有 2ph/3ph 两变体，
     **本机用 2ph 表出图** ⇒ 本机是 2ph 变体；补丁正文必须点明，否则 review 首问就是「为何不复用 3ph」。
  4. 副作用：`PITFALLS #446`（原厂 `.ko` not stripped ⇒ 寄存器表可直接取 + 对账要扫全表再定性）；M4 系列 README §4 的 R1/R2 已改写，
