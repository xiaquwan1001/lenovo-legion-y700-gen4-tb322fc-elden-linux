## 2. 定因进展（只写能被证据支持的部分）

- **ABL/内核交接不是失败点**：`logfs` 每条 a 槽记录都到 `Shutting Down UEFI Boot Services`，时间稳定 ≈13.3 s；
  唯一一条 4.1 s 的是另一次（recovery/fastboot）。⇒ 排除「ABL 拒绝启动」这一类（11-17 那一轮的死因）。
- **不是电量**：82% + Charging。
- **不是镜像写坏**：三次写入都有读回核对；v1 回刷逐字节一致。
- **「logo 后掉电」的 confound 已找到**：`misc` 的 BCB 在 EDL 后是 `bootonce-bootloader`、在 recovery 退出后是 `boot-recovery`。
  这两次「logo 后掉电」期间的 BCB 状态没被记录，因此**不能断言那次尝试的是 Android 还是 recovery**。
  ⇒ 下一轮必须把「清 BCB」作为**EQL 之后、reset 之前的最后一步**，并在 reset 前读回校验 BCB=全 0。
- **v3 第一次那发是真 Android 启动失败**（起了 ZUXOS 动画 = system_server 已在跑）：这才是「卡动画」的有效样本；
  它证明 v3 的空目录占位 + 布局裁剪**不足以**解决首启卡死。
- **pstoredump 无 panic** ⇒ 卡在 userspace（init/system_server）而不是内核崩溃。
