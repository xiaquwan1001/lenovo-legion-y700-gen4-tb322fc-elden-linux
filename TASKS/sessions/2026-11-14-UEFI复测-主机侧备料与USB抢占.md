# UEFI 复测（本轮主测）：主机侧备料完成，设备窗口被「隔壁项目残留 fastboot 进程」阻塞

**日期**：2026-11-14（会话 `2026-11-14T13-23-59-069Z`）
**主题**：按用户指令主测 UEFI（flashed / 间接两形态复测）→ 三次崩溃 → 定案为**主机侧 USB 命令通道被抢**
**结论一句话**：三次崩溃（`fastboot boot` / `fastboot reboot-bootloader` / 仅 `getvar`）**都不是 UEFI 载荷或 fastboot 写法问题**，
而是隔壁项目 `kirin-tool-linux` 留下的 **13 个孤儿 `fastboot oem dump-emmc ptable` 进程**在循环重试同一 USB 设备；
设备每次都安全回落 b 槽。主机侧备料（GRUB arming 件 + 文档矛盾修正）已完成，等隔离后即可上机。

**证据指针**：`reports/artifacts/uefi-retest-20261114-212908/`（21 个文件 + `README-取证摘要.md`）

## 1. 崩溃定案（排除法）

| 时刻 | 我们发的命令 | 结果 | 排除项 |
|---|---|---|---|
| 21:29 | 进 fastboot 后 `getvar`（截断） | 设备从 `18d1:d00d` 消失，21:30:19 以 `1d6b:0104 TB322FC mainline` 回 Linux | 与 UEFI 载荷无关（`fastboot boot` 还没发出去） |
| 21:35 | `fastboot reboot-bootloader` | `< waiting for HA2EXB0E>` 后崩溃 | **`reboot-bootloader` 是合法命令**（`fastboot --help` 有 `reboot [bootloader]`），不是写法问题 |
| 21:43 | **只发 3 次 `getvar product`** | 三次全 `< waiting for HA2EXB0E>`，随后黑屏崩溃 | **命令本身零风险** ⇒ 只能是通道被抢 |

**抢通道的是**：`pgrep -f "fastboot oem dump-emmc"` = **13 个进程**，`PPID=2043`（`systemd --user`，父进程已死 ⇒ 孤儿），
最早 11:37 起存活 10 小时；cwd 分别落在 `~/src/wt/kt-warnB1`(deleted)、`~/src/wt/kt-warnBplus`(deleted)、
`~/gitlab-runner/builds/OZBE_geh6/0/xqh/kirin-tool-linux-refresh`；stdin = 各仓库 `tests/suites.txt`（已删）。
状态 `wchan=hrtimer_nanosleep`（在 `fastboot` 自身重试 sleep 里），**无常驻 USB fd** ⇒ 周期性重开设备重试。

> 判据纪律：`fastboot devices` 每次崩溃前都能列出 `HA2EXB0E` ⇒ USB **枚举**正常，问题在**命令通道**。

3. **ESP 身份定案（修正文档矛盾）**：`\EFI\BOOT\BOOTAA64.EFI` = **`244c5f65…` = v3b-bigfont GRUB**，

   ⇒ 直接 `set_active a` 必黑屏无字（`PITFALLS #622`）。**这是本轮最重要的「会白跑一发」的坑**。
6. `/boot/initrd.img`（11-12 12:58，`3282ae6c…`）= 真 gzip+cpio，解压 181 MB ⇒ `#623` 已修（设备侧件是好的）；
   内核 config 已含 `CONFIG_SYSFB_SIMPLEFB=y` / `CONFIG_FB_EFI=y` / `CONFIG_FRAMEBUFFER_CONSOLE=y`。
7. logfs 里 `R68LOG n=9 … s9:esp-ld-ok` 仍是 **11-10** 那条（本轮三次都没进 UEFI）⇒ 不能当本轮判据。

## 4. 隔离完成后的恢复顺序（判读，不是命令）

1. 清孤儿：`pkill -f "[f]astboot oem dump-emmc"`（字符组避免自匹配）；确认 `gitlab-runner` 里
   `xqh/kirin-tool-linux-refresh` 没有排队 job 会重启它们。
2. **先只发一次 `getvar product`** 验证通道不再崩，再谈 UEFI。
3. 换 ESP GRUB 为 arming 件：`scripts/esp-install-grub.sh --efi out/grub-20261114/grubaa64-arming-v6.efi --tag arming-v6 --activate`
   （回滚 `--rollback`；旧 v3b 件仍在 `\EFI\grub\grub-v3b-restore.efi` 与 `BOOTAA64.EFI.v3b-restore.bak`）。

## 6. 一条可复用的教训（待并入 PITFALLS）

**多项目共用一台 USB 调试主机时，「设备能枚举」不等于「命令通道可用」**：`fastboot devices` 正常
只证明枚举；真正的判据是**发一条无副作用命令（`getvar product`）能否返回**。崩溃/黑屏时先
`pgrep -af fastboot` 数孤儿进程，再怀疑固件或载荷。
