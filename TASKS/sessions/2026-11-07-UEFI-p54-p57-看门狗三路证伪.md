# 2026-11-07（深夜·二）— UEFI p54→p57：三条「关看门狗」全证伪 + 复位「不是独立定时器」的反证

- **日期**：2026-11-07（深夜·二，接 `2026-11-07-UEFI-p49-p50-令牌见证.md` 与 p51–p53 轮）
- **pi 会话 id**：见 `.pi/sessions/*.jsonl`（关键词「wdog-arch SetTimerPeriod / QcomWDogDxe 摘除 / 0x17410014 外部中止」）
- **主题**：用户「顺着上一次会话关于 UEFI 的进度继续，上一次待测是 p54」⇒ 把 p54 上机，并按判据连续做出
  p55/p56/p57 三发
- **结论**：
  1. **p54（R49）**：`[K] wdog-arch loc=ok set=Success` —— UEFI 标准
     `EFI_WATCHDOG_TIMER_ARCH_PROTOCOL->SetTimerPeriod(0)` **存在且关成功**，但内核仍 **4.1077 s** 硬复位。
     同发 `[K] wdog-scm loc=ok st=Device Error rsp=-4`，环里 `tz_armv8_smc_call failed, TzStatus=0xFFFFFFFE,
     SmcId=0x2000107` ⇒ TZ 侧 secure wdog 这条 SIP 在这版 TZ 上不可用。
  2. **p55（R50）**：把 `QcomWDogDxe` 从 `APRIORI.inc`/`DXE.inc`/`DXE.dsc.inc` 三处同步摘掉（FV 清单已核无该件）
     ⇒ 仍 **3.9038 s** 硬复位，形态不变 ⇒ 武装者不是我们 FV 里那个 DXE 驱动。
  3. **反证（本轮最重要）**：p56 探测踩到 `esr=96000010 far=17410014`（同步外部中止）进 fault handler，
     整机**在那里活了 15 分钟以上没复位** ⇒ 交棒后 ~4 s 的复位**不是**「无人喂就必咬」的独立定时器
     （否则自旋期间也会咬），更像「某个东西在 `ExitBootServices` 时一起停了」或「内核侧动作自触发」。
  4. **APSS 看门狗不在 `0x17410000`**：p57 逐条读时**第一个字**（`far=17410000`）就外部中止 ⇒ 停止盲探
     （每次中止 = 一次人工长按断电）。`HW Wdog Setting from PCD : Enabled` 那行其实是 **ABL 自己**的 log，归属需更正。
  5. **判据纪律新增**：GUID 引用可能链接失败（本地定义 + 强转）、arch protocol 方法名是 `SetTimerPeriod`、
     一次读多个 MMIO 字会让整行值随异常丢失（必须读一个打一个）。

- **下一步**：① p58 用已备料的 **R46 nosdcc**（`mmc0` 置 disabled）单变量切 `mmc0 ADMA` 现场；
  ② 从 `uefi_a` 分区解出 stock `KernelInterfaceDxe`（PrePi 里有 `KernelInterfaceInit` 字符串，说明 stock 有该组件，
  ABL 靠它 `WdogDisable()`）；③ 最便宜的一发 = EB 之后 `CpuDeadLoop` 不跳内核，看是否 ~4 s 被咬（判 A/B 形态）。
