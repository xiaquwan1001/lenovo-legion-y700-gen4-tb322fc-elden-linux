## 1. 为什么做工具而不是再打一发

三条屏上通道全废（`PITFALLS` #506 ConOut no-op / 帧缓冲串口在该路径不上屏 / NV 变量不跨上电），
R21 已把最后一条标记塞进 fastboot 响应（`diag st=%r last=[%a]`）。缺的只是「按阶梯跑、按字符串判定」的自动化 ——
上一轮靠人工一档一档敲 + 拍照判读。上游 issue #12 维护者原话同样是这个方向：
「你要是没有办法把屏幕拍给AI调试，就去弄个UEFI的USB ACM Gadget」（2026-10-29T04:19:30Z，见
`reports/uefi-github-scan-20261103.md` 同源的 issue #12 全量评论核查）。

## 2. 两个工具

| 文件 | 作用 | 关键自校验 |
|---|---|---|
| `scripts/uefi-sbstop-patch.py` | 把 `sbstop=N ` 写进 boot.img v2 头的 cmdline（**offset 64**，字段长 64 B） | magic/`header_version==2`/`page_size==4096`；除 `[64,64+len)` 外逐字节不变；token 能从字段读回 |
| `scripts/uefi-r21-sbstop-ladder.sh` | 造件 → 排产 → 上机 → 判据 → 汇总（`--mkimg-only` / `--dry-run` / `--selftest` / 默认全跑） | 判据分类器 7 条合成样本全过；全程 `timeout -k`；设备锁 + 只 `fastboot boot`（零写盘） |

## 3. 本机事实（决定了做法）

- R21 镜像 cmdline **恰好写满 64 B 无 NUL 空位** ⇒ 只能前缀覆写，`console=ttyGS0,…` 开头被顶掉。
  在 sbstop 路径上无害：每档 `SB_STOP(n)` 都以 `EFI_ABORTED` 返回，**从不调用 `LinuxKernel()`**（连 7 档都在 `CpuDeadLoop()` 之前）。
- 实测只差 **8 字节**（`sbstop=N ` 与 `console=` 第 5 位都是 `o`），`cmp -l` 落在 1-based 65–68、70–73。
- 变体件放 **`out/r21-sbstop/` 子目录**：`vk-identity.py` 扫的是 `out/*.img`，顶层放实验件会
  让 `versions/vk-kernel-identity.tsv` 立刻判过期（`check-doctor` §5d FAIL）。同理**不要**往 `out/` 写手搓 `*.manifest`（§5e 要 `config_sha256`）。

## 5. 20:3x 首次上机（control + sbstop=5）与判据修订

- **宿主链路全通、零拍照**：ABL `fastboot boot` R21 件 → `Booting OKAY 10.108 s` → **13 s 后 UEFI 侧 fastboot 出现**
  （序列号 `51318dc0`；USB 从 `18d1:d00d`(ABL) 重新枚举为 **`045e:0c2f`**(UEFI)，Mfr Google）。
- **control（未改动 R21 件）也卡死** ⇒ 卡死**与注入的 `sbstop=N ` 令牌无关**（令牌只改 offset 64 起的 8 字节）。
- 卡死形态：`Sending OKAY 1.496 s` → `Booting` → 无终局；随后 `getvar product` 报
  `reap_urb(0) failed … Cannot send after transport endpoint shutdown`（端点 shutdown，设备描述符仍被宿主缓存）。
- **屏上日志给出崩溃 ELR `0xCFE988F0`，经 `PlatformMemoryMapLib` 复算落在 DXE Heap
  `[0xB90C0000, 0xD6610000)` 内 ⇒ 跳进堆（坏函数指针），不是模块代码跑飞**。
  与 `BootLinux.c` 尾部「`FreeVerifiedBootResource` → `FreeBootLogoBltBuffer` → `ShutdownUefiBootServices`」
  的屏上时序吻合。详见 `reports/uefi-screenlog-crash-20261105.md`。
- **判据修订（重要）**：崩在 `ShutdownUefiBootServices` 附近时 USB 端点已死 ⇒ `FastbootFail("diag …")`
  **结构性送不出去**。改用「**崩不崩**」本身作宿主判据：打完 20 s 后 `getvar product` 仍有 `product:` ⇒ 该档没崩；
  报 endpoint shutdown ⇒ 崩在该档之后（含该档）。代价 = 每次崩需一次物理断电（用户动作）。
- 工具修订：`usb_gone()` 认两种 VID；新增 `svc_ok()`/`svc_dead()`（不能拿「有输出」当活着，端点 shutdown 也有输出）；
  新增 `NO_SERVICE`/endpoint-shutdown 分支、`--control`、`--keep-going`（默认遇卡死即停，不白耗断电次数）。

## 6. 夜场：10 发零写盘把崩溃点锁进 `LoadImageAndAuth` 前导

⇒ 最终窗口 = `LoadImageAndAuth` 前导 3 步；首要嫌疑 `FindBootableSlot()`（`PartitionTableUpdate.c:1603`）。
崩溃 ELR 固定 `0xCFE988F0` 且落在 DXE Heap 内 ⇒ 跳进堆（坏函数指针/返回地址），不是模块代码跑飞。

**重要副产物（判据工程）**：
- 崩后 USB 端点 shutdown（`reap_urb(0) failed … transport endpoint shutdown`）⇒ `FastbootFail` 送不出去，
  必须用「宿主是否收到 `diag`」当判据；每次崩 = 一次物理断电（用户动作）。
- UEFI 侧 `getvar product` = **`sun`**，ABL 侧 = `elden_prc_wifi` —— 一眼分清在跟谁说话。
- 镜像一律落 `out/r21-sbstop/`（顶层 `out/*.img` 会让 `vk-identity` 判过期，`check-doctor` §5d FAIL）；
  不要手写 `out/*.manifest`（§5e 要 `config_sha256`）。
- 构建补丁必须用 `difflib` 对 `git show HEAD:<file>` 生成；跨子模块的补丁用 `git apply --include=<path>` 单独应用。
