## 1. 为什么做工具而不是再打一发

三条屏上通道全废（`PITFALLS` #506 ConOut no-op / 帧缓冲串口在该路径不上屏 / NV 变量不跨上电），
R21 已把最后一条标记塞进 fastboot 响应（`diag st=%r last=[%a]`）。缺的只是「按阶梯跑、按字符串判定」的自动化 ——
上一轮靠人工一档一档敲 + 拍照判读。上游 issue #12 维护者原话同样是这个方向：
「你要是没有办法把屏幕拍给AI调试，就去弄个UEFI的USB ACM Gadget」（2026-10-29T04:19:30Z，见
`reports/uefi-github-scan-20261103.md` 同源的 issue #12 全量评论核查）。

## 2. 两个工具

| 文件 | 作用 | 关键自校验 |
|---|---|---|
| `scripts/uefi-sbstop-patch.py` | 把 `sbstop=N ` 写进 boot.img v2 头的 cmdline（**offset 64**，字段长 64 B） | magic/`header_version==2`/`page_size==4096`；除 `[64,64+len)` 外逐字节不变；token 能从字段读回 |
| `scripts/uefi-r21-sbstop-ladder.sh` | 造件 → 排产 → 上机 → 判据 → 汇总（`--mkimg-only` / `--dry-run` / `--selftest` / 默认全跑） | 判据分类器 7 条合成样本全过；全程 `timeout -k`；设备锁 + 只 `fastboot boot`（零写盘） |

## 3. 本机事实（决定了做法）

- R21 镜像 cmdline **恰好写满 64 B 无 NUL 空位** ⇒ 只能前缀覆写，`console=ttyGS0,…` 开头被顶掉。
  在 sbstop 路径上无害：每档 `SB_STOP(n)` 都以 `EFI_ABORTED` 返回，**从不调用 `LinuxKernel()`**（连 7 档都在 `CpuDeadLoop()` 之前）。
- 实测只差 **8 字节**（`sbstop=N ` 与 `console=` 第 5 位都是 `o`），`cmp -l` 落在 1-based 65–68、70–73。
- 变体件放 **`out/r21-sbstop/` 子目录**：`vk-identity.py` 扫的是 `out/*.img`，顶层放实验件会
  让 `versions/vk-kernel-identity.tsv` 立刻判过期（`check-doctor` §5d FAIL）。同理**不要**往 `out/` 写手搓 `*.manifest`（§5e 要 `config_sha256`）。
