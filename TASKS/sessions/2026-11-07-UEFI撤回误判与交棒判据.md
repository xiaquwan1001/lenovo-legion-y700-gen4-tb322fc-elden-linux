# 2026-11-07（深夜）— UEFI：撤回 p46「打通」误判 + R42 去掉写死 fastboot + R43 cmdline 排他判据

- **日期**：2026-11-07（深夜）
- **pi 会话 id**：见 `.pi/sessions/*.jsonl`（关键词「UEFI 误判 / SerialNumber / elden_bootpath」）
- **主题**：用户质疑「p46 的『UEFI 引导成功』是不是把掉电重启进 Linux 当成 BootLinux」⇒ 复查主机 USB 日志并按 SerialNumber 归属 → 判定撤回；随即用 R42/R43 两枚补丁把这条线做成**可判死**
- **结论**：
  1. **p46 判定撤回（= 未证实，不是「确认误判」）**：判据缺陷两条 —— ① 「内核起来」的旁证（主机 USB 事件 `1d6b:0104`）**不可归属**：同型号机 gadget iSerialNumber 是硬编码常量 `HA2CB1KY`（`rootfs/usb-gadget:37`），`ssh 192.168.7.1` 也不区分机器；② 唯一跳转证据是**易失 DDR 环**（环形、跨启动残留、同窗口混有乱码），无法排除「跳转后复位、ABL 自己引导」。⇒ `TASKS` §0/§1/§5、`INDEX` §3、p46 报告均已改口径；坑 `PITFALLS #549`。**当日我还在「是哪台机」上连错两次（先当成打通、再误指 U1），根因都是拿 gadget 串当机器身份。**
  2. **R42 生效（新事实）**：删掉 `LinuxLoader.c` 里上游漏删的裸语句 `BootIntoFastboot = TRUE`（`patches/uefi/20261107R42-normalboot/`）后，p47/p48 的**持久 logfs** 记录为 `[K] flags fb=0` → `LIA st=Success` → `pre-BL` → `BL-in` → `preeb-go` ⇒ **UEFI 自己走进了 `BootLinux()`，不再需要宿主 `fastboot continue`**。
  3. **p48 屏上 dump 证到跳转点**：`eb-ret st=Success` → `posteb-skip` → `EB-OK` → `pph-ok` → `JUMP-BANNER eb=Success`；随后 `[K] dump-in jump` → `[K] FLT pc=0 esr=86000010`（IABT）—— 这是**我自己 R43 v1 在 EB 之后调 `SbDumpLog()`（gBS 已失效）**造成的，同 `PITFALLS #543/#546`，已删。
  4. **R43 v2 = 排他判据**：`UpdateCmdLineParams()` 扩容后追加 ` elden_bootpath=uefi` ⇒ 内核 `/proc/cmdline` 里有没有这个串，一刀切区分「UEFI 交棒」与「ABL 自己引导」。p49 已构建（69 枚补丁、`elden_bootpath` 在 `LinuxLoader.efi` 里、EB 后 dump 已删净），**待设备断电恢复后上机**。
