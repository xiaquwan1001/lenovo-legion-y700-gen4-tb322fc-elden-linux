# 2026-11-08（清晨）— G1-29 后半主机侧备料：arm64 GRUB 造出来 + QEMU 端到端跑通「读 ext4 起内核」

- **日期**：2026-11-08（清晨，接 11-07 深夜 p58「间接引导打通」轮）
- **pi 会话 id**：见 `.pi/sessions/*.jsonl`（关键词「grub-arm64-standalone / vvfat / 1024 MiB 尾空闲」）
- **主题**：p58 打通后的剩余项「BDS/GRUB 菜单 + 直接从 FAT/EXT4 读 kernel/initrd」，本轮只做**主机侧备料**
- **结论**：
  1. **arm64 GRUB 可在本机（x86）造**：Ubuntu 不发 `grub-efi-arm64-bin`（只有 amd64/ia32 模块），
     从 ubuntu-ports 取 arm64 deb 解包即可交叉打包；`scripts/grub-arm64-standalone.sh` 一次产件
     `build/grub-arm64/grubaa64.efi`（6 877 184 B，`7993adfc…`，**两次重建 sha 相同 = 可复现**）。
  2. **「从 ext4 读 kernel/initrd」全链在 QEMU 端到端成立**：AAVMF BDS → FAT 卷上 `\EFI\BOOT\BOOTAA64.EFI`
     → 本 GRUB → `search --label linux17` 命中 **ext4** → `/boot/grub/grub.cfg` → 菜单 →
     `linux /boot/Image`（vk184 的 EFI-stub 内核 **63 MB 未压缩**）+ `initrd`（64 MB）+ `devicetree` →
     内核打出 `Linux version 7.3.1-debug-vk184-…`（随后因 virt 缺 SM8750 硬件而 panic，属预期）。
  3. **文件与 cmdline 是设备形状**：三件全部由 `scripts/grub-bootfiles.sh` 从 `out/boot-elden-vk184.img`
     解出（boot.img 里的 kernel 是 **gzip**，GRUB 不认 ⇒ 必须解压成裸 Image；dtb 在 v2 头里是独立段），
     grub.cfg 的 cmdline 直接沿用 boot.img 头里那串。
  4. **写盘前提已摸清**：本机 GPT **尾部 262 144 扇区（1024 MiB）空闲** ⇒ 可用**纯追加** 512 MiB ESP，
     不必缩 `userdata`、不移动任何分区（回退 = 删该分区）。
