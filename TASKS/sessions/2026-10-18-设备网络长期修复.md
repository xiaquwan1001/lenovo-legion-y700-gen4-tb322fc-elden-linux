## 做了什么

1. **定位 ①**：`find /etc -type f -size 0` 发现 8 个 0 字节配置，每个旁边都有内容完好的 `.apk-new`；其中 `ca-certificates.conf` 空 ⇒ bundle 恒空 ⇒ 全站 HTTPS 失败。
   **关键陷阱**：`apk fix ca-certificates` **修不了**（0 字节活文件被当"用户改动"，只再写 `.apk-new`），实测两次仍 0 字节 —— 这条已写进 PITFALLS #340。
2. **定位 ②**：修好信任链后仅 Fastly 段（fd.o/gnome）10–55% 随机失败。做了完整排除（TCP 握手 60/60 通 ⇒ 否证热点封锁；网关 100 包 0% 丢；国内站 0 失败），再用 `tcpdump` 抓到「满 MSS 首段丢 + 服务端 `ack 1` 回退 + SACK 只认尾段 ⇒ 无限重传」，并用 `openssl s_client -msg` 量出 `X25519MLKEM768` ClientHello = **1423 字节 > 1400 真实 MTU**，40 次对照实验 80% vs 98%。
3. **落地**：新增 `scripts/net-selfheal.sh`（三件事：0 字节配置自愈、信任链重建、PMTU/power_save 校正），双触发（OpenRC `local` 等 wlan0 UP + `NM dispatcher.d`），**注入故障态后冷启动验证通过**。
4. **回灌仓库**：`rootfs/build-rootfs.sh` helper 清单、`rootfs/persistent-overlay/{usr-local-sbin,etc-local.d,etc-NM-dispatcher}.tar.gz` + `restore.sh`。
