# 2026-11-11（第八段）— UEFI「掉电」判读全线重估 + GRUB 显示模块缺失 + T18 充电修复

- **日期**：2026-11-11 21:50–23:30
- **pi 会话 id**：本段会话（关键词「注意 usb 不充电/充电和开机有关」「grub 没有你的 exp」「阶段性整理总结」）
- **主题**：用户三次现场取证把「UEFI 后掉电」这条线彻底翻案；同时修 T18 充电时序。
- **结论**：
  1. **「60–70 s 硬件掉电」判读作废**（`PITFALLS #620`）。三臂屏上日志全是 `Kernel panic`，栈逐字相同：
     `memcpy_toio`/`asm_cpu_toq` ← `persistent_ram_write` ← `ramoops_pstore_write` ← `pstore_console_write` ←
     `console_flush_one_record` ← `console_unlock` ← `_printk` ← `free_reserved_area` ← `free_initmem` ← `do_populate_rootfs`。
     **新判据纪律：无 `Kernel panic`/`Oops`/`end trace` 不得写「硬件掉电」；pstore 空不能当「没 panic」。**
  2. **真现象 = 只有背光、无屏显、约 20 s 后重启**。根因已定：第 2 轮我造的**内嵌 GRUB 模块列表里没有任何显示模块**
     （`MODULES` 默认只有 `normal linux fdt ext2 fat ...`，无 `all_video/gfxterm/video/font/efi_gop`）
     ⇒ 菜单不显 + `set timeout=20` ⇒ **盲等 20 s 后起默认臂（A）→ panic**。
     ⇒ **「约 20 s」= timeout + panic 的组合，不是固件计时器**；**「无屏显」本身不证明没走到 GRUB**。
  3. **第 1 轮无效的原因**：cfg 写到 ESP `/EFI/grub/`，而 GRUB prefix 是 `/boot/grub`；
     且当时 `BOOTAA64.EFI` 是 11-08 的单条目 `chainloader Loader.efi` ⇒ 实际走 **Loader.efi 的菜单**，
     三臂都起 `boot2.img`（内核串 `...00003-gec74c4795a43` 对上），`efi=noruntime`/`noefi` 一次没生效。
  4. **ramoops DT 缺陷 = 本夜最强候选**：`record-size` 缺失 + `console-size+pmsg-size == mem_size` ⇒ `dump_mem_sz=0`；
     项目里 **2026-10-22 就写好的** `patches/dt/0001-arm64-dts-qcom-sm8750-elden-ramoops-record-size.patch`
     **从未 apply 到 `build/daily`**。本轮已应用 + 重建 DTB（4 MiB→8 MiB、加 `record-size=0x200000`、`pmsg-size=0x400000`）
     + 重打包 `build/exp-cmdline/boot-elden-vk187b-ramoopsfix.img`（kernel/ramdisk 逐字节不变，脚本自证 SAME/SAME/SAME）。
  5. **GRUB v2 件已就绪**：补齐显示模块 + `insmod all_video/gfxterm/gfxmenu` + `gfxmode=1024x768,1280x720,auto` +
     `terminal_output gfxterm` + `timeout=30`，sha `4f91a8fd…`，已 `--activate` 到 ESP（读回一致）。**未上机验**。
  6. **T18 充电**（用户提示「和开机有关」）：真机制 = `charge-watch` 在 boot 后 **9.0 s** 启动，
     而 `qcom-battmgr-usb` 节点 **12.84 s** 才出现 ⇒ 首轮空转，下一轮 ~19 s；脚本注释自证「ADSP defaults it to 100 mA」
     ⇒ 插电后最长 ~20 s 净放电。已修：`wait_for_usb()` 阻塞等节点 + 轮询 10 s→2 s + **udev 事件兜底**
     （`90-elden-charge.rules` + `charge-icl-fix.sh`，用 `RUN+=` 不能 `ATTR{}`）。上机判据全绿。
     另：我一度把 `charger_pd state 0x1fffffff` 读成 DOWN，实为 `SERVREG_SERVICE_STATE_UP`（`pdr.h:13-19`），已更正。
