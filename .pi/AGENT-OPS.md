## 1. 自主执行标准（默认自主，按风险分级）

判据顺序：**是否破坏当前可用系统 > 是否可回退 > 是否可观测 > 是否在设备上**。

| 级别 | 范围 | agent 行为 |
|---|---|---|
| **A 自主执行** | 主机侧一切：构建/打包/编译/静态分析/检索/写脚本/跑基准；设备侧**只读探测**、**幂等可回退**且输出可即时验证的操作；经 `scripts/device-lock.sh` 的串行访问 | 直接做，不必逐条请示 |
| **B 声明后执行** | 设备侧**写操作**（分区/GPT/boot_b/dtbo/vbmeta 写入）、有副作用的设备脚本 | **由用户亲手执行**：agent 准备资产 + 给**可直接手敲的单条命令**；除非用户在本轮**显式授权** agent 执行该类命令 |
| **C 请求物理干预** | 进 fastboot/EDL、按键组合、插拔 USB/充电器/耳机、断联后复位、救砖、覆盖 a 槽前取证 | agent **停下**，给出精确步骤与预期现象，**请用户操作**；不反复试错 |

- **「简单、可观测」的判据**（A 级的边界）：操作幂等、可回退、且在主机侧或只读；输出能立即验证。不满足即降为 B/C。
- **授权升级**：用户可在本轮把某类 B/C 操作授权给 agent（例：「这轮 fastboot 命令你自己跑」）；授权只对当轮有效。
- **凭据/账号/权限/隐私**：属外部干预，一律直接上报用户，不自行反复试错（见 `~/.pi/agent/pi-hermes-memory/STANDING.md`）。
- **用户自订底线**（不可被本文件放宽）：复杂刷写/GUI 工具由用户亲自操作，agent 准备资产并给精确步骤。
- **原理**：把「谁执行」讲清，而不是把动作一律禁掉；该机 fastboot 对批量/连续命令容错差，故 B 级强调**单条**。

## 2. 设备安全纪律

- **不跨容量档复用 GPT 二进制**；每单元现 dump（`scripts/gpt-dump.sh`），手术读实际 GPT 参数。
- 动分区/刷写前：`fastboot fetch` 备份将覆盖分区 + GPT 双表 dump；**写后读回校验**（不看「传输完成」）。
- 默认只动 **b 槽 + LUN0 GPT**；**agent 不改 active slot**（`fastboot --set-active` 属写操作）；设备恢复时用户按 `RUNBOOK-BRINGUP.md` 执行。
- 覆盖 a 槽前先做真机对照取证（`TASKS.md §5` Q5）；回收 Android 专属分区需 G1 全绿 + EDL 备份在手。
- **零写盘优先** `fastboot boot`；严格区分 **`-ram` 纯 RAM 变体（无桌面/服务）** 与**持久变体（RAM 内核 + 磁盘根）**——功能/服务级测试必须用持久变体（`PITFALLS` #92/#93）。
- **封装脚本**：主机侧构建/打包脚本可跑；**不要用封装脚本代跑 fastboot/EDL**——该机对批量/连续命令容错差，命令一律拆单条（经验见 `PITFALLS` #3）。

## 3. 研发纪律

- **先查本地既有结论**：引导链（BL/AVB/降级/GPT/EDL）及反复出现的问题，先 `grep` 技能 `references/` + `archive/topics/` + `PITFALLS`；命中则本轮只做「确认或推翻」，差量重推（`PITFALLS` #87）。
- **判据在设备侧**：主机侧构建/编译/能进 BDS 一律只算「未上机验证」；**无设备证据不得写「已修复/已解决」**（`PITFALLS` §0 纪律 4）。间歇性故障**单次样本无效**（须同口径量化 + 单变量 + 长时窗）。
- **归因分层**：报「驱动/内核坏」前先分清 initramfs/rootfs 打包（C）与用户态配置（D）（`PITFALLS` #115）。
- **主线优先**（服务上游化）：厂商私有 compatible 先找主线等效驱动，只补 DT/config/固件命名；主线没有则分「架构性不可做 / 私有 / 可自研」，只立第三类。
- **一次正反判断**：同一方案/推理/建议只做一次正反判断，不重复论证。
- **失败先复盘**：长任务反复失败无进展时，先落盘复盘（操作史/根因/文件清单）再换方案。
- 不硬编码其他机器的 home 路径；用 `~` 与项目相对路径。

## 4. 文档与写入权限

- **SSOT**：唯一入口 `INDEX.md`；领域层（4 份：`DEVICE`/`TASKS`/`RESOURCES`/`RUNBOOK`）与经验层（`PITFALLS`）只在各自文件维护，其余用链接引用。
- **单写者**：任何时刻一个文件只有一个写者。**领域层 4 份 + `PITFALLS` + `.githooks` + `versions/` = 父 agent 专属**；子 agent 不碰。
- `archive/` 只增不改；结论以领域层为准，archive 不得被引用为「当前结论」。
- 结论可反转：保留推翻记录（见 `ATTRIBUTION-AUDIT-2026-10-06.md` 的分层更正）。

## 5. 汇报与时间盒

- 汇报**先数字结论、后细节，一页内**；阶段性收官后先总结再推进。
- 长跑任务必须设**自动截止时间盒**（脚本内 `timeout -k <秒>`），并用 `ps`/`pgrep` 核实进程真的结束。
- 状态词只允许「未解 / 未证实 / 未上机」；失败与半成品必落盘。

## 6. 协作与并发

- 需要并发时走 `.pi/CONCURRENCY.md`（基线+fork、单写者、提交 trailer、vk registry、入口 `scripts/lane.sh`）。
- 子代理 = `Agent` 工具（`pi-subagents`）+ `.pi/agents/<role>.md` + `.pi/missions/<topic>.md`，**无守护进程**。
- **worker 自报成功不可信**：编排者必须独立重跑测试与全量回归。
- 并发上限 ≤3 个后台子 agent（为限流/预算留余量，见全局 `AGENTS.md`）。
- 子代理的**行为标准一律以本文件为准**；`.pi/agents/*.md` 只写角色专属补充，不另行定义自主/授权边界。
