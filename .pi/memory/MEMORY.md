busybox 的 `pgrep -x NAME` / `pkill -x NAME` 匹配的是 argv[0] 全串，不是 comm：进程以 /sbin/udevd 启动时 `pgrep -x udevd` 恒 rc=1（假阴性），而 GNU procps 的 -x 匹配 comm（相反语义）。后果：Alpine/busybox 设备上所有 `pgrep -x` 守卫都是空操作。修法：装 procps-ng，或改用 `ps -eo comm | grep -qx NAME`（busybox/procps 都成立）；kill 用 `ps -eo pid,comm | awk '$2=="NAME"{print $1}'`。另：若装 GNU coreutils/grep/sed/findutils，注意 init 的 PATH 通常也把 /usr/bin 排在 /bin 前 ⇒ 会同时 shadow busybox，必须重启回归验证。
