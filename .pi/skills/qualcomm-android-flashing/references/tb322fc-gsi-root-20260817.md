## LTBox root pipeline (source: ~/下载/刷机-四代/tools/LTBox-src, v3.2.3)
- `root_pipeline/mod.rs`: download payload → **dump current boot/init_boot FROM THE DEVICE** → patch → **AVB resign** (`resolve_signing_key` via `key_map`; unknown signed pubkey aborts before writes) → flash to active slot.
- `RootImageTarget`: GKI mode / APatch / Skroot / TB320FC-family → `boot`; else (Magisk/KSU default) → `init_boot`.
- Families: Magisk (ramdisk injection), KernelSU (init→ksuinit + kernelsu.ko, same mechanics as ksud), APatch (kptools+kpimg), Skroot (direct kernel binary patch: init_cred byte-pattern scan + do_execve hook + avc_denied/avc_check patches).
- Simple Flasher (`workers/flash/simple.rs`): VERBATIM rawprogram/patch flash — no FP check, no signing-key check, no region/ARB/country edits, wipe decided solely by the firmware package. So LTBox full-flash init_boot = stock bytes (source-verified).
- LTBox is GUI-only (iced; `--help` swallows). User runs the GUI; agent prepares assets + steps.
