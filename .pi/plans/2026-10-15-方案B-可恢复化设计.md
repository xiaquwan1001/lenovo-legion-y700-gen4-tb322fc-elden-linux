# 方案 B 设计分析：把「坏发即放弃」改成「可恢复」（2026-10-15）

> 依据：`reports/q28-armA-20261015.md`（★不变量 = 「面板黑」，不是 `-110`）、
> `reports/local-cleanup-q24-q28-20261015.md` §3 方案 B、`reports/b5-dsi-resoc-20261013.md`（H19/H37/H38/H41 分类）。
> 纪律：本文件是**设计分析**，不含上机结论；「点亮」只认面板实测（`PITFALLS #251`）。

---

## 0. 一句话

**现状把「一次 DMA 超时」升级成「永久放弃」**：`dsi_bonded_cmd_failed` 是个**只写不清的全局闩锁**，
一旦置位，`dsi_mgr_*` 的 5 处路径全部 early-return，**连关电源/关中断都跳过**（H37/H41）；
而 `dsi_mgr_bridge_enable` 里还有一处**主动**再置位（H38，`panel is not prepared`）。
⇒ 面板 bring-up 失败后，**系统进入一个自我封闭的状态**，只能整机复位。
**方案 B = 让失败可重试，而不是让失败永久化。**

## 1. 现状机制（逐点，基于 `m1-73/baseline` 实读）

| 位置 | 代码 | 后果 |
|---|---|---|
| `:41` | `static bool dsi_bonded_cmd_failed;` | **全局状态**，无计数、无复位 |
| `:52-55` | `msm_dsi_manager_cmd_failed()` = `uses_bonded_cmd() && READ_ONCE(latch)` | 供 5 处 early-return 用 |
| `:649` | `xfer` 失败 ⇒ `WRITE_ONCE(latch, true)` | **置位点 1**（DMA 超时，= Q28 `-110`） |
| `:377` | `!panel->prepared` ⇒ `WRITE_ONCE(latch, true)` + `return` | **置位点 2**（H38：**主动**放弃） |
| `:292` | `bridge_power_off` 开头 early-return | **H37**：失败后**不关 IRQ、不关电源** ⇒ 电源/时钟悬空 |
| `:314` | `bridge_pre_enable` 开头 early-return | **H38**：失败后不再 power_on |
| `:367` | `bridge_enable` 条件里含 `cmd_failed()` | 失败后**永不** `msm_dsi_host_enable` |
| `:396` | `bridge_disable` 条件里含 `cmd_failed()` | 失败后不 disable host |
| `:429` | `bridge_post_disable` 开头 early-return | **H41**：失败后**不关电源、不 disable IRQ、不 save PLL** |
| `:615/:681` | `xfer` 入口 early-return（`-EIO`） | **置位后所有后续 DCS 命令直接失败**（不再触碰硬件） |

### 1.1 为什么这是「不可恢复」的根源

三个机制叠加：

1. **闩锁永不解除**：`WRITE_ONCE(..., true)` 之后**没有任何地方写回 `false`**（全树 grep 确认）。
2. **闩锁短路了清理路径**：H37/H41 让 `power_off`/`post_disable` **跳过硬件状态回卷**
   ⇒ 下次 modeset 面对的是**被污染的前一个状态**（IRQ 未关、电源未关、PLL 未 save）。
3. **失败被「沉默」**：`:615/:681` 返回 `-EIO` 但**不再触碰硬件**，
   ⇒ 重试**不可能成功**（因为根本没重试到硬件层）。

⇒ **与七臂 vk116–vk125 的关系（★已核对原文，修正一处早期说法）**：
我最初推测「七臂被闩锁污染」——**这个说法过强，已核查推翻**。
**vk117/vk125 实际上已经做了 `WRITE_ONCE(dsi_bonded_cmd_failed, false)`（清闩锁）+ 双链路 ctrl/PHY 复位**
（见 `patches/q28-dsi-recover2.patch`）。所以它们**已经**触及了闩锁语义。

**但仍然有一处未覆盖**（经逐行核对 `patches/q28-dsi-recover2.patch`）：
`dsi_mgr_bridge_power_off` / `post_disable` 的 early-return（H37/H41）**原样保留**
（补丁里的 `-/+ if (msm_dsi_manager_cmd_failed())` 只是函数位置移动的 diff 上下文，**不是删除**）。
⇒ **vk117 的恢复路径是在「清理路径仍被闩锁短路」的形态下跑的**：
它自己调用了 `dsi_mgr_link_power_off(mid)`，但 `post_disable` 那条**正规清理**仍不执行。

**⇒ 修正后的命题（弱但更准确）**：
七臂**不**证明「硬件救不回」；它们证明的是
「**在 vk117 那种『自己补一次 link 复位』的形态下救不回**」。
**方案 B 的差异 = 不再自己补复位，而是把「失败不应短路清理」这条语义正则化**，
让**既有的**清理路径（H37/H41）在失败后仍执行 —— 这是**删代码**，而不是加一条新的恢复序列。
**两者不重复**：vk117 = 加一条带守卫的复位；B1 = 删掉短路清理的守卫。

## 2. 设计目标与约束

| 目标 | 说明 |
|---|---|
| **G1 可重试** | 一次 DMA 超时不应永久毒化后续尝试 |
| **G2 状态可回卷** | 失败后**必须**执行清理（关 IRQ / 关电源 / save PLL），使下次 bring-up 面对干净状态 |
| **G3 有界** | 重试次数必须有上限（**不得**变成无限重试循环，`PITFALLS #106` 类卡死风险） |
| **G4 不掩盖真失败** | 仍要在 dmesg 保留明确的失败记录（诊断能力不能退化） |
| **G5 单变量可测** | 必须是**最小改动**，否则无法与 baseline 做 A/B |

**约束（来自项目铁律）**：
- 判据只能靠**面板实测**（`PITFALLS #251/#255`）；agent 不能自证点亮。
- 不得把「未定根因」写成「硬件事实」（上游化铁律）。
- **不改** `boot_b`；实验走 `fastboot boot` 零写盘。

## 3. 候选设计

### 3.1 方案 B1（★首选）：闩锁 → **有界重试计数** + 清理路径解耦

**核心两处改动，语义正交**：

**(a) 把闩锁改成「有界重试」**

```c
/* 现状 */
static bool dsi_bonded_cmd_failed;
if (ret < 0) WRITE_ONCE(dsi_bonded_cmd_failed, true);

/* 改为 */
#define DSI_BONDED_CMD_MAX_RETRY 3
static int dsi_bonded_cmd_fail_count;      /* 累计失败次数，非永久闩锁 */
if (ret < 0 && ++dsi_bonded_cmd_fail_count >= DSI_BONDED_CMD_MAX_RETRY)
        WRITE_ONCE(dsi_bonded_cmd_failed, true);   /* 只在耗尽后放弃 */
```
⇒ **G1**（前 N-1 次失败不再毒化全局状态）+ **G3**（有上界）+ **G4**（失败仍打日志）。

**(b) 清理路径不再被闩锁短路**（H37/H41）
```c
/* 现状：power_off / post_disable 开头 */
if (msm_dsi_manager_cmd_failed())
        return;                    /* ← 连关 IRQ/关电源都跳过 */

/* 改为：删掉该 early-return（清理永远执行） */
```
⇒ **G2**。这是**删代码**，符合「删比加更干净」。

**为什么 (a)(b) 必须成对**：只做 (a) ⇒ 重试面对被污染状态（IRQ 未关/电源未关），大概率仍失败；
只做 (b) ⇒ 闩锁仍永久置位，`:615/:681` 仍直接 `-EIO`，重试到不了硬件。
**⇒ 两处必须同臂。** 这也说明本臂**不是**「单行修复」，需如实标注。

### 3.2 方案 B2（备选）：只删「坏发即 return」，保留闩锁
**否**：闩锁仍在（`:615/:681` 的 `-EIO` 短路仍在）⇒ 重试无法到达硬件。**不成立。**

### 3.3 方案 B3（激进）：失败后**主动重跑一次完整 modeset**
= 让 panel prepare 失败返**可重试错误**，由 DRM 重走 atomic commit。
**前置未知**：「重走 modeset ≡ 冷启」**未验证**（`PITFALLS` 无此结论；本方案 §4 列为独立任务）。
**⇒ 先做 B1（廉价），B3 视 B1 结果再定。**

## 4. 关键前置问题（必须在 B1 之前或并行回答）

| # | 问题 | 为什么重要 | 怎么答（零/低成本） |
|---|---|---|---|
| **P1** | **「重走 modeset」与冷启是否等价**？ | 决定 B1 的失败是否可单靠重试补救；也决定 B3 是否可行 | 在**已知 GOOD 台**（如 s7）上跑 `modetest`/DPMS off→on 循环，看面板是否仍亮 + `dsi_isr` 是否继续增长。**不需要坏发** |
| **P2** | 闩锁置位后，硬件**实际**处于什么状态？ | 验证「H37/H41 让状态悬空」这一推断 | 在坏发台上读 `clk_summary`（IRQ/电源是否还开着）+ 对比好发 |
| **P3** | 重试**几次**合理？ | G3 有界性 | 先取 3（与上游 `-EPROBE_DEFER` 类做法同量级）；可后续调 |

⚠️ **P2 的一个诚实限制**：坏发台上我们**只有 SSH**（显示坏但系统活），
可读 `clk_summary`/`interrupts`/`pm_genpd`，但**读不到 DSI/PHY 寄存器原值**
（`/dev/mem` 被 `STRICT_DEVMEM` 挡住）。⇒ P2 只能作**间接**验证。

## 5. 判据（本臂成功/失败的定义）

**必须有用户目视**（`#251`）。辅助量：

| 量 | 好发值 | 用途 |
|---|---|---|
| **用户目视** | 面板有内容 | **唯一最终判据** |
| `dsi_isr` | 41 | 辅助（arm A 上恒 0，故**臂特异**，只在本臂内比较） |
| `l1` 签名 | 0 | 辅助 |
| `dsi_bonded_cmd_fail_count` | 打印出来（新加日志） | **本臂关键观测量**：看它是否 >1（证明重试真的发生了） |
| dmesg 里重试次数 | — | 证明 (a) 生效 |

**★ 本臂有「样本内信号」**（不必等率对比）：
坏发时若 dmesg 出现**第 2 次/第 3 次**尝试记录（说明 (a) 生效），
且**随后面板点亮**（说明 (b) 生效），则**单发即可判定**。
这与 vk125 的「杀手判据」设计同类（`PITFALLS #230` 的做法）。

## 6. 风险

| 风险 | 缓解 |
|---|---|
| **无限重试 ⇒ 卡死**（`#106` 类） | 硬上界 3（G3）；`fail_count` 只增不减直到放弃 |
| **删除 early-return 后，清理路径在「从未 bring-up」时被调用** | 检查 `powered` 标志（`:366` 已有 `to_dsi_bridge(bridge)->powered` 守卫） |
| **污染台架**：从坏显示态暖链会污染（`#256`） | 每发**真 POR**；实验前 `q28-watchdog off` |
| **新变量混淆**：本臂改了 2 处语义 | 明确标注为「B1 = (a)+(b) 同臂」；若要分离可后续单出 (a) 臂 |

## 8. 与上游/其它工作的关系

- **上游化**：本臂是**实验件**，不是可提补丁（「有界重试」若要上游化，须先有根因与上游讨论；
  但「清理路径不应被失败闩锁短路」本身**是可论证的正确性修复**，可作独立 RFC 素材）。
- **与 arm A 的关系**：arm A 证了「命令路径非不变量」；B1 **不**依赖命令路径选择，
  可与 vendor bonded 路径共存（B1 建在 baseline 上，保留 bonded）。
- **与七臂 vk116–vk125 的关系**：那些臂在「闩锁闩死清理」前提下复位硬件 ⇒ 结论受污染。
  **B1 修的是那个前提**；若 B1 后仍救不回，**才**能说「硬件层真的救不回」。
