# 内存盘构建区（RAM build scratch）规划

> 2026-10-15 立 · 状态 **规划（未落地）** · 关联 `scripts/env-build.sh`、`scripts/lane.sh`、`.pi/CONCURRENCY.md`、`.pi/AGENT-OPS.md`
> 起因：把「编译过程产生的文件」放进专门的内存区，加快改代码后的重编译。

## 0. 数字结论（先看这 10 行）

1. 本机 RAM **61 GiB**；稳态 `MemAvailable` 50–56 GiB；`-j8` 编译期间 `MemFree` 最低 **2.0 GiB**（page cache 正常行为，非告急）。
2. **内存盘不需要新建、不需要 root**：`/tmp` 与 `/dev/shm` **各已是 31 GiB tmpfs**（内核默认 = 50% RAM）；实测 `/tmp` 用量 2 GiB、`/dev/shm` 31 MiB。`sudo` **非免密**（`sudo -n true` 失败）⇒ 新建 `/mnt/xxx` 挂载要你输一次密码。
3. 内核树体积：**空树 1.81 GiB**；**编完的树 7.4–16.3 GiB**（产物 5.6–14.5 GiB；`vmlinux` **669 MiB**、`.o` **10 898 个**，`CONFIG_DEBUG_INFO=y`）。
4. 现存内核 worktree **24 个 / 112 GiB**；根盘 **86% 满、剩 64 GiB**。已有 **3 个 worktree 就因为建在 `/tmp` 被清空成 `prunable`**（`/tmp/dailyid`、`/tmp/vk125src`、`/tmp/vk125wt`）——前车之鉴，见 §5 风险。
5. ccache `~/.cache/ccache-elden` **12.6 / 20 GiB**，命中 **52.4%**（可缓存调用中），**32.6% 调用不可缓存**。12.6 GiB 已基本驻留 page cache ⇒ **ccache 读本来就是 RAM 速度，搬上内存盘收益≈0**，不要动它。
6. **一次性判定（不再重复论证）**：内存盘对 **gcc 编译阶段（CPU 密集）几乎无收益**；收益只在三处——① 链接/元数据**写**路径（一次写 669 MiB `vmlinux` + 万级小文件，tmpfs 免 ext4 日志/分配）；② **根盘减负**（每树省 5.6–14.5 GiB）；③ 与 ccache 组合后「推倒重建整棵树」代价下降。**预期增量提速 10–20%**，必须由 P2 实测决定是否推广。
7. 比内存盘更大的两个杠杆（放到 §8 一次判完）：**迭代树关 `CONFIG_DEBUG_INFO`**（产物≈1/3、链接明显变快）、**ccache 跨树命中率**（`CCACHE_BASEDIR` 等）。
8. **`uname -v` 是故意保留的身份判别器**（`uname -r` 被 LOCALVERSION 钉死，只能靠 `uname -v` 的 `#N + 时间戳` 证明新内核真启动了，PITFALLS #119；Q28 还依赖 `#N`/时间戳长度影响 `.rodata` 布局）⇒ **禁止**把 `KBUILD_BUILD_TIMESTAMP` 固定进 `env-build.sh`。A/B 只在比对脚本里临时固定（默认 `init/Makefile:57` = `$(shell LC_ALL=C date)`，每次编译都变）。
9. 环境坑：`pi.bash` 里 `rm -rf` 被换成「移入 `~/.pi/trash`」⇒ 对 tmpfs **EXDEV 失败且删不掉**；删内存盘上的树必须 **`/bin/rm -rf`**（实测：plain `rm` rc=1 且目录残留；`/bin/rm` 成功）。
10. 现成插入点齐全，**不用改任何调用方**：所有内核脚本走 `$ROOT/linux`（symlink）/ `KDIR=` / `WT_ROOT=`（`lane.sh`）/ `K=`（`sd-variant-build.sh`）；`check-doctor.sh` 已 SKIP `linux`/`geekidos-linux`，**新落点必须在项目目录之外**（否则要遍历 9.6 万文件）。

## 2. 设计：三层（RAM 易失 / 磁盘持久 / 快照只存不可再生的）

| 层 | 介质 | 装什么 | 丢了怎么办 |
|---|---|---|---|
| **热层** | **tmpfs（内存）** | 内核树整体：源码工作树 + `.o` + `vmlinux` + `Image.gz` + DTB | 重编；产物由 ccache 兜底 |
| **持久层** | ext4（根盘） | ① `~/.cache/ccache-elden`（12.6 GiB，**不动**）② git（worktree 元数据 + commit，**commit 本身不丢**） | — |
| **快照层** | ext4，几 MB | 只存**不可再生**的东西：`git diff` + 未跟踪文件 tar + HEAD/分支 + `.config` | — |

**要点**：
- **产物不进快照**。内存盘上的树是**可丢弃**的；唯一不可再生的是**未提交的源码改动**。
- 树的**身份**（commit/sha/UTS）由 git + 打包前硬门保证，与落点无关；`.config` 快照让小树重建后立刻可编。
- 内存盘上的树**若落在项目目录内**会被 `check-doctor` 全量遍历 ⇒ 落点一律在 **`/dev/shm/elden/`** 或 **`/mnt/rambuild/`**。

### 2.1 落点三选一（推荐 R1，今天就能上）

| 方案 | 落点 | 容量 | root | 评价 |
|---|---|---|---|---|
| **R1 ✅推荐** | `/dev/shm/elden/`（0700） | **31 GiB** | 否 | 无年龄清理、无 app 垃圾、立即可用，零系统改动 |
| R2 | `/tmp/elden/` | 31 GiB | 否 | **已被证明会丢**（3 个 prunable worktree 就在 `/tmp`）+ `tmpfiles.d` 10 天清理 + 与 pi/其他工具混用 ⇒ **不用** |
| R3（可选） | `/mnt/rambuild` = 独立 tmpfs 24 GiB + systemd mount 单元 | 自定、开机自动 | **是**（需你输一次密码） | 隔离最好、可持久挂载；但新增 fstab/unit = 扩大「可用系统」的改动面，只在需要 >31 GiB 或要开机自动挂载时上 |

### 2.2 容量预算（硬上限 31 GiB，目标数据 ≤24 GiB）

| 项 | 大小 |
|---|---|
| 日常树 `geekidos-linux`（带 debug，全建） | 16.3 GiB |
| lane 树（空 / 带 debug 全建 / 关 debug 全建） | 1.8 / 7.4 / ~4–5 GiB |
| **允许组合** | 日常树 + 1 棵 lane 树 = **18–24 GiB** |
| **禁止组合** | 两棵「带 debug 全建」的树（≥23.7 GiB，且与系统抢内存） |
| 必须保留 | `MemAvailable` ≥ 12 GiB（编译进程 -j16 工作集 ~5 GiB + 应用 ~10 GiB） |

**守卫**：建树前检查 `df /dev/shm` 与 `MemAvailable`；不足则**明确报错退出**（否则 make 撞 ENOSPC，报一堆误导性编译错误）。

## 3. 实施步骤

> 纪律：每步先 `timeout -k 60 <N>` 设截止时间盒，跑完用 `pgrep` 核实；**改任何现有文件前先备份**（`.bak.<ts>`）；不动 `scripts/env-build.sh` 的默认身份语义（§0-8）。

### P0 基线测量（不改任何东西，~60 min）

```bash
ROOT=~/y700-elden; WT=$ROOT/build/m3-6-worktree      # 1.8 GiB 空树，先确认闲置
cd $WT && git status --porcelain                      # 必须为空；非空换一棵
. $ROOT/scripts/env-build.sh
# P0-a 冷编基线
timeout -k 60 3600 bash -c 'time make -C '$WT' -j16 Image.gz dtbs' 2>&1 | tail -5
# P0-b 增量基线（改 1 个 .c → 重编+重链）
touch $WT/drivers/gpu/drm/panel/panel-novatek-nt36536.c
timeout -k 60 3600 bash -c 'time make -C '$WT' -j16 Image.gz' 2>&1 | tail -5
```

同时把已有采集器开着（**复用现成仪表，不重写**）：

```bash
systemctl --user list-timers | grep tmpfs          # 2026-10-14 已装 tmpfs-usage-log.timer（5 min 一条 CSV）
~/.local/bin/tmpfs-usage-report.sh | tail -5        # 记录构建期 tmp/shm/swap/memfree 峰值
```

产物：`reports/rambuild-baseline-<date>.md`（P0-a/P0-b 墙钟 + 内存峰值 + image sha256 + UTS）。

### P1 加一个封装脚本 `scripts/rambuild.sh`（新增文件，零风险）

```
rambuild.sh status                 # 显示 /dev/shm 用量 + MemAvailable + RAM 树清单 + 快照状态
rambuild.sh ensure                 # 幂等：建 /dev/shm/elden（0700）、按清单 git worktree add 重建缺失的树、git worktree prune
rambuild.sh new <name> <base-ref> [--kernel|--bare]   # 在 /dev/shm/elden/t-<name> 建 worktree（自动挂 .config 快照）
rambuild.sh adopt <existing-tree>  # cp -a 把 ext4 上的树搬进内存盘（用于 A/B 与迁移）
rambuild.sh snapshot <name>        # 落盘 git diff + untracked tar + .config + HEAD → .pi/rambuild/<name>/
rambuild.sh evict <name>           # 归档快照 → /bin/rm -rf 树 → git worktree prune（腾空间）
rambuild.sh guard <need-GiB>       # 空间/内存守卫：不足 exit 3 并打印明确原因
```

实现要点：
- 全部 `rm` 用 **`/bin/rm -rf`**（§0-9）。
- `ensure` 修复「重启后 `git worktree list` 全是 prunable」这一必然现象（清单 = `.pi/rambuild/manifest.tsv`：name/base/created/branch）。
- 每次 `new`/`adopt` 前调 `guard`。

### P2 A/B 实验（决定 go/no-go，~90 min）

## 5. 风险与回退

| 风险 | 证据/概率 | 处置 |
|---|---|---|
| **重启/断电丢树** | 必然（tmpfs 易失） | 树可丢弃；未提交改动靠 `snapshot`（P1）＋`ensure` 幂等重建（P4 纪律）。**已有 3 个 `/tmp` worktree 就这么丢的** |
| `rm -rf` 删不掉内存树 | 已实测（EXDEV） | 统一 `/bin/rm -rf` |
| ENOSPC / OOM | 31 GiB 上限 + 61 GiB RAM | `guard` 前置拦截（空间 + `MemAvailable`），禁止「两棵全建带 debug 的树」 |
| 误删仍在跑的 lane 树 | 中 | `evict` 先查 `pgrep -af make` 与该树路径；先 snapshot 再删 |
| 换路径导致镜像字节不同 | 低（`localversion` 不含路径） | A3 判据 + 临时固定 `KBUILD_BUILD_TIMESTAMP` 才做 sha 比对 |
| 落点落进项目目录 | 会拖慢 check-doctor | 一律 `/dev/shm/elden/` 或 `/mnt/rambuild/` |
| 收益不达标 | 存在（§0-6） | P2 是硬门；不达标即作废，不迁移 |

## 8. 伴随优化（不与内存盘绑定，按 ROI 排序，一次判完）

| # | 杠杆 | 依据（实测） | 预期 | 代价 |
|---|---|---|---|---|
| **L1** | **迭代树关 `CONFIG_DEBUG_INFO`**（显式 profile，默认不变） | `vmlinux` 669 MiB、`.o` 10 898 个、树 14.5 GiB 产物**绝大部分是 DWARF** | 产物 ≈1/3、链接明显变快；**内存盘放得下 2–3 棵** | 丢 gdb 符号（真调试时切回默认） |
| **L2** | ccache 跨树命中：`CCACHE_BASEDIR=$ROOT`、审查 `hash_dir`、`sloppiness=file_stat_matches` | 现 52.4% 命中；24 棵树各自从零重编 | 跨 lane 复用 `.o`，冷编显著变快 | 需 A/B 验证不产出错误命中 |
| **L3** | 树总量收敛：112 GiB / 24 棵 → 「1 日常 + ≤3 活跃 lane」 | 24 棵里多数已归档 | 根盘从 86% 降到 ~70% | 需逐棵确认（D4） |
| **L4** | `-j` 与内存联动：`JOBS` 上限随 `MemAvailable` 调整 | `-j16` + 24 GiB tmpfs 同抢 61 GiB | 避免 OOM 抖动 | 低 |

> L1/L2 与内存盘**互补**：L1 让内存盘容得下，L2 让「树丢了」也不疼。实施顺序建议 **P0→P2（内存盘收益验证）→ L1 → L2**。

体积：树 **7453 → 3227 MB（−57%）**；`vmlinux` **673 882 896 → 80 533 480 B（−88%）**。
内存：全程 `MemAvailable` ≥ **43.9 GB**（tmpfs 上驻 7.3 GB 树）；A4 ✓。
身份：DTB sha 跨路径**相同**（`6c07499f4025c51a`）；`Image.gz` sha **不同** —— 差异仅 **GNU build-id 20 字节**（`cmp` 定位），树路径**未**进入 Image（`grep -c` = 0）⇒ **A3 不成立，但原因是判据本身不适用**：build-id 由含 DWARF 的 vmlinux 摘要得出，换树路径必然变。跨落点/跨树的同源判据只能用 `uname -r` + config 锚点 + System.map 符号（即现成的 `assert-kernel-sane.sh`），**不能用镜像 sha256**。

### 9.2 裁决

1. **内存盘构建区：不落地（A1 未达标）。** 结论与 §0-6 的一致：增量环只有 **31 s**，且写路径不是瓶颈（ext4 日志 + page cache 已足够）；把树搬进 tmpfs 反而吃掉 7.3 GB 常驻内存。**日常树 `linux` 符号链接保持不动**（未做 P3/P4）。
2. **`/dev/shm` 只作临时 A/B 用场，用完即清**（已清）；不再保留常驻内存盘。
3. **§8-L1（迭代树关 `CONFIG_DEBUG_INFO`）落地为显式 profile**：增量环 **−31%**、树体积 **−57%**、`vmlinux` **−88%**。默认不动；做法 = `CONFIG_DEBUG_INFO_NONE=y` + `# CONFIG_DEBUG_INFO_DWARF5 is not set`（**必须同时改 choice 成员**，只写 `# CONFIG_DEBUG_INFO is not set` 会被 `DEBUG_INFO_DWARF5` 的 `select` 拉回 `=y`——实测第一次就是如此失败）。
4. **方法论教训（比结论更重要）**：**ccache 是冷编墙钟的主导变量**。p2a(566 s) 之所以不慢于 p0a(560 s)，靠的是热 ccache；L1 改 config 后 cache 全 miss，反而把 no-debug 的编译收益掩盖成 +5.6%。**换 config 的 A/B 必须让两侧 ccache 状态同构**（同路径、同 config 已预热，或两侧都清空 cache），否则量到的是 cache，不是变量。
5. 副产品：`rambuild.sh` 保留为**测量/守卫工具**（不再承担默认构建路径）；`snapshot` 已加护栏（已编译的树未跟踪文件 > 2000 个 ⇒ 不打包产物）。
