> 口径来源：`TASKS/README.md` §5 Q28 / §7 M6、`reports/local-cleanup-q24-q28-20261015.md` §3 方案 A、
> `reports/upstream-q24-q28-standard-20261015.md` §2。

## 0. 这是什么实验 / 为什么值得做

**假设**：本板面板**不需要** vendor 的自定义 bonded 广播命令协议；标准 `IS_SYNC_NEEDED()` 双写路径
（`msm_dsi_manager_cmd_xfer()` 的 `need_sync` 分支，**仍在树内**）就够用。

**为什么旧否证不算数**（本实验的立论前提）：

| 旧证据 | 问题 |
|---|---|
| P2b「上游 DSI 路径 1 发 GOOD、无 Q28 签名」（2026-10-13） | ① 单发；② 复测 4/4 未复现；③ **从未做面板实测** |
| P2b/P2c「上游 DSI 点不亮面板」 | 取证窗口 = **2026-10-13/14 上午**，而 M1 树的显示回归 **2026-10-14 12:40 才由 E1b 修复** ⇒ **整批结论被污染** |

⇒ 「上游命令路径点不亮」这个结论**从未在 E1b 修复之后复测过**。arm A 正是补这一课。

**收益（二值都有信息量）**：
- **亮** ⇒ 删掉 **≈500 行** vendor 命令协议，且 Q28 的 `-110` 签名**从源头消失**（协议不存在，故障模式随之改变）。
- **不亮** ⇒ 缺口精确收缩到 **H39/H40**（`msm_dsi_host_enable` 时机）或 **PHY** 增量，可只保留那几行。

## 3. ⚠️ 判据陷阱：本板坏发是「假 GOOD」

**2026-10-15 实测（真坏发，`L1FAIL`）**：

```
l1=5  l2=2041  card0=1  connected=1  session=1  phoc=1  phosh=1  wayland=1  backlight=160
card0-DSI-1=connected        <-- 假 GOOD 诱饵
dsi_isr = 0                  <-- 真判别量：DSI 中断一次没来
```

⇒ **`card0-DSI-1 connected` / phoc / phosh / wayland / grim 出图，在坏发上全部为真**。
唯一可信的组合判据：

- **`l1 == 0`**（无 `command DMA timeout` / `bonded command DMA failed` / `Failed to initialize panel`）
- **`dsi_isr` 非 0**（`/proc/interrupts` 里 `dsi_isr` 行；**好发实测 = 41**，坏发 = 0）
- **★ `core_irq` 受激递增**（见下方修正——**不要**用固定时间窗）
- **用户目视面板有内容 + 可触摸**

> **⚠️⚠️⚠️ 判别器修正 v3（2026-10-15 s3 **用户目视**后，**最高优先级**）**
>
> **软件侧没有任何单一量能判「面板亮了」。** s3 实测：DPMS On、connector `enabled`、背光开
> （用户按电源键 160→511 生效）、`disp_cc_mdss_pclk0/1_clk_src = 172991986 Hz` 被
> `ae94000.dsi`/`ae96000.dsi` 认领、`byte*` 全部认领、`crtc intf_mode=2`、
> 受激 `core_irq` delta=8/次、`grim` 出 1904×3040 且解码 151 个不同字节值 ——
> **而面板是黑的（用户实拍）**。
>
> - `grim` 抓的是**合成器自己的 buffer**，不是面板输出 ⇒ **不能**当「点亮」证据。
> - `core_irq` / `msm` IRQ 递增只证明 **DPU 在跑**，不证明**面板收到了有效视频**。
> - ⇒ **`PITFALLS #251/#255` 是对的：唯一可信判据 = 用户目视。**
>
> **★ 唯一在软件侧有判别力的量（本会话经验，n 小仍须目视确认）**：
> **`dsi_isr`（`/proc/interrupts` 里 mdss IRQ 4 那条）**
> —— 好发（baseline s2，用户确认亮）= **41**；arm A 两发（用户确认黑）= **0 / 0**。
> ⚠️ 但 arm A 换了命令路径、IRQ 记账方式可能随之不同 ⇒ **`dsi_isr` 仍不能单独作数**，
> 只能作**辅助**，最终一律以目视为准。
>
> **已排除的伪判据**：`DSI PLL(0) lock failed status=0x0` ×4 与 `orphan reparent failed -110` ×4
> 在**三发样本（含 GOOD 的 s2）中完全相同** ⇒ 属早期 probe 伪影，**无判别力**。
>
> **采样纪律变更**：**每一发都必须有用户目视读数**（亮 / 黑 / 仅背光）。
> agent 不能自证「点亮」，采样节奏必须配合用户在场。

**反面参照（坏发上「照常」的静态属性，切勿当判据）**：`card0-DSI-1=connected`、
`crtc-0/state` 的 `intf_mode: 2` 与 `core_clk_rate: 815673600` 非 0、phoc/phosh/wayland 在、
背光 `actual_brightness=160`。

## 4. 采样设计（同会话交替配对）

**理由**：Q28 坏发 ~50% 且**按时间成簇（会话级）**（`PITFALLS #223`）⇒ 单样本 A/B 无判别力，
**跨会话比较也不成立**（10-14 出现过同窗口 6 连坏）。必须**同会话交替**。

**队列（每臂 3 发，交替；共 6 发）**：

```
armA  -> baseline(正常开机) -> armA -> baseline(正常开机) -> armA -> baseline(正常开机)
```

- **armA 发**：用户 POR → `fastboot boot out/boot-elden-armA-nobonded.img` → 判据 → 落 record
- **baseline 发**：用户 POR →（不执行任何 fastboot boot）正常盘启 = 父臂 → 判据 → 落 record

**统计**：配对符号检验（窗内同率 ⇒ 无效应）。3+3 只够判「大效应」；
若结果落在「armA 全好 / baseline 有坏」⇒ 再加到 5+5。

**时间盒**：每发 ≤ 6 min（POR→判→收）；单会话 ≤ 6 发（坏发簇内不必耗）。

### 每发命令

```bash
# 0) 前置
cd /home/xuqianhui1001/y700-elden
bash scripts/trial.sh gate            # 槽位健康门（succ=1 / unbootable=0）
ssh root@192.168.7.1 '/usr/local/sbin/q28-watchdog.sh off'

# 1) 等用户 POR / fastboot 就绪（armA 发）
fastboot devices                       # 出现设备 = 用户已 POR

# 2) armA 发：零写盘 RAM 启动
fastboot boot out/boot-elden-armA-nobonded.img

# 3) 判据（等 ~90 s 到桌面/失败态）

ssh root@192.168.7.1 "grep -E 'dsi_isr|msm_mdss' /proc/interrupts"   # dsi_isr 必须非 0

  "grep -oP 'count:\K[0-9]+' /sys/kernel/debug/dri/0/debug/core_irq | paste -sd+ | bc"; sleep 3; done

  --image out/boot-elden-m1-baseline-f3.img --reset por --deploy none \
  --probe q28 --verdict <…> --logdir logs/<dir> --note "父臂 sN; dsi_isr=<n>; 目视=<…>"
```

## 5. 判定与后续分支

### 5.0 实时战果（2026-10-15 会话，进行中）

**★ 本表一律以「用户目视」为最终判据（软件侧只能作辅助）。**

| 样本 | 臂 | l1 | `-22` | `dsi_isr` | 用户目视 | 判定 |
|---|---|---|---|---|---|---|
| s1 | armA | 0 | **162** | 0 | （未同时目视） | **BAD-NOSCAN** |
| s2 | baseline | 0 | 0 | **41** | ✅ **亮** | **GOOD** |
| s3 | armA | 0 | 0 | **0** | ❌ **黑**（电源键控背光 160→511、音量/音频正常） | **BAD-NOSCAN**（原误判 GOOD，已更正） |
| s4 | baseline | — | — | — | — | 待取 |
| s5 | armA | — | — | — | — | 待取 |
| s6 | baseline | — | — | — | — | 待取 |

**当前计数：armA 0 GOOD / 2 BAD；baseline 1 GOOD / 0 BAD。**

### ★ 初步结论（n=3，方向性，**未定案**）

1. **arm A 到目前为止 2/2 坏，且是「面板黑但软件全正常」的形态。**
   ⇒ **「删掉 vendor bonded 命令协议」很可能不是解**——它把 Q28 的 `-110` 签名去掉了
   （s3 `l1=0`、`reset failure=0`），**但面板依然不亮**。
   **这恰好复现了 P2b/P2c 的命运**（上游命令路径：DRM/合成器全 GOOD、面板无内容）。
2. **s1 与 s3 软件侧表现不同（162×`-22` + core_irq 停滞 vs 0×`-22` + core_irq 前进），
   但两发都是「黑」** ⇒ arm A 自身也不稳定，且有**至少两种**「黑」的形态。
3. ⇒ **arm A 的价值从「候选修复」转为「诊断证据」**：它证明
   **「Q28 的 `-110` 命令 DMA 超时」与「面板不亮」不是同一件事**——
   去掉 bonded 协议能消除前者，**消除不了后者**。后者才是真需求（`local-cleanup` §1 需求 a）。

**若后续 s5（armA 第三发）仍为坏** ⇒ 建议**提前收口 arm A**（0/3 ⇒ 否证），
把 POR 预算转给：① 方案 C 新 delta（GDSC `HW_CTRL_SKIP_DIS` 的零成本 `gdscr` 只读判别）；
② `local-cleanup` 方案 B（把「坏发即 return」改成可恢复）。

## 6. 并列待办（不占 POR 窗口）

### 方案 C ★ 一行修（上游 Pengyu 指路）— 🟡 **2026-10-15 静态调查已完成：指路被「反转」，另挖到一条新 delta**

**结论：Pengyu 指的 `dsi clk source select for the 10-bit CPHY plane` = PHY 的
`DSI_7nm_PHY_CMN_CLK_CFG1.DSICLK_SEL[1:0]` + 它决定的 `disp_cc_mdss_pclk{0,1}_clk_src` 输入频率，
不在 DPU 里**（DPU 全目录 `CLK_SEL|clk_sel|clk_src` 命中 **0**）。

**★ 前提被反转：本树不缺这个 hack。** 三方对照：

| | C-PHY 选择 | pclk_div |
|---|---|---|
| pristine `24a19b953e` | `DSICLK_SEL(3)` / `pll_post_out_div` | 4/7（不可达） |
| **本树** | **`SEL(0)` / `pll_bit`**（payload `640b0e49db`，`dsi_phy_7nm.c:843-861`） | **2** |
| **原厂** `dsi_pll_3nm.c:1196-1217`（bpp=30,lanes=3） | **`sel=0`** | **2** |

数值闭环：`756839941/2 × 16/35 = 172991986 Hz` = 实测 `pclk0/1_clk_src` 逐位吻合
（`{16,35}` 在上游 `clk-rcg2.c:1120`）。⇒ **本树 = 原厂；pristine 才是错的那侧。**

**与 Q28 吻合度 = 不吻合**（4 条判别量全不吻合）：DSICLK_SEL 是 probe 期**一次性静态 mux**；
坏发首命令前寄存器与好发**逐字相同**、好坏发 pclk rate 全同；若它错，症状是上电期
`Failed to set rate pixel clk -22`（= P1/P1b），**根本走不到发 `ff 20`**。
⇒ **停止在 DSICLK_SEL 上投 Q28 工时**；但它是一条**高价值上游化 patch**
（pristine 的 `SEL=3` 对 elden 这类 30bpp/3-lane C-PHY 是错的）→ 记入 M3 显示片。

#### 🆕 新 delta（此前无任何报告涉及，机制上比 DSICLK_SEL 贴 Q28）：GDSC `HW_CTRL_SKIP_DIS`

`git diff 24a19b953e HEAD -- drivers/clk/qcom/dispcc-sm8750.c` **全文仅 2 行**：
`mdss_gdsc`(`:1762`) 与 `mdss_int2_gdsc`(`:1774`) 被 payload 加了 **`HW_CTRL_SKIP_DIS`**
（配套 `gdsc.h:73` 新宏 + `gdsc.c:365-370` 新分支）。

**静态机制**：主线 `gdsc_disable()` 本该调 `gdsc_hwctrl(sc, false)` 清 `HW_CONTROL_MASK`(BIT 1)，
把 GDSC 从 **HW-trigger 模式**交回 SW 控制；`HW_CTRL_SKIP_DIS` 让该调用**永不执行**
⇒ **GDSC 永久停在 HW-trigger 模式**（硬件自行门控）—— 正是「域被闩住、SW/DSI 复位清不掉」的语义。

**为什么值得优先**：payload 独有 · 原厂无 · **全 mainline 仅此一处** ·
作用域正是 **DYN pclk 域所在的 dispcc/GDSC**。

**⚠️ 证据缺口（必须诚实）**：Lenovo stock GPL 包**不含 clk 驱动** ⇒ 只能证明
「vendor display 源码/`reference/` 里没有」，**不能**证明原厂 clk 驱动没有。
且既有观测「`mdss_int2_gdsc` 好坏发都 `off-0`」**看**似有张力——但 `clk_summary` 的 off-0 是
**SW 投票计数**，而本 flag 影响的是 **`HW_CONTROL_MASK` 位**，两者不是同一个量，
**不构成否证**。全程为**静态推断，非硬件事实**。

**建议动作（性价比排序）**：
1. **零成本只读判别**：坏/好发各读一次 `dispcc+0xb000`（`mdss_int2_gdsc`）与 `mdss_gdsc` 的 `gdscr`
   **BIT 1（`HW_CONTROL_MASK`）**，看是否好坏发二分 —— **不需要重建**。
2. 若判别成立：单变量臂只删 `mdss_gdsc` 的 `HW_CTRL_SKIP_DIS`（1 行），按本协议跑 ≥5 发。
3. ⚠️ 回退前先确认 payload 当初加它**不是在修别的东西**（squash 提交看不出意图）。

### 方案 B 把「回避」改成「可恢复」
恢复必须发生在**更高层**（控制器级复位已七臂否证）：panel prepare 失败返回**可重试错误**，
由 DRM/用户态**重走一次 modeset**（而非整机重启）。**前置问题**：「重走 modeset」与冷启是否等价？
先在**已知 GOOD 台**上验证重启 modeset 不破坏显示。
