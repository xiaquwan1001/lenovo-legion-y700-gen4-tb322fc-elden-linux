## 1. P0 — 立即可做（低风险、纯主机侧）

### 1.1 `pack.sh` 是死代码
- 证据：活跃 `scripts/*.sh`、根目录 6 份维护文档均无调用；仅 `flashing-bundle/`（归档快照）和 `archive/` 引用。功能与 `scripts/build-boot.sh` 的 `mkbootimg` 调用重复。
- 优化：删除 `pack.sh`（git 有历史），或标注 legacy；统一由 `scripts/build-boot.sh` 出镜像。

### 1.2 设备锁逻辑复制 5 份，而集中版没人用 ★
- 证据：`scripts/flash-b.sh:15`、`scripts/kexec-boot.sh:23`、`scripts/mod-loop.sh:20`、`scripts/to-fastboot.sh:20`、`cycle.sh:10` 都是**注释里写「see scripts/device-lock.sh」但正文内联同一段 `flock`**；全库无一处 `source`/调用 `device-lock.sh`。
- 优化：各脚本改成 `exec scripts/device-lock.sh <原命令>` 或 `. scripts/device-lock.sh` 后复用；单一真源。改一处即全站生效（当前改锁语义要改 6 处）。

### 1.3 boot 镜像构建逻辑三处重复
- 证据：`scripts/build-boot.sh`、`build-boot-slim.sh`、`build-initramfs.sh`、`build-manifest.sh` 各自探测内核 UTS、拼 cmdline、调 `mkbootimg`。
- 优化：抽 `scripts/lib-bootimg.sh`（cmdline + UTS 探测 + mkbootimg argv），三处 source。

### 1.4 解包器两份
- 证据：`tools/mkbootimg/unpack_bootimg.py`（AOSP 官方）与 `env-pass/tools/unpack_initboot.py`（自研 init_boot 解包）。
- 优化：核实 `unpack_bootimg.py` 是否已覆盖 init_boot header v4；若覆盖则删自研版。`env-pass/` 本身是并行的安卓取证小工作流，应明确它是「历史证据区」而非第二工具链。

### 1.5 init 化石清理
- 证据：`rootfs/init.bak-20260930`、`rootfs/` 下旧 init 副本；设备侧历史有 6×`patch-init-*.sh`（见 `.pi/plans/2026-10-06-用户态查漏补缺.md` §0）。
- 优化：唯一真源已定为 `initramfs/init`（P3），删除 `rootfs/init.bak-*`，legacy 回退路径保留但写清退场条件（`/etc/elden-init-mode`）。

### 1.6 check-doctor 增加防回归静态检查
- 内容：① bashism 扫描（`#!/bin/sh` 文件里出现 `[[`/`$'...'`/数组/`pipefail`）；② 死脚本（`scripts/*.sh` 无被引用）；③ 锁块是否仍被复制（检测 `flock -w` 出现次数 > 1 处）。
- 依据：P1/P2 的根因是「脚本语言/工具选择」，靠一次性修复会回归。

## 2. P1 — 可用标准工具替代自研（需小验证）

### 2.1 自研 GPT 编辑器（3 个 Python）
- 现状理由（脚本自述）：「sgdisk/gdisk 假定 512 扇区，会误读 4 KiB 扇区设备，故手写」。
- 本机实测：
  - `sgdisk -p env-pass/gpt-20261002/gpt_primary.bin` → 报 `Sector size (logical): 512 bytes` + `Creating new GPT entries in memory`（**确实误读**）。
  - `sfdisk -l --sector-size 4096 ...` → 正确识别 `扇区大小(逻辑/物理)：4096`（**sfdisk 原生支持指定扇区大小**）。
  - `losetup -b 4096` / `losetup --sector-size 4096` 可把 dump 挂成 loop 后给 `sgdisk`/`parted` 用。
- 结论：**GPT 分区编辑是半轮子**——标准工具能做到，但需 `losetup -b 4096` + 完整几何；而本项目的 dump 是 header-only（34 扇区）且 A/B slot 属性读取无标准 CLI。
- 优化建议：
  1. `gpt-surgery` / `gpt-restore` 的**分区增删/改大小**优先改用 `losetup -b 4096 <dump> && sfdisk/sgdisk`，Python 只保留 header-only dump 的薄封装；
  2. `slot-attr.py`（读/写 GPT entry attribute 的 A/B 元数据）**保留**——`sgdisk -A/-i` 可读写属性但语义弱于其专用逻辑，属真轮子理由充分；
  3. 若保留 Python，至少在脚本头写明「已核实 sfdisk --sector-size 4096 可用，仅因 header-only dump 自研」。

### 2.2 `scripts/bisect/eldtest.sh` → `git bisect run`
- 现状：自研渐进触发 + 矩阵表 + 版本映射。
- 优化：`git bisect run` 处理「哪个提交引入回归」，`eldtest.sh` 只保留「矩阵表/flash-b 动作/串口事件等待」作为 bisect 的 action 脚本；回归区间已定位（vk34→vk40），此优化价值中等，不急。

### 2.3 等待/重试轮询
- 证据：`cycle.sh` 的 `wait_fastboot/wait_linux`（sleep 2/3 轮询）、`net-up.sh`、`ath12k-retry.sh`、`time-sync.sh`。
- 优化：设备侧已上 OpenRC，网络/服务就绪用 `nm-online`/`udevadm settle`，慢起服务用 OpenRC `respawn`/`supervise-daemon` 替代手写循环；`eldtest.sh` 已示范「事件驱动（串口 banner）优于 tight 轮询」，可推广。

### 2.4 `extract-avbpubkey.py`
- 现状：手写 AVB header 偏移解析，注释称原脚本丢失后重建。
- 优化：`tools/avbtool.py`（已 vendored）能解析 image 结构；核实能否用 `avbtool info_image` + `avbtool extract_public_key` 覆盖，覆盖则删自研。低优先。

### 7.1 强候选：标准工具直接可替代自研（建议优先核实）

| 自研物 | 生态对应物 | 说明 | 来源 |
|---|---|---|---|

### 7.1.1 qbootctl vs `slot-attr.py` 能力矩阵（源码级，2026-10-07）

| 维度 | `slot-attr.py`（自研） | `qbootctl`（标准） |
|---|---|---|
| 扇区大小 | 硬编码 4096 | `ioctl(BLKSSZGET)` 自动 ⇒ **4K 无风险** |
| 多盘/LUN | 手写按设备/dev/sde | `update_slot_attribute` 按盘分别提交（注释举 `/dev/sde`） |
| mark successful | ✅ `mark-successful b` | ✅ `-m b`（写 primary+backup+CRC，**不走 UFS BSG**） |
| 状态读 | ✅ `show` | ✅ 无参 dump / `-n` / `-b` / `-c` / `-a` |
| set active | 可 | `-s`（**额外走 UFS boot-LUN BSG 切换 xbl**；`-i` 忽略 BSG） |
| retry 计数单改 | ✅ `set --retry 7` | ❌ 无独立参数；但 `-s` 写 `AB_SLOT_ACTIVE_VAL=0x3F` 即 retry=7 |
| 离线 dump 编辑 | ✅ `--image x.bin` | ❌ 无 file 模式（必须 by-partlabel） |
| 自动开机置成功 | ❌ | ✅ `qbootctl-openrc` 服务 |

**结论**：`-m`/状态读 可由 qbootctl 取代；**离线 dump 编辑 + retry 单改** 保留 `slot-attr.py`；**`-s` 慎用**（本项目 xbl 不走该 boot-LUN 路径，用 `-i` 或缺省 `slot-attr.py`）。

### 7.1.2 主机侧合成 GPT 冒烟（已备脚本；设备侧已直接实测）

> **2026-10-07 设备侧实测已完成（WiFi 10.42.0.246，elden/vk47clean/OpenRC），结论：qbootctl 可完全取代 `slot-attr.py mark-successful`。**

**实测结果**：

| 步骤 | 命令 | 结果 |
|---|---|---|
| 只读基线 | `slot-attr.py show` vs `qbootctl`/`-n`/`-b` | **逐项一致**（boot_a active0/succ0/unboot0；boot_b active1/succ0/unboot0） |
| 前置 | `apk add qbootctl` | Alpine 有包；`/dev/disk/by-partlabel/boot_a→sde12`、`boot_b→sde45`（LUN4）均在 |
| 写入 | `qbootctl -m b` | boot_b byte6 **0x0f → 0x4f**（succ=1）；boot_a 保持 0x3a |
| 独立校验 | 手写解析 primary+backup 条目 | primary idx44=0x4f、backup idx44=0x4f，**两表都写** |
| 回读 | `qbootctl -n b` / `slot-attr.py show` | 都报 succ=1 |
| GPT 完整性 | 内核 dmesg | 写入后重扫全部 78 分区**无 CRC 错误** |

**两个关键注意点（上机暴露）**：
1. **cmdline 无 `slot_suffix`** ⇒ `qbootctl -m`（不带槽位）会回退到 **slot a**（`getCurrentSlot()` 失败返 0）——**必须显式 `qbootctl -m b`**；或给 boot cmdline 加 `androidboot.slot_suffix=_b`。
2. 写入会触发内核分区重扫，**紧跟其后的 `qbootctl -n` 可能瞬时报 “No slots found”**（by-partlabel 在重扫窗口内暂不可见）；等 1–2 s 再读即正常，非 GPT 损坏。

**残留**：`-s`（set active，走 UFS BSG 切 xbl）**未测**，本项目也不需要；`slot-attr.py` 保留用于**离线 dump 编辑**与 **retry 单改**。

> 主机侧合成冒烟脚本仍保留在 `.pi/plans/2026-10-07-qbootctl-synth-test.sh`（用于日后回归，需 sudo）。

| **整套构建/刷写层**：`build-rootfs.sh`(chroot+apk) + `build-initramfs.sh` + `build-boot.sh` + `flash-b.sh` + `lane.sh` + 自研 deviceinfo/GPT 脚本 | **`pmbootstrap` + `pmaports`（postmarketOS / 现名 Nura）** | pmbootstrap 就是「chroot 里构建 Alpine rootfs + 内核/模块包化 + 生成 initramfs/boot.img + 安装到设备」的统一工具；pmaports 有 `device-*`/`firmware-*`/`msm-firmware-loader`/`qbootctl` 等设备包体系。**注意**：本项目在 `archive/topics/USERLAND-STACK-2026-10-05.md` §4 只把 postmarketOS 当作**用户态栈备选**评估过，**从未评估用它的构建/刷写工具链替代自研脚本**（`pmbootstrap` 全库 0 命中）——这是本次新增的对比维度 |
| 同上 | **`alpine-make-rootfs`** | 轻量级 Alpine rootfs 构建脚本（比 chroot 手写更标准）；仅覆盖 build-rootfs 一半 |

> **判断**：pmbootstrap 替换是「用一个成熟工具链换掉 ~10 个自研脚本」，收益大但引入外部依赖/学习成本/与现有 lane/vk 版本体系冲突；**建议作为用户级决策项**，不擅自替换。

## 8. 结论（扩展后，一页）

- **代码层轮子**：P0 已修（设备锁/死代码/静态门禁）；剩 P1（GPT 编辑器、eldtest→git bisect）与 P2（保留项登记）。
- **qbootctl 实测结论（设备侧）**：✅ **可完全取代 `slot-attr.py mark-successful`**（含 primary+backup 双表、4K 扇区、LUN4）；保留 `slot-attr.py` 仅用于离线 dump 编辑与 retry 单改。使用注意：**显式带槽位 `-m b`**；写入后隔 1–2 s 再读。
- **生态层轮子**（本次新增最强）：
  - ★ **`qbootctl` 大概率可取代 `slot-attr.py`**（官方 boot_control HAL，Alpine 有包）；
  - ★ **Alpine `mkinitfs`** 覆盖 `build-initramfs.sh` 的模块/固件收集；
  - ★ **`pmbootstrap` 可整体取代构建/刷写脚本层**（从未评估过，属用户级决策）；
  - ★ **`waydroid_script`** 覆盖 G2 的 GApps/Widevine 注入。
- **不该动的**：`pil-squasher` 反向、postmarketOS 用户态栈、上游 DT（GEEKiDoS/Pengyu Luo）、Box64 路线——都有意选取或已评估，避免反向造轮。
