## 0. 要回答的唯一问题

`fastboot boot` 形态下 ESP 能枚举（`fs=8`、loader 起、内核从 ESP 起），**flashed 形态（写 `boot_a`）下只有 `fs=1`**
⇒ 路线 B 还不能当默认启动。p62 加了两种新证据：

1. **普查行**（回退路径必经）：`[K] pi n=` / `[K] pi <i>=<GPT 分区名>` / `[K] fs i=<n> p=<分区号> nm=<名>`；
2. **兜底**：按 GPT 名 `eldenesp` 找 `PartitionInfo` 句柄 → `ConnectController(TRUE)` → 按分区 GUID 认回 SFS 卷 → `LoadImage`。

判据通道（本轮定案，`PITFALLS #580`）：**`logfs` 只在回退到 FV `LinuxLoader` 时才被写** ⇒

| 现象 | 含义 |
|---|---|
| logfs **无新记录** + `/efi/loader.log` 新写 + 内核 cmdline 带 `elden_bootloader=esp` | **成功**（R63 兜底成立） |
| logfs **有新记录**（含 `[K] esp in v=R63` + 普查行） | **失败**，按普查读数分类（见 §3） |

## 2. 动作（每步可中断回退）

```bash
# 0) 留底
ssh root@192.168.7.1 'sha256sum /dev/disk/by-partlabel/boot_b; cat /efi/loader.log | md5sum; cat /efi/espboot.log | md5sum'
#    ↑ 记下 loader.log 的**当前内容指纹**，判定「新写」就靠它（ESP 上的文件会跨启动保留）

# 1) 进 fastboot
ssh root@192.168.7.1 'sync; eldroid-bootctl reboot bootloader'; sleep 12; fastboot devices

# 2) 写 p62 → 槽 a（写盘，需批准）
fastboot -s HA2EXB0E flash boot_a out/r21-sbstop-p62/uefi-preamble62-r1.img
fastboot -s HA2EXB0E --set-active=a
fastboot -s HA2EXB0E reboot
```

## 3. 判定分支

| 结果 | 下一步 |
|---|---|
| **成功**（见 §0 表） | 进入「正式化」：去掉 `\espboot.force` 依赖、确认 `BootIntoFastboot` 不再写死、决定是否把 UEFI 做成默认启动；并评估「BDS 连上存储后标记活动槽 successful」（第三方 `retro98boy` 同机型机制，防 retry 耗尽回退） |
| 失败且 `[K] pi n=0`（或没有 `eldenesp`） | 分区层没出来 ⇒ 搬第三方 `StorageConnect.c`：非可发现 UFS 设备 → 逐 LUN `ScsiIo` 连接（`Lun>=8` 跳过），并把 `UFSDxe` 在 `APRIORI.inc` 排到 `QRKSDxe` 之后（`mu_wide_platforms#13`） |
| 失败但 `pi` 里有 `eldenesp`、`espb n=0` | 分区在、Fat 没绑 ⇒ 下一步直接读 FAT 引导扇区（绕开 SimpleFileSystem/ConnectController） |
| 设备进 fastboot 或回 `_b` | 回灌 `backup/boot_a-pre-uefi-20261108.img` → `--set-active=b` → 起来后 `mark-successful b`；把 logfs 新记录归档 |
