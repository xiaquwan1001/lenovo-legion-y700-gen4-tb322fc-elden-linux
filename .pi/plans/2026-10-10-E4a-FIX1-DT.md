## 1. 结论：FIX-1 落点 = `RPMHPD_MXC`（**不是** 任务书写的 `*_AO`）

任务书/深研文档把 FIX-1 写成「改挂恒开对等体 `RPMHPD_MX_AO` 或 `RPMHPD_MXC_AO`，依据
`rpmhpd.c` active_only peer」。**源码核查证伪了这条依据**，已升级为需决策项并由上级批准改为 A)
`RPMHPD_MXC`（非 AO）。依据链：

| # | 源码事实（本树实测） | 位置 |
|---|----------------------|------|
| 1 | `RPMHPD_MX_AO`=9 / `RPMHPD_MXC_AO`=11 确实存在，SM8750 域表暴露 `mx_ao`/`mxc_ao` | `include/dt-bindings/power/qcom,rpmhpd.h:18-21`；`drivers/pmdomain/qcom/rpmhpd.c:647-665` |
| 2 | **AO ≠ 恒开。** `to_active_sleep()`：`*active = corner; if (pd->active_only) *sleep = 0; else *sleep = *active;` ⇒ 挂在 `*_AO` 域 = 只投 ACTIVE_ONLY + WAKE 票，**SLEEP 票被清 0**（深空闲/suspend 允许该轨塌，wake 再恢复）；挂在**非 AO** 域（现役 `RPMHPD_MX`）active==sleep，才是 Linux 侧更强地板 | `drivers/pmdomain/qcom/rpmhpd.c:951-959`（`to_active_sleep`）、`:971-1020`（`rpmhpd_aggregate_corner()` 分别下发 `RPMH_ACTIVE_ONLY_STATE` / `RPMH_WAKE_ONLY_STATE` / `RPMH_SLEEP_STATE`） |
| 3 | AO 只是 genpd 内部聚合用的 peer（`mx.peer = &mx_ao`、`mx_ao.active_only = true`，同一 `res_name = "mx.lvl"`，同一 ARC 地址），**全树 DTS 无任何节点挂 `*_AO`**：`grep -rn "RPMHPD_[A-Z0-9]*_AO" arch/*/boot/dts/` → **0 命中** ⇒ 把设备挂 AO 索引无上游先例，不可上游 | `drivers/pmdomain/qcom/rpmhpd.c:178-205`（mx/mx_ao、mxc/mxc_ao 定义） |
| 4 | 上游同树写法均用**非 AO** 域：`camcc` = `<&rpmhpd RPMHPD_MMCX>, <&rpmhpd RPMHPD_MXC>`（上游 v3→v4 changelog 称 MXC 是 always-ON 轨）；衍生 SoC `kaanapali` 的 cambist = `<&rpmhpd RPMHPD_MMCX>, <&rpmhpd RPMHPD_MX>` | `arch/arm64/boot/dts/qcom/sm8750.dtsi:3733-3742`、`arch/arm64/boot/dts/qcom/kaanapali.dtsi:1567-1583` |

⇒ 「让该轨在本块生命周期内根本不塌」的意图，只有**非 AO 的 MXC** 才同时满足：① 脱离可关断的 MX；②
落在上游明确称为恒开轨的相机侧 MXC；③ 保留 SLEEP 票（比 AO 更强）；④ DT 一行、可上游化表述。

**本补丁的性质（须写清，不冒充上游对齐）**：设备侧实验变体。上游 2026-09 RFC（`[PATCH RFC 11/15] arm64:
dts: qcom: maili: Add support for cambistmclkcc and camcc`）里 cambist 仍是 `MMCX + MX` 双票，主线尚未意识
到该问题；原厂 DT 该块只挂 `vdd_mx`。故本改动是「把 Linux 对可关断 MX 的票换成对 MXC 的恒开票」的**单变
量实验**，成败由 §5 的 ≥9 轮熄屏扫掠判定。

## 2. 改动（唯一功能改动 = 1 行）

`linux/arch/arm64/boot/dts/qcom/sm8750.dtsi`，节点 `cambistmclkcc: clock-controller@1760000`（:2092）：

```diff
-			/* H1 experiment: dropped power-domains/required-opps
-			   (matching the vendor vdd_mx-supply style).
-			   H2: bind to MX only -- the upstream v3->v4 series
-			   describes MX/MXC as the always-on rail, so MMCX is
-			   the collapsible one; verify the MMCX coupling. */
-			power-domains = <&rpmhpd RPMHPD_MX>;
+			/* Q24 FIX-1: bind to MXC, the camera-side always-on
+			   rail used by camcc below, instead of the collapsible
+			   MX.  This block has no GDSC and no clock consumer, so
+			   qcom_cc_really_probe() leaves it programmed (PLL0 +
+			   SLEEP_CLK CBCR, AHB clock kept on by GCC) after its
+			   trailing pm_runtime_put(); collapsing its rail then
+			   hangs the NoC and drops PS_HOLD.  RPMHPD_*_AO is not
+			   the always-on choice: rpmhpd.c to_active_sleep()
+			   zeroes the sleep vote for active_only domains, so
+			   only a non-AO domain holds a floor in deep idle.
+			   Device-side experiment variant, not upstream parity
+			   (upstream cambist still uses MMCX + MX, and the vendor
+			   DT supplies this block from vdd-mx). */
+			power-domains = <&rpmhpd RPMHPD_MXC>;
 			required-opps = <&rpmhpd_opp_low_svs>;
```

- `required-opps` 不变（`low_svs`）；`clocks`/`reg`/`#*-cells` 不变。
- 变体唯一性：`sm8750-lenovo-elden.dts` **不覆盖** cambist 的 `power-domains`（只引用
  `&cambistmclkcc` 出 MCLK3/MCLK4，:2280/:2318），故 SoC dtsi 一处生效，无第二处变体需同步。
- 生效验证（反编译产物）：`power-domains = <0x24 0x0a>`（phandle 36 = `rpmhpd`，index **0x0a = RPMHPD_MXC**）。

- 剩余路线：FIX-2（probe 后不 put、常持票）/ FIX-3（lazy-on + runtime_suspend quiesce）/ 或不从 Linux 实例化该块（原厂 = vdd_mx-supply + 从不触碰，行为等价「零相机模块」规避态）。

## FIX-3 / FIX-2 上机判定（2026-10-10 深夜，卡 logo / 起不来）

- **FIX-3（vk82，e1d2c658a）**：卡联想 logo，无法启动。**根因分析**：FIX-3 删掉 `desc.use_rpm` → `qcom_cc_really_probe` 不再 `pm_runtime_resume_and_get`，probe 内部立即读写未 resume 的 MXC 电源域下的 MMIO → NoC hang 拖死后续 probe（显示链挂）→ logo 卡住。**已 revert（67fcff7f0）**。
- **FIX-2（vk83，86193a58a，revert+FIX-2）**：两次 boot：第一次卡 logo；第二次过 logo 但内核起不来（无 ssh，屏幕只剩充电标志）。
- **结论（初步，需下次上机复核）**：cambist 驱动侧 PM 改动（FIX-2/3）都影响启动链路——共同点 = 都动了 probe 的 runtime PM 票时序；而 vk81（E4a MXC DT + 原版 probe）能正常启动。候选解释：① probe 后常持票/不持票都让 GCC/显示 probe 顺序出问题（CAM BIST MCLK 域在 boot 早期被显示/相机路径依赖，任何状态都错）；② 偶发（vk83 第二次过 logo 但内核不响应 ssh = 另一形态，可能 Q28 变体或内核 panic 静默）。
- **下一步（待续）**：① 用 ttyACM0 串口（设备 boot 时枚举）抓 vk83 卡 logo / 不响应的早期 dmesg 定位；② 或回退到 vk81 判定态（E4a MXC + 原版 probe 可启动 + 熄屏即死），把「换轨无效 + 驱动侧两条路都破启动」一起写进 v2 邮件 follow-up 发上游；③ FIX-2/3 镜像（vk82/vk83）保留作为证据。
- 设备安全：卡 logo/无 ssh 形态均物理重启即恢复；boot_b（vk64 持久版）未受影响。
