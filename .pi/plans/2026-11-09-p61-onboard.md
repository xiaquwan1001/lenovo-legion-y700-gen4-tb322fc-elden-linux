## 0. 要验证的唯一问题

`fastboot boot` 形态下 ESP 能枚举（`fs=8`），而 **flashed 形态（写 `boot_a`）下只有 `fs=1`** ⇒ 路线 B 无法走向「默认启动」。
p61 = p60 + `20261108R62-espconn`：`fs < 2` 时对 `LocateHandleBuffer(AllHandles)` 逐句柄 `ConnectController(..., TRUE)`，
`Stall(300 ms)` 后重扫，并打 `[K] esp fs2=<n> all=<n>`。

**判据（一发定成败）**：固件环行日志里出现 `[K] esp fs2=` 且数值 `>= 8`，随后 `[K] esp ld=Success i=<n>`，
内核起来且 `/proc/cmdline` 含 `elden_bootloader=esp`、`boot_b` sha 不变。

## 2. 动作（每步都可中断回退）

```bash
# 0) 设备仍在 Linux 时留底
ssh root@192.168.7.1 'dd if=/dev/disk/by-partlabel/boot_b bs=1M | sha256sum'   # 记下，末步比对

# 1) 进 fastboot（长边口，PITFALLS #…）
ssh root@192.168.7.1 'reboot bootloader'; sleep 12; fastboot devices

# 2) 写 p61 → 槽 a（写盘动作，需批准）
fastboot -s HA2EXB0E flash boot_a out/r21-sbstop-p61/uefi-preamble61-r1.img
fastboot -s HA2EXB0E --set-active=a
fastboot -s HA2EXB0E reboot

# 3) 观察（120 s 内）：USB 是否回 NCM、ssh 是否起、面板上是否有菜单
#    屏上：R60 菜单（音量上/下移动、电源确认）→ 选中后 loader 读 ESP
#    日志（设备回来后可读）：ESP 上 \loader.log 与固件 ring（scripts/uefi-boot-trial.sh 的 abl-log 通道）

# 4) 判据采集
ssh root@192.168.7.1 'cat /proc/cmdline; uname -r; sha256sum /dev/disk/by-partlabel/boot_b'
```

## 3. 判定分支

| 结果 | 结论 | 下一步 |
|---|---|---|
| `fs2>=8` + `ld=Success` + 内核起（cmdline 带令牌） | **R62 成立**，flashed 形态可用 | 正式化（去 `\espboot.force`/`BootIntoFastboot` 写死）+ 决定是否把 UEFI 做成默认启动 |
| `fs2` 仍 `< 8` | 不是「ConnectController 时机」问题 ⇒ 是 ABL 传参/DTB 差异 | 改按 GPT 名 `eldenesp` 找 `BlockIo` + 手工读 FAT 引导扇区（绕开 SimpleFileSystem 枚举） |
| 设备进 fastboot / 回 `_b` | 与上一发同型（内部回退） | `flash boot_a backup/boot_a-pre-uefi-20261108.img` 复位；记录 ABL 日志 |

## 4. 回退（任一时刻）

```bash
fastboot -s HA2EXB0E flash boot_a backup/boot_a-pre-uefi-20261108.img
fastboot -s HA2EXB0E --set-active=b      # 若当前在 a
fastboot -s HA2EXB0E reboot
```

## 5. 需要人做什么

- **批准写 `boot_a` 这一次写盘**（唯一不可逆面是 Android 槽 A 的内核，已备份）。
- 设备起来若停在菜单：按**音量上/下**选择、**电源键**确认（这一步是物理动作）。
- 若彻底不回（预期不发生）：长按电源 10 s 断电重开。
